# 按变更选择检查

下面路径是 FS-Workbench 的导航线索，不是永久活动源。先在当前树核来源映射和线上回执；文件迁移时更新指针，不从历史副本恢复规则。

| 变更/症状 | 必查内容 | 够用的验收依据 |
| --- | --- | --- |
| 昨日归档优先或窗口缩短 | 闭合时区、共享发布的实际日期切片、目标字段覆盖、原任务 ID、等待状态、临界时刻旧证明 | 跨午夜归档未齐不采价，正常发布后只续跑一次，超时和重启不补跑错过的时段，实际入口显示等待且原操作仍可对账 |
| 优惠或统计日期窗迁移 | 共享取数、金额加权、冻结的发布和日期修订、写前重新读取、前端日期、Hermes 与知识、历史回执版本 | 有昨日时使用完整新窗，缺日或变更拒写。跨日重算新窗口。订单结构、成本、效果各按自身合同核对 |
| 财务、优惠或分档规则 | 主/近期订单结构、金额加权分母、购买/赠送/交付量、原生舍入、候选冻结与实际可写表 | 正常及边界候选从真实生产者走到写前证明；目标和底线分别验，不把平均假设说成每笔保证 |
| 平台、商品或写入协议 | 商品模型/站点、ALL 底稿、原数量/赠送、原生联动、当次成功回执、指定主站完整价表 | 写前漂移拒绝、一次提交、主站逐档读回；旧协议历史原编号仍能对账 |
| 改价后同步消费者 | Players 分类同步、Evolutions、Bundles、SBC 的实际数据源与单位 | 读取函数/实际回执各自核验；上游成功不替代消费者成功，旧待核任务不能清掉冒充恢复 |
| 监控误报/自动化卡住 | 监控基准所用协议、每平台确认时间、公开观测时间/规格、探针输出字段与恢复状态机输入 | 新鲜匹配、新鲜错价、旧观测/缺数据各一例；原自然探针及恢复状态，失败码与报警事件含义正确 |
| 自愈/通知 | 原编号队列重试、对账及后续办理、恢复后下一原周期；通知接受与实际送达 | 近期真实回执；服务商 accepted 不等于已送达，记录缺证明而非伪称失败或成功 |
| 新老客/成本覆盖异常 | 同批订单在共享 ES 当前发布、旧效果快照及消费者字段映射中的覆盖 | 在机内同订单关联，只输出聚合；有效原生标记能流入效果归档，缺失保留合法旧值，冲突显式，不用区间首见冒充终生新客 |
| 规则影响复盘/学习 | 小额/大额、平台、同钟点窗口、可比价差、归属/成本/客群覆盖、Hermes 引用版本 | 当前执行事实与预测、自然报告、模型实际消费分开；能判断总体经营时不为局部缺数否定全部，自动晋升仍按当前合同 |
| 文档/定时任务/图索引 | 当前合同、排障入口、已启用复查任务说明、知识目录、图的实际 checkout | 当前规则不被历史参数覆盖；保留原周期与暂停状态，文档/装载/模型使用分别核验 |

## 行为检验例子

仅当相关分支改动时选用：

- Admin 已明确保存并核对主站，新公开观测还没到：保留 Admin 确认，公开观测标待核；不得拿改价前价格制造错价或称公开已匹配。
- 同一有效当前操作的新鲜公开价只一个平台不一致：只标对应平台，不抹平为全站正常或全平台坏。
- 效果归档标记不足但共享 ES 有同订单原生标：先查消费者/修订，复用共享事实补齐；不让用户重新提供已存在的数据。
- 保存回执丢失但现价恰好相同：沿原编号查真实结果；不能换 ID 再写，也不能凭巧合认旧操作成功。
- 规则上线而 24 小时未满：工程验收可结束，经营效果由原定复盘续接；不另建高频采集或等待一天才交付。
