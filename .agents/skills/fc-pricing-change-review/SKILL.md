# FC 定价规则变更验收

把“新规则已实现”核到“相关链路实际按新规则工作”。按变更范围裁剪，不把每次改价做成全仓审计；实际经营效果与工程验收分别结论。

纯 UI 文案或样式修改直接沿项目 UI 维护规范检查受影响页面，不进入下列定价流程。只有涉及定价行为、数据口径、执行或监控复盘时，才选择对应链路检查。

## 先确定本次改什么

1. 确认实际 Git 工作树、未提交改动、远程版本及线上活动源。读取该树 AGENTS.md、docs/ops/HOTFIX.md 和适用来源映射；有 CodeGraph 时核其 projectPath 与提交版本，图不能证明部署状态。
2. 以用户最新明确决定和当前正式合同列出本次规则差异：输入口径、价格单位、平台/站点/数量段、赠送、优惠、成本与利润约束、候选选择、写入/确认方法、复盘条件。数值从当前合同读取，技能不固定利润率、时间窗、竞品名单或价格。
3. 区分真实缺口与旧数据/旧消费路径。先复用同代码、同输入、同环境的有效证据，仅补受影响检查。列一张简表：变更点 → 生产者 → 消费者 → 所需证据 → 已过/失败/未验/不适用及理由。

## 沿受影响调用链验收

按 [检查分支与源码线索](references/checks.md) 选择相关分支。规则迁移须确认以下消费者是否受影响，而非只验证算价函数：执行器、监控与恢复、效果归档、Hermes/定时任务、控制台/导出、业务知识。未受影响项可引用现有合同说明。

- **归档到调度**：依赖闭合日数据时，从消费者实际可读的共享发布核覆盖、时区和字段。验证午夜等待、保留原轮、发布后只续跑一次，以及在途原操作继续核账。把等待状态带到监控和前端。
- **日期窗贯通**：列出优惠、订单结构、采购成本和效果各自的用途与边界。逐项核生产者、冻结证明、写前复核、显示、复盘和知识。真实日期从回执读取，历史按原版本解释。
- **数据到证明**：同平台/同商品/同时间范围的真实输入进入候选证明；金额、单位、数量与赠送各有归属。新数据字段必须走到实际消费者；源库覆盖与消费者快照覆盖分开核。
- **证明到写入**：真实生产者能冻结可执行候选，而不是仅测试手工拼出的理想输入。写前身份/版本比对、单写入者、原操作编号、明确回执和当前指定目标读回一起验证。
- **写入到监控**：监控识别新协议的确认回执与规格；写前公开页观测不能验证写后结果，旧协议字段缺失不能制造全平台误报。缺观测保持可见，真实新鲜不一致仍报警。
- **监控到恢复**：核对实际状态字段和调用方一致；除了显示正常，还要核旧故障状态能否按原规则解除并恢复自动流程。未知写入沿原编号核账；不能以清锁、换编号重发或盲目覆盖制造成功。
- **效果到复盘**：共享订单库按需筛选、固定版本和同订单关联；新老客、成本、价格归属分别列覆盖。有效旧标记与新原生事实按当前合同合并，冲突显式处理。系统运行、经营改善、相关性和因果结论分别表述。

## 修复、发布与结束

发现具体缺陷时，先复现或取得可验证依据，再做最小关联修复。回归覆盖新旧协议兼容、真实输入结构与失败/未知状态；保护原有自动化能力。普通样式变更只做相称检查。

沿当前项目原 PR/正式 CI/publisher/备份/发布锁推进已有授权，不另加逐阶段确认。技能本身不授权上线、改价、发送消息、恢复暂停任务或修改业务参数；已有用户授权继续有效。生产验证优先实际只读入口和原自然周期；未经相应授权不为测试制造改价、模型调用或群通知。自然窗口未到则登记原任务与下一观察点，不空转等待整日。

写入超时或中断先查原回执和状态。自动纠偏必须绑定明确原操作、当前合法目标及真实写入核验；不将任意未知状态变成“自动覆盖价格”。没有完备恢复证据时如实说明边界。

最后给用户通俗结论：完成了什么、验证到哪层、还有什么影响经营判断、下一步由哪个现有任务承接。必要证据只保留提交/PR/CI、发布回执、关键操作/快照、测试结果与自然周期状态。故障文档提供当前入口，历史规则明确标历史。

涉及正式知识和定时复查说明时，沿原知识收尾及任务管理入口同步已授权内容，保留人工正文、原周期、通知偏好和暂停状态；不新增重复监控。CodeGraph 若落后，只更新本次实际使用的选定索引，先保护工作树已有修改。

结束条件：受影响源码与合同一致，必要检查完成，已授权发布和真实入口核对完成；未来经营效果与具体外部阻碍单列。不能把代码存在、HTTP 200、服务 active 或候选打包当成端到端验收。
