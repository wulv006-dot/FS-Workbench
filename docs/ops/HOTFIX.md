# 全仓唯一执行规则

适用于吴律、陈超及双方 AI。用户当前明确任务和授权优先；其它仓库文档只提供事实、模块合同或历史证据，不另设审批流程。平台安全政策和工具审核独立生效，不能靠改仓库规则取消。

1. 一个负责人、一个分支/PR、一个发布者。先用一句话写明要恢复的行为、直接相关模块和已授权范围；Git 与共享发布串行，保留他人未提交内容。
2. 定位 → 最小改动 → 直接相关检查 → 备份发布 → 实际使用确认。已授权范围连续推进，不在每步再询问、不要求双方逐个相互 Approve。新增业务范围或明确必要授权只问一次具体缺口。
3. 小修只检查原问题、改动代码和直接受影响消费者。受影响的真实失败、越权/错价、凭据泄露或不可恢复损失阻断；无关模块未验不阻断本模块。P2按实际影响处理，截图、长报告、无关全套回归和归档后补。
4. 同 head/base/输入/环境已有有效证据就复用；改动后只重评受影响项。代码没变不手动重复跑同一套。PR仍必须满足实际 main CI；新base造成组合变化按实际影响检查，不复制旧绿。
5. PR复用 pr-fast，不每个Bug新增workflow。未覆盖代码只登记一次最小实际检查；检查为空、必需skip、失败、超时或环境缺失如实报未覆盖/失败，不关闭CI掩盖。driver-check/结构/语法通过必须写明范围，不能代替集成或UI验收。
6. 沿用模块既有publisher、身份与发布锁，必要备份后实施已授权修复；merge本身不授生产权限。紧急恢复若已在业务发布授权内，可先受控小发布、再补PR和资料；Git合并仍遵守实际main规则。
7. 终点是从真实入口确认原问题恢复，并读回版本及业务结果；QA绿、merge、部署、HTTP200都不是终点。未完成就报未修复/部分成功/unknown，不宣布成功。
8. 普通Bug目标60分钟：10分钟定位、30分钟补丁、45分钟必要检查与发布、60分钟真实结果。预计超时即报原因、负责人和下一动作；到时仍未恢复真实报警。无人值守计时通知未配置，不声称已有自动提醒。
9. 吴律负责FC/NBA/MLB；陈超负责D4/PoE2/Aion2。共享改动列实际消费者，保持既有归属及已授权范围；owner表不是技术ACL。不依据旧三管理员代码覆盖现场角色，不增加账号、凭据、生产权限或费用。
10. 价格、登录、凭据和不可逆操作保留合法身份、来源、范围、幂等、备份/回退及读回。动态数量/系数/竞品价读取当前合法数据，原失败证据保留；unknown先查原ID，不能换ID或盲重放。回滚保留DB、账本、队列、锁、回执、策略与审计，不用旧整包盖回，不恢复退役publisher或擅改正常采集计划。
11. 历史manifest、releaseReady=false、旧审批和旧环境故障仅描述各自对象/时点，不是全仓永久门槛。发布只核本次受影响载荷、活动来源、现场基线和回退，不为文档小修刷新全部库存或上传旧服务器QA包。
12. 环境错误先核一次并及时用已允许路径继续；工具/平台明确拒绝则停止该动作，报告动作、来源和原理由，只有准确新授权或允许的修正才能继续，不绕审核。仓库规范、CI失败、平台审批分别说明。
13. 仓库为公开仓库。凭据、生产数据库、日志和缓存不入库。维持 0 美元额外预算和既有到额停止设置，不购买资源。当前main要求PR＋GitHub Actions pr-fast通过及最新base，0人工Approve、禁强推/删除、无bypass；仓库允许auto-merge仅表示能力，需逐个已授权低风险PR启用。Codex机器人quota不是门槛。

自动检查范围以 tools/pr_fast.py 为准：HTML/CSS是基础结构检查，删除/改名源路径及未覆盖运行格式不能假绿；注册目前PR只作driver静态合同，实际Linux/Nginx接线必须看专用增量运行结果。专用旧workflow只用于对应固定输入复现，不是日常小修前置。本规则不新建部署器、生产凭据或安全设置。

知识及项目摘要收尾复用[统一入口](../planning/knowledge-layering-20261023/CLOSEOUT.md)：自动识别受影响知识、准备摘要/来源/版本/Notion候选、冲突检查和相关测试；正式业务规则或生产发布提交一份具体清单，经当前用户批准后沿同一变更ID连续执行原发布器、实际读回与Notion摘要同步。同意同步不包括新增权限/凭据/安全设置。未知或拒绝先对原操作，不盲重放；文档更新不重启业务。日常收尾和老D原凌晨复盘按同一ID去重，保留人工正文及历史，不新增定时或第二套发布器。本条本身不授权生产切换。
