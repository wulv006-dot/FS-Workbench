## 183 root 管理入口与验收

在本机执行以下命令。若 WorkBuddy 根目录不同，先使用上表的跨设备映射定位原封装。

```powershell
& 'E:/WorkBuddy/大超服务器/server_183/access/Invoke-Server183.ps1' -Action Check
$LASTEXITCODE
```

- 通过条件为主机名与本机运维归档一致、登录用户为 `root`、退出码为 `0`。
- 公网 TCP 22 连接或 SSH 握手超时时，先核对工作机实际公网 IPv4 和实例现有的 SSH 来源规则。需要更新时，在已确认的目标实例及其安全组内按实际授权配置单一来源 `/32` 的 TCP 22 入站规则，再读回规则并执行原 `Check`。
- 2026-11-23 验收：本机出口变更后，为 183 新增一条单地址 SSH 入站规则。控制台读回成功，原封装返回约定主机名和 `root`，退出码为 `0`。规则标识、具体来源地址及操作记录保存于本机 183 访问目录。
- ECS Workbench 需要单独验证，登录前核对控制台提示及实例的安全组范围。187 到 183 的受限采集通道使用自己的身份、协议及固定任务，以其健康回执验收。

## 使用边界与差异

- 读到导航、找到封装或本地文件存在，不等于获准连接、认证或执行服务器操作。动作必须来自当前任务的具体授权，并遵守 [HOTFIX](HOTFIX.md) 与对应业务合同。
- 历史连接成功只能说明当时结果，不证明当前连通性、当前账号权限、部署状态或服务健康。仅为找文件不运行 SSH、认证或生产检查。
- 文档路径与本机实际目录／配置不一致时，明确记录差异和待核项，保留原配置；不能为了与文档一致而暗改配置。
- 2026-11-12 已核对上述两份本机入口文件。其他电脑的路径映射与环境状态按本机情况核对。
- 仅定位入口时，检查本机路径即可。连接验收记录主机与用户，凭据和完整访问配置保存在本机授权目录。
