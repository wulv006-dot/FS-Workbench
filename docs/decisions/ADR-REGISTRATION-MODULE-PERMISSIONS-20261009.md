# 新注册账号模块权限存储与消费者边界

日期2026-10-09；用户明确选择按模块只读/指定模块可编辑，编辑先开放工作任务台与绿茵计划。范围仅已批准的新注册账号，现有员工与管理员保持。

复用现有append-only审计账本保存完整七模块模式，依申请ID与注册UUID绑定；不新增第二套账号表或角色库。申请版本与最新权限审计ID双CAS，管理员原因必填。保存递增epoch、删除原注册会话，原检查点验证照常。

首次权限保存在同一事务中设置user_version=4，原schema3结构保持。新runtime仅接受3/4；version3存在权限事件视为回退冲突。旧runtime只接受3，所以无法忽略ACL恢复全局只读。代码回退不能恢复数据库、撤销记录或检查点；发布器检测4或权限事件即拒绝旧runtime回退，应提交兼容4的修复。

认证输出按请求所属模块给readonly/editor；写方法与路径只允许已有本人任务执行接口，原任务后端还要核身份、active成员、执行人和字段。注册执行人以reg:UUID、viewer登记到原成员表，成员记录本身不授予editor，inactive不自动激活。前端分别报告权限保存与成员登记结果，未知结果不重放。

读访问仍遵循现有RouteGuard精确合同；共享session仅两个任务模块有任一权限才开放。其它模块写入、员工角色修改、全局管理员授予及未接入消费者均不在本次范围。无访问时直接入口/API也拒绝。

独立测试证明两进程CAS、撤销旧会话、schema4重启、元数据回退拒绝和真实临时taskboard处理器跨账号/结构/成员拒绝。合并、受控发布、真实Nginx/角色与线上生命周期尚待各自记录；文档决定不表示生产验收。
