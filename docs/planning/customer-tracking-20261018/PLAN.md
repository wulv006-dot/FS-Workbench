# 智体客单追踪实施范围

状态：2026-10-18 用户授权实施，当前处于接口核验与独立候选开发；未上线。

分期修订：用户随后明确一期只针对FC专项测试。本期仅开放FC27配置与端到端验收，原数据专区其他游戏能力不改；底层保留可复用链路，二期在FC流程跑通后再逐游戏核验并开放全业务，不把通用代码当成已验证支持。

## 工作流
1. FS每日按可配置规则筛选上一完整日；默认FC27、Coins和Items、订单金额严格大于500 USD、优惠金额严格小于25 USD、新老客均纳入。可手动查询指定日期。缺优惠金额不当0，未知新老客单列。
2. 读取受控ES归档，再按原订单号核Admin主站订单、已支付状态、UID及订单邮箱。保留原状态、产品类别与站点范围；不把全ES范围直接当主站。单订单去重，类别行重复不重复计算整单金额或优惠。
3. 管理员查看候选并手动加入持续名单。用户明确网站不强制注册/登录，邮箱为支付必填，因此UID=0是正常游客订单；邮箱有效且核对一致即可跟踪，UID只作辅助。同一客户邮箱跨游客/注册UID仍追踪后续订单。新老客采用后台原始标记，不能把游客当新客。精确核订单客户邮箱，不通过模糊搜索、同名、电话、IP或另一个支付邮箱猜同一客户；不擅自去除邮箱加号或点号。
4. 追踪以加入时间为起点，持续读取订单变化并在第7/14/30天反馈。区分触发订单日期、加入日期、历史消费及后续窗口；缺页/未成熟窗口明确显示。记录人工维护动作，供后续复盘，不能冒充已发券或已联系客户。
5. Hermes可按需调用授权只读客户查询，解读消费、优惠、履约与复购并提出可执行策略。使用原独立HTML产物机制，自主设计报告；节点任务有稳定ID，结果未知时核原任务，不换ID重复生成。

## 界面与权限
- Hermes智体下分“智体决策报告”和“智体客单追踪”；保留原对话/调查/报告能力。
- 客单页和原始客户明细仅管理员访问。订单号、UID、邮箱不进入普通用户共享报告池、普通汇总接口、URL参数、浏览器持久存储或通用日志。
- 新模块独立私有账本，不放宽现有 aggregate_only 限制。模型没有订单修改、发券、邮件发送、任意命令或凭据读取权限。
- 维护记录与客户追踪属于业务数据，不是长期系统规则；长期规则仍只接受用户通过Codex或桌面端的明确更新。

## 金额口径
ES订单金额为USD；实付金额按实付币种（如GBP）保存；优惠金额统一USD。筛选比较订单USD和优惠USD，绝不拿原币实付与美元阈值比较，也不使用“订单USD减原币实付”计算优惠。折扣比例为1仍可能有固定满减，以实际优惠USD为准。没有折扣码不等于优惠金额为0。
