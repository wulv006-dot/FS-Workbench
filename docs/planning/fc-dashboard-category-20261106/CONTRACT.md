# FC 经营看板商品分类与订单利润规则

- 稳定合同标识：`fc-dashboard-category-v1-20261106`
- 范围：FC 商品分类、FC 看板/趋势/导出分类筛选，以及采用 RS 通用看板交互约定的页面。
- 规则状态：用户已确认的业务口径；本地 Git/Hermes 知识源候选，代码接通、部署和真实加载尚待分别验证。此文件不记录生产读回或 Notion 同步。
- 当前维护源：本文件。RS 维持现有通用合同 `fs.dashboard.shipping-profit` 与其来源；本合同仅覆盖 FC 特有分类及其消费规则。

## 商品全集与订单归属

FC 商品筛选应提供“全部商品、金币、球员卡、SBC、Packs、其他”。先读取并识别同一完整订单的全部商品，再按站点和原始订单号将整单唯一归入一个类别，优先级为：球员卡 > SBC > Packs > 其他 > 金币。订单同时含球员卡与 Packs 时，整单归球员卡；其他类别组合也遵守同一优先级。代练及未列为专类的商品归“其他”。“全部商品”包含所有类别。

订单商品未知、分类信号冲突、完整订单明细缺失或跨平台关联无法确认时，应显示未知/冲突及可核实的原因和数量，不推断为某类、不丢弃、不重复计数，也不以部分明细宣称已完成分类。分类规则作用于看板、趋势、导出和项目/操作规则，展示的分类值和订单归属保持一致。

## 发货利润统计

看板发货统计以 Order 发货统计的交易时间为时间轴，金额使用人民币。每个统计范围的销售额取该范围的人民币销售总额，毛利为销售额减采购总额；展示总毛利和总发货额，汇总毛利率按总毛利除以总发货额计算。FC 商品分类先按上述规则确定订单整单归属，再以站点及原始 Order 订单号关联成本和发货记录，整单金额及成本进入唯一类别。组内毛利是订单组汇总，不代表每个商品的单品毛利；不得用 Admin 付款销售额或游戏总率替代这项交易时间发货统计。

订单数量按站点及订单号去重；销售额和成本按发货明细的唯一记录ID去重后求和。不能把真实分批发货金额因订单号去重而丢掉，也不能重复计入同一发货明细。缺失成本、缺失/不完整订单、未知分类、冲突及无法确认的跨平台映射须保留原状并单独透明显示；不补零、不按比例硬分配成本或销售额、不挪到其他类别以平账。对不完整数据，明确展示可核实的总数、未核实部分及其状态；不能让看板汇总掩盖缺口。

## 对比与交互

同一分类组内的项目对比仅在“全部商品”视图提供。用户选择金币、球员卡、SBC、Packs 或其他时隐藏组内对比，避免将整单归属金额解释为单品对比。

FC 页面沿用 RS 通用的连续页面结构与控件约定：复用通用的日期、网站/范围和商品类目交互；次要筛选和细节使用原生 `details/summary` 收起；默认优先呈现用户消费所需的核心数字，支持键盘操作和窄屏阅读。FC 可提供其商品分类选项，但不改变 RS 的范围合同。

## 一致性与状态边界

FC 看板主展示、趋势、导出、项目规则和 Hermes 选取的知识条目都以本合同的分类优先级和未知/冲突处理为准。RS 通用统计口径继续由原 `fs.dashboard.shipping-profit` 知识条目维护；涉及 FC 分类时同时读取本合同。业务口径获确认、代码存在、真实页面/接口接通、部署及生产读回是不同状态，必须逐项记录证据，不得互相推定。
