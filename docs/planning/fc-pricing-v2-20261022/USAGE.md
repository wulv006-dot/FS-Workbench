# FC自动定价V2使用说明

入口：[FS里的FC自动改价页](https://47.85.224.112/dashboard/fc27-coins.html)。首页显示PS/Xbox共同市场和PC市场；当前公开价、候选价、有效成本、最低安全价、最差优惠后实收和采购毛利放在一起。先看来源时间和缺口，再看建议。

## 日常使用

- 正常自动运行：保留当前开关、平台及120分钟周期。每轮核同批价格和成本，再让Hermes分析；Hermes未完成时，程序仍可用本轮合格基准继续，模型建议不会在超时后偷偷补执行。
- 想立即看新行情：点“采集最新数据”，保留原操作编号等结果。队列忙时保留正在运行的原任务。不要因为等待换页面反复提交。
- 想核某个价：高级操作中填写美元100K标价和理由，PS/Xbox只填一份共同价，PC一份。重新核算仅产生候选；核对后台预览后才能执行。
- 想让Hermes接手：点“Hermes核算并受控执行本轮”，真实会话编号、任务和模型运行号会读回。这次入口包含本轮核算、预览和执行授权。它可以核资料、比较方案、自定经过程序核验的候选，再沿原队列操作。会话完成不等于价格已生效，仍看原操作记录。

## 监控与干预

关注四项：来源是否新鲜、后台写入是否确认、前台公开价格是否实际读回、成交订单的真实收入/成本与同范围营销效果。采购毛利与广告后利润分开，不把短期销量起落当策略效果证明。

紧急阻止后续改价：关闭运行设置里的“允许改价”并保存，读回新的配置版本。已经发出或结果未知的请求须继续核原编号，关闭开关不等于撤回已派发动作。保留错误，不重放原未知请求。

执行显示失败也可能已有部分修改。先核原执行audit的changed、sync_confirmed、after、ALL步骤和对账标记；PARTIAL/UNCERTAIN不能换编号重试。后台确认、清缓存、同一操作的写后公开读回须分别通过，历史matched不代表本轮已成功。

恢复旧价：从一条已确认操作生成恢复预览，程序按当前成本、优惠和共同市场约束重算。旧价不安全时拒绝恢复；应采集新数据、核新候选。不要直接抄历史售价或后台“采购成本”参数。

需要Hermes协助恢复时，在恢复栏填原操作编号，点“Hermes协助恢复这条原操作”。这次只额外授予该原操作的恢复权限；普通本轮分析不自动获得其他历史操作权限。同一轮报价重算后，旧建议须重新评估。

本机模式需要电脑、Chrome、采集组件和工作台持续可用；位置选择沿现有控件，不静默回退服务器。采集位置与自动改价开关是两件事。页面刷新状态不会触发价格采集。

## 如何判断有进步

先核“后台确认→前台暴露→订单/履约成本→营销后贡献”完整链路，再比较相近客户、优惠、套餐和时段。展示成本覆盖率和缺失数据；未覆盖订单不补零、不把发货拆分收入当Admin整单收入。

Hermes每次说明：为什么调整或保持、还缺哪项数据、销量要增加多少才能弥补单笔毛利下降、哪些结果会推翻判断。每周Astra复核业务变化、真实效果及Hermes新场景表现；新方法通过受控学习审核、发布和撤销机制更新，10%硬红线不能随学习降低。

## 当前限制

V2代码与真实入口已部署；本轮实际后台、公开读回、自然周期和模型学习的分别状态以同目录验收记录为准。普通VIP、积分、码、券按用户确认互斥，当前最低留存70%；已核售后补偿1259单独按实际扣减记账，面值与次数不替代金额。其他未核固定券、来源变化或过期时，程序拒绝新价格。10%指已核有效采购成本下的采购毛利，不等于已证明扣除所有费用后仍有10%净利润。
