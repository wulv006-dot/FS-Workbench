# FC27 自动定价 V3 使用说明

适用：MMOEXP FC27 Coins，Site 266、Game 1327、Gold、All Server。本文解释2026-10-27修订后的目标行为；实际已发布版本、英国优惠状态和真实操作以交付凭据及页面读回为准。

## 一、日常怎么用

打开 [FC27 定价台](https://47.85.224.112/dashboard/fc27-coins.html)，先看顶部的运行状态、当前策略、最近公开价格、最近成功时间及下次周期。顶部公开价格是最近真实采样；下面的候选是待执行方案，两者不能混为一谈。

1. 选择经营目标。常态选“日常经营”；月末需要提高净销售额选“冲销售额”。同一轮只计算当前策略，不需要同时启动五套。
2. 选择全球Console、PC及需要控制的沙特平台。PS与Xbox共用全球基础价和成本池；PC独立。沙特最终价由全球基础价和对应平台地区系数共同决定。
3. 确认期限。限时促销和冲销售额在页面填写结束时间。月目标可留空，系统据真实收入优化，不会编造完成率。
4. 展开参数时才调整偏移、分配和容量余量；不熟悉时使用默认值。所有策略已取消预算，无须填写日额、累计金额或活动总额。
5. 建立并启用计划。程序采集当前策略所需证据、计算合法候选、预览后台，执行后核后台、缓存和公开价格。正常每轮不等Hermes审核。
6. 首轮后台、缓存和公开全部成功后才算完成。后续从成功完成时点起默认每120分钟一次；可修改“自动改价间隔”。改间隔不会恢复暂停计划，也不会补跑暂停期间的旧轮次。

有合法候选不代表一定要改价；核算后当前价合适会记录“无需改价”。“后台已确认”“缓存已确认”“公开待核”均不是全部完成。结果未知时查看原操作编号，不重新点一个新请求碰运气。

## 二、五个策略怎么选

| 策略 | 主要判断 | 默认候选 | 适合场景与限制 |
| --- | --- | --- | --- |
| 日常经营 | 总采购贡献，兼看收入 | 计划锚点−8/−4/0/+4/+8% | 常态经营；增单但总贡献下降不自动更好 |
| 拉新增长 | 有效首次付款客户，兼看首单贡献与成熟复购 | −20/−15/−10/−5/0/+5% | 有拉新需求；客户身份或投放归因不足会列缺项，不编CAC |
| 交付积压 | 可交付待交付K、新增负荷与供应能力 | 0/+5/+10/+15/+20% | 供给吃紧时控制新增压力；容量不足不靠涨价冒称履约合格 |
| 限时促销 | 活动期限内累计采购贡献与真实优惠承诺 | −25/−20/−15/−10/−5/0% | 有明确活动期限；所填范围全低于毛利底线会显示无解 |
| 冲销售额 | 净收入、目标差距与可比竞争位置 | 有效竞品锚点低5/6.25/7.5/8.75/10% | 月末冲量；默认偏好7.5%，全部候选仍受双20%红线约束 |

其他策略的偏移以计划保存的锚点为基数，不能每轮对上轮价格重复打折。冲量以本轮有效竞品锚点一次计算，不能对已经降过的区间上界再降5–10%。

积压仅考虑“已支付新单、验证通过、发货中”：Admin 11/21/31与Order正常1/2按原单号取交集。暂停、问题、再次发货、部分发货及其他状态排除；账号密码问题不作为供应压力。含赠整单K上界与扣掉已交付后的真实余额分别展示。

## 三、冲量如何比较价格

全球使用Lootbar无优惠券公开价和ItemD2R同平台可比价。沙特再比较Arab-UT普通发货价；fast不参与，PC没有普通发货报价时保留缺口，不能拿PS填PC。

先统一到美元，再按实际交付数量计算：

`每100K交付有效单价 = 实际USD总价 ÷ (购买K + 赠送K) × 100`

比较实际平台、购买量、赠送量、配送方式和时点；不能仅看商品总价。例如赠送不同的两个“100K”商品，实际交付口径可能不同。

默认取Lootbar与ItemD2R中的较低有效价。以下情况可以由ItemD2R接替：

- 有同一个6小时内的已保存基准，当前成本和ItemD2R各涨至少5%，Lootbar变化绝对值不超过2%，两站差距至少5%时进入成本响应。进入后保持原基准，差距回到2%或成本/ItemD2R同向信号消失后退出。
- 没有可靠趋势历史，但低Lootbar的完整5–10%区间在当前财务和共同写价条件下无解时，可尝试ItemD2R，标记“当前成本冲突”。这不代表已经知道竞品的采购成本。

沙特使用已解析的全球锚点再与Arab-UT普通价比较，不会把已因成本响应排除的低Lootbar重新加入。

页面同时展示采用的候选、实际有效单价和相对每个竞品的百分比。负数表示我们低，正数表示我们高。某个市场未达5–10%不能标成已达标。

如果竞争区间与完整财务证明没有交集，但来源有效且有合法写入路径，系统采用**最低可写合法底价**，标记“财务底价兜底 / MARGIN_FLOOR_FALLBACK_20”。这表示守住经营底线，不能视为赢得竞争。缺成本、缺必要市场、来源过期、原操作UNKNOWN或不存在合法中间路径时，不能靠底价兜底放行。

## 四、两条20%红线是什么

第一条：未使用客户优惠时，实际套餐采购毛利率至少20%。

第二条：按最近七个完整日真实优惠金额结构估算，平均采购毛利率至少20%。

`采购毛利率 = (对应销售收入 − 全部交付K的采购成本) ÷ 对应销售收入`

两条都要满足，覆盖全部套餐、赠送、整数K自定义购买、地区系数和金额舍入。地区优惠、Hermes建议、手动操作及故障恢复都不能绕过。合法的某一笔优惠订单仍可能低毛利或亏损；平均结构不能因此破线。采购毛利不是扣除全部广告与经营费用后的净利润。

预算已完全取消：没有日额、24小时额度、活动总额、负贡献限额、机会成本上限、预占或“预算耗尽自动退出”。页面保留实际折让与贡献，是为了复盘；它们不再作为隐藏额度阻断执行。旧账本及当时的历史预算退出保留，不影响新计划。

## 五、地区和英国优惠

全球Console/PC基础价变化后，程序按Admin实际匹配规则重新计算受影响地区和套餐。沙特Region21，PS 21587、Xbox 21585、PC 21589各自使用四位小数系数。

英国临时0.9100的指定行已获用户授权在补丁验证后立即取消，取消前按真实0.91继续核红线；取消后应验证PS、Xbox、PC均继承全球基础价。实际取消、清缓存和公开读回必须有独立操作记录，不能仅凭本说明认定已经取消。其他地区规则保持各自真实配置。

## 六、参数怎么理解

| 页面参数 | 用途 | 调整时看什么 |
| --- | --- | --- |
| 自动改价间隔 | 五策略统一的自然周期；默认120分钟 | 来源新鲜度与已完成时点；不等于报价有效期 |
| 结束时间 | 活动或冲量的授权期限 | 真实活动截止；结束后进入日常经营须重新核证 |
| 月度净收入目标 | 冲额所追求的同范围USD净实付 | 可留空；实际月累计、已核下界和今日缺口不混用 |
| 候选偏移 | 相对本计划锚点生成备选价格 | 偏移范围与双20证明共同生效，不能承诺每个偏移都可执行 |
| 偏低目标 | 冲量5–10%中的次级偏好，默认7.5% | 收入目标优先，不能压过财务红线 |
| 对照/优选/探索比例 | 六小时分配块中的试验选择 | 三项合计1；重启和普通重试不重新抽签 |
| 容量余量 | 积压模式给供应能力留余量，默认10% | 真实共享供应能力只计一次；观测吞吐是估计时应标明 |

默认对照/优选/探索：日常20/60/20%、拉新20/40/40%、积压0/100/0%、限时促销10/60/30%、冲量10/70/20%。它们是试验分配，不是竞品价格权重；旧80/15/5生产加权已退役。

## 七、预测基数从哪里来

| 基数 | 核算方法与条件 |
| --- | --- |
| 六小时订单数 | 同网站/游戏/Coins/价格组的已核付费订单数÷实际覆盖小时×6 |
| 净客单价AOV | 同批净实付USD÷同批付费订单数；已经含优惠，不再重复扣一次 |
| 每单交付K | 同批购买K加历史实际赠送K，计数量倍数后÷订单数 |
| 成本与汇率 | 当前有效平台采购成本、单位和CNY/USD；PS/Xbox共同池，PC独立 |
| 新客比例 | 下单时原始新客标记及已核客户身份，游客UID=0不排除、不自动算新客 |
| 需求弹性 | 初始中心2，0.5/1/2/4作敏感性情景；足够真实价格窗口后再估计 |
| 供应能力 | 已核承诺，或明确标为估算的近期真实吞吐；不把吞吐当SLA |

需求初始公式为`Q(p)=Q0×(p/p0)^(-弹性)`。收入、成本按实际AOV和含赠交付K估算，不能把所有订单当100K订单。初始假设允许已授权探索，但预测和情景不叫实际收益。没有绝对基数时只显示相对指数，缺字段不补0。

实际学习只使用已公开确认的价格窗口，将订单按创建时间和实际价格绑定，再回填付款、退款、迟到成本与客户结果。无法唯一绑定的订单列覆盖缺口。纯影子销量不进入真实训练。

## 八、Hermes与影子怎么工作

Hermes每天一次，通过独立定价存储、队列和模型通道，按前一天真实分时段订单比较预测与实绩，解释基数、缺口、变化原因及下一日建议。低峰/高峰由真实订单判断，不预设白天一定低、晚上一定高。本阶段只评估和提建议，不逐轮审批、不自动切换策略；模型失败不会阻断程序正常定价。

每天北京时间02:20结合现有数据排程运行前一日影子比较，保存五条独立连续路径。只使用当天保存的时段快照，不补采竞品、不写生产价。首日不足完整一天、容量或历史报价缺失时列明缺口。

“每日回放与长期影子”可读取五条路径；手动历史支持7/14/28完整日及上个完整自然月。区分真实实绩重建、固定订单金额重算、需求情景和实验效果估计。缺历史汇率、原优惠条款或价格窗口时保留缺口，不拿今天规则替代过去。

## 九、常见状态与处理

| 状态 | 含义与操作 |
| --- | --- |
| 暂停 | 阻止新写入；原在途/未知请求继续按原ID核对；恢复后不补跑旧轮 |
| 结束/退出 | 结束活动并按当前授权进入日常流程，重新核成本与财务 |
| 报价过期 | 证据超过15分钟，重新采集证明；不等于服务故障 |
| 当前无可行价格 | 查看具体受影响范围、红线和参数范围，不放宽证明来制造通过 |
| 后台已确认/公开待核 | 保留原操作，继续缓存与公开核验；不新发一次相同保存 |
| UNKNOWN/部分完成 | 只按原操作核请求、回执和真实状态；不要换ID、删记录或盲重启 |
| 模型每日复盘失败 | 查看独立每日回执；程序周期继续，不能写成审核成功 |
| 某个平台竞品缺项 | 展示真实缺口和影响范围；PC不复制PS，旧报价不冒充本轮 |

人工指定价或按历史操作恢复时，先预览，再用当前成本、优惠、地区及市场重新证明；“恢复旧价”不代表旧价今天仍然合法。

## 十、如何判断系统运行合格

逐轮看同一原操作编号的报价、后台保存/同步、地区规则、缓存、全球及受影响地区公开读回。再看自然周期是否只有一次执行、旧策略是否被拒绝、是否出现反复重启或价格回摆。

经营效果按实际生效窗口追踪订单、净收入、采购贡献、新客、交付K与预测偏差。初期样本不足先看覆盖与方向，不因短期多单就宣布增利；因果判断需要合格的原试验分配及足够样本。历史回放和模拟通过不代替线上验收。
