## 日常怎么用

打开[FC27定价台](https://47.85.224.112/dashboard/fc27-coins.html)，先看当前计划、下一自然轮和三平台最近公开价。采集和执行每60分钟一次，可在“自动改价间隔”修改；改间隔不恢复暂停计划、不补跑错过的旧轮。

1. 选择“日常运营”或“冲销售额”。一般经营选日常，以提高净销售额为目标时选冲额。
2. 选择Console和PC；PS/Xbox共用基础价和采购成本池，PC独立。需要调整Saudi时选对应平台地区范围。
3. 结束时间可留空，表示持续运行；填写后按该期限结束。既有计划原截止不会因更新程序自动延长。
4. 冲额月目标可空。不设预算，也不需要填写日额或活动额度。
5. 创建并启用计划；查看同一轮的后台、缓存和公开结果。正常周期不等Hermes，内部只选一套最终方案，不把每个候选逐一执行。

右上角“立即执行一轮改价”与下方“立即运行当前策略”共用同一个现役执行入口：按当前活动计划重新采集、核算，并在合法且有必要时真实写价；新成功受理的操作使用新幂等键，结果未知仍按原键对账，不能盲点第二次。“刷新采集价格”只采集并保存来源快照，不写价；“更新统一状态”只读取已保存状态。暂停只阻止后续新写入，原在途和未知请求仍按原编号核对。结束会退出计划；原来填写的结束时间到达时按既有退出流程核算。

## 价格卡与当前利润率

顶部显示最近真实公开售价，而不是候选价。下面依次显示采购成本USD/K及CNY/K、100K购买档含全部赠送K的采购成本、未优惠红线价、8日平均红线价。

- **未优惠红线 $X · 当前Y%**：X为100K购买+赠5K档未优惠毛利达到20%的最低全球基础价；Y按上方最近公开的本档套餐售价和105K交付采购成本计算。
- **8日平均红线 $X · 当前Y%**：X再考虑D-9至D-2的8个完整日真实优惠金额结构；Y使用同一公开价乘真实净留存比例后计算。

`未优惠采购毛利率=(当前套餐售价−全部交付采购成本)÷当前套餐售价`

`8日平均采购毛利率=(当前套餐售价×真实净留存比例−全部交付采购成本)÷(当前套餐售价×真实净留存比例)`

当前利润跟随公开读回后的新售价更新，不停留在改价前快照。采购毛利不是扣完广告、费用的净利润。两条红线价格只核100K购买+赠5K档，分别考虑105K交付成本、8日净留存和实际分币舍入，不取小额、其他档位或全整数K下界的最大值；全球卡不代替Saudi本档核验。成本和公开价各有时点，旧数据会保留原日期。

## 竞品价格在哪看、怎么刷新

策略上方“竞品价格追踪”按PS/Xbox/PC展示Lootbar无券、ItemD2R及Saudi Arab-UT普通发货。大号金额是原套餐USD报价，下面是按实际交付量折算的每100K有效价；购买量、真实赠币、交付方式和采集时间同时展示。

`每100K有效价=原套餐USD总价÷(购买K+实际赠送K)×100`

ItemD2R恢复原100K口径，不将礼包折算成5K赠币。Lootbar及我方真实赠币仍计入实际交付。不要只比较两个“100K”商品的总金额。

“更新统一状态”只读取现有记录；“刷新采集价格”才会重新采集，但不会写价。要等任务完成和采集时间变化后才算刷新。若失败，页面显示原失败原因并保留旧快照时点，不把旧值冒充刚采到的价格。超过15分钟的报价仍可追踪，执行时必须重新采集证明。

Saudi只取Arab-UT普通发货。对应平台未取到、过期或不可核时，该授权平台系数1跟全球，不因本地缺价卡住全局；PC不复制PS报价，也不补假零价。已有可核普通报价继续按实际比价。

| 默认偏好 | 依据贡献与真实需求基数排序 | 低7.5%为次级偏好，不覆盖收入目标与红线 |

高级参数平时保持默认即可。候选是内部计算组合，不是多次写价；程序每轮只采用一套最终方案，基础价最多更新一次，各必要地区系数各更新一次。对照/优选/探索是六小时块的试验分配，合计1，重试不重新抽签；它们不是旧80/15/5竞品权重。

日常候选按本计划锚点计算，不能每轮对上轮反复打折。冲额按本轮 Lootbar 无券与 ItemD2R 的较低有效价一次计算，正常目标低5–10%、默认偏好7.5%。低价带不满足100K购买+赠5K档双20或共同Console约束时，直接求该基准档最低合法价；不切换到更高的 ItemD2R 锚点。Item 本来更低仍正常取低。Saudi 额外比较更低的 Arab-UT 普通报价，缺价平台系数1跟全球。

2026-10-28 起，成本响应趋势不再授权切换高价锚点。页面保留两家原始报价、实际交付K及可比价差；财务底价可能仍高于较低竞品，必须如实说明。最低合法价必须由本轮100K购买+赠5K档成本、8个完整日实际优惠、地区及舍入证明共同求出，不能拿旧下界直接写价。当前策略版本为 `sprint_5_10_lower_quote_floor20_v3`，旧报价和旧计划参数需沿原版本迁移入口处理。

## 两条20%红线与地区

daily与revenue_sprint都以100K购买+赠5K档核未优惠实际采购毛利和D-9至D-2八完整日真实优惠金额结构下的估算平均采购毛利，两者均至少20%。本档成本计足105K交付并核地区系数及舍入，小额、其他档位和全整数K诊断不阻断本档合格的新价；合法的某笔优惠仍可低毛利或亏损，平均线不能因此放宽。Hermes、人工或恢复不能绕过本档红线。

最终价满足策略竞争要求；切换过程逐步核双20，不为中间每一步都卡5–10%折扣而反复改基础价。过程允许短暂更便宜，随后到最终价；不能在已达到的竞争价格上限之上临时涨价。

竞争带和财务没有交集，但来源完整、新鲜、计划有效且存在合法单次基础价路径时，可执行完整证明的最低可写底价，并明确显示“财务底价兜底/未达到竞争降幅”。缺成本、必要全球报价、权限、过期或UNKNOWN，不能用底价兜底放行。

Saudi Region21三个平台分别核实际Admin规则和100K购买+赠5K档双20。旧优惠系数使任一红线失守时自动归1、继承全球；保留旧行和调整回执，不用提高全球价迁就破线系数。英国临时ID1/0.9100已取消，当前三平台系数1继承全球；原行和回执保留，其他地区不随之修改。

## 预测基数从哪里来

| 基数 | 核算与验证 |
| --- | --- |
| 六小时订单数 | 同范围实际付费订单÷覆盖小时×6，注明窗口和样本 |
| 净客单AOV | 同批净实付USD÷付费单数，已经含优惠，不再扣一次 |
| 每单交付K | 原生商品行购买K、历史赠送K和倍率逐行相加÷同批订单数，不把每单固定为100K |
| 成本与汇率 | 当前有效平台记录及CNY/USD，PS/Xbox共同池、PC独立，全部含赠计算 |
| PS/Xbox成本取样 | PS最近一小时有效Order发货按交易时间倒序取六条、用其中最高CNY/K；不足六条扩两小时并按原边界继续扩窗；Xbox跟随PS，PC沿原最新有效单规则 |
| 8日净留存 | 同批净实付÷(净实付+ES实际优惠USD)，按金额加权；状态变化沿原后台重建，采集和写前使用同一已核基数 |
| 需求弹性 | 初始中心2，0.5/1/2/4仅是敏感性；成熟真实曝光窗口后才拟合 |
| 月目标与进度 | 目标可空；实际累计、截至日、今日缺口、下界/区间分别显示，不编完成率 |

初始需求公式为Q(p)=Q0×(p/p0)^(-弹性)。以真实AOV、含赠交付K和当前成本估算收入与采购贡献。估算不是实际收益，缺绝对基数只给相对指数，不补零。

实际学习绑定已公开确认价格窗口和订单创建时间，回填付款、退款、迟到成本。无法唯一归属的订单保留缺口，纯影子销量不进训练。用户不需要逐单核所有问题单；确实核不明的订单另列原编号与影响，必要时由用户协查。

## Hermes、影子与历史回放

Hermes每天一次，使用独立定价通道按真实订单时段判断高低峰、比较预测与实绩、解释参数和提出建议。本阶段不逐轮审批、不自动切换、不因模型失败阻断程序。旧报告带报告日期及当时规则，可展开阅读，不代表当前合同。

每日北京时间02:20，用前一日已保存时段快照比较日常与冲额，并保存两条连续影子路径。没有快照或必要来源就列缺口，不补采，不写价。按月统计收入不会强制月末结束或自动切换影子策略。

页面历史支持7/14/28完整日和上一完整自然月，分别提供真实实绩重建、固定订单金额重算、需求情景和实验效果估计。缺档案沿既有只读Admin/ES补齐；缺历史汇率、优惠条款或价格窗口，继续保留限制，不拿今天规则代替过去。旧权重和钉价算法仅供隔离只读回放，没有生产控制权。

## 常见状态

| 状态 | 含义与处理 |
| --- | --- |
| 已登记/采集中 | 等原任务完成，勿重复点击 |
| 无需改价 | 已核当前价合适，仍核公开结果 |
| INFEASIBLE | 当前无合法方案，保持原价、记录原因，按正常间隔再算，不技术重试 |
| 采集失败 | 原因和原编号保留；卡片保留旧时点，不代表刷新成功 |
| 后台确认/公开待核 | 尚未完整完成，沿原请求继续核缓存与公开价 |
| UNKNOWN/部分完成 | 先核原请求和实际状态，不换ID盲重发、删记录或盲重启 |
| 已核实未发送并取消 | 已有明确未发送证据；原失败与取消审计保留，不假报改价成功 |
| 暂停/结束 | 暂停阻止新写入；在途继续核原编号；结束按现有退出流程处理 |
| 每日模型失败 | 看独立回执，程序周期继续；不把失败称审核通过 |

判断运行是否合格，要看同一轮报价、一次基础价保存、必要地区规则、ALL、缓存和公开回执，再观察后续自然周期是否重复写价、回摆或重启。实际经营效果需足够样本与成本覆盖，不由代码、CI或一次改价成功推定长期增利。
