# FC27 V3：Hermes经营决策、参数核算与持续验证合同

版本：2026-10-26。适用Site 266、FC27 Game 1327、Gold、Server 7645及本轮授权的地区价格。本文是本轮替代合同；实际加载版本、代码和生产验收以DELIVERY与SOURCE-MAP的最终回执为准。仅保存本文件不代表Hermes已学会或服务器已生效。

## 1. 决策责任

Hermes负责解释经营目标、比较同一真实快照下的五策略、选择当前计划内的候选、说明取舍、审核证据并复盘实际结果。它可以选择与程序默认排行不同的可行候选，必须保存选择理由和原实验分配偏离。不能把Hermes变成只解释程序结论的旁观者。

程序负责金额、套餐与地区价格计算、双红线、预算、资源归属、期限、唯一操作ID、写后核验和UNKNOWN对账。Hermes不能覆盖程序拒绝的财务证明，也不能另开一条后台写价通道。候选提出、审核通过、已受理、后台确认、缓存确认、公开价确认、真实经营效果是不同状态。

模型无有效结果时，沿本轮明确授权的V3确定性可行候选路径继续；记录模型故障和真实选择来源，`review_approved`不得伪造为真。不能回到旧加权、临时钉价或隐式尾价，也不能仅因模型故障擅自降低既有自动化能力。迟到模型结果只保留证据，不能覆盖已经完成的动作。

## 3. 预测基数：每个字段如何算

| 字段 | 单位与来源 | 计算与核算条件 | 缺失时如何处理 |
| --- | --- | --- | --- |
| `orders_per_block` | 实际付费订单/6小时；同网站、游戏、Coins及价格组的Admin订单 | 订单数÷实际覆盖小时×6；七完整日为168小时，不能误除84个两小时块 | 用已核覆盖建立并标识初始估计；没有数量依据只给相对指数，不伪造绝对销量 |
| `reference_regular_usd` | 当前可见100K常规商品USD价格 | 与实际平台、地区系数、套餐和币种一致；历史均值映射到当前价属于冷启动假设 | 不用旧历史价格冒充当前公开价 |
| `target_revenue_per_order_usd` | 同批真实净实付USD/订单 | 同批净收入÷付费订单；是混合客单价，不是100K商品价 | 可用明确标注的估计，但不能把原币实付直接当USD |
| `purchase_k` / `bonus_k` / `delivered_k` | K金币，1K=1000金币 | 原订单购买K、历史赠送K分别核算；交付K=购买K+赠送K，乘订单行数量 | 不拿当前赠送规则替换历史赠送，不将未知补零 |
| `delivered_k_per_order` | K/实际订单 | 同批交付总K÷订单数，包含所有赠送 | 缺失时不能把每单固定当100K或105K |
| `new_customer_ratio` | 有效新客人数/同批订单 | 用已核客户邮箱去重及该笔下单时ES「是否新客户」（是/否），不得用Admin列表isNew或当前会员身份回推；窗口内首次合格订单归属，UID=0保留 | 单列身份覆盖；不将所有游客、GA newUsers或总订单当新客 |
| `retained_ratio` | 净保留比例 | 与所用AOV/优惠路径采用同一分母；净AOV已经含历史优惠，不能再重复扣一次 | 明示缺口，不混用地区系数与优惠留存 |
| `elasticity` | 无量纲 | 初始中心2，敏感性0.5/1/2/4；仅有真实有效价格曝光和订单后才能拟合 | 初始假设可以用于获授权探索，不能称拟合事实 |
| `backlog_k` | 当前可交付积压K | 按用户最终白名单，仅已支付新单、验证通过、发货中三种；按后台原生枚举映射，不限近7日付款，已暂停和所有其他状态排除。问题单（账号/密码错误、待客服或重新验证）排除，不为其逐单校验；退款、争议和待客户动作不混入供给压力 | 已知部分单列覆盖，不能填0或冒充完整当前积压；问题单可单列数量，但不驱动提价/限流 |
| `capacity_k_per_block` | 可交付K/6小时 | 已核供应能力；没有承诺值时可用明确标注的近期观测吞吐推算并持续验证 | 观测吞吐≠供应承诺；说明样本窗口、旧cohort遗漏与估计性质 |
| `capacity_reserve_ratio` | 0至小于1 | 默认留10%容量余量；按全局/价格组真实共享关系一次合并入流 | 不给Console和PC各自使用同一份全局容量 |
| `mtd` / 区间 | 当月同范围净收入USD | 只用已核付款日期、目标范围与金额口径；截至日、今日缺口和未分类上界一起显示 | 已核下界可用于决策，但不称实时精确累计；目标为空不编造目标值 |

## 5. 投入与预算参数

`R7d`是所管价格组最近七个完整日日均实际净收入。设计默认日额：daily=max($20,1%×R7d)，acquisition=max($50,5%×R7d)，flash_sale和revenue_sprint=max($100,8%×R7d)；backlog不新增促销投入。缺收入字段可用固定美元初值并标记`budget_initial_fixed`，确认零收入与未知分开。最终显式用户额度/已启用计划值优先，不能仅凭文档默认擅自扩大已启用预算。

三种预算分开：新增折让、实际负贡献、预测机会成本。折让参照使用持久`budget_reference`，不是每次降价后重置锚点。真实订单不是100K等价订单：按同一订单金额/数量口径计算多让出的USD，不能以100K差价直接乘真实大订单数。负贡献不能与盈利订单相抵销后隐藏。机会成本相对合法参考贡献的设计初值为10%/35%/30%/30%，积压容量目标优先；参考贡献非正时改用明确绝对额度，不套失真的百分比。

有限计划总额=启动日预算×计划小时/24；延长活动不自动加总额。Console/PC各自预算池，地区动作归属对应平台池；所有模式共享同池滚动24小时累计，换模式/跨月不清零。预计金额先按原操作预占，UNKNOWN保留；真实订单、迟到成本、退款修正原订单记录，不能重复新增整笔，成本待到也不能直接当零释放预算；历史券条款或现金差额尚未核清时同样保留预留，已付款不代表已完成实际投入结算。若尚未接入逐单结账实时预占，必须称软预算并说明在途订单可能超出，不能承诺绝对零超支。

## 6. Hermes每轮决策和审核次序

1. 读取当前`state`和计划：run、generation、作用域、模式、锚点、预算、截止、控制权、是否有原操作待对账。
2. 读取同快照五策略、市场、地区、模型状态。先区分已核事实、初始估计、缺项；检查币种、K、时间单位和覆盖范围。
3. 看双红线可行域、竞争带、容量、客户承诺、剩余预算。无解说明冲突，不手工放宽硬条件。
4. 在当前计划候选中选择，给经营理由和代价：预计收入/贡献/新客/交付，敏感性，为什么优于可行对照；不把销量最多当所有模式共同目标。
5. `recommend`必须绑定本轮run、原bundle SHA、候选action SHA、稳定request_key、理由和证据引用。换模式另建计划；不能让旧推荐覆盖新版。
6. 程序重核、原ID执行后，通过`operation_read`追踪后台、缓存和公开价。模型会话完成或队列accepted不等于写入完成。
7. 按“状态变化—证据—原因—动作—复查”报告。同decision/operation/incident贯通，明确未验证的层级。

工具名以部署后的capabilities为准；当前合同包括state、compare_strategies、read_quote、recommend、plan_propose、授权执行、operation_read、simulate及simulation_read。plan_propose只能产生可审阅建议；影子和历史回放无生产写入资格。历史旧算法只从指定版本只读回放入口访问，不暴露为生产模式选项。

## 7. 持续学习：样本如何进入、何时更新

真实价格窗口须由公开确认的操作建立，记录实际开始/结束、平台/地区、价格、计划与原实验分配。无法证明实际生效的时段保留为未执行/待确认，不能按意图价训练。不同资源独立窗口，不能因共享证明锁错误终止无关平台曝光。

订单按已核创建时间及平台/地区绑定其下单时有效价格窗口，随后按真实付款、退款与成本状态更新结果；不得把迟付款订单误归付款时的新价格窗口。原生时间戳须与显示时间一致，按历史购买K、赠送与数量倍数重建的地区常规价须吻合该窗口实际价格且只能唯一绑定；缺项或冲突进入learning_coverage缺口，不能仅凭时间相近贴窗。客户、数量、优惠、净收入、实际成本覆盖各自记录。使用有效小时或可核曝光作为分母，禁止混用两种单位。0曝光且0单是无机会，0曝光有单是绑定错误，不能补1掩盖。价格变化同时来自基价与地区系数时只算最终有效价格，不能重复施加弹性。

保留原随机分配概率、执行失败、预算退出、模型改选、实际生效延迟和未知状态。主要实验分析按原分配单元保留所有偏离；只看成功写入样本不能证明因果增益。影子订单不进入真实训练，历史无价格窗口的观察只作初始统计/相关证据。

模型更新保存训练截止、样本数、有效小时、价格变动覆盖、模型版本、参数、边界命中和适用范围。首版正则化Poisson可用于逐步更新弹性；价格没有足够变化时继续显示初始先验。较多样本不自动代表因果成立，月末、活动、广告或交付变化须在复盘注明。

## 8. 追踪、测试和再估计

| 对象 | 追踪指标/核验 | 何时处理 |
| --- | --- | --- |

| 预测 | 同生效窗口预测与实绩的订单、收入、采购贡献、有效新客、交付K偏差 | 每窗口成熟后回填；先查实际价格/曝光/成本变化，再估参数，不靠重置历史改善误差 |
