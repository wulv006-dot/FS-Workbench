本轮交付目标是一个实际生效、可以持续运营的新系统。旧策略不能继续藏在 fallback、人工意图、Hermes 提示词、过期队列或恢复脚本中。

## 04 统一价格和经营口径

### 04.1 三种价格必须分开

1. 基础商品价格：购买100K的商品总价，单位USD/购买100K。
2. 地区实际商品价：地区系数与商品规则计算后的当地商品价格。
3. 比价单价：客户实际获得的完整Coins数量对应的等价单位价，含真实赠送。

旧 /pricing/evaluate 的 console_usd、pc_usd 接收100K总价；内部 quotes/proposal 才是USD/1K。新API用明确字段与unit枚举，不猜单位。旧入口若保留适配，必须执行 $8.50 → 0.0850 → $8.50 往返测试。[S8]

所有金额使用Decimal或整数最小币种单位。地区系数用固定精度十进制；截图显示四位输入，但后台实际精度、截断或四舍五入需读回确认。禁止二进制float决定分币边界。

### 04.2 销售额与贡献

销售额目标优先继承Admin现有月目标口径。保存 target_basis、target_scope、target_currency、source、data_cutoff。

若新建目标且没有既有定义，默认：
- 已付款、优惠后实际收入；
- 已知退款按对应目标定义冲减；
- 未付款订单不计；
- 支付费、履约费和广告费进入贡献成本，不擅自从销售额定义中扣掉；
- 金额与退款的归期明确，迟到数据通过原订单调整，不重复计数。

Admin为经营主源，Order补充实际成本、履约和订单细节。范围以用户负责的站点及FC品类为准，排除不归团队负责的G2G/ELD分销订单；ELD竞品监控与分销收入归属是两件事。

净实收先按来源字段标准化，已经冲减的优惠、退款和费用不得再次扣除。贡献 = 净实收 − 完整实际交付采购成本 − 尚未计入净实收的支付费用 − 增量履约/发货/售后成本 − 同范围可归属广告投入。退款额若已冲减收入不再扣一次；退款产生的额外处理费或补偿，只扣尚未计入前述项目的部分。广告按期间计一次，不能同时扣总投入和逐单CPA。

采购毛利、贡献利润和会计净利润分开显示。缺广告归属时输出“已核订单贡献/广告待归属”，不填0后声称净利润。

## 05 双红线与地区系数的统一处理

### 05.1 必须保留的两条规则

- 第一条：原定义下的未优惠采购毛利率至少10%。
- 第二条：最近七个完整日真实优惠结构下的估算平均采购毛利率至少10%。

共同要求：
- PS/Xbox沿用共同验证成本池，PC独立。
- 采购成本包含完整实际交付量及赠送。
- 覆盖全部受影响发布套餐、允许的整数K、自定义量与原舍入规则。
- 个别合法优惠订单可以亏损；不逐笔加优惠后10%拦截。
- 40%预警、50%紧急复核保留为经营提示，不成为利润率上限。
- 当前硬证明用真实历史结构；需求模型的预测利润不能代替红线。
- “低销量可用先验探索”不等于允许伪造缺失的成本或七日硬证明。

将既有 common_cost、hard_floor、prove_price、catalog_floor、prove_catalog、required_history_ratio 等财务能力抽取为唯一模块，使用原真实夹具验证继承结果。旧选价逻辑可以删除，财务定义不能顺手改掉。

### 05.2 地区系数进入真实价格链

先对接一个权威价格函数：

~~~text
render_effective_price(
  global_base_prices,
  region_platform_coefficients,
  catalog_tier,
  region_rules_and_priority,
  purchase_quantity,
  customer_eligibility,
  currency_and_fx,
  verified_rounding_contract
)
→ regional_regular_price
→ actual_payable_price
→ delivered_quantity
→ applied_rule_trace
~~~

Work必须通过后台请求和公开/购物车报价查清：
- 地区系数是形成地区常规商品价，还是作为优惠项扣除；
- 商品级、类目级、服务器级、游戏级规则如何选择；
- 多条规则择一还是相乘；
- 地区、商品优惠、数量优惠、券、VIP、积分的先后及互斥；
- 当前地区系数是否已包含在历史“优惠金额”中。

若地区系数构成地区常规商品价，第一红线使用该地区未使用其他优惠时的商品价；若后台将其作为优惠，保持既有未优惠定义，并在第二红线的变更后回放中纳入它。必须按同一真实交易语义处理，不能为了通过红线临时改变归类。

### 05.3 防止历史折扣与新系数重复计算

历史逐单若满足以下已验证的乘法结构：

~~~text
paid_i / global_list_i = old_region_factor_i × other_retention_i
~~~

则先按每单得到 other_retention_i，再将候选 new_region_factor 代入。若历史分母已是地区商品价，历史retention本来就不含地区系数，不能再除一次。

固定额、门槛、封顶、满减和金额舍入必须重新执行真实优惠规则。不能用“全站平均retention ÷ 平均地区系数”替代逐单或分层回放；二者一般不等价。

硬证明至少保存：
- 原七日真实样本及覆盖证明；
- 原价格/地区/优惠版本；
- 分解后的优惠路径和权重；
- 候选价格与地区系数回放结果；
- 继承的原聚合公式、舍入和差异说明。

仅用于说明的比例形式为：

~~~text
estimated_average_margin =
  (candidate_regular_price × replay_retention − delivered_cost)
  / (candidate_regular_price × replay_retention)
~~~

正式计算必须保留既有金额加权口径，并对非线性优惠逐条重放。

### 05.4 新阿拉伯地区没有历史订单时

新地区无需等七日才开始：
1. 复用同一已验证FC Coins最近七个完整日真实优惠结构；有可靠同平台分层时可使用分层，否则继续用当前共用Coins口径。
2. 对这些真实资格/优惠路径，在候选阿拉伯地区系数下重新计算。
3. 明确标注 source_scope=global_pooled_actual_mix、application_scope=region_21、status=regional_projection。
4. 系数必须进入地区投影，不能因为该地区历史订单占比为0而被排除。
5. 地区积累足够真实样本后，再以版本变更切换为地区实际结构，展示前后差异。

这仍然是平均结构校验，允许其中部分真实优惠路径亏损。不得将借用结构写成“沙特七日实际数据”。

若历史字段不足以判断地区系数是否已包含在优惠中，先完成最小价格轨迹映射；该缺口只阻止无法证明的新增地区写入，不阻止已能证明的全球真实试验、监控和影子计算。

## 06 五套经营策略

| 模式ID | 运营名称 | 主目标 | 关键限制和选择 |
| --- | --- | --- | --- |
| daily | 日常经营 | 未来周期总贡献 | 涨跌均可，比较单笔贡献与需求变化 |
| acquisition | 拉新增长 | 首次付款客户数 | 折让/负贡献预算、成熟回访贡献，身份缺失不造数 |
| backlog | 交付积压 | 控制新增交付负荷 | 在容量可承受候选中选贡献较高者 |
| flash_sale | 限时促销 | 活动期限内累计贡献 | 真实优惠承诺、预算、开始/截止与到期退出 |
| revenue_sprint | 冲销售额 | 月目标缺口收敛与目标口径收入 | 竞品持平/略低、地区联合价格、双红线和履约能力 |

一个真实价格控制单元同一时刻只有一个有效计划。Console与PC可以选择不同目标，但共享地区系数形成耦合时，必须由联合求解器协调，不能两个模式轮流覆盖同一系数记录。

### 06.2 各模式行为

日常：优化总贡献。广告缺口如实显示，允许有预算的真实探索。地区系数默认保持已有效规则；若计划明确选择地区作用域，则在相同执行合同下优化该系数。

拉新：以站内去重首次付款客户为主目标。总订单和首次购买FC另列。首单贡献、已满观察期7/14/30日贡献、预测复购分别显示；预测LTV不直接增加可花预算。身份缺失时，利用部分使用合法参考/贡献较好候选，探索仍继续，并标注新客目标待核。

积压：按完整交付K、已承诺到期积压和可信交付能力计算。默认预留已核能力10%；不存在能缓解超容量的合法价格时显示CAPACITY_UNRESOLVED_BY_PRICE。不能凭涨价宣布积压解决。自动状态检测开启，是否自动抢占沿现有已明确授权配置；没有授权时不擅自覆盖用户活动。

促销：保存真实开始/结束、优惠承诺、预算和退出策略。首版支持公共价和已接通地区系数；新增券需真实核销合同，不能用改全局价冒充新客专属优惠。活动开始前SCHEDULED，到期必须退出；不通过重建计划无止境延期。

冲额：以第07节月目标模型选价，以第08节竞争窄带约束，阿拉伯地区通过第10节系数联合求解。降低单价不自动等于提高销售额。

## 07 冲销售额的目标与月初月末机制

### 07.1 目标模型

设：
- T为本月目标销售额；
- R_MTD为截至当前数据时点已完成销售额；
- H_month为到本自然月结束的剩余可经营小时；
- H_plan为当前冲额窗口剩余小时，上限不跨本月末。

~~~text
gap = max(0, T − R_MTD)
H_month = max(0, month_end − now)
H_plan = max(0, min(plan_end, month_end) − now)
required_daily = gap / (H_month / 24), if H_month > 0
projected_month_end =
  R_MTD + forecast_policy_calendar(now, month_end)
~~~

以上时间差统一换算为小时；本月已结束时进入结算，不除以0。只剩六小时不能仍当作剩一天。月初五日是冲额运行窗口，不是要求五天完成整个月目标。月末预测必须按真实策略日历接续窗口结束后的日常或已定模式，不能假设月初冲额价持续整月。月份和窗口均按北京时间半开区间处理，使用实际月末，包含二月和跨年。

候选动作a先计算当前窗口收入；月目标判断按整个剩余月策略日历推演。具备连续预测能力时，将窗口动作对后续复购、交付和预算的影响带入余月预测；暂不具备时标明当前窗口收入代理，不能把短期预测当完整月度增量。

候选动作a的收入：

~~~text
expected_plan_revenue(a,H_plan)
  = Σ expected_paid_orders(segment, tier, region, a, H_plan)
      × expected_target_basis_revenue_per_order(...)
~~~

在竞争区间、双红线、预算、容量与客户承诺的交集中，选择预计目标口径收入较高者。差异低于模型可分辨程度时，依次选贡献较高、额外折让较少、变动较小者。

展示：
- 目标、已完成、差额、所需后续日均；
- 按当前模式预计月末金额；
- 按冲额模式预计月末金额及剩余缺口；
- 预计订单、售K、新客、贡献和交付压力；
- 预测状态、数据截止和敏感性范围。

若所有可行候选仍不足以达到目标，直接显示“预计仍差X”。不得编造未来流量、无限降低价格或把未付款订单加入完成额。

### 07.2 月初月末默认窗口

设计初值：
- 月初：每月1日00:00至6日00:00，即前五个自然日。
- 月末：下月1日00:00向前七个自然日。
- 日期窗口之外，可手动启动或做what_if模拟。
- 自动模式日历在重构上线时接通；只接管由日历管理的计划，不覆盖明确人工锁定模式。
- 目标未完成，且按真实剩余流量/时段预测进度不足时自动进入；预测不足以判断时使用按历史时段分布或明确线性进度的启动基准，标记依据。
- 没有真实目标时自动达成判断关闭；本轮人工授权的首个冲额计划仍可按收入最大化运行，目标值保持空。
- 目标已达成、窗口结束、预算耗尽或已启用积压抢占时退出。
- 退出重算当前合法日常价与地区系数，不写回旧月初价格。

月目标不是每个价格组各自重新分一份总目标。若按平台/地区分配子目标，子目标合计与总目标一致；无法归属的收入单列。一个订单只在月度总目标计一次。

### 07.3 降价能否冲额的检验

实收结构不变时，降价5%至少需要订单增加：

~~~text
1 / 0.95 − 1 = 5.263%
~~~

才能保持原销售额。降价20%需要订单至少增加25%。因此，系统按预测收入选择竞争带内的价格，不能按“单量最多”直接判定冲额成功。

## 08 竞品监控与持平略低的精确定义

### 08.1 来源职责

| 来源 | 监控用途 | 进入冲额执行约束的条件 |
| --- | --- | --- |
| Lootbar | 全球核心竞争报价、赠送与异动 | 同游戏/平台/交付方式/资格/数量可比且新鲜 |
| ItemD2R | 全球核心竞争报价与异动 | 同上，不延用旧钉价逻辑 |
| Arab-UT | region21阿拉伯地区普通发货专门对照 | 实际选中normal，平台、数量、币种与交付量核实 |
| U7Buy及现有其他来源 | 市场参考、异常交叉核查 | 默认不获得新生产价格权重 |
| ELD | 已有独立观察迁入统一来源注册表 | 维持观察用途，不混入分销经营数据 |

所有来源复用同一个采集注册表，五策略和影子共享同一份采集结果。不可为每个策略分别再抓一次竞品。

### 08.2 可比单价

以每实际交付100K的等价价格为展示单位：

~~~text
competitor_unit_100k =
  comparable_payable_amount_in_common_currency
  / actual_delivered_K
  × 100
~~~

我方同样计算，包含真实赠送。付款资格必须一致：
- 普通公开价与普通公开价比较；
- 新客专属优惠另列，不冒充所有客户可买价格；
- 支付方式、必需附加费、币种、汇率版本明确；
- 商品/购物车价已核、支付附加费未核时，只能标为该已核层级比较，不能声称最终支付总价保证。

采用公开普通客户可实际购买的同口径报价作为主约束。继承旧系统排除支付手续费的页面价格口径时，应明确price_basis=public_merchandise；结账费用另列。只有双方费用证据齐备，才升级为checkout_total比较，不能一边含费一边不含。

不能直接把1M展示均价除十当作已经验证100K套餐；数量折扣、最低购买量及赠送可能不同。首个强制比较锚点为100K，随后覆盖实际主销档位；目录双红线覆盖范围始终完整。UI按档位显示已核覆盖，不能用一个锚点声称全档位最低。

### 08.3 冲额竞争区间

全球每个合格平台/档位：

~~~text
C_global = min(Lootbar_comparable_unit, ItemD2R_comparable_unit)
competitive_band = [0.98 × C_global, C_global]
~~~

阿拉伯地区在相同条件下：

~~~text
C_ar = min(
  region-comparable Lootbar unit,
  region-comparable ItemD2R unit,
  Arab-UT normal unit
)
~~~

如某来源不服务该地区或交付方式不可比，不把它伪装为可比。记录明确原因。Lootbar与ItemD2R是本轮承诺的核心来源；任一必需来源缺失时，该执行范围不能宣称“同时不高于两家”，也不能用旧价悄悄补齐。

“持平/略低”的定义是锚定最低可比报价、最多低2%的初始带宽，并展示相对每家的差值。两家报价差异较大时，不能声称同时与两家都相差2%以内。

四种合法候选来源：
- 最低竞品的100%、99.5%、99%、98.5%、98%；
- 竞争区间边界；
- 财务下限与系数精度产生的可行边界；
- 当前价或模型解析价，但也必须位于竞争区间。

没有隐藏.99尾价、额外减一分、旧降幅档位或二次乘95%。

### 08.4 双红线优先与不可行情形

假设归一到同一商品口径后：
- Lootbar=$9.50；
- ItemD2R=$9.20；
- 竞争带=$9.016～$9.20，按分币可选$9.02～$9.20。

若财务底价为$9.12，可选区间是$9.12～$9.20；不能为了低1%写$9.11。

若底价为$9.25，交集为空。返回：
INFEASIBLE_COMPETITIVE_PRICE_AND_DUAL_FLOOR

显示竞品价、最低合法价、差额、成本/优惠结构原因。保留或按原硬规则纠正当前合法价格，不标记“已完成对标”，不因业务不可行重启系统。

这项保证针对本次已核新鲜证据、平台、地区、档位及资格。竞品后续变价会触发重新计算；过期或不可比数据不支持新的保证。

每份竞争证明包含valid_until。到期时UI和接口自动从“已核对齐”切为“上次已核／当前待刷新”，不等待下一次采集返回。冲额核心来源默认每10分钟刷新、执行证据有效期15分钟；网络失败等造成有效期空档时明确显示待刷新，不放宽有效期伪装覆盖。刷新只读取所需来源，不为每个平台和策略重复整轮采集。

~~~

英区0.9100作为已知保护值，默认不自动改写；但英国实际价格会随全球基础价变化，必须参与影响评估和红线证明。

阿拉伯默认采用三条地区×平台精确规则。全球PS/Xbox基础价保持共用，阿拉伯PS与Xbox的最终价格允许通过不同系数分别优化，这是用户本轮明确补充的能力和用途。

| 21 / ar / Saudi Arabia | 7645 / AllServer | 21587 / PlayStation 4\|5 | k_ar_PS |

### 10.2 按平台求系数 并处理已有泛规则

默认分别求k_ar_PS、k_ar_XBOX、k_ar_PC；每个系数仍需覆盖该平台下所有匹配商品和档位。若实际存在不限游戏区的泛规则，先验证精确规则是否替代它，不能假设二者相乘。只有仍实际共用同一条系数的商品才求共享交集。

在已验证“地区价格=地区前商品价×系数”的简化情况下，对于同一系数实际影响的所有商品j：

~~~text
K_j(P) = {
  k:
  双红线通过，
  且有竞争承诺时有效单价在对应竞争带内，
  且满足活动及预算约束
}

K_shared(P) = intersection(K_j(P) for every affected j)
~~~

若各商品可以写成价格上下界L_j、U_j：

~~~text
k_min = max_j(L_j / before_region_price_j(P))
k_max = min_j(U_j / before_region_price_j(P))
~~~

系数下界向上取至后台精度，上界向下取至后台精度，再执行真实金额舍入和全部商品证明。最终可行集合以精算结果为准，不以这个连续近似代替。

一条不限商品/服务器的系数可能同时作用于主机和PC，不能分别算两个k后交替覆盖同一条记录。

共同区间为空时：
1. 联合调整全球主机/PC基础价，再求地区系数；
2. 采用已由截图确认的游戏区细分能力，按已核优先级拆成PS/Xbox/PC规则；必要时再按商品细化，分别证明，不能制造重复覆盖；
3. 仍不可行则返回具体冲突，不以放宽红线解决。

有Arab-UT PS报价、无PC报价时，可以独立计算和执行PS地区系数；PC保持当前已核规则，或继续它自身不依赖Arab的合法计划，不声称PC已对齐Arab。涉及全球Console基价的动作仍需检查PS和Xbox两平台；仅改PS精确系数的动作按真实影响集验证，不牵连无关PC。

### 10.3 每次基础价变化都重新计算系数

目标地区价不能仅靠一次保存系数维持。全局基础价、商品档位、赠送、地区优先级或优惠发生变化，均使相应平台原地区价格证明失效。每个地区×平台系数独立重算；保持其他地区系数的动作也要重算其实际金额和财务影响。

单纯乘法条件下：

~~~text
desired_region_coefficient =
  desired_region_regular_price / current_pre_region_price
~~~

再按共同范围、精度和完整价格函数求可执行解。禁止“全球价格已改、阿拉伯仍沿用旧系数、界面继续显示已对标”。

### 10.4 联合算例

以下是验算用假设数据，不是当前实际报价：
- 我方购买100K赠5K，全球商品总价$10.50；
- Arab普通交付有效单位价$8.80/实际100K；
- 目标约低1%；
- 每单完整成本$7，其他优惠平均保留比例0.90；
- 示例假设地区系数直接相乘，商品总价四舍五入到美分。

得到系数0.8712：
- 地区总价：$10.50×0.8712=$9.1476，示例舍入为$9.15；
- 有效单位价：$9.15/105×100≈$8.7143；
- 比$8.80低约0.9740%；
- 未优惠采购毛利率约23.4973%；
- 示例平均优惠后采购毛利率约14.9970%。

仅把系数写成0.99会使地区价约$10.40，并不能对齐$8.80的单位价。正确系数来自商品数量与实际价格计算。

## 11 需求模型与贡献计算

### 11.1 首版可实现模型

采用分组、分层收缩的订单模型：

~~~text
orders_i ~ Poisson(mu_i)

log(mu_i)
  = log(exposure_or_effective_hours_i)
    + intercept_group
    + time_and_business_features_i
    − elasticity_group × log(effective_customer_price_i / reference_price_i)
~~~

- 一个模型版本只使用一种offset：合格曝光或有效经营小时，不能逐行混用量纲。
- 0曝光且0订单作为无机会记录；0曝光有订单是数据合同问题，不能取log(0)或补1掩盖。
- 价格特征使用客户实际可见、可购买的地区商品价及已知优惠资格。全局基价和地区系数都改变最终价格时，不能把同一次降价重复计两次弹性。
- 新客与老客、主机与PC可分层；地区数据少时向全局价格组收缩。
- 时间、流量、广告、游戏活动、交付速度、竞品差价作为可获取的上下文；缺字段显式标注。
- 库存不是当前无库存订单驱动模式的核心变量；供应能力、已承诺交付和供应商成本进入模型。

初始中心弹性2，敏感性0.5/1/2/4；它们是设计先验，不是已拟合事实。可将弹性限定于合理计算域0～8并记录边界命中，避免低样本估计发散。

零订单或低流量不阻止合法探索；同时不能把零订单解释成已经知道降价一定有效。真实历史模型标observational_fit，真实试验更新后标experiment_updated，验证结果注明有效范围。

### 11.2 简化解析解与候选搜索

固定100K档位、平均实收系数r、单笔相关成本c、弹性epsilon>1时：

~~~text
N(p) = N0 × (p/p0)^(-epsilon)
contribution(p) = N(p) × (r×p − c)
p_star = epsilon×c / (r×(epsilon−1))
~~~

若每单购买q K而p是100K价格，收入系数须为r×q/100。手续费按比例收取时同步调整收入系数。epsilon≤1时只搜索有限候选，不计算无穷最优价格。

实际多档位、地区系数、赠送和非线性优惠，使用有限候选+精确重放；解析式只提供候选。冲额还要进入竞争窄带，不能直接使用贡献最优价替代收入目标。

### 11.3 模型更新

- 正式训练只用真实订单、曝光、真实价格版本和实际分配。
- 地区零样本时可以借用分层模型，但标明借用范围。
- 价格历史与订单需按实际曝光/报价或订单绑定时间关联，不能仅按支付时间把延迟付款归给最新价格。
- 复购7/14/30日结果在观察期成熟后回填；未成熟样本单列。
- 模型更新保存训练截止、样本覆盖、特征版本、参数、诊断和适用范围。
- 同一实验时间块内不因模型重算反复抽签；下一块使用新模型，必需规则变化例外并有修订记录。

## 12 真实试验设计

### 12.1 按真实受影响资源确定实验单元

全局Console基价变化会同时影响PS、Xbox和英国等地区；这种动作以一个联合action_vector分配，不能当成两个独立随机实验。

若只改变阿拉伯某平台系数且固定全球基础价，可以按该地区×平台分配。必须证明其他地区/平台未被规则优先级或通用系数联动影响。

候选生成先受plan.allowed_mutable_resources约束，未获当前计划控制权的基础价和地区规则保持不变。最终选定动作重新推导完整写入和依赖资源；preview、证明、授权、锁、CAS、UNKNOWN检查与读回使用同一个影响集合。锁内发现规则匹配或影响集合改变，退出重算，不在旧锁范围内继续扩展。

每个实验保存：
- experiment_id、plan_id、revision、assignment_id；
- action_vector及实际受影响范围；
- 对照、较优、探索的分量标签；
- 最终动作合并后的分配概率；
- 随机种子/抽样记录、模型版本、数据快照；
- 起止时间、计划截止、证据有效期；
- 预期价格、后台价格、公开价格、实际订单报价。

### 12.2 分配与边界

- 默认六小时时间块，按星期和时段分层随机，避免固定ABAB与自然流量周期重合。
- 首块工程验证后立即开始，不等六小时。
- 相同舍入后动作合并；概率按完整动作向量而不是只看基础价合并。
- 对照若不满足竞争带、双红线或真实促销承诺，移除并重新归一化概率。
- 没有探索候选，探索权重转给较优候选；只有一个候选时执行确定性动作并标注，不宣称随机试验。
- 每块只分配一次，服务重启或Hermes超时不重新抽取。
- 竞争报价、成本、商品或地区规则变化使原动作不再合法时，结束原分配，生成有谱系的新修订；不是继续执行过期六小时动作。
- 报价证据有效期与实验分配有效期分开，每轮重新获取必要证据。六小时分配不延长15分钟报价有效期。

当前价与候选相同时，也记录有效价格曝光，不制造虚假执行单。未能执行的分配、预算退出、公开价延迟仍留在实验账本。

### 12.3 效果评价

主因果分析保留原始分配及所有偏离，按实际随机化单元分析，不能删除失败或预算退出时间块后宣称策略增益。

实际曝光、订单报价与履约分析另列。跨块携带效应、价格缓存、客户回访、跨地区访问和不同时段流量要在报告中说明。观测拟合和影子预测不自动获得因果结论。

积压模式没有强制随机对照，因为其目标优先控制负荷；相应效果按运行证据评估，不包装成随机实验。

## 13 预算 月目标与经营投入

### 13.1 三种约束分别记账

| 项目 | 含义 | 初始实现 |
| --- | --- | --- |
| 新增折让预算 | 相对冻结预算参照，同一实际订单多让出的金额 | 按真实金额回填，预计金额先占用 |
| 实验负贡献预算 | 试验订单发生的负贡献总额 | 与折让分开记录，不能互相抵销 |
| 预测机会成本额度 | 相对合法参考方案预计少获得的贡献 | 候选筛选与风险展示，不能当实际损失 |

日常、拉新、促销、冲额的预测机会成本初值分别为10%、35%、30%、30%；积压按容量目标优先。参考贡献非正时不使用失真的百分比，改用明确绝对预算。

负贡献预算默认与表内新增折让额度同值，但为两个独立约束。积压“零新增促销投入”不改变原合法优惠的承诺，也不成为逐笔不亏条件。

### 13.2 预算作用域与去重

- 默认按全局价格组管理滚动24小时总投入；地区子计划占用该组额度，不能每新增一个地区再无条件多领一份。
- Console的PS/Xbox地区动作仍共享Console预算池；PC独立。
- 一个订单相对冻结完整价格向量的折让只算一次，不把全局降价与地区优惠的重叠金额重复相加。
- 预算参照与实验价格锚点分开，存为持久budget_reference。
- 切模式、换实验、跨月、重启服务都不清空滚动消耗。
- 有限计划总预算=启动时日预算×计划时长小时/24；延长时间不自动增加总额度。
- 已有明确额度优先；新额度有版本、范围和生效时间。

### 13.3 预占与结算

执行锁内再次检查预算，并用operation_id做幂等预占。UNKNOWN保留预占，直到原操作对账完成。订单迟到成本/退款差额更新原订单，不重复新增整笔。

若当前结账系统不能逐单实时占用，明确显示预算是基于已知订单与待支付暴露的软预算；考虑在途购物车/已给报价承诺，不能宣称绝对零超支。硬预算需要真实结账接入，不能仅在每两小时监控中许诺。

预算耗尽触发同一队列中的退出/重算动作，不等下一六小时块。退出动作不能被已耗尽的旧促销预算永久拦住；它仍受当前双红线、客户承诺与执行合同约束。

## 14 长期影子模拟

长期影子从首个真实新策略周期同时启动，默认持续开启、无到期日。它用于持续比较和诊断，不阻挡真实运行，也不自行切换生产。

### 14.1 轨道A 同一真实场景的五策略比较

每次真实数据快照就绪后，使用同一模型版本和同一真实状态并行计算五个模式：
- 全球基础价及各地区×平台系数；
- 实际地区商品价、交付单位价与竞品差；
- 预计销售额、订单、新客、贡献和交付量；
- 双红线、预算、容量、期限与适用条件；
- 当前可执行/不可执行及原因。

这回答“此时换一个经营目标，模型会怎么选”。每轮都基于真实状态，不把这些单轮结果相加成虚构的连续经营收益。

### 14.2 轨道B 五条长期独立经营路径

每个模式维护独立模拟状态：
- 自己的订单、新客身份与复购路径；
- 地区和平台价格、规则版本；
- 预算、报价承诺与在途订单；
- 交付积压、可交付能力使用；
- 最近七个完整日模拟优惠结构；
- 月度累计销售额及目标缺口；
- 活动开始、到期、模式退出；
- 模型/策略版本与随机种子。

同一批情景共享外部流量、成本、竞品、供应能力及随机冲击，方便比较。订单、优惠结构、预算、积压按各策略自己的结果滚动。不能每轮重新装入真实队列和真实预算，又声称已经模拟了一个月独立策略。

每条长期路径的“日常策略”也会按自身规则处理财务冲突与失效；限时促销和冲额要有明确的活动日历。无活动时可以计算what_if，但不能假设全年每时每刻都是促销期。

### 14.3 影子数据与真实结果分离

所有记录带 mode=shadow、simulation_kind、as_of、model_version、policy_version、assumptions。

报告区分：
1. 已发生真实实绩；
2. 同场景预测；
3. 连续情景模拟；
4. 有实验条件支持的效果估计。

影子订单不进入Admin/Order，不消耗真实预算，不回写生产训练标签。正式模型不能用自己模拟出来的销量证明自己正确。

模拟结果用于提出参数/策略修订；不能仅因模拟排行第一自动获得新生产权限。五个经营目标不同，报告同时展示目标完成和代价，不只按利润一列给所有模式排输赢。

### 14.4 运行与汇总

- 与真实采集共用快照，不重复抓五遍竞品。
- 影子工作进程无价格写入、Admin地区修改和发布权限。
- 幂等键含snapshot_id、policy/model版本、simulation_kind、路径编号。
- 计算积压时合并过时的单轮对比任务，但保留必须连续推进的路径状态或明确缺口。
- 默认每日摘要、滚动7/14/30日及月度汇总；不新增对外消息渠道。
- 原始细粒度结果默认保留180日，月度摘要和模型/策略版本至少24个月；容量按实际规模调，必要历史凭据不因通用清理丢失。
- 对每类来源显示覆盖、最近成功、数据时点和版本。
- 初期以明确弹性/流量/成本情景运行；只有在分布有依据时再做Monte Carlo，不能把随意抽样区间称统计置信区间。
- 影子资源设独立CPU/内存/并发上限；影子失败不会占用生产writer锁或重启生产浏览器。

## 15 历史模拟与旧策略比较

默认先跑最近七个完整日，扩展14/28日和完整自然月。当前真实试验无需等待历史补齐。

| 模式 | 内容 | 结果名称 |
| --- | --- | --- |
| actual_reconstruction | 原价格、地区、优惠、订单、成本与交付 | 历史实绩 |
| fixed_orders_reprice | 保持订单和资格，代入其他价格/系数 | 固定订单金额重算 |
| demand_counterfactual | 订单随价格变化，后续状态滚动 | 需求反应情景模拟 |
| causal_evaluation | 依赖真实随机分配或合格识别条件 | 实验效果估计 |

比较对象包括实际已执行策略、新五策略，以及冻结旧80/15/5、ItemD2R临时持平等历史算法。旧算法只进入独立只读simulation registry，不返回生产可执行决策ID。

### 15.1 历史时点与规则

- historical_asof使用当时实际可知成本、竞品、地区规则、活动和价格；没有证据的字段标缺失。
- common_guard_benchmark使用统一当前规则比较不同选价目标，单独报告。
- as_of与available_at同时约束，不能把后来才取得的数据放回当时决策。
- 历史实际流量可作为明确的事后情景路径，但不是当时已知未来流量。
- 竞品缺失不可用今天价格回填；地区系数缺历史版本不可用今天记录伪装历史。
- 不修改系统时钟，不向生产evaluate提交旧报价，不通过跳过freshness做历史模拟。
- 历史政策抽样概率缺失时，不能伪造概率来执行反事实因果评估。

### 15.2 连续模拟的动态反馈

每条路径自行滚动：
- 实际可完成K不超过模拟待交付K与情景能力；
- 不直接复制历史已完成订单数来充当不同需求下的交付量；
- 新客首次付款后变为老客；
- 优惠结构、地区占比、预算及月目标进度随该路径更新；
- 延迟退款、复购和订单报价跨期有明确规则；
- 固定历史优惠结构模式与动态结构模式分别命名，不能混合计算后给一个收益数字。

- UNKNOWN对账；
- 影子派发与汇总。

默认调度器每60秒检查due任务，不等于每60秒抓竞品或写价。一般模式保留120分钟采价初值；冲额核心竞品默认10分钟刷新，限时促销可设30分钟，仍由同一调度器管理，不能每个来源、策略、地区各起一套业务timer。

正式执行用满足现行时效合同的证据。竞品执行初值继承15分钟内、关键比价采集跨度不超过5分钟；成本、汇率等若有更严现行要求继续遵守。来源刷新频率与报价有效期分别管理；普通模式间隔长不等于可以执行过期报价。每次实际写入按需补齐新鲜成本等必需证明。

同一已完成采集事件触发真实计算和影子分支。未完成进度更新只更新UI，不触发新run。

调度按任务类型分队列和优先级。UNKNOWN对账、写后缓存/公开核验和截止事件不以完整采价成功为前提，只补取当前阶段必要的证据。唯一调度入口不等于一条串行执行队列；一个180秒采集超时不得挡住已到期事件和其他资源的对账。

### 17.2 计划与操作状态分开

计划状态：
DRAFT → SCHEDULED → ACTIVE → SUSPENDED/ENDING → ENDED

运行可标业务结果：
READY、NO_CHANGE、INFEASIBLE、DATA_PENDING、REVIEW_PENDING、BUDGET_EXHAUSTED。

实际写入操作状态：
PREPARED → AUTHORIZED → DISPATCHED → BACKEND_CONFIRMED → CACHE_CONFIRMED → PUBLIC_CONFIRMED → COMPLETED

异常分支：
- DISPATCHED后结果不清楚 → UNKNOWN；
- 联合动作仅部分确认 → PARTIALLY_APPLIED；
- 已证实尚未派发的拒绝 → REJECTED_PREWRITE；
- UNKNOWN或PARTIALLY_APPLIED只能进入原动作对账，不新建ID盲重放。

对账必须能走到明确终态：已确认步骤不重发；已派发未知步骤继续只读核实；有耐久证据证明从未派发的步骤，可在当前所有权、期限、证据和中间态重新通过后，沿原bundle/step派发一次。若原目标已过期、被接管或不再合法，停止未派发步骤；查清已发步骤后生成带parent_operation_id的明确退出/补偿动作，重新证明再执行。不得清除原dispatch标记来“重试”。

NO_CHANGE不是虚假COMPLETED写价；仍可形成带地区公开核验的曝光记录。

### 17.3 控制权

每个可变资源绑定plan_id、revision、engine_generation和有效租约。资源包括全局基础价、地区规则行及其真实覆盖商品。

优先关系：
- 人工暂停/明确接管；
- 已启用的积压紧急抢占；
- 对客户已生效的活动承诺；
- 当前人工选择或日历托管计划；
- 日常默认。

竞品变价、模型建议、影子赢家不能各自越过协调器写价。

## 18 基础价与地区系数的执行合同

### 18.1 复用既有鉴权和真实接口

地区表单是SPA路由，不等于API。Work沿现有已授权Admin会话读取页面实际请求，核实list/detail/create/update/toggle、分页、错误码、返回ID和读回方式。禁止猜路由、另建凭据缓存、导出敏感会话。

复用现有FS鉴权、角色、Origin/CSRF、发布和连接通道；价格能力只开放必要站点、游戏、类目、地区和平台范围。地区写入纳入同一writer协调器，不能作为Hermes可绕过价格证明的独立任意工具。

### 18.2 写入前必做

锁内重新确认：
- 当前generation和plan ownership；
- 所有affected_resources的真实版本；
- 当前基价、地区规则、目录和匹配优先级；
- 新鲜成本、有效优惠结构、竞争证据；
- 完整双红线；
- 预算和计划期限；
- 当前生效审核合同；
- 无冲突UNKNOWN或未完成联合动作；
- 动作与preview/authorization哈希一致。

拟创建地区记录时，使用精确作用域查询是否已存在；正常创建一次并保存返回ID。网络超时后先按原ID、精确scope和预期值核对，不能再次点“添加”制造重复规则。

### 18.3 联合动作的中间状态

基础价和地区规则可能通过不同接口写入，终态合法不代表中间态合法。

对旧动作(P_old,K_old)到新动作(P_new,K_new)：
- 先改基价时验证(P_new,K_old)；
- 先改系数时验证(P_old,K_new)；
- 多条PS/Xbox/PC系数分步保存时验证每个实际中间组合；
- 每一步检查双红线、已生效客户承诺，以及已经取得的竞争状态是否仍成立。

优先使用实际支持并已核验的原子发布接口；没有原子能力时，只执行有合法顺序的组合。若当前尚未进入竞争带，合法过渡仍不得新增财务违规，并在终态读回前不宣称已对齐；已有竞争承诺不能在中间态静默失效。

没有合法执行顺序时，选择只改系数/只改基础价等合法候选，或保持当前状态并返回NO_SAFE_COMMIT_PATH；不能在未证明的中间低价暴露后靠回滚补救。

新动作共享一个decision_bundle_id，基础价与地区规则各有step_id及dispatch证据。多个资源按固定顺序加锁，避免死锁。

### 18.4 写后证明

分别读回：
1. 后台全局价格；
2. Admin地区规则ID、scope、系数、状态及匹配优先级；
3. 缓存刷新结果；
4. 真实地区上下文中的PS/Xbox/PC公开价格；
5. 适用时购物车/权威报价中的普通客户及首单优惠；
6. 负面范围：英国0.9100未被改写、无关站点/品类/地区没有被覆盖。

读取“系数已保存”不等于“客户看到正确价格”。旧 pricing_sources 直接比较unit×100×retained_ratio，缺地区项；必须换成地区感知投影，否则会误报价格不一致或漏掉地区折扣。[S9]

## 19 Watchdog与故障恢复统一重构

### 19.1 先分类 再处理

| 分类 | 系统行为 |
| --- | --- |
| NO_CHANGE、目标已完成、无竞争可行解 | 正常业务状态；展示原因，不重启、不刷错误告警 |
| 可选竞品缺失 | 其他合法流程继续，显示覆盖不足 |
| 当前动作必需竞品缺失 | 暂停对应依赖动作，不影响无关平台/地区 |
| 成本或财务证明缺失 | 阻止相关新写入，按依赖故障恢复 |
| 429/暂时网络故障/只读超时 | 尊重Retry-After，统一有界退避 |
| 平台、商品、身份或价格合同不符 | 隔离来源；不能改为“成功”继续 |
| 模型/Hermes超时 | 记录REVIEW_PENDING或使用已明确批准的新引擎确定性路径；不回旧策略 |
| 写入结果未知 | 原ID对账，禁止同资源重复派发 |
| 后台成功、缓存或公开核验失败 | 仅恢复相应后置阶段，不重做价格写入 |
| 监控自身读取失败 | 标记observability_degraded及last_success，不宣布业务恢复 |
| 浏览器不健康 | Supervisor统一检查与恢复，其他探针不直接restart |

最后已确认价格可以暂时维持，但“上次确认”不代表按今天变动后的成本仍通过红线。若现价可能违规，标记CURRENT_PRICE_RISK，并在证据具备时生成新架构内的安全纠正动作，不能静默称安全保持。

### 19.2 统一错误结构

~~~text
ErrorEvent
  incident_key / root_cause_key
  code / category / phase / dependency
  affected_scopes / affected_resources
  operation_id / original_run_id / attempt
  retryable / write_started / timeout_kind / exit_code
  first_seen / last_seen / last_success_at
  evidence_refs / recovery_action_id
~~~

禁止丢掉真实退出码后统一改成collector_failed。应用边界输出稳定错误码，原始诊断进入受控日志，不在页面暴露凭据、客户资料或完整请求。

### 19.3 根因归并与通知

incident_key按根因、依赖和固定业务主体构造，不包含每轮run_id或不断变化的完整范围列表。affected_scopes作为可变字段，影响扩大在同一incident中升级记录和通知，不重新制造同根因告警。

一个浏览器故障可以形成一个父incident，下面展示多个来源受影响；保留各来源覆盖，不重复发十条同义通知。

沿已授权的原通知通道，只有首次、等级升级、影响扩大、必要间隔提醒和恢复产生通知。outbox持久化，未知发送状态按原记录核对，不重复投递。未授权的新邮件、群聊或外部频道不由本次施工自行增加。

界面显示：影响什么、从何时开始、已尝试什么、下次何时恢复、是否影响价格/交付、最后一次确认成功。正常业务无解与技术故障使用不同状态颜色和文案。

### 19.4 重试与熔断

- 重试只有Coordinator/Supervisor拥有调度权，采集器内部重试计入同一个总预算。
- 纯读取默认有界5/15/30/60分钟退避，加入小幅随机抖动；尊重更长Retry-After。
- 到上限后进入熔断，低频探测恢复；不形成“采集器×worker×watchdog”多层指数重试。
- 保留当前P2PAH180秒执行限额及正确timeout分类，后续调整必须有测量依据。
- 浏览器由一个Supervisor决定恢复，继承-displayfd就绪、会话隔离、原锁和空闲条件。
- 不删除登录profile、不反复清锁、不绕过网络白名单、不因为竞品拒绝访问不断换身份。
- 生命周期恢复与业务恢复分别验收。CDP能连接不等于报价成功，报价成功不等于价格已公开生效。

正常依赖故障可以恢复，外部站点也可能持续不可用。重构验收的是故障不扩散、不重复写、不无限重启、能准确定位和恢复，不是承诺所有外部调用永远不报错。

### 20.2 旧文档和历史代码

- 仓库活动说明和Hermes正式知识只指向新主合同。
- 旧施工文档添加SUPERSEDED与新版本链接，移入历史索引，不作为当前执行指令。
- 旧策略代码如保留历史回放，位于隔离legacy_simulation区域，无writer、Admin凭据或生产调度入口。
- 旧release包作为历史证据可保留；活动manifest不得引用其旧selector。
- 当前原来的财务函数、幂等、日志、UNKNOWN与已修复浏览器能力迁移后保留语义。
- 共享FS或RPG watchdog保留其他业务，仅移除旧FC分支并接入新FC状态投影。

### 20.3 防止旧任务复活

切换生成新的engine_generation和控制epoch。旧generation不能获取writer租约、修改地区系数或恢复旧策略。

代际校验必须位于真正dispatch边界。旧writer若尚不识别generation，先停止或隔离其发新请求能力。已派发操作的耐久资源占用与普通worker租约分开，不因TTL、进程死亡或版本切换自动释放；新系统接管对账责任，但未决资源查明前不能执行新写入。

尚未完成的原操作在迁移表中保留原ID、原请求与dispatch状态，允许只读对账。不能为了清队列将UNKNOWN标为成功、删除锁或换ID再发。

自动回滚不得直接恢复旧加权/临时钉价控制。新架构故障时可保持最后已核价格，或回退新架构的上一个已验证版本；若确需历史程序恢复，应作为另一个明确恢复决策，不通过隐藏fallback发生。

旧100K evaluate入参仅允许经当前计划和真实作用域转换为新schema的只读测算，返回不可直接执行的结果。旧preview/execute不会因字段兼容重新获得执行权；必须取得新generation、完整地区影响集、新证明和新preview/authorization。禁止兼容层重新调用旧selector。

- 预算和截止；
- 故障影响与恢复状态。

- pricing_compare_strategies
- pricing_region_impact
- pricing_sprint_target
- pricing_simulate
- pricing_plan_propose

## 24 截止 退出与跨月

所有有限计划在创建时写入耐久截止任务，与调价使用同一调度器和writer。

到期检测、UNKNOWN对账和退出任务先读取控制账本，不依赖新一轮完整竞品采集成功。退出使用独立、短有效期的EXIT授权，引用原plan/revision及退出原因，不把已过期的活动授权再拿来校验。EXIT可终止原计划并按当前合法策略接管资源；它不绕过当前双红线、真实价格证据或已给客户承诺，也不能被“旧计划已过期”或“旧活动预算已耗尽”永久拒绝。

任务执行时比较plan_id和revision，不要求仍等于最初assignment epoch；日常换块会改变epoch，但不能使真正到期任务永久失效。

创建或修改计划revision/截止时间时，计划状态与该revision的截止任务在同一事务更新。旧截止任务失效前必须存在替代任务。退出到日常只获取日常动作必需的来源，不再强制补齐已退出冲额模式的全部竞品；退出不重新消耗已耗尽的旧活动促销额度，按新退出动作自身适用的预算规则核验。

- 未来开始的活动保持SCHEDULED。
- 当前时间满足starts_at<=now<ends_at才允许活动写入。
- 每次授权有效期是证据、计划、分配、预算授权有效期的最早者。
- 同一资源已被用户新计划接管，旧截止任务只终结旧计划，不能覆盖新模式。
- 拉新七日、促销截止、冲额月初月末都使用同一退出实现。
- 跨月更新目标周期，滚动24小时预算及未结承诺继续保留。
- 已给用户的有效报价/购物车承诺按站点真实合同处理，不能追溯更改已支付订单价格。
- 到期时某依赖不可用，记录EXIT_PENDING并在原计划谱系恢复；不得永久保留活动价却显示已结束。
- 恢复系数要按所有权、当前匹配规则与现成本重算。用户后来手动改了某地区规则，不用旧快照覆盖。

## 26 必须通过的验收

### 26.1 价格与经营计算

- A01：100K接口、1K内部、实际交付单位价转换正确。
- A02：赠送、数量档、整数K、固定金额优惠、门槛、封顶与舍入精算。
- A03：未优惠与七日平均两条10%红线继承一致。
- A04：个别合法七折订单亏损仍可在平均红线通过时执行。
- A05：降价增加订单但降低收入时，冲额不误判为更优。
- A06：冲额所有候选位于最低可比竞品的允许窄带。
- A07：底价高于竞品返回不可行，零违规写入。
- A08：.99、旧权重、额外减价和临时parity不再改变新引擎结果。
- A09：目标口径、订单去重、退款和跨月归期正确。
- A10：低销量允许先验探索，硬成本/历史证据缺失不会被伪造。

### 26.2 地区与平台

- R01：准确映射Admin 1327、Order 1322及三个游戏区ID。
- R02：PS/Xbox共用全局基价，地区系数及最终价可以不同。
- R03：精确游戏区规则与ALL规则的实际优先级正确，没有误叠乘。
- R04：英国0.9100保护不被修改，全局变价后英国实际价格重新校验。
- R05：Arab仅PS报价不会伪造Xbox/PC覆盖；独立平台系数可以独立推进。

- R07：旧地区折扣已含/未含在历史retention中的两种数据均正确。
- R08：新地区无订单时采用真实共用结构投影，系数仍影响平均红线。
- R09：无法分解历史优惠时不伪造精确证明，缺口作用域明确。
- R10：地区普通价、首单价、后台、公开和购物车对应同一规则版本。
- R11：部分平台来源故障不会阻塞不受影响的独立地区动作。
- R12：基础价与多个系数的所有中间态通过要求，没有合法路径则不盲写。

### 26.3 实验 影子与预算

- E01：同一块重启不重新抽签，完整动作相同才合并概率。
- E02：联合主机基价动作不伪装为两个独立实验。
- E03：保持原价也记录有效曝光，无虚假写价单。
- E04：失败、预算退出和偏离保留在原分配分析中。
- E05：换模式、跨月、重建活动不重置滚动预算。
- E06：一次订单的基础价/地区让利不重复计算。
- E07：UNKNOWN预算预占不自动释放并再次消费。
- E08：五条影子路径分别更新预算、积压、优惠结构与目标。
- E09：影子故障不影响真实写价，影子数据不污染真实训练。
- E10：历史模拟不泄漏未来数据，不调用生产旧quote执行。

### 26.4 运行与旧机制退役

- O01：进度文件反复变化不会重复采集；完成事件重复投递只消费一次。
- O02：写入请求发出后超时，恢复不会第二次派发相同业务写入。
- O03：后台成功、缓存失败只恢复缓存；公开核验失败不重写基础价。
- O04：地区创建超时后按原动作核对，不创建重复规则。
- O05：部分联合动作成功后统一对账，其他周期不能并发覆盖资源。
- O06：浏览器未就绪不会形成多watchdog重启风暴；继承-displayfd。
- O07：P2PAH超时分类正确，退避在同一恢复谱系内。
- O08：业务无解不触发进程重启；可选缺源不升级成全系统宕机。
- O09：旧计划到期不会覆盖新计划；日常epoch变化不会使真实截止失效。
- O10：旧generation、旧preview和旧fallback不能写入。
- O11：共享FS/RPG未受误删，原对外告警不重复投递。
- O12：告警探针不因策略版本变更静默失明。
- O13：五策略切换、暂停、恢复及重启后控制权唯一。
- O14：首个新常规周期与人工恢复周期区分，保留真实成功/失败分母。

这些测试针对实际财务和运行风险。无需为凑数量扩大到无关全仓测试；已有相关测试能证明的能力可复用。

## 28 核心流程伪代码

下列用于明确控制流与职责，辅助函数按前文合同实现；不是已部署程序。

~~~python
def pricing_cycle(ctx):
    now = current_time()
    control = read_durable_control_state(ctx)
    # Control recovery is independent of new quote collection.
    if control.has_due_exit:
        record_exit_due_and_enqueue_once(control.due_plan)
    if control.has_unresolved_dispatch:
        return reconcile_original_operations(control.original_operation_ids)
    if control.has_due_exit:
        return process_independent_exit_task(control.due_plan)

    plan = resolve_plan_owner(control.requested_resources, now)
    if plan.is_future:
        return mark_scheduled(plan)
    if plan.has_expired(now):
        return enqueue_independent_exit_authorization_once(plan)

    snapshot = collect_required_snapshot(ctx, plan)
    # The small outbox event is durable; shadow computation is asynchronous.
    persist_snapshot_and_ready_outbox(snapshot)
    region_contract = resolve_region_match_contract(snapshot)
    candidates = build_joint_candidates(
        mode=plan.mode,
        snapshot=snapshot,
        base_groups=("console", "pc"),
        regional_platforms=("PS", "XBOX", "PC"),
        frozen_anchor=plan.price_anchor,
        region_contract=region_contract,
        allowed_controls=plan.allowed_mutable_resources,
        preserve_all_other_controls=True,
    )

    feasible = []
    for action in candidates:
        impacted = calculate_actual_impact(action, snapshot, region_contract)
        prices = render_all_effective_prices(action, snapshot, impacted)
        finance = prove_original_dual_redlines(
            prices=prices,
            actual_seven_day_mix=snapshot.discount_mix,
            candidate_region_replay=True,
            impacted=impacted,
        )
        market = prove_mode_market_constraints(
            mode=plan.mode,
            prices=prices,
            quotes=snapshot.market_quotes,
            coverage=plan.competitive_coverage,
        )
        if not finance.pass_all or not market.pass_required:
            continue
        score = evaluate_mode_objective(plan, prices, snapshot)
        if budget_capacity_and_promise_fit(plan, action, score, snapshot):
            feasible.append((action, impacted, finance, market, score))

    if not feasible:
        return record_scoped_infeasible_result(plan, snapshot)

    assignment = reuse_valid_assignment_or_create_once(
        plan=plan,
        feasible_actions=feasible,
        merge_by="complete_action_vector",
        snapshot=snapshot,
    )
    scope = calculate_actual_impact(
        assignment.action, snapshot, region_contract
    ).all_required_resources
    recheck_authorized_scope_and_plan_ownership(plan, scope)
    if has_unresolved_dispatched_operation(scope):
        return reconcile_original_operations_for_resources(scope)

    commit_path = prove_safe_commit_path(
        before=snapshot.current_action_vector,
        after=assignment.action,
        impacted=scope,
        financial_contract=ctx.financial_contract,
        promises=plan.promises,
    )
    if not commit_path.exists:
        return record_no_safe_commit_path(plan, assignment)

    authorization = obtain_required_review_and_authorization(
        plan, assignment, snapshot, commit_path, scope
    )
    if not authorization.complete:
        return record_review_pending(plan, assignment)

    with lock_resources_in_order(scope):
        write_now = current_time()
        revalidate_action_impact_matches_locked_scope(assignment, scope, snapshot)
        revalidate_generation_owner_and_versions(plan, snapshot, ctx, scope)
        revalidate_no_unresolved_dispatch(scope)
        revalidate_fresh_sources_and_all_proofs(authorization, write_now)
        revalidate_deadline_budget_and_capacity(plan, authorization, write_now)

        if action_already_effective(assignment.action, scope):
            receipt = verify_actual_region_prices(scope, assignment.action)
            return record_no_change_exposure(assignment, receipt)

        operation = prepare_original_operation_once(
            authorization=authorization,
            commit_path=commit_path,
            assignment_id=assignment.id,
            resources=scope,
        )
        reserve_budget_once(operation.id, plan, authorization)
        result = dispatch_only_unclaimed_steps(
            operation,
            before_each_dispatch=lambda step: revalidate_step_with_fresh_clock(
                step, operation, plan, authorization, scope
            ),
        )

    if result.unknown_or_partial:
        return enqueue_original_reconciliation(operation.id)
    return complete_cache_public_and_exposure_stages(operation.id)
~~~

必须由writer/数据库控制dispatch是否已经发出；函数重入不能再发。每一步的持久状态在网络请求前保存。实际后置读回耗时不能一直占住无关组的资源，但未完成联合动作的资源所有权必须保留。

### 29.2 切换顺序

1. 完成只读基线与待对账清单，备份数据库和原配置。
2. 部署新代码为未持有生产控制权的版本，验证必要接口与纯计算。
3. 在原发布锁/队列锁下停止旧系统产生新dispatch；已发出的后台请求不能靠generation切换取消。将其完整影响资源迁入耐久冻结租约，按原ID只读对账；未解冻前新writer不得接管这些资源，无关资源可以先启动。
4. 迁移计划、预算、截止和操作映射，保留原历史。
5. 只有已证明无在途/UNKNOWN操作的资源才授予新generation写租约。旧generation失去新dispatch权限，但其原请求的迟到回执仍按原记录接收和对账，不能因版本旧而丢弃。
6. 启用新调度、五策略及平台地区规则执行。
7. 同批启动影子，不为影子再复制真实采集。
8. 读回真实价格和控制权，停止/移除旧独占FC入口，检查其无剩余writer路径。
9. 逐项记录retirement inventory最终状态。

不能先把全部旧服务删除再开始开发，也不能为了“无停机”让两个writer并行。切换窗口的价格状态和待执行任务必须可解释。

### 29.3 回滚

优先回退新架构上一已验证版本，控制epoch与退役状态不倒退。新模型问题可以切回新引擎的确定性候选/保持动作；不能自动打开旧80/15/5或ItemD2R钉价。

若某地区动作需要撤销，用原scope、规则ID、所有权及当前成本重新证明后执行补偿。已经被用户更新的规则不被旧补偿覆盖。UNKNOWN先对账，不能先回滚再查是否写过。

发布成功、价格生效、运行稳定、经营有效分别验收，不互相代替。
