## 新增「阶段维护」范围

与两份周名单并列的第三个范围，目前只开 FC27。

**入池**：先在 ES 订单里按 Buyer ID 汇总历史单笔最高有效订单金额，达到共享合同第 6 节门槛（≥$200）才按订单号小批量去 Admin 核邮箱入池；不达标的 Buyer ID 直接过滤，不取邮箱。无 Buyer ID 的游客订单用订单邮箱判断。

**分组**：价值档（超高 / 高）× 阶段（沉默 / 流失 / 长期流失）× 新客/老客。近期阶段的客户只计数，不进维护列表。

**每日运行**（北京时间凌晨，跟在现有日更后）：重算每个入池客户的阶段，生成「今日新进入某阶段」事件。只有新进入事件触发规则；规则启用时已在该阶段的存量客户列为「存量名单」，由用户手动选择处理。

## 规则

一条规则 = 条件 + 动作：

- 条件：游戏、价值档、阶段、新客/老客（可选）。
- 动作：发券（Admin 券模板 ID，可为空）、预警（在页面「待跟进」列表标红）、分配给负责人（负责人名单可配置）。
- 状态：预演 / 自动 / 停用。新建规则默认预演。

**预演**：每日照常计算，列出「本来会发给谁、发哪张券、分给谁」，不发券、不分配。
**自动**：程序直接执行，不逐笔确认。

**保护（都可配置）**：

1. 同一客户每进入一次某阶段，同一规则最多执行一次（幂等键：客户 + 规则 + 阶段进入事件）。
2. 同一客户 30 天内最多收到一张自动券（跨规则）。
3. 每条规则每日发券上限，超出顺延到次日，不丢失。
4. 发券沿 `grant` 一次提交、不自动重试；结果不明时按原批次号 `reconcile`，未核清前不重发。

**分配**：客户已有人在跟进（任一范围的未结认领）时不改派，只记录本次发券；否则按规则分给负责人。认领、反馈、导出、回购结果全部复用现有能力，与周名单共享同一份记录。

## 券模板

Claude 起草「档位 × 阶段 → 券面额 / 有效期 → 负责人」矩阵，用户确认后，由 Claude 在 Admin 按清单建券模板（site 266、game 1327），把券 ID 填入规则。建券前先核实现有账号的 `market.Coupon` 新建权限；无权限时报告，由用户在 Admin 建好后提供 ID。

## 效果

每条规则：触发人数、发券人数、券使用人数、触发后 7/30/60 天回购人数与金额。基准为同一价值档 × 阶段在规则启用前的历史回购率；页面同时标注当期所处赛季位置，提示赛季开启本身会拉高回购。不设随机对照组。

## Hermes 与连接器

- 读：分组名单、客户详情与时间线、规则效果、预演结果。
- 写（留记录、可撤回）：分配/改派负责人、写跟进备注、调整客户价值档。
- 不能：新建或修改规则、切换预演/自动、直接发券。

## 配置编辑

客户维护页的管理员设置里可修改共享合同第 5、6 节的阶段天数和价值门槛，写入 `/var/lib/fs-customer-segments/segments.json` 新版本；用户分析页读取同一文件。

## 验收

1. 单测：Buyer ID 过滤、档位、阶段进入事件、三条保护、顺延、`grant` 结果不明时只 `reconcile`、已认领不改派、预演不发券。
2. 预演上线：用真实数据跑一天预演，人工抽查 20 个客户的档位与阶段。
3. 自动发券：用户确认预演名单后，选一条规则切自动，核对 Admin 发放记录与本地记录逐条一致。
4. 真实入口：新地址可打开、旧地址跳转、周名单功能未受影响。
