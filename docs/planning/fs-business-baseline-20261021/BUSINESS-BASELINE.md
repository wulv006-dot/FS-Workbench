### Admin 逐笔订单查询的一个月上限（2026-10-21 实测）

`/admin/order.Order/index` 在支付时间 `paytime` 为 2026-09-17 至 2026-10-20 的真实只读请求中，返回 HTTP 200、`code=0`、`data=null`，错误为“下单时间查询范围不能超过一个月，请按月查询或缩小时间范围”。这是接口范围拒绝，不能当作登录失效、空订单或响应截断，也不能靠延长超时消除。

长区间逐笔订单查询采用按自然月或最多28天连续窗口切分的保守方案，每段保留游戏、站点、状态、实际时间字段和时区，完成分页、范围、重复订单及数量完整性检查后才能合并；任一段失败必须标为不完整，不能跳过异常行或放宽校验后发布。服务端精确按滚动天数还是自然月判定尚未核实，不能据此认定所有跨月查询都被禁止。

限制仅有上述逐笔端点的证据，不推广到 Admin 原生经营汇总、ES 导出或 Order 服务。原生汇总已有 34 天及 112 天完整返回的单次证据。继续通过全局 Admin 8767 消费现有会话，不恢复独立登录入口。

付款状态还需逐行核验：实测该端点在 `pay_status=1` 筛选中混入 `pay_status=2`、标签 `Refunded` 的记录，触发原 `cohort_paid_scope`。付费投影只纳入状态1；退款状态2须经过同样的游戏、站点、时间、身份、排序及分页校验后单独计数排除，未知状态继续失败。`source_scanned_total`/`source_scanned_received`记录完整源枚举，`source_total`/`received`记录付费投影，`excluded_refunded`记录排除退款，两者必须对账；不能直接用宽筛选总量当付费总量。这一投影不改写原生经营总盘或其他模块退款口径。规则确认、知识同步、补丁上线和真实完整取数/模型掌握分别验收，部署结果见本次修复验收记录。

## 2. 订单详情与问题原因

入口：**Order → 订单管理 → 订单列表 → 选择对应游戏 → 查看订单**。可筛游戏区服、付款/下单时间（保留实际字段）、商品类别、订单状态、产品标题、订单号、关键字。

这里的**关键字对应下单客户邮箱，即角色名字段**，不是供应商名。邮箱关联以实际核实一致为准，不能按姓名、电话、IP、相似邮箱猜同一客户，不擅自去除邮箱加号或点号。订单号精确查询优先于模糊匹配。

订单详情中的**订单日志**记录从下单到交付的过程及问题，问题单、退款单、CB/欺诈单的说明在此复核。汇总只能发现异常，不能代替逐笔日志判断原因。记录原订单、筛选条件、日志时间和原因分类；普通模型证据只传必要脱敏事实，客户邮箱和自由文本不进入公开报告或长期经验。

指定订单还可走 **Admin → 订单管理 → ES订单日志**，已核页面路由 `/admin/orderes/orderlog`；输入对应订单号查询该笔订单全部日志，结合原订单状态、日志时间、备注及操作人复核。与Order详情日志互作查证入口，不未经核验宣称两源日志逐条相同或覆盖完整一致。只查必要订单、处理分页，避免把额外时间/操作人筛选造成的子集叫全部日志；无结果不等于从未出过问题。

当前 Order 列表默认只显示部分活动状态；调查全部订单必须明确状态筛选，不能把默认列表当全量历史。仅用户界面可查询不等于 FS 已实现相应工具；工具不支持时明确缺项，继续已有来源可支持的判断。

## 3. Admin 全站订单下载、优惠和客户

入口：**Admin → 订单管理 → 销售订单下载（ES 销售订单下载）**。既有已核入口 `/admin/order/makeExcelByEs`，后台下载端点和身份沿现有受控导出服务，不另建登录。

按日期下载当日全部原状态订单，再按游戏、品类、金额、状态、新老客、来源及优惠筛选。已核导出字段含订单号、订单金额、实付及币种、付款时间、支付方式、新老客、订单来源、推广人、折扣码、国家、优惠类型、折扣比例、折扣金额；产品 SKU、站点与平台是否存在按实际版本核对，不能由汇总猜补。复用同一窗口原导出档案，不因切分组重导出；分页/文件集/去重冲突独立标示。

- 订单金额 USD；折扣/优惠金额 USD；实付金额保留实际支付币种，例如 GBP。不可用订单 USD 减原币实付推算优惠，不用折扣比例替代实际折扣筛选。
- 无码不等于无优惠，折扣比例不能替代固定满减。整单折扣只计一次，保留原正负号；退款是否冲回依实际记录，不自行补算。收入已扣优惠时不得再次扣同一折扣。
- 同订单多商品行不重复累计整单收入或整单优惠。混合订单的整单金额不能全部称为某个 SKU 收入，不无依据分摊。
- UID=0 是正常游客；支付邮箱必填不意味着客户邮箱与支付账号字段必然相同。以已核客户邮箱关联，UID 辅助，新老客按该笔订单下单时ES「是否新客户」（是为新客、否为老客）；缺失/未匹配/冲突单列，不用Admin列表isNew或当前会员身份回推，游客不自动归新客。
- 新客订单数不等于去重客户数；期间老客占比不是同批新客留存。首单 30% 是已确认经营策略，不证明全部新客标记订单都符合资格或实际核销 30%。

## 4. 履约采购、供应商与成本

入口一：**Order → 订单管理 → 发货记录 → 订单交货记录**。可筛游戏、产品类型、交货类型、时间、订单号、关键字。**这里的关键字对应供货商名，与订单列表的邮箱含义不同。** 读取实际单笔成本、数量、类型、利润率、供应商及时间；金币数量统一 K，金额无特殊说明均 CNY（人民币）。

## 6. 金币价格管理：四个同名陷阱

入口：**Order → 游戏产品（界面亦称游戏&产品）→ 金币价格管理 → 游戏/平台**。

| 页面字段 | 真实含义 | 可用于什么 |
|---|---|---|
| 最新采购价 | 对应平台最新订单成本单价，CNY/K；实际输入仍核订单类型与时效 | 当前成本线索，非历史整段成本 |
| 采购成本 | 控制售价的参数，不是实际采购经济成本 | 反算/设置 B2C 参数 |
| 利润率 | 页面固定的售价公式参数，不是实测经营利润率 | 仅用于页面换算 |
| 货币汇率（如 6.65） | 固定的售价公式参数，不是真实当前 FX | 仅用于页面换算 |
| B2C 价格 | MMOEXP 前台金币页每 K 售价，USD/K | 与实测前台/套餐核对 |

页面换算：`B2C USD/K = 采购成本参数 CNY/K / (1 - 利润率参数) / 汇率参数`。若页面显示百分数，计算时先除以 100。反算控制参数：`采购成本参数 = B2C USD/K × (1 - 利润率参数) × 汇率参数`。参数原值沿现有配置读取，不能用固定 6.65 证明当前经营换汇价。

真实采购成本、页面调价参数、实际市场汇率、Order 参考利润率分别存放、命名和解释。报价毛利核原引擎对赠送、成本及有效汇率的定义；基线计算价、实际前台价和候选模拟价三者分开。

### 尾价偏好（本次用户确认）

用户偏好整数临界附近采用 .99，**$10.09 → $9.99 只是可接受幅度的示例，不能固化为全价位 $0.10 阈值**。先分三步：实际当前套餐价为 `P0`；主策略研究选定但尚未附加尾价的套餐候选为 `P1`；尾价为 `T=floor(P1)-0.01`。**下列预算公式中的 `P` 统一指 `P1`，控制的是 `P1-T`，不是 `P0-T` 或 `P0-P1`。** 没有主策略调整时才令 `P1=P0`。原引擎模拟基线另列，不替代任何一者。`P1` 必须按前台展示套餐总价/单位计算，不能把每K参数当套餐总价。不向上凑价；主候选已是 .99 保持。

本次实施的保守控制预算（实施者计算控制，不冒称用户逐项指定）：相对主候选的附加让利不超过主候选套餐价 1%、主候选采购毛利额 5%、主候选采购毛利率下降 1 个百分点，且不能突破原利润底线。四者同时满足，以最严格者确定每行可让利空间：`min(0.01P, 0.05(P-C), P-C/(C/P+0.01), P-C/(1-m))`，小于 0 时取 0；`m` 用小数。仅当 `P1-T` 在预算内才取尾价。**预算不限制 `P0→P1` 的主策略研究幅度；主候选及所有备选仍需分别满足现有底线、平台联动及其他适用保护。** 成本含实际交付金币及赠送，汇率用有效实际源，不用页面 6.65 参数。

这使同为 $10.09 的两个套餐在成本不同的情况下可以作不同决定，也允许高价套餐的美元绝对调整大于低价套餐；不以固定数值强行套全部平台。预算及原价/候选/毛利变化在模拟回执中列出，后续按真实效果复盘，不能宣称 .99 已被证明增加销量或利润。

必须用尾价重新核原利润底线、赠送、优惠与平台联动。尾价被拒时保留已通过保护的主候选 `P1`，不能改用 `P0` 算出另一份宽预算来放行同一尾价，不能为尾数放宽底线。最终建议和每个备选都须逐平台回代，不能一边保价另一边降价而破坏已声明的同价联动。主候选本身不合格时另行拒绝，尾价“不追加调整”不代表主候选安全。Coins 以每 K 参数联动各套餐，一个参数无法保证所有套餐都独立 .99；按引擎实际支持的展示基准与回读落实，不把总价让利误施到每 K，更不绕过原 writer。规则偏好不证明任何真实售价已改变。

### 利润与反证的计算边界（v2澄清）

采购毛利为同口径实收减实际交付成本；广告后贡献再减同范围可归属广告费，其他费用未扣齐不称净利润。两期分别列账。保本订单增量不是需求预测，需说明成本/套餐/结构不变等假设；连续门槛、最少整数订单及差额分开报告。算术分解中的价格项、结构项只是固定顺序下的恒等式，不等于识别了价格造成的销量或利润净效应。广告费差/订单差最多是两期描述比，分母为零时未定义，不冒充可外推的增量获客成本或新执行阈值。

反证先固定具体命题、范围和期间。完整同口径账本可核当期描述；以后成本或下一期结果不改写已核当期事实。价格因果需要有效识别和不确定性；广告同时变化或证据不足只表示未识别，不证明零效应。优惠反证须先核政策的合法基数、资格、舍入和状态；一个符合这些定义的已核偏离可否定“所有合格订单均正确执行”，不能据此说活动从未执行。订单数量多数、总体金额比例及合法资格差异不能替代逐单联合证据。

## Astra FC Coins 固定决策流程（v8，2026-10-22）

FC Coins 定价与复盘必须先调用 `fc.run_pricing_workflow(action=review,profile=FC27,start,end)`，使用本任务的来源、时间、覆盖、原执行账本及核算回执。pending 按同查询继续读取；回执省略时使用 fc.read_evidence。程序结果与自己的估计分开，不能用口头重算覆盖机器结果。此流程不改变现有自动跟价、120分钟周期、开关、10%底线或其他商品公式。

固定顺序：①范围和真源；②后台执行与前台实际暴露分开；③历史实际采购毛利、当前方案利润、广告后贡献分开；④保持/涨价/降价比较，先找最小必要变动；⑤PS/Xbox合并为共同供应成本和互通市场的一套基础价，PC独立；按合法客户成交/优惠组合逐一核验；⑥提出反证条件、观察窗口和下次复盘。采购毛利率底线是比例，广告后贡献是金额，不能互相代用。当前成本不可回填历史成本，净收入不再扣一次优惠。

需要候选核算时调用同工具 action=scenario。声明的美元套餐价、含赠送交付成本、合法优惠情景和同范围广告只是假设，不是已核市场价或需求预测。主改价 P0→P1 不受尾价预算限制，P1→T 的 .99 处理独立受1%收入、5%采购毛利、1个百分点毛利率和原底线约束，逐优惠情景检查；任一合法共同成交情景尾价失败则共同保留P1，主方案本身失败不推荐。销量盈亏平衡点是需要达到的条件，不是销量必然增加。成本/可比竞品不足时可给条件方案，不给新的可执行售价，也不据此停用已有自动化。

Hermes 的工作：解释机器回执、识别竞争解释和缺证，提出需求假设、最小核验与反证，不负责凭语言记住复杂算术。新场景可用固定核算验证；完成且实际使用本流程的真实任务进入原学习候选队列。候选须有来源、适用范围、反例、有效期；沿现有审核、CAS发布及撤销生效，不能自行改写本流程、业务底线或自动策略。经验只记录可迁移方法，当前成本、价格、广告数值仍属有时效的业务事实。完成、通过一个案例、模型自称学会均不等于长期迁移验收。

## 采购毛利逐单核算更正（v10，2026-10-22）

同字段Admin优先。Order订单概览整单金额、商品行金额、历史发货销售额是不同字段；后两者不得代替Admin整单收入。对同一已完成订单群体，人民币收入采用Admin逐笔订单原amount_rmb_format，每单只计一次；人民币采购成本累计该单全部有效订单发货记录，以记录ID去重，采用最新完整范围成员。多次发货不能重复加收入；缺收入或成本保持未知，SCM缺口不补零，已确认历史零成本商品沿精确单据规则。

采购口径毛利=该群体Admin收入合计−实际采购成本合计；毛利率=采购毛利合计/同群体收入合计，不平均订单率。记录币种、付款群体、完成状态、来源及采集时间；Admin人民币格式值不是擅定的固定换算率，不能反推为财务实结汇率。未获完整支付费用、退款结算、广告等费用时不称净利润；不能将已完成覆盖群体毛利率套用全部付款收入。全盘数据不完整时，原Admin总盘×同期Order参考率仍只能另列估算，不冒称已被逐单实算替代。

验证未通过订单属于欺诈，排除经营订单数、销售额、客单价和占比分子分母；明细及原状态保留，待退款/申诉。退款申请不等于实际退款，按已核实际退款状态或支付退款标记处理。测试单排除规则、问题/发货中订单尚不核算利润、优惠券零成本精确确认规则保持。

新旧缓存不混算：缺Admin单笔人民币收入字段的旧完整范围保留旧法并标回补；完成完整分页与身份/范围校验、整段取得新字段后再切到新法。旧收入/利润证据保留原口径，不改写为新实算。完整历史订单继续复用，确证晚到成本沿原后台自动刷新补核；较新完整发货范围替换其成员，不能只追加记录导致旧成员残留。

已核事实是收入字段不等价；商品金额分摊/封顶规则、历史人民币换算时点、Order原生利润率分母仍按独立证据核实。不得把推断写成源合同，亦不因这些缺口改用已知错误的发货收入字段。执行价格的利润红线与历史实际毛利分开，本更正不修改任何采价、策略、自动化开关或生产写价。
