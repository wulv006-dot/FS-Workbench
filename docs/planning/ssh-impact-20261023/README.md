# FC 与 RPG 自动改价 P0 恢复及防复发

2026-10-23，北京时间。本任务集中负责自动改价；22端口、安全组和服务器安全事件由“排查187服务器22端口依赖”专项独立核查。最终FC修复12:51:29已受控发布，RPG新自然整批已通过；FC原定自然周期正在验收，长期趋势与群告警接线另列。

## 原因

1. **资源限制生效，但没有消除资源增长。** 内核在10月22日05:58及23日10:51记录FC浏览器达到3GiB容器上限并杀死Chrome进程。今天被杀进程约2.38GiB匿名RSS。3GiB是容器隔离上限，不是防止浏览器自身故障的机制。
2. **旧刷新只覆盖采集时刻。** 活动采集器仍为10月16日的3c53cdad版本；完整采集前刷新会释放上一文档，却立即生成新文档及Worker。两次120分钟采集之间仍长期驻留外部页面。旧长期趋势事项没有验收关闭，不能把短时采集通过当长期无内存问题。
3. **共享故障域放大影响。** 8768 Order身份探针与FC竞品共用Chrome。Chrome实际CDP连接挂起后，FC六来源失败；RPG两批六单在获取Order cookie阶段失败。浏览器信息接口仍200，不能作为真实就绪证明。
4. **另有独立接入和恢复缺陷。** RPG主站缓存仍使用旧独立Admin登录；部分工单价格已成功而缓存失败。原执行器对未知/部分写入也可能跨ID派回本机，存在重复执行风险。

5. **真实浏览器另有页面保留行为。** 12:24原入口新采集完成后，导航空闲页使`page.workers`为空，但浏览器级Target仍保留新商品Worker；清浏览历史无效，Chrome不支持直接关闭该Worker target。12:31在原锁内建立新空闲页、关闭旧商品标签后，浏览器级Worker才从1降至0，cookie指纹不变。不能用页面局部Worker列表代替真实资源释放。
6. **Order上游另有间歇性慢查询。** 隔离后的Order容器未OOM/未重启，仍出现商品搜索60秒超时；同一全局cookie直接HTTP读取身份页200、两个商品查询超时，证明不只Chrome页面加载问题。原RPG12:32自然工单已发出11次写请求，正在原ID复核，不能用重启或换ID写价处理这类故障。

这是可验证的资源生命周期、依赖隔离和恢复状态问题。事故时没有保留下来的Chrome堆快照，尚不能唯一定位第三方脚本具体哪一个分配函数；恢复后现存Worker的10秒采样没有重现大堆增长。不能将其认定为187中毒，也不能据此排除独立安全事件。

## 防范与恢复机制

- **源头生命周期：** 外部竞品文档仅在采集或人工主动维护时存在；完整采集结束先准备受控空闲文档，再关闭旧商品标签，使旧文档及Worker实际退出。原有页面上的PS-only不刷新；受控空闲页可唤醒读取，人工入口仍可打开原商品页。保留同一浏览器、context及profile，释放失败独立记录，不能抹掉已验证有效的采集结果。
- **故障域隔离：** Order会话不再依赖竞品页面或FC浏览器进程；Admin继续唯一全局8767。登录过期按现有身份合同报错，不延长cookie期限或恢复各模块独立登录。
- **资源和真实就绪：** 保留原3GiB上限，不扩大内存、不禁OOM。区分容器usage、RSS、cache和Chrome堆；用真实CDP、DOM及受控空闲页/Worker状态检查，不能只验HTTP200。
- **受控恢复：** 在原锁和空闲条件下先释放文档，持续失联或释放无效才恢复浏览器。保留原业务周期、价格规则、来源、会话及账本；一次事件有确定ID、回执、冷却和原Docker状态读回。真实写入UNKNOWN/部分写入先对原工单，不换ID再写。
- **告警接线规划：** 自动采价失败、共享会话失效、未知写入、发布/缓存未完成列为P0。应从原任务终态即时送入原告警链，并复用原五分钟监控兜底、原事件去重和UNKNOWN发送对账；原23/02/05/08巡检保留。当前原桥接仅导出快照，RPG逐单write_state尚未完整进入Hermes监控；本轮不能宣称这项群告警增量已启用或实际送达。具体最小接线和消警条件见[RPG监控规划](RPG-MONITOR-WIRING-PLAN.md)。
