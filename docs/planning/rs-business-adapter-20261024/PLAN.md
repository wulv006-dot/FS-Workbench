## 数据与口径

同字段 Admin 优先，缺失才用 Order 补缺，有效零不丢失。USD 收入使用原生统计金额；区服明细使用 Admin `amount_usd_format`，不把原币实付当 USD。

常用的网站和类目直接消费 Admin 原生 `/admin/order.Order/orderStaticsDetailByEs`。现场核实 RS game=506；网站 ID：RSOrders=320、RSMalls=333、RSFast=254、MMOEXP=266，每次读取校对网站目录。产品类型是原生 `cid`：货币=1、代练包=5、物品=0，不能用真假判断丢掉 0。全部保留 Admin 原始全部网站/全部类目范围，不把四个展示选项的部分和冒充全盘。

销售趋势、国家、支付方式和设备使用同一原生响应，趋势单量/金额须与该响应总盘核平。复购、新客等沿用原生定义，不从 UID 或当前会员状态猜测。

用户随后提供并指定更准确来源：Order“统计管理→发货统计”。RS区间利润及每日利润率统一改用该页面的同网站、类目、区服与交易时间；利润金额为人民币销售总额减采购总额，保留原生利润率并核公式。Admin付款时间USD销售独立显示，不跨来源相乘。详细字段、真实回执和范围见[利润来源合同](SHIPPING-CONTRACT.md)。旧订单统计率/美元估算仅保留历史证据，不再供RS新卡片/曲线使用；其他游戏保持。

低频区服：Admin 原生汇总实测忽略 `aid`，不能伪装成区服独立统计。指定区服改用 Admin 订单列表原生 `aid/cid` 关联筛选、28日内分段、完整分页、付款时间末端不含、USD 和网站复核。关联查询会重复返回同一订单：仅完整记录完全相同才去重，冲突拒绝；整单收入只计一次，记录原始扫描行数与重复数。退款状态 2 单列排除，未知付款状态失败。客户、新客、复购等未建立相同区服原生定义的字段继续明确标注“全部区服参考”，不擅自重定义。全部区服不承诺仅由两个快捷区服相加构成。
