# 渠道效果看板实施与验收

看板已受控发布并从真实 wulv 入口验证：[渠道效果看板](https://47.85.224.112/dashboard/channel-effects/)。维护源：`fs_channel_dashboard_20261021/`；私库路径：`releases/fs-dashboard/channel-effects-20261021/`。代码、CI、合并、发布与业务覆盖分别见 [ACCEPTANCE.md](ACCEPTANCE.md)，文件映射见 [SOURCE-MAP.json](SOURCE-MAP.json)。

## 用户已确认口径

- 入口：FS 数据分析，数据看板与数据分析工具之间，名称“渠道效果看板”。结构参考 RPG 销售系统，使用当前 FS 主题；原流量页不改。
- 默认全游戏、MMOEXP；日期按订单付款时间、北京时间。优惠码页顶部仅计实际用码和推荐人无码。“自然流量（对照）”指无码且无推荐人的订单，是本看板的业务分类，与 GA4 自然搜索分开。
- 折扣码忽略大小写匹配，保留原码；同码冲突待核。使用此次 Excel 的可见“折扣码映射”页，隐藏模板不构成规则或授权。分销仅为推广分类，不据此剔除 MMOEXP 订单。
- 推荐人无码保留推荐人 UID；仅在渠道唯一时归入渠道，且不计用码订单。
- 优惠券按模板/活动与发放批次追踪，渠道没有依据保持未归类。优惠码与优惠券可以重叠，模板和批次也可以重叠；顶部订单去重，分项不得直接相加。
- USD 销售与客单价取 Admin 订单美元金额，保留所选订单状态范围。CNY 销售、采购、毛利仅核算已完成订单，综合利润率按同一已完成核算群体加权。问题、发货中等未完成订单不计成本和利润；验证未通过按欺诈单观察、待退款或申诉，后台原状态不改。缺成本不补零，不拿调价参数、最新采购价或固定 6.65 汇率代替真实历史成本。
- NBA2K、ARC 已完成但无 Order 成本的订单由 SCM 自动履约，单列来源缺口，不推断成本为零。已删除的 `2*10% FC27 早鸟优惠券` 仅对用户确认的两笔历史订单按零成本、利润等于该笔 Admin 原人民币金额核算；不泛化所有 Items，不在源码仓库保存真实订单号。
- 用码占比的分母保持同游戏、同日期、同状态、同国家/支付筛选下的全部用码订单与全站订单，不随项目或单码筛选缩小。
- “排除退款”只表示排除后台已标退款单，未解释成全部已完成、已结算或不存在问题单。
- 新老客只认该笔订单下单时 ES「是否新客户」：是为新客、否为老客。缺失、未匹配和冲突单列；不使用 Admin 列表 `isNew`、当前会员状态或 UID 推断。已修正旧缓存的读时投影，订单明细显示“新老客（ES）”。
- 国家筛选、对比表与订单明细显示中文名及原国家代码，例如“美国（US）”；筛选值与统计键仍为源代码，无法识别的原值保留。

## 取数与复用

复用 Sales 的 Admin8767 共享会话客户端，不独立登录。Admin 订单按站点 266、精确付款区间分页；优惠券使用日志已真实验证支持订单号 IN，空结果与失败分开。后台配置、Excel 与 Sales 推广人目录分别保留来源，团队目录沿用原 Sales 的明确归属修正优先级，不带入 Aion2 特化游戏/区服规则。

Admin 逐笔订单接口单次不得超过一个月；本看板统一拆为最多 28 天的连续闭合窗口。每段先校验完整分页、源总数、重复记录、站点和付款时间，再对跨段订单身份去重校验；所有段均通过后才合并发布。任一段失败保留上一份完整结果，不能把前几段当作完整长区间。该限制不扩大为原生汇总、ES 或 Order 接口的规则。

现有 Sales 发货缓存含多个站点，消费时再次筛到 www.mmoexp.com、订单发货、精确订单号。它只能证明 Aion2 已有发货覆盖，不能冒充全游戏实时成本。

用户安排维护 Order 共享源。本任务不改凭据、不另起登录、不重启共享源。期间出现过 `global_order_unavailable`，该失败保留；最终共享源 ready，已读回 2026-10-14 至 10-21 18:49 的完整全游戏发货缓存 11,319 条。完整源读取不代表每笔订单都有关联发货成本。该页有明细与汇总两张表；交易时间使用两位年份，有些单元格还显示“改”后的修改时间，解析时区分原交易与修改时间。

看板先发布完整 Admin 订单结果，再在后台通过同一共享源关联成本。发货按固定的已结束分钟截止读取，覆盖订单付款起点至该截止，以包含晚交付；全部产品类型 cid=-1、genre=1、MMOEXP 过滤，每页严格去重及校验。Order 读取互斥，最多两项看板请求；失败保留已有结果与成本缓存，不将缺数补零。跨期已核发货缓存按记录 ID 保留，不因新查询丢弃其他日期。

按用户后续明确要求新增渠道专用服务器任务：北京时间每日00:35采集昨日，01:00–07:00低优先级补齐2026年8月1日至10月31日已结束日期。分日完整分页、按源总数/重复/范围校验后原子保存，空日也保存；前台采集或成本锁忙时让路，已完成日可断点复用。失败保留上一完整数据；新老客源缺失不冒充完整，沿既有ES导出账本核原请求。

历史查询先合并完整日归档立即呈现，保留原十分钟有效期后的后台自动刷新，让后续退款、状态及归因继续更新；取数忙时先返回已校验旧结果并等待空位。缺日仍走原按需链路，手动刷新沿原互斥和一分钟冷却。归档时间范围在口径说明中显示，不把采集时点当最终结算。新增的仅为两个渠道任务；现有Sales定时、FS/Google更新、采价、策略、写价、上品及售卖链路保持原状态。具体发布/实际执行/首次自然周期分别记入验收，不因本段存在而视作启用。
