# 渠道效果看板实施与验收

本目录记录当前施工，不把代码、测试或 PR 当作上线。维护源：`fs_channel_dashboard_20261021/`；私库路径：`releases/fs-dashboard/channel-effects-20261021/`。

## 用户已确认口径

- 入口：FS 数据分析，数据看板与数据分析工具之间，名称“渠道效果看板”。结构参考 RPG 销售系统，使用当前 FS 主题；原流量页不改。
- 默认全游戏、MMOEXP；日期按订单付款时间、北京时间。优惠码页顶部仅计实际用码和推荐人无码，无推广归属单作对照，不称已证明自然流量。
- 折扣码忽略大小写匹配，保留原码；同码冲突待核。使用此次 Excel 的可见“折扣码映射”页，隐藏模板不构成规则或授权。分销仅为推广分类，不据此剔除 MMOEXP 订单。
- 推荐人无码保留推荐人 UID；仅在渠道唯一时归入渠道，且不计用码订单。
- 优惠券按模板/活动与发放批次追踪，渠道没有依据保持未归类。优惠码与优惠券可以重叠，模板和批次也可以重叠；顶部订单去重，分项不得直接相加。
- USD 销售与客单价取 Admin 订单美元金额。CNY 销售、采购、毛利来自关联订单的 Order 常规发货记录；综合利润率按同一发货覆盖群体加权。缺成本不补零，不拿调价参数、最新采购价或固定 6.65 汇率代替真实历史成本。
- 用码占比的分母保持同游戏、同日期、同状态、同国家/支付筛选下的全部用码订单与全站订单，不随项目或单码筛选缩小。
- “排除退款”只表示排除后台已标退款单，未解释成全部已完成、已结算或不存在问题单。

## 取数与复用

复用 Sales 的 Admin8767 共享会话客户端，不独立登录。Admin 订单按站点 266、精确付款区间分页；优惠券使用日志已真实验证支持订单号 IN，空结果与失败分开。后台配置、Excel 与 Sales 推广人目录分别保留来源，团队目录沿用原 Sales 的明确归属修正优先级，不带入 Aion2 特化游戏/区服规则。

Admin 逐笔订单接口单次不得超过一个月；本看板统一拆为最多 28 天的连续闭合窗口。每段先校验完整分页、源总数、重复记录、站点和付款时间，再对跨段订单身份去重校验；所有段均通过后才合并发布。任一段失败保留上一份完整结果，不能把前几段当作完整长区间。该限制不扩大为原生汇总、ES 或 Order 接口的规则。

现有 Sales 发货缓存含多个站点，消费时再次筛到 www.mmoexp.com、订单发货、精确订单号。它只能证明 Aion2 已有发货覆盖，不能冒充全游戏实时成本。

用户已说明 Order 共享源可能更换密码并安排修复。本任务不改凭据、不另起登录、不重启共享源。后续健康检查已为 ready，但完整发货验收仍须实际读取。已核明该页有明细与汇总两张表；交易时间使用两位年份，有些单元格还显示“改”后的修改时间，必须区分。

看板先发布完整 Admin 订单结果，再在后台通过同一共享源关联成本。发货按固定的已结束分钟截止读取，覆盖订单付款起点至该截止，以包含晚交付；全部产品类型 cid=-1、genre=1、MMOEXP 过滤，每页严格去重及校验。Order 读取互斥，最多两项看板请求；失败保留已有结果与成本缓存，不将缺数补零。跨期已核发货缓存按记录 ID 保留，不因新查询丢弃其他日期。

新看板只做按需读取与私有缓存，十分钟内复用同区间结果，手动刷新沿用查询互斥及一分钟冷却；仅取数中的页面轮询进度。不取消、降低或改变原有自动化能力。现有 Sales 定时、FS/Google 更新、采价、策略、写价、上品及售卖链路保持原状态。
