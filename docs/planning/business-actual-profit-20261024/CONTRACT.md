# 经营看板逐单实际成本毛利

决定日期：2026-10-24。用户授权替换原发货利润卡和每日曲线，覆盖全局、分游戏及RS站点筛选，验证后上线并同步Git及业务规则。此决定取代看板发货利润v1作为默认主展示的规则；旧发布证据和历史报告保留。

主展示为「逐单实际成本毛利（¥）」「逐单实际成本毛利率」「已完成成本覆盖」「收入或成本待补」「未完成订单」。复用原卡片及曲线布局，不再另列重复的“独立核对”区。Admin订单、美元销售、国家、支付和设备口径保持。

- 群体：所选网站、游戏、RS类目/区服及北京时间付款区间内完整枚举的Admin已付款、未退款订单。原已确认测试单、欺诈单排除规则继续生效；未完成单单列。
- 已核完成订单：Admin整单人民币收入只计一次，减同网站、同订单号的Order实际历史订单发货采购成本合计。多次发货不重复计收入；采购金额可为有效0，未知成本不当0；已确认零成本/测试单仅按原精确订单、游戏、USD身份规则，主站确认不扩至卫星站。
- 毛利率＝已核完成群体总毛利÷该群体Admin人民币收入×100%。不平均订单/游戏/每日比例，不用USD销售额乘参考率，不将覆盖单利润率外推全体。零收入率不适用，亏损保留负数。不是扣齐手续费、投放、退款/CB最终结算的净利润。
- 覆盖＝已核完成单数÷全部完成单数；无完成单显示分母0及率不适用。收入或成本待补＝完成但缺任一金额的单数。未完成单不核毛利。无经营订单的有效空群体金额0、率不适用；来源未完整、拒绝、失败保持未知/部分。
- 每日曲线按同批订单付款日期分组，与区间卡同一次响应、同一分母规则。逐日金额和数量加总须等于区间值；仅显示完整日，今天卡片可显示截至读取时的值。迟到成本可补核历史，显示收入/成本读取时点及部分、过期、失败状态，不拿发货统计补缺日。
- RS网站：全部、rsorders.com、rsmalls.com、rsfast.com、mmoexp.com；类目：全部/货币/代练包/物品；区服放更多筛选。Admin商品关系连接产生的相同整单重复行须完整枚举后去重，冲突失败。Order成本按网站和订单号关联；Admin/Order游戏ID由服务器现行映射分别取用。
- FC客户、平台、商品、金额档、卫星站细分尚无同粒度逐单成本证据时，毛利明确不可用并立即清理上个范围的值，不展示整游戏值。该限制为原核算能力边界；订单等原细分能力保持。

新接口复用原鉴权路由`/dashboard/channel-effects/data.json?mode=actual-profit&profile=...`，服务器规范化选择并映射ID，返回合计和逐日聚合，不返回客户及订单明细。主站日范围复用原日归档；其他合法范围复用原Admin/Order共享会话及同一2工作线程池、互斥锁，私有范围缓存与原主站归档隔离。读取失败保留最后已核值及来源时点，拒绝清空可见数据；不独立登录、不新建定时器。

看板summary显式`profit_basis=actual`，不自动请求Order发货统计或发货利润历史。现有发货统计取数、`profit-history`及Hermes按需能力保留；默认/显式shipping旧调用兼容。需要发货统计时必须按对应网站、游戏、原生Order类目及交易时间单独查询，分清与付款订单采购毛利的群体差异。

不改订单、价格、FC v15双红线、80/15/5参考权重、调度、权限、认证或费用预算。不恢复暂停的FC/RPG跟踪。代码、正式CI、合并、上线、真实入口及Hermes规则加载分别验收。
