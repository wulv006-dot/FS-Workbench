## 1. 为什么要改

现行市场定位锚只看竞品，不看我们自己的利润率：

- 11-14 到 11-18，主机采购成本从约 $5.72/100K 降到约 $4.5–4.6/100K（约 −20%），售价仍贴着 Lootbar 定位，毛利率从约 21% 升到 34%–39%（V6 证明口径粗算，小额，按平均优惠 9.6%）。吴律反馈看板毛利率已超过 37%，订单明显下降。
- 阶段 4 周阶梯只有"抬 p"和"订单大跌才降 p"两个动作，没有"利润率过高就降价"的方向，而且一周才动一次。
- 吴律确认的经营目标：毛利率 **30%–32%**。低于这个区间要修价，高于这个区间要让价冲单。18% 硬底线不变。

## 2. 目标

1. 每小时自动把价格拉回 30%–32% 的利润率区间：利润率低就往上修（不超过竞品上沿），利润率高就往下让（不低于竞品下沿）。
2. 竞品定位继续限制价格的上下范围，保证不会因为追利润率而明显贵过或便宜过市场。
3. 一个自然轮内响应，不增加价格抖动：成本小幅波动由中位数和保持区间吸收，来回抖动由反向加宽阻止。
4. 周阶梯改为校准目标利润率，让实际成交毛利率落在 30%–32%。

## 4. 规则（每小时自然轮，逐平台、逐量段）

### 4.1 竞品走廊

- 上沿 `high` = 现行定位锚目标价 `min(Lootbar × (1+p), U7Buy × (1+u))`，函数 `market_anchor_targets` 原样计算，含 U7Buy 比值替代等缺失处理。
- 下沿 `low` = `Lootbar × (1 + p_low)`，Lootbar 缺失时用现有 `U7Buy × r` 替代值。`p_low` 是新增参数。
- 两家都缺（`floor_only`）时本轮不启用利润率带，按现行逻辑处理。
- 按现有方式换算到每个量段的原生锚点价（按到手量，含赠送）。

### 4.2 量段利润率

- 用本轮证明输入（3 小时中位数成本、D-3 至 D-1 实际平均优惠、原赠送和舍入），计算**主篮**（`main`）中属于该量段的成员路径的组合采购毛利率：`Σ(净收入 − 安全成本) / Σ净收入`，按主篮原权重加权。
- 量段之间互不影响：一个量段的利润率只取决于它自己的价格，因此两段可以分别求解。
- 新增纯函数 `band_margin(proof, band)`，放在 `average_discount_v6.py`，紧挨 `minimum_band_price`，复用 `band_price_usd`、`forecast_receipt` 和同一套路径数据。

### 4.3 选价

设该平台目标利润率为 `t`（初始 31%），保持区间为 `[t − 1, t + 1]`，即初始 30%–32%。

1. 在当前已确认价上计算 `m = band_margin`。
2. `m` 在保持区间内：期望价 = 当前价。
3. `m` 在区间外：**本轮立即**改到在 `[low, high]` 内使 `band_margin ≥ t` 的最低分值价，不等下一轮确认。
   - 新增 `band_target_price(proof, band, target, low, high)`，写法照 `minimum_band_price`：在分值网格上二分，把 `HARD_MARGIN` 换成参数 `target`，搜索范围限定为 `[low, high]`。
   - `high` 也达不到 `t`：期望价 = `high`，记 `margin_band_capped_by_market`。
   - `low` 已经超过 `t`：期望价 = `low`，记 `margin_band_capped_by_corridor`。
4. 期望价最后夹到 `[low, high]` 内。竞品变动使当前价跑出走廊时，本轮直接回到走廊边沿。
5. 之后全部沿用现有流程：编译价表 → 证明 → 18% 底线保护（`minimum_band_price`）→ 1.5% 死区 → 15%/40% 保险 → 原 writer → Admin 回执 → 主站 266 完整价表读回。

成本数据出错时，价格会跟着错。下面三道防护不增加正常情况下的反应时间（从发现到改价仍是一个自然轮）。

| 防护 | 规则 | 正常行情下的影响 |
|---|---|---|
| A. 中位数成本 | 沿用阶段 2：3 小时中位数，不足 6 笔用最近 6 笔中位数。单笔测试单、异常单拉不动中位数 | 无 |
| B. 样本过滤 | 沿用阶段 1：偏离上次确认成本 [0.5, 2.0] 倍以外或低于 0.05 CNY/K 的样本先剔除，再取中位数（第 6 节加测试） | 无 |
| C. 成本骤降确认 | 只限"因成本下降而降价"：本轮中位数比上一自然轮确认的中位数低 8% 以上，且 3 小时内有效样本少于 6 笔时，本轮按两者中较高的成本算目标价；下一轮中位数仍然低，再按新成本走。记 `margin_band_cost_drop_unconfirmed` | 只在样本稀少且成本骤降时晚一轮，主要影响 PC |
| D. 反向改价加宽 | 3 小时内刚因利润率改过价的量段，若要朝反方向改，触发线向外放宽 1 点（例如刚降过价，要到利润率低于 29% 才回涨）。竞品走廊夹取和 18% 底线不受此限 | 不影响首次反应，只阻止来回抖 |

- 成本上涨导致的涨价不设确认：往上修是安全方向，立即执行。
- 防护 C 不适用于 PS（每小时约 8 单，3 小时内样本通常足够）。
- 防护 D 按账本里该平台该量段最近一次利润率改价的时间和方向判断（`margin_band.last_move`），人工采集和失败轮不计入。

## 5. 周阶梯改为校准目标利润率

现行 `weekly_ladder.propose_adoption` 调整 `p`。在利润率带启用的计划上，改为调整每个平台的 `t`，量段不再轮流。`p`、`u`、`p_low` 只通过人工计划修订改。

用现有 `read_week` 的同单实际数据：R = `procurement_gross_cny / revenue_cny`（整周、该平台两段合计）。M 为其余两平台订单环比，限制在 [0.85, 1.15]，算法不变。

| 条件（按顺序判断，命中即停） | 本周动作 |
|---|---|
| R > 32.5% | `t` −1 点 |
| R < 29.5% | `t` +1 点 |
| 订单 < 上周 × M × 0.85，且 R ≥ 30% | `t` −0.5 点 |
| 上周 `t` 降过，且订单 < 上周 × M × 0.95（降价没换来量） | `t` +0.5 点，冻结 2 周 |
| 其他 | 不动 |

- `t` 限制在 [27%, 35%]。允许超出 30%–32%，是因为小时证明口径（平均优惠、安全成本）和实际成交毛利口径有差，周校准用 `t` 吸收这个差，目标是让**实际 R** 落在 30%–32%。
- 提议、过期（周三 24:00）、前 4 周确认、自动开启、Hermes 推送、幂等键全部沿用现有实现，只把 `delta_p`/`before_p`/`after_p` 换成 `delta_t`/`before_t`/`after_t`，规则名换成上表对应名。
- 已知限制：阶段 4 验收记录里 `read_week` 目前报 `weekly_actual_cost_archive_unavailable`。数据不全时照旧不出提议，小时利润率带独立工作，不受影响。

## 8. 上线步骤

1. **测试先行**（`tdd`），至少覆盖：
   - 利润率在区间内：不动。
   - 高于区间：本轮降到 `t` 对应价。
   - 低于区间：本轮升到 `t` 对应价，但不超过 `high`；`high` 不够时记 `capped_by_market`。

   - 期望价低于 18% 底线：底线保护照旧生效。
   - 期望价变动超过 15%：保险截断照旧生效。

## 10. 已知局限

- 小时证明利润率与看板"Order 发货统计"毛利率口径不同（平均优惠假设、安全成本、篮子权重、发货统计按交易时间）。周校准只能逐步收敛，前两周可能有 1–2 点偏差。
- 防护 C 在样本稀少（主要是 PC）且成本骤降 8% 以上时会晚一轮；其他情况从发现到改价都是一个自然轮。
- 订单下降有多少来自价格，目前没有对照组证明；周阶梯第 3、4 条规则只能按前后两周近似判断。
