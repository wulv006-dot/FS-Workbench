# 日常收尾与老D凌晨维护衔接

这是交接模板，不是调度安装包。原凌晨Notion任务由老D负责，精确job ID及执行环境仍待原维护记录核实；本次不新建、不停止、不改写它。原Hermes日报及06:00/06:10记忆审核任务各自保持，不能用这份文档宣称这些任务已切换模板。

日常变更完成后，Codex用同一change_id更新“受影响知识版本+项目当前摘要”，记录Git固定版本、服务器回执和Notion读回；只触及受影响条目，不每天全读Notion/历史。老D在原周期读取首页当前区与当日变更索引，汇总已完成收尾和仍有缺口的项目；同change_id/revision不再次发布或创建相同日期页，不覆盖日常收尾维护的正文。发现新想法先列候选；发现冲突标记并交原模块维护者，不自动选mtime最大者。

## 负责人能看懂的每日复盘模板

标题：`FS项目复盘｜YYYY-MM-DD`。页面属性/正文首部：日期、更新时间、维护者、change_id列表、Git固定提交、服务器发布ID/知识版本、证据链接、上一日/项目首页链接。

1. **今天实际完成了什么？** 用业务结果说明：解决的问题、影响对象。分别写已合并、已部署、实际加载及业务效果，不只列PR。
2. **哪些结论或规则变了，证据是什么？** 列稳定ID、原revision→新revision、生效时间、唯一Git原文、批准决定与读回证据。没有规则变化就明确写无。
3. **哪些只是建议或仍未验证？** 区分事实、维护者判断、模型推断、候选与待验证结果；有冲突或缺数据直接说明。Notion候选不自动升格。
4. **哪些问题已解决，哪些继续保留？** 给解决证据；保留失败/unknown/阻塞的原ID、责任方和影响，不能把缺失填成0或成功。
5. **下一步优先做什么，哪些需要负责人决定？** 只列少量具体动作与选项；正式规则/发布确认合为具体清单，新权限/凭据/安全范围单独提出。

首页只链接最新日期复盘和必要历史，不长期堆积全文。旧页、人工记录、原决策及原始失败可追溯，不永久删除，不改共享范围。

## 切换维护方式的核对项

- 原维护方核实唯一job及执行环境，读本模板和CLOSEOUT；无需另建调度。
- 确认能识别change_id、知识revision、管理块标记和已完成回执。
- 用一个已有日期做只读预演：去重、缺口、版本与原链接均正确后再协调采用模板。
- 本施工可准备候选与模拟结果；没有原任务的实际自然回执，状态仍为“模板完成、原任务衔接待验证”。
