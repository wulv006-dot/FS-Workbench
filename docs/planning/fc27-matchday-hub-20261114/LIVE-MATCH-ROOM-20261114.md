# FC27 赛事专区：焦点比赛直播与球迷互动施工稿

状态：2026-11-14 产品与技术方案；**尚未接入赛事 API，尚未上线真实赛况、投票或奖励**。现有正式群频道：`📅・fc27-matchday`（1571043454136484082，只读）与 `🗣️・fc27-match-chat`（1571043570268242014，可聊天）。

## 频道职责

| 位置 | 玩家看到什么 | 发言方式 |
| --- | --- | --- |
| `fc27-matchday` | 今日/本周赛程、焦点比赛索引、终场归档、My club 入口 | 机器人与管理员发布；玩家通过按钮获得仅本人可见的赛程与关注设置 |
| `fc27-match-chat` | 今日焦点赛置顶比分卡、关键事件卡、赛前/半场/赛后球迷话题 | 玩家公开讨论；机器人只在阶段或核验的关键事件发帖 |
| `fc27-chat` | FC27 游戏日常交流、阵容、Evo、SBC | 每日最多一条赛事入口或与游戏球员相关的引导，不复制赛况刷屏 |
| `fc27-players` | 精选球员与现有私密实时报价 | 由赛事卡的 `FC27 players` 按钮精准跳转；无商品映射就不显示价格 |

比赛多时在 `fc27-match-chat` 为每场焦点赛开**公开讨论串**，频道主界面只保留总览和最高价值事件。Discord 线程继承父频道的主要权限，需实测普通会员可查看与发送。一个比赛对应一个线程，防止两场比赛的实时评论混在一起。玩家不进入线程也能看到主频道的比分和终场结果。

## 一场焦点赛的玩家体验

1. **赛前 24 小时**：运营从 FS FC27 赛事页选择 1–3 场焦点赛。`matchday` 更新今日索引；`match-chat` 发一张置顶预告卡。选了球队身份的玩家点 `My club` 可私密看自己球队赛事，其他玩家也可浏览。
2. **赛前预测**：预告卡有 `Pick winner` 按钮。弹出仅本人可见的 Home / Draw / Away 选项，允许开赛前修改；开赛锁定。公开卡仅显示参与人数与汇总比例，不公开个人选择，也不自动 @ 球队身份组。
3. **开赛**：原预告卡编辑为进行中比分卡，展示赛事、当前比分、分钟、来源及 Discord 本地化更新时间。`Join live chat` 跳到该场讨论串；频道不每分钟新发一条比分。
4. **关键节点**：进球、红牌、点球、VAR 改判分别按核验过的事件发布紧凑事件卡。卡上可点 `🔥 Clutch` / `😱 Shock` 等反应；按钮公开汇总票数，个人点击回执仅本人可见。`Discuss` 跳到该场线程。赛况更正时编辑原卡并标记 `Correction`，不把错误比分当成新进球再推一次。
5. **半场**：比分卡更新状态，Chat Assistant 发一条战术提问，例如 `What would you change at half-time?`；不在已有高活跃讨论里反复插话。
6. **终场**：原卡更新最终比分；发一次 `Fan MVP` 投票与 `Build the XI` FC27 游戏话题。结果稳定后关闭 1X2 预测，计算无奖励积分；同一场不重复发终场卡。

### 文案示例（仅是假数据布局，不代表真实赛况）

```text
⚽ GOAL · Man City 2–1 Real Madrid · 73′
Verified by [source] · updated <t:timestamp:R>
Was that the turning point?
[🔥 Clutch  84]  [😱 Shock  31]  [💬 Discuss]
```

比分总览卡使用 MMOEXP 自有蓝橙视觉，比分数字最大；主文案只包含赛事实况、状态、来源和时间。球员照片、赛事徽章、俱乐部商标须另核实授权；不能因为数据接口能返回图片 URL 就直接复用。若用户点击了互动但消息过期或比赛已锁定，给私密解释和 `Open current match`，不显示笼统报错。

## 发帖节奏与反刷屏

- `matchday` 每日一张索引卡，状态变化编辑原卡；每场 `match-chat` 一张置顶卡。数据每分钟轮询**不等于每分钟发帖**。
- 主频道关键事件只发：确认的进球、红牌、比赛开始、半场、终场。普通换人、黄牌与细节进线程或卡片展开，首版不推送；单场主频道自动新帖上限建议 8 条，超过后合并为摘要。
- 同一供应商赛事 ID + 事件 ID + 类型 + 修订版本去重。事件先经过短暂稳定窗口并对比比分/事件列表；重启后沿用消息账本。VAR 撤销时更新原事件卡和总览，不复制传播错误进球。
- 比赛数据落后超过 3 分钟显示 `Updates delayed`；超过 10 分钟停止发布新的进球事实，保留最后可信比分与来源时间；运营可暂停/纠错。
- 不自动提及所有球迷。仅主动 `Follow match` 的用户可以选择赛前或终场提醒；默认不开启私信轰炸。

现有 Welcome 球队身份是订阅偏好，不是赛事频道的阅读门槛。`My club` 由明确的球队 ID 映射过滤赛程；暂未覆盖的球队仍可手动关注比赛。每周可做 `Club Clash`，按球队身份统计有足够样本的预测参与率/正确率。优惠券奖励属于二期：需先有 FS 发券/核销接口、每人限领、风控、预算与错判撤销规则；首版只给无现金价值的积分/徽章。

## 数据合同与账号申请

用户已排除付费 API，并确认已取得 ESPN 负责人免费使用授权，书面函件预计周一补充。2026-11-14 已在 187 启用 ESPN 每 6 小时隔离只读采集；正式 Partner API 和展示要求仍待核对。目前不向正式群自动发布 ESPN 赛况。

主源为 [OpenLigaDB](https://api.openligadb.de/index.html)：无 key，公开数据按 [ODbL 1.0](https://www.openligadb.de/en/license) 可商业展示，需在赛事卡署名 `Data: OpenLigaDB (ODbL 1.0)`；2026/27 英超、西甲、德甲、欧冠数据已读到，法甲未见同赛季覆盖。社区维护可能延迟或出错，因此更新时间和来源必须清晰显示，不把它当作优惠券自动结算的唯一依据。OpenLigaDB 实测含进球记录，**尚未验证红牌等事件覆盖**，这类自动提醒先关闭。ESPN 备用源试验与待核项见[单独记录](ESPN-TRIAL-20261114.md)。

最小数据对象：`provider, fixture_id, season, league_id, home_team_id, away_team_id, kickoff_utc, status, minute, score, events[], fetched_at, coverage`。事件须有供应商事件 ID；若没有稳定 ID，用固定字段生成指纹并保留修订记录。供应商适配器只输出标准对象，Discord 发布器不直接解析原始 API 字段。赔率不做预测依据；首版不接博彩数据。

## FS 控制台与服务边界

在 FS 的 FC27 控制台单独增加 `赛事` 页：联赛白名单、焦点赛选择、今日最多 1–3 场、消息预览、发布/暂停、赛源健康/额度、球队 ID 映射、事件更正、互动统计。`AI 聊天`部分只设置话题频率与语气。187 采集器读取供应商数据并持久化快照；FC Assistant 负责比分卡/按钮/预测；现有 FC Chat Assistant 只读消费快照负责话题与被 @ 后对话，避免让两个机器人同时维护同一条卡。

阶段验收：旧赛季回放测试状态机和 VAR 更正；D4 VIP 测试群验证一场模拟比赛的公开与私密按钮、权限、线程、时区、断流和去重；再用真实当前赛季数据连续观察一轮焦点赛。正式群先开赛程/终场，再开进行中事件，最后开预测和游戏联动。所有阶段都要核对供应商时间、最终比分、重复推送数和消息编辑成功率。

## 当前边界

已存在赛事频道、静态导航和 ESPN 隔离只读采集；**直播卡、比赛线程、互动投票、主备切换及优惠券尚未实现**。当前 FC Chat Assistant 每天 20:00 对测试群与官方群的 FC 游戏聊天频道发通用随机话题，未接赛事频道或赛事数据。
