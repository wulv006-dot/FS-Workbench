## 本次组件

`opt/mmoexp-fc-community/matchday_selector.py` 从调用方提供的 Discord 消息对象中筛出候选，并输出可由现有 `matchday_editorial.load_plan` 接受的候选计划与可解释回执。只接受指定群、频道、Smart Score 应用 ID 和精确消息链接；卡片必须是六小时内发布、含完整单场字段、尚未开赛且在未来 15 分钟至 48 小时内。按比赛身份去重，优先重点联赛、编辑预设球队和英美观看时段；默认每个伦敦自然周最多两场。已有 `hold` 场次跳过并要求人工核对。

同名联赛或范围模糊的赛事采用保守规则：英超、西甲、德甲、意甲、法甲只有出现已列明的焦点俱乐部才进入候选；不猜测同名联赛所属国家。这里的俱乐部表只用于避免误选，**不是社区成员兴趣数据**。选中原因和被排除原因记录在回执中。没有合格来源时输出 `had_source=false`；调用方必须保持原计划，不得用空结果覆盖。

这只是候选生成，不读取凭据、不调用第三方命令、不自动修改线上计划、不发 Discord 消息。现有发布程序在真正发卡前会重新读取并核验 Smart Score 原消息，以防比分、时间或赛程变动。

## 接入顺序

1. 取得可以自动、合规读取未来 48 小时赛程的输入：Smart Score 官方接口/推送，或已确认授权的独立赛程源。若继续依靠 `/live upcoming`，只能把它视为人工或运营代理按需查询，不宣称每日自动采集；Bot 不能代替另一个 Bot 执行 slash 命令。新输入须保留来源 ID、时间和更正信息。
2. 在**测试群**把实际公开消息适配给筛选器，持久化候选回执。先核对机器人能否收到 `type=20` 的应用响应；若 Gateway 不派发，使用经过授权的公开频道历史读取，不用个人 Token 或私有接口。
3. 增加安全计划合并：保留既有 `hold`、已发布场次及发卡账本；按同一比赛 ID 修改时间，不重建第二个话题；写入采用原子替换并保留上一版，空来源不写入。
4. Hermes 每日最多生成一轮候选和话题草稿；确定性代码复核球队、联赛、开球及消息来源。运行回执记录选中理由、来源、跳过原因、成本、改期与失败。测试群连续经历真实开赛、改期和完场后再扩至正式群。
5. 正式群发布前核对普通成员可见性、讨论入口、每周容量与自然消息去重；有来源冲突或状态未知时静默跳过并记录异常。

`tests/test_matchday_selector.py` 覆盖伪造/过时消息、已开始比赛、同名联赛、排序、`hold`、最新卡去重和既有发布计划格式。测试命令使用仓库 Python 3.9 环境：`python -m unittest discover -s tests -p 'test_matchday_*.py'`。
