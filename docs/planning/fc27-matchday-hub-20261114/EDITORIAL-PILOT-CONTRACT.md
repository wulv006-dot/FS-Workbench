# Matchday Host 赛前排期试运行合同

本阶段只接入**已经选定且有公开 Smart Score 赛程卡**的焦点赛事。Hermes 自动发现与排序、赛程更正和正式群自然赛事验收仍是独立后续工作；不能把本模块描述为已完成每日自动选赛。

## 输入与事实边界

FC Chat 服务可选启用 `matchday_editorial`，使用绝对路径 `plan_path` 和 `state_path`，并明确列出 `allowed_guild_ids`；测试期只列测试群，不允许排期文件把比赛投到官方群。另可设置 `max_matches_per_london_week`（默认 2，允许 1–4）。未启用时现有 Chat 和 Smart Score 事件桥行为不变。Hermes 或运营任务需原子替换 JSON 排期文件；文件中不能放密钥或玩家数据。

```json
{
  "version": 1,
  "matches": [
    {
      "fixture_id": "fixture-demo-001",
      "guild_id": "1565922092518613064",
      "home": "Home Club",
      "away": "Away Club",
      "competition": "Example League",
      "kickoff_utc": "2030-01-01T15:00:00Z",
      "smart_score_message_url": "https://discord.com/channels/1565922092518613064/1568260661010497627/123456789012345678"
    }
  ]
}
```

上述值仅说明结构，**不是一场经核验的实际赛程**。运行时只接纳当前起未来 48 小时内的赛事、允许的群与来源频道、伦敦当地一周内不超过配置数量的比赛。发送前通过 Discord 重新读取来源消息，检查作者确为 Smart Score 应用、双方球队名及与排期相差不超过 15 分钟的 Discord 时间戳。若 Smart Score 当前公开卡没有机器可读开球时间，本阶段不发赛前卡，需要先确认正式来源适配方式。

2026-11-15 实测官方 Matchday 中一张[公开 Upcoming Matches 卡](https://discord.com/channels/1041923524601851914/1571043454136484082/1571196245639303179)：一条消息含 10 个比赛字段，每个字段分别写球队、联赛、状态和 `<t:...:F>` 开球时间。当前核验器只接受这种卡片结构；核验必须在**同一个比赛字段内**同时匹配这些值，不能把 A 场球队和 B 场时间拼成一场。修正后的核验器在隔离环境对该真实卡验证了 Georgia–Hungary 的正确时间为真、错配另一场的时间为假。该卡涉及的比赛已过，不是未来赛事实发验收。

一场比赛最多发两张公共赛前卡：T-24 小时至 T-2 小时之间一次，以及 T-60 分钟至 T+10 分钟之间一次。卡内使用 Discord `<t:…>` 时间戳，玩家看到本地时间；不提未经核验的首发、比分和伤停。卡片附原 Smart Score 消息链接。发送意图以 `guild_id + fixture_id + phase` 持久化，发送状态不明时冻结该阶段并查原记录，不自动重发。

## 测试及正式启用前条件

1. 在 D4 VIP 测试群取得一条真实、公开、可读取的 Smart Score 未来赛事卡，确认其包含双方球队和开球 Discord 时间戳；没有这样的卡时保持功能关闭。
2. 把单场计划放入测试群排期文件，运行服务级检查，观察赛前两阶段的真实消息、来源跳转、重复抑制、无额外提醒以及机器人断线后的状态读回。
3. 补上延期/改期/取消的更正流程和同一场讨论入口，再开启正式群；当前排期文件改动不会编辑已经发送的卡，运营需暂时人工处理实际赛程更正。
4. Hermes 每日选择器接入时，它必须提供来源消息、选中原因、48 小时候选范围及记录；本模块只消费核验后的结果，不让语言模型独立制造赛程事实。

## 2026-11-15 测试群实发回执

测试群用 Smart Score 原生命令取得[未来赛程卡](https://discord.com/channels/1565922092518613064/1568260661010497627/1571210846107861104)，选择其中 `Anderlecht W vs Club Brugge W`（Super League Women，UTC 18:00）进行一次赛前阶段验证。187 隔离进程重新读取该公开卡后，在同一测试频道发出[赛前互动卡](https://discord.com/channels/1565922092518613064/1568260661010497627/1571211465317163021)，读回机器人作者、标题与消息 ID；同一排期再次运行仍读回相同 ID，未生成第二张卡。这是**测试群的一场赛事、一个阶段**的回执，不能代替正式群自然赛程、赛程更正或每日 Hermes 自动选赛验收。

持续运行的测试灰度使用 `allowed_guild_ids` 固定为 D4 VIP 测试群，并接续上述已确认消息的状态账本；即使排期文件误写官方群 ID，也不会向官方群发卡。正式群需另行完成真实焦点赛和更正流程验收后再扩展允许范围。
