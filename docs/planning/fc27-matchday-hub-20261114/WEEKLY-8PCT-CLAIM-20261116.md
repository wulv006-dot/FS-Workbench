## 资格与身份

[Discord Developer Policy 第 16 条](https://support-dev.discord.com/hc/en-us/articles/8563934450327-Discord-Developer-Policy)不允许将 API Data 用作福利资格判断，第 20 条不允许抓取 Discord 服务数据。既有 [奖励合同](REWARDS-REDEMPTION-20261116.md)因此不接受机器人读取 Unify 身份组、排行榜、消息或截图来签发现金券。中档身份组的视觉效果可保留，但发券资格必须来自独立、可审计的证据，例如 Unify 合作方提供的受控服务端资格回执；其返回需含稳定玩家引用、最终资格、唯一事件 ID、周次、撤销语义和可验证签名或受控调用身份。未拿到此证明前，不能把“中档身份组领取 8% 券”宣传为已上线。

首期可以由管理员根据**不来自 Discord API 抓取或机器人角色判定**的合规独立证明，签发一次性凭证。当前代码只处理已经批准的凭证，**不验证上游证明，也没有公开签发 API**。`evidence_id` 和 `subject_ref` 必须由可信签发端提供，不得用玩家自报、昵称或机器人从 Discord API 读出的身份组代替。一码只可绑定一个 MMOEXP 会员账号；同一证明、同一外部玩家引用和同一 MMOEXP 会员 ID 在同一周都只能使用一次。原始凭证只在签发结果返回，SQLite 仅保存哈希。

玩家私密输入 MMOEXP 邮箱后，FS 后端应按邮箱查会员并确认该账号的邮箱已验证且有效；优惠券只发到这个邮箱对应的账号。**邮箱输入不证明 Discord 玩家拥有该账号**。若要防止玩家替别人代领，需站内邮箱确认链接或已登录会员会话；第一版如接受“送达该邮箱即完成”，页面应明示此行为并记录该邮箱对应的会员 ID，不能声称完成账号归属绑定。公共频道只展示活动入口，不显示邮箱、会员 ID、凭证或发券结果。
