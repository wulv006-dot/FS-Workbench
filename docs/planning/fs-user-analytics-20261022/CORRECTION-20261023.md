## 已查明的问题

原Admin只允许每次最多一个月。显式全历史请求返回code0，提示按月查询；没有绕过限制。已按月盘点取得2025年与更早真实订单。9月12日原回补被未知状态53阻塞，现场核到“投诉升级·未追回”、pay_status=1；只补状态识别，支付/退款、欺诈及测试单投影不变。

后续8月27日又核实32“发货·联系买家”和74“调查·追回”，均pay_status=1。已审源状态字典只补经实际记录和人工判读确认的枚举，不自动放过未知状态，不修改既有支付或排除规则；私有证据含原片摘要、名称与数量，片回执记录字典SHA。工具将逐片覆盖压为连续区间，保留缺口与完整/失败片数，避免全历史增长撑大摘要。

- 已确认主邮箱精确关联，一个邮箱一个客户，UID=0游客纳入，继续只去首尾空格，不擅自合并大小写、点号或加号。

## 历史回补

backfill_history.py是一次性、有限、可续跑的原通道读取任务，不新增定时器。按月先核总数，非空月按日完整分页，空月以total0证明；逐片复用原锁、幂等事务、支付状态和完整分页校验。每页1000已在同一Admin入口实际核实，原重复/总数/排序校验保持。让出原03/18/33/48作业窗口，正常采集和FC调价不改。

范围依次向前到1970年源时间下限；只有所有片连续覆盖、盘点摘要与版本相符才生成可取得全历史证明。该证明不证明上游从未删除或归档更早数据，也不扩大到未接入卫星站。进度与原始记录只保留服务器私有目录；结果未知先查同一窗口的原事务/回执，禁止盲重放。

分析改为按购买和阈值边界累积每日阶段，避免每日重扫全部客户；项目比较不重复生成无用日趋势；内存读取只保留计算所需订单投影。原单与历史退款修订、冻结快照均保留。
