# 用户分析怎么用

先看一句话：**一个已确认邮箱算一个人，用全部已覆盖的有效订单找他的首次和末次购买，再看他距今天多久没买。** 日期筛选用来查看期间发生了什么，不缩小今天的客户池。

[打开正式用户分析](https://47.85.224.112/dashboard/users/)；也可从 FS 的「数据分析 → 用户分析」进入，沿用现有登录。

## 第一次用，先看这三步

1. **选谁、选哪段时间。** 看整体就选「已接入整体」；看 FC27 就选「具体项目 → FC27」。默认看「今天的状态」，日期决定要观察哪段购买经历。开始和结束日期都包含当天，按北京时间计算。
2. **点「查询」，先看「数据范围」。** 确认正在看哪个站点、来源最近读到什么时候，以及有没有“历史不足”“部分覆盖”。目前已接入主站 266，不能当成所有卫星站的公司总人数。
3. **先看阶段，再看经历。** 上面的阶段按今天距末次购买判断；点击沉默、流失等阶段，可继续选「期间一直未再购买」「期间买过，随后沉睡或流失」「唤醒或回流后再次沉睡」等小组，再展开个别客户的购买与阶段变化时间线。

只有主动改选「历史回看」时，阶段才按所选结束日期当时计算。今天状态与历史回看会在标题、观察日和快照中明确区分。

查询或刷新快照读取的是已经采到的数据，不等于后台刚刚发生的每笔订单都已同步。切换筛选后要点「查询」，以页面写明的“当前结果”为准。

## 页面上的话，换成日常说法

| 页面用词 | 你可以这样理解 |
|---|---|
| 区间购买客户 | 这段时间至少买过一次的人；一个人买十单也只算一人 |
| 已确认首次购买 | 有足够历史证明，这是这个范围内的第一次购买 |
| 已确认老客购买 | 能找到这段时间开始前的购买记录 |
| 首购身份待确认 | 本期买了，但更早历史还没齐，暂时分不清新客还是老客 |
| 区间复购 | 本期买了不止一次；和“新客七天内二购”是两回事 |
| 沉默唤醒 | 有一阵没买，后来又买了 |
| 流失回流 | 停买更久后，又回来买了；“流失”是按天数划分，不代表永久离开 |
| 今天的客户阶段 | 全部已覆盖历史客户，按末次购买距今天的天数分组；与期间筛选无关 |
| 历史回看 | 查看结束日期当时的阶段，不使用那之后的订单 |
| 首次购买 D0 | 这个范围中已核实的第一次有效购买；不会随期间开始日期重置 |
| 本期进入沉默 | 期间曾跨进沉默阶段的人，后来可能又买了；不能直接当期末沉默人数 |
| 快照 | 本次查询固定下来的一份结果；页面、名单和 Hermes 用同一份，才好对数 |

**“首次”跟范围有关。** 第一次买 FC27，不一定是第一次在主站买；他可能早就买过 NBA 或其他游戏。跨游戏的人数也不能直接相加为整体人数。

## 两种天数，不要混在一起

「阶段规则」回答：**多久没买，归到哪个阶段？** 按最后一次有效购买到观察日的北京时间自然日计算。

| 选用规则 | 近期购买 | 沉默期 | 流失期 | 长期流失 |
|---|---|---|---|---|
| 统一 30 / 60 / 90 天 | 不满30天 | 满30、不满60天 | 满60、不满90天 | 满90天 |
| FC 14 / 30 / 90 天 | 不满14天 | 满14、不满30天 | 满30、不满90天 | 满90天 |

选择 FC 项目或 FC 系列时，页面会默认选择 FC 规则。项目比较选「各项目规则」时，FC 项目用自己的规则，其他项目用各自规则；要按相同标准横向比较，选「统一规则横比」。**整体上方的规则，不一定就是下方每个项目的规则，先看表里的「规则」列。**

「二购观察 7天 / 30天」回答：**已确认第一次购买后，在这段时间内有没有再买一笔？** 它不会改变沉默、流失的天数。等待期还没走完的人不进入已成熟分母；分母为0或历史不足时，不能说二购率是0%。

## 五个实际使用情景

以下人数均为**虚构示例，只演示读法**。

### 1. 最近来买的人少了吗？

选「具体项目 → FC27」，先查最近七个完整日，再查前七日。比较「区间购买客户」，同时确认两段都采齐了。

假如从1,000人变成800人，可以说“同口径购买人数少了20%”。先不能说“流失了200人”：新客减少、老客少买、退款修正、游戏热度或覆盖变化，都可能影响人数。再展开复购、趋势，把原因分开核查。

### 2. 是不买 FC 了，还是整个主站都不买了？

点「查看同版项目比较」，看下面的「项目状态」和「整体状态」。

假如某组显示“FC27 流失期、整体近期购买”，意思是这批客户较久没买 FC27，但最近仍在主站买过其他项目。应先研究他们买了什么，不要直接当成主站客户流失。目的项目之间可能有同一人，人数不能相加；历史未齐时也不能把它当完整换代迁移结论。

### 3. 我想先核查以前买得多、最近停下来的客户

管理员点「高价值且刚进入沉默」，查看当前快照的脱敏名单，必要时展开个别客户详情。

这里的“高价值”按**已覆盖历史消费**分组，不是终身价值；这组人是本期曾进入沉默的人，核查时还要看他今天有没有再次购买。也可以直接点上面的「沉默期」，再按期间经历细分。先核对订单和购买间隔，再由负责人决定是否采取运营行动。看板不会自动联系客户、发券或改价。

虚构例子：小李1月首购、2月再次购买，之后一直没买；小王1月首购、6月流失后回来买，之后再次停买。两人今天都可能是长期流失，但时间线会显示：小李一直未再买，小王曾回流后再次流失。判断状态看末购，理解原因再看整个过程。

### 4. 新客看起来很多，留下来了吗？

先看「首购身份待确认」。假如本期100人购买，其中90人待确认，不能说来了90个新客。

只有首购能被历史证明，且完整走完7天或30天观察的人，才适合看对应二购率。若显示“历史不足”，目前能做的是继续补历史、观察本期复购，暂时不判断新客留存好坏。

### 5. 我不想自己读全部表，让 Hermes 解释

查好范围和日期，在页面底部选择一个已有持续会话，点「交给 Hermes 分析」，再到「Hermes 智体 → 持续对话」查看异步结果。“已提交 / preparing”只表示已进入处理。

可以在同一会话继续问：

> 用我刚交给你的这份用户分析，先告诉我：谁还在买，谁只是少买这个项目，哪些数字因为历史不齐还不能下结论。列出证据、其他可能原因，以及负责人下一步查什么、哪天复查。不要联系客户、发券或改价。

让 Hermes 写出快照编号，与页面核对。今后复查新日期，需要新快照，旧快照保留作对照；一直重读旧快照不会出现后来的订单。模型报告仍需核对，尤其是每个项目的规则和历史缺口。

## 看到这些提示，怎么处理

| 提示或现象 | 应怎么做 |
|---|---|
| 完整 | 只表示该指标在所选已接入范围内具备所需覆盖；不代表所有历史、所有站点都齐了 |
| 部分覆盖 / 历史不足 | 数字只描述已覆盖客户池；流失0不等于实际无人流失，确认首购0不等于没新客 |
| 观察中 / 未成熟 | 等观察期走完，先不要拿来算成熟二购率 |
| 等待回补 / 暂不可用 | 当前不能判断，不能当0；查看数据范围与缺口 |
| 刷新失败但旧结果还在 | 旧结果保留供核对；看其日期和来源读取时间，不当成刷新成功 |
| 名单或导出入口不可用 | 普通账号可看聚合；客户名单、邮箱和订单详情沿现有管理员权限开放 |

管理员点击数字卡片可查看同快照名单，导出的是当前分群的脱敏数据；邮箱与原单详情需要单独展开。不要把客户身份复制到普通报告。

当前限制：完整历史起点、全部旧订单退款变化和卫星站身份仍未核全。可以用它核对已覆盖区间的购买人数、复购和项目关系；对终身新客、长期流失及成熟新客留存，先看覆盖提示。当前部署、验收和后续自然日切状态见 [DELIVERY.md](DELIVERY.md)。
