# 本地候选与发布接线

本轮完成本地 FC 看板改造、相关离线及浏览器验证，并对真实来源做只读核查。没有合并或部署，没有改变自动改价、权限、会话、后台订单、worker 或 timer。

维护源和候选 SHA 在 [SOURCE-MAP.json](SOURCE-MAP.json)。三个前端实际入口各保留自己的非 FC 投影；不是用一份文件覆盖其他两个入口。新增 `fc_dashboard.py` 必须与三个既有 FC Python 文件作为同批载荷装配，避免缺模块；`range_api.py` 不在载荷中，保留现场管理项目、桌面及实时订单接线。

发布候选使用 `dashboard-refresh-20261025/deploy/fc_dashboard_release.py` 薄适配器，继续委托原 `actual_release` 的 CAS、fence、备份、锁和回退。适配器要求显式内容版本 `FS_FC_DASHBOARD_VERSION=fc-dashboard-20261106-<12位hash>`，目标仅为三份 JS、一份 CSS、四个 FC Python 和原导航配置。它不执行发布，也不复用历史 manifest。实际发布前需从当时活动路由生成精确导航、刷新逐目标 CAS、装配原发布器依赖，沿现有发布流程执行并读回。本轮未生成可直接重放的生产 manifest。

## 独立复核后的修正

- 环图发现分类完整金额为 null 时会漏掉该分类并重算成完整 100%。三个入口现在使用已有 `known_*` 小计，明确标“已知金额子集”、列出缺失分类，并说明不代表完整销售额占比。金币已知 100、球员卡已知 100 且有缺价订单的示例显示已知子集各 50%；没有任何已知金额时不绘制环图。
- 已 matched 的原生发货读取和 Admin 订单关联分开保留状态。关联超时只使 `membership_status=partial`，不清空已核实总体；指定品类仍不套总体。PermissionError 仍传播到 CLI 77 且无输出，原生发货本身失败仍 unavailable。
- 新增环图四种数据情形×三个实际渲染入口的回归，并在三个入口各执行缺价场景 Playwright。后端新增超时、权限和源失败边界后，相关 61 项测试在 Windows 与 183 Linux 均通过；183 包 SHA256 为 `884331421a8cc33752b3f23dd52b2e3632fa8389b5b4d4f75ccab523cb283bb7`。本轮未重新调用生产数据接口，模拟故障不能冒充生产故障演练。
