## 问题原因与最终运行位置

同一飞书应用曾被两个服务器网关接收：旧独立容器没有 `/fs`，主容器有挂载。两个配置分流造成能力和身份答复不一致；不是看到 `terminal.backend=local` 就能判断为用户电脑。普通聊天还缺研究任务专用的FS工具，单纯改运行位置不会自动获得它们。

现在唯一群网关由原 `hermes-dingtalk.service` 管理，运行于 `fs-hermes-desktop` 服务器容器内，共享 `/profile`、`/fs`、`/fs-source`，沿用原单实例机制。服务器客户端与群使用同一持久记忆、技能和会话库；不同聊天仍有各自上下文。FS研究工作进程保留原权限隔离和任务注入机制。

原MEMORY及三个business-context文件在两配置中已相同。保留主配置较新的技能、USER及聊天库；旧USER差异和旧聊天库留服务器存档，没有用旧副本覆盖。原本地配置和旧窗口保留。

## 日常使用

1. 关闭以前打开的本地Hermes窗口，双击桌面 **Hermes** 或 **Hermes智体（服务器）**。默认Hermes快捷方式现在也调用原服务器连接器。
2. 连接器建立已有专用SSH隧道，客户端连本机19442转发至服务器8942；客户端只负责显示，工具执行与记忆保存在服务器。电脑关机不影响已迁移的服务器巡检。
3. 在新窗口直接提出分析任务即可；群内继续在原群 `@Hermes`。两入口不需要互相转派到另一个Hermes。
4. 要保存长期偏好或项目经验，明确说“把以下内容记入服务器长期记忆/项目经验”。仅出现在某段聊天中的内容不能保证自动成为长期经验；保存结果应让Hermes读回确认。

若客户端未连接成功，先重新双击服务器入口，不据旧离线窗口的回答判断当前服务器能力。原默认本地快捷方式已备份至项目被忽略的运行目录，不在源码同步范围。
