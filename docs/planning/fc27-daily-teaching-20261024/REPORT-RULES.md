# FC27经营报告：字段使用与呈现规则

版本：2026-10-24-r2。来源：用户对10/23日报的逐项纠正及本轮反馈。适用于FC27经营日报及相关经营报告；业务口径与授权仍以现行业务基准和具体模块合同为准。

## 阅读入口

- [逐字段手册](FIELD-GUIDE.md)：遇到来源、字段、单位、分母、计算和结论边界问题时读取相关章节。
- [真实调用与分析实例](PC-QUERY-APPLICATION.md)：需要主动补查商品订单、处理pending、识别订单/商品行/件数/K及完整性时读取。日期、PID、金额和数量属于带日期案例，不当当前事实或通用常量。

Git负责方法版本与变更追溯，项目规则负责发现入口，Hermes正式技能负责执行时引用，实际任务回执负责证明加载和应用。仅入Git、仅写项目规则或模型口头确认都不等于实际使用，更不等于长期掌握。教材不覆盖现行Admin优先/Order补缺、USD/原币及同单成本合同；新任务重新绑定证据。

## 使用数据

每个重要判断走完：业务问题→来源/字段路径→状态/范围/单位/时点→原值或公式→合法比较→可支持结论→竞争解释→下一项最小补查及负责人动作。缺项先检查现有目录、相关子源和已授权接口；pending按原参数接续，失败/unknown按原请求核对，不盲重放。缺真实交付K时，客单、件数和整单均额不能代替每K成交价；quality.complete不等于全部字段完整。结论和标题采用同样的证据强度。

## 对比数据默认图表化

1. 涉及可比期间、平台、渠道、客群、目标/实际的数据，默认用图承担比较；正文提炼业务判断、影响、动作与验证条件，不重复逐项报数。详细原值和计算可折叠，关键结论与缺口可见。没有比较或信息量很小的单值无需强凑图。
2. 两期绝对值用分组柱/条形或哑铃图；多期用趋势/小倍图；结构用堆叠条；贡献分解用瀑布/桥；目标进度用子弹图。图形按问题选择，不规定图数。
3. 多维多指标优先用少量明确的切换控件：期间、维度、指标分开；切换同步更新数据、单位、标题、对照和来源范围。金额、人数/订单、百分比和百分点不用同一裸轴；不同来源/分母分面，不用互动制造虚假可比性。
4. 金额变化率用%，率差用pp；涨红跌绿，同时保留符号和方向。柱状图从0起，截断点图明确标轴；缺失留缺口，不补0；不可比期间只展示自身结构并注明原因，不连成趋势。
5. 保留语义图注和可展开原值表；控件使用原生button/select及可见焦点，切换状态可感知；实际检查桌面/手机、键盘、浅暗主题。离线图与表可读，打印保留必要对照；不靠颜色单独表达意义。

## Ads与流量的权重及顺序

本次FC27日报默认阅读顺序：01重点行动→02当日与趋势→03平台/商品→04 Ads、流量与相关活动→05利润与目标→06发货履约/售后→07客户→08跟进。导航、标题编号、锚点和正文实际顺序一致；调整的是分析与展示重心，不是预算权重或自动投放策略。

Ads/流量在全维扫描与重点判断中单独分析，不能只写“partial/待查”。优先使用已有有效子源，展示可比规模、结构、效率及商业落地页表现，配图并交代业务影响、候选解释、主责、下一证据及复查条件。异常足以改变决策时进入顶部行动卡。

Ads按实际channel_type区分，名称规则FC系列、共享跨游戏PMax、全账号分别标范围；暂定归因与回补成熟度可见，0平台归因转化不等于0真实订单。GA4全站、Coins页面及FC/PC专属切片分开；页面会话、跳出率与Admin订单不强拼CVR。GSC缺日不补0，也不抹掉有效GA4/Ads。采购毛利、参考利润与广告成本分开，不把它们直接混算成净利；未核同范围成熟数据时不下投放因果或预算增减硬结论。
