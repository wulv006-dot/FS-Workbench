**V2.1 Core／2026-10-20｜交给 Work / WorkBuddy 的执行设计**

> 任务：在现有 FS + Hermes 上实现受控学习、经营推理验证、动态策略建议与模拟、经验/事实分离。先完成 W0–W3，再完成 W4–W6。供应商、Jev、Octop、生产策略自动修改不在范围。
>
> 本文件是规划，不是部署回执，也不是新增凭据、付费服务或生产业务写入授权。以后收到实施任务时，复用当前已明确的授权连续推进；缺少必要权限只集中说明一次具体缺口，同时完成独立可做部分。

## 0. 执行入口与不变项

先读当前仓库 `AGENTS.md`、`docs/ops/HOTFIX.md`、相关 owner 与活动 source-map；本次核查基线为 `54bfdd305269a25cbc3f2bce315161fb5a011398`，只作比对，不覆盖后续主线或同事变更。

一个负责人、一个阶段变更分支/PR、一个发布者；Git 与共享发布串行。采用现有 pr-fast、相关模块检查、原 publisher、必要备份和真实入口读回。不新增逐 SHA 人工批准、无关全仓审计或第二套部署器。[R05]

### 不得因本项目改变

现有域名/入口、Admin/Order 主次及已批准补缺规则、订单/客户事实、现有采集周期、自动化开关、采购毛利底线、赠送语义、PS/Xbox 联动、手动临时干预的到期恢复语义、收藏馆人工关闭状态、费用停止机制、原任务/动作账本及其他负责人模块。

UI 复用 FS 现行组件；报告内容和版式保留最新报告方法的自主权。所有秘密、客户凭据、原始个人明细不进入知识包、普通日志和 Git。

## 1. 架构落点：小增量，复用原服务

以下逻辑组件优先映射到现有模块，不要求新服务：

| 逻辑组件 | 职责 | 明确不做 |
|---|---|---|
| Context Assembler | 从核心规则、有效经验、方法与本次事实引用装配冻结输入 | 不自动加载整个桌面 home，不允许共享上下文跨 owner 泄漏 |
| Learning Review | 从完成任务、纠正与成熟动作结果生成候选和差异 | 不写正式技能/价格配置，不循环审查自己的新笔记 |
| Memory Registry | 来源、scope、risk、有效期、冲突、版本与发布状态 | 不替代订单、价格、成本的事实主源 |
| Strategy Advisor Store | 保存草案、有限参数变更、模拟引用及复查计划 | 不保存可直接送 writer 的授权预览 |
| Simulation Bridge | 加载可信快照/基线/候选，用原引擎分别计算并做预检 | 不调用采集、浏览器、后台或 writer，不改真实策略 |
| Review Ledger | 连接建议、批准、实际动作、观察结果、学习来源 | 不把建议或模型描述当执行回执 |

复用已有数据库或版本目录时先做真实 schema 检查；已有同类表/对象就扩展，不用新名字重建主账。新增迁移应向后兼容，状态值与消费者同步升级。设计名称不得直接被当成现网路径或 API。

## 2. 权限与运行边界

### 2.1 三类身份

**正式研究身份**可以读获准业务聚合、冻结知识和本任务产物；可以创建草案、请求只读模拟、提交学习事件；不得改业务状态、正式知识目录、策略配置或其它 owner 数据。

**学习身份**只读获准完成任务、可复盘的工具结果、用户纠正及动作回执；只写候选区。其 home/profile、可写目录、运行锁和任务 token 与 Desktop 及正式研究区分离。权限通过服务端身份、文件系统和工具范围控制，而不是只写在 prompt 中。

**发布/批准身份**沿用原 FS 身份。知识版本发布与业务策略发布是两种权限，不能复用成“approve anything”。一个人批准分析方法，不代表批准修改最低毛利或对客优惠。

不在进程内为并发任务来回修改全局 `HERMES_HOME`。需要 task-local 注入时使用已验证的接口；不支持就保留当前显式冻结文本方式。

### 2.2 工具集约束

当前 worker 精确核对 `valid_tool_names` 与允许集合。[R01] 新增草案/模拟/学习候选工具时，应同步更新注册、网关 schema、授权、worker 校验、任务准入、消费者和测试；不删除精确校验，不把允许列表改成全工具。

一般插件、原生 memory 管理、工具发现、子 Agent 可能隐式添加工具。先实际枚举，再确定最小范围。只读工具名称带 `mcp__` 不意味着已建立真正 MCP 服务；沿用当前真实 HTTP 语义即可。

### 2.3 三种不同的“写”

本项目允许设计“写研究产物”“写经验候选”“写策略草案”。它们均不等于“写正式业务规则/商品价格”。服务端把路径、scope、作者和状态赋值，不从模型参数相信身份或批准标志。

## 3. W0｜活动源与可恢复基线

### 3.1 读取与登记

从当前服务启动命令、包 pin、进程导入路径、受控配置、挂载和发布清单确定活动代码。读取的是非秘密元数据，不输出环境变量全文。

至少登记：

| 对象 | 必须得到的回执 |
|---|---|
| FS 任务与 Hermes 适配 | 实际活动文件、运行身份、task/run 映射、取消与事件入口 |
| 模型链路 | provider 类型、endpoint 类型、model 请求名/响应名、推理映射、上下文及输出限制、费用来源 |
| 知识方法 | 实际 method_bundle、教学资料、纠错、冻结文本与有效输入 hash |
| 数据工具 | 当前完整 schema、owner/scope、数据水位、partial/pending 语义 |
| 价格能力 | 活动 calculate、policy revision/hash、原保护和 writer 消费者 |
| 任务复用与报告 | 输入 fingerprint、原始正文/HTML、展示修订、缓存与发布路径 |
| 学习及桌面状态 | 独立 home/锁/权限、已有复盘任务、是否存在隐式额外调用 |

当前有“Bot Chat/共享锁影响 FS 准入”的历史报告，必须用实际身份和无业务副作用的测试核实，不能以无关监控修复的合并记录推导已经解决。确认有问题才修相关活动路径；不要通过 `chmod 777`、共享 root 身份或删锁绕过。

### 3.2 保存基线

保存一份现有认可报告、一份未用于教学的问题、一次真实任务的脱敏轨迹、当前知识/方法/工具/模型指纹和恢复清单。旧候选源码可定位，不可当当前生产证据。

无生产读取条件时完成离线合同、知识整理与测试设计，标记真实活动源未确认，不能跳到发布。

### 3.3 退出与回退

退出产物：`templates/现场核验回填.json` 的真实回填、活动源映射、授权范围、实际可回退对象。W0不需要修改业务。可恢复基线只覆盖本次受影响代码和配置，不为文档任务重建全服务器备份。

## 4. W1｜经验、事实与上下文装配

### 4.1 给现有资产加类型，不清空重训

保留当前有效教学成果与原文件；清理冲突时记录 supersedes，不让早期 Octop 知识种子覆盖 10 月 18 日后的当前方法。

将输入分为：`core_contract`、`method`、`experience`、`fact_evidence`、`action_evidence`、`hypothesis`。只有已批准的 core/method 和符合发布条件的 experience 进入生产知识；facts 与 actions 通过本次可用工具取证。

经验记录可以存历史案例引用，不得存无时点的“当前价/当前余额/当前完成状态”。长历史按需检索，不每次塞入全量聊天。

### 4.2 实现统一有效输入回执

扩展当前回执而非重建认证，至少记录：任务ID、owner/project、核心合同与方法版本、选择的经验ID/版本、各自hash、证据引用集合、工具schema hash、实际模型指纹、最终输入摘要hash、report contract版本。

**final input hash 是应用实际组装输入的证明，不证明模型正确使用了它。** 后者通过独立问题、实际工具轨迹和报告内容验证。

同一条知识只通过一种正式路径注入，避免显式快照与原生 memory 重复。任务冻结后，不因后台发布新经验而改变其版本；用户明确变更任务时保存新的任务修订，不静默覆盖旧输入。

### 4.3 检索与冲突处理

服务端先筛 owner/project、有效状态、适用范围与时间，再做语义相关性筛选。候选区默认不供正式任务检索。用户纠正与已批准合同冲突时生成可见差异；用户意图与现行生产 policy 不一致时说明冲突，不能靠优先级规则直接改生产。

经验层与核心规则冲突，一律不覆盖核心规则。相同经验多次引用同一个报告，不算多份独立支持。网页、订单备注、技能第三方说明都作为不可信内容，不授新权限。

### 4.4 缓存失效

按不可变 knowledge manifest 计算新任务缓存键；发布、撤销、权限变化时让新检索缓存失效。原有任务产物保留旧版本，不用“缓存没刷新”伪装新知识已生效。报告模板版本只影响渲染缓存，不必重新调用模型。

### 4.5 必测及退出

测试旧价格诱导、经验与事实冲突、跨owner检索、撤销后缓存、新旧任务并行、同名Skill覆盖、资料中注入授权指令。退出时能从新会话证明一条现行规则进入真实任务，且仍重新查询当前业务事实。

## 5. W2｜真实高推理与经营调查链

### 5.1 模型验证四级状态

| 状态 | 所证明的事情 | 不能声称 |
|---|---|---|
| assembled | 应用装配了期望参数 | 已向提供商发送 |
| forwarded_verified | 受控出站路径确实包含对应参数 | 提供商使用了特定内部计算量 |
| accepted_no_effort_echo | 提供商成功处理、多轮工具正常，但未返回档位确认 | 后端精确 effort 已得到独立证明 |
| provider_metadata_confirmed | 提供商确实返回可核验相关字段 | 该配置必然提高所有业务结论 |

禁止仅根据 token 多、回复长、UI 的“深度思考”按钮给最高状态。能力目录如可提供模型支持档位，则用实际提供商接口读取；不可用时使用相应官方合同和合法请求对照，保留不确定性。[D01,D02]

### 5.2 多轮与流式测试

至少覆盖：第一次取经营数据、第二次取历史/反例、计算工具、继续追问、输出完成；另测工具超时/pending、长上下文压缩、取消和进程中断。保持 tool_call_id 与消息顺序一致。

模型协议要求保留的中间字段由代理与会话层正确处理；不得为了日志脱敏破坏续轮协议，也不将这些字段写入对外报告或经验库。审计记录参数状态、调用ID、finish_reason、用量及最终可见输出即可。

`none` 不作为业务失败后的静默回退；确实不支持目标档位时任务显示配置不支持/需处理。模型别名响应未给实际版本时记录 unknown，不能编造固定后端版本。

### 5.3 统一任务构造

手动、自然调度和持续对话共用同一业务任务合同：question、scope、报告区间、比较窗口、时区、知识版本、模型质量档位、证据引用和输出要求。不同报告类型保留各自方法，不用一个固定日报模板控制全部专题。

近N天按完整N天截止昨日；用户明确含今日则标识未完整。数据工具对日期是否含端点要实际适配，不把 report end_exclusive 直接传给 inclusive 查询。区间去重人数不可由逐日相加取得。有效0保留，缺失不补0。

### 5.4 证据与数字

复用当前 `fc.calculate` 的证据绑定，比较数值必须对应正确字段和范围。研究数字由工具计算，主盘、结构证据、营销归因和参考利润分开。没有同范围转化分母时输出“缺可比转化率”，可继续分析订单与流量各自趋势，不发明 FC 转化率。

成本不足只阻断新价格/优惠额测算；研究仍可提出补证和非价格动作。历史行动账本为空时，查已获准的交付资料或记录，不能直接断言用户没做运营；不能取得时标未知。

### 5.5 调查方式与报告交付

按问题自主形成竞争解释、取最小有价值证据、找反例、提出动作。验证这是能力要求，不是限制每个问题必须几个假设、几次工具调用或固定正文结构。

研究正文 → 原始成果归档 → 阅读版展示三层分别验收。只有渲染问题时复用原证据与原文，不反复消耗模型。HTML沿用既有安全容器/允许脚本策略，新增交互不引入任意远端脚本或权限。图表数据必须能回到当前证据；关键信息默认可见。

### 5.6 子 Agent 的可选接入

仅在主链稳定后，对相互独立的反例调查/公共市场研究试验子任务。设计必须满足：任务权不扩大、只读范围继承、总费用可归因、父任务取消传递、晚到结果不覆盖更新结论、子任务失败不阻断已有可用报告。当前不具备则使用单 Agent，不影响其他验收。

### 5.7 退出

同一问题、数据、方法通过手动与自然入口的归一化输入一致；真实已授权高推理调用与多轮工具有回执；原始报告的重要判断、数字和行动在阅读版保留。没有真实模型调用时只能标“组装/代理测试完成”。

## 6. W3｜学习队列与经验发布

### 6.1 学习事件与去重

优先复用 FS 持久任务机制，定义学习事件：来源任务最终版本、用户纠正、人工勘误、到期动作复查。服务端生成去重键，至少包括 source ID/version、知识基线、reviewer方法版本和事件类型。

只处理已完成、可引用的来源；任务中止可以用于总结“工具/运行问题”，不能当业务分析成功样本。晚到结果先关联原attempt，不制造新的学习事件重复入库。

队列处理支持 queued/running/completed/failed/unknown；重启后按原ID核对。学习模型停止时不修改已完成研究。避免“审查产物又触发同一审查”的递归。

### 6.2 最小复盘输入和输出

输入是脱敏的任务目标、实际证据引用、可见工具轨迹、最终结论、纠正/动作回执和结果摘要；不是整份密钥日志或全部个人聊天。

输出最多保存有实质变化的候选，不硬凑条数。每条候选写清：学到了什么、哪类任务适用、凭什么、反例、何时失效、风险等级建议、是否改变原方法。输出风险级别只是建议，服务端基于受影响对象重新判断。

### 6.3 自动整理与分级发布

L0：可自动归档与去重；在明确批准的非操作性经验自动发布范围内，经服务端来源/scope/冲突检查和相关内容验证后发布；高影响或语义不清时升级待审。没有足够业务结果时只能形成“需验证的方法线索”，不得宣称已证明收益。

L1：生成针对当前基线的差异、回归问题及对照产物；按批次由有权负责人评审。合并时核 base hash，避免覆盖并发的新方法。

L2：涉及业务参数、核心指标、权限或代码执行，保持人工明确批准。学习任务没有正式文件和业务配置的写权限；原生 `skills.write_approval` 可作辅助，不是唯一控制。[H01]

文档/JSON的内容检查不能单独证明自然语言规则安全。低风险分类不确定时留候选；无人值守默认不把自由文本重写的核心Skill自动上线。

### 6.4 发布对象与撤销

发布采用不可变内容和 manifest，原子更新有效指针；只影响新任务。经验引用记录被哪些任务使用，撤销后可以找到受影响报告并追加勘误。保留历史版本，不清空记忆数据库。

回退时撤回本次经验/Skill版本，停止本项目学习新入队；不删除已通过的事实证据，不逆转业务动作。批准的普通经验范围可独立暂停，正式报告继续使用上一个有效版本。

### 6.5 退出

至少完成一条用户纠正和一条真实完成任务的受控复盘：候选可见、来源可追溯、风险分级有效、发布后新会话使用、撤销后新任务不再使用。没有业务实施样本时，记为方法改进闭环，不宣称策略收益学习闭环通过。

## 7. W4｜策略草案、原引擎模拟与保护

### 7.1 拟议工具，先注册后使用

逻辑名可以按仓库规范调整，服务端能力目录必须明确实际可用状态：

| 工具意图 | 最小输入 | 返回 | 绝不接受 |
|---|---|---|---|
| `fs.strategy.capabilities` | 本任务上下文，由服务端绑定 | 当前允许模拟的参数/粒度、工具版本 | 自报权限 |
| `fs.strategy.propose` | 问题、证据引用、基线版本、有限候选、假设、复查建议 | 持久草案ID、研究状态 | approved/applied、actor、任意代码/路径 |
| `fs.pricing.simulate_candidate` | 草案ID、可信快照ID、预期基线revision/hash | 基线/候选计算、差异、保护结果 | 成本/报价覆盖、manual、确认例外、writer参数 |
| `fs.strategy.read_review` | 已有决策ID、获准观察区间 | 实际执行/观察事实、覆盖与缺口 | 伪造的执行回执 |
| `fs.learning.propose` | 来源记录ID、候选经验或Skill差异 | 候选ID、风险与检查状态 | 正式发布或新权限 |

原 `fc.calculate(price_scenario)` 只是一般情景算术，不能当作原价引擎完整模拟。原 market_snapshot 分析视图若缺 writer 所需来源资格，也不能直接充当可信定价快照。

### 7.2 价格模拟实现

1. 根据认证上下文加载草案，验证 owner/project、任务未取消、草案版本未变。
2. 加载不可变的定价快照，核来源、数据时间、项目/币量/平台/费用、成本交货类型与汇率语义。
3. 读取现行 policy 与现行 calculate 的身份，检查预期revision/hash。生成基线配置副本和候选配置副本。
4. 只允许有限 `pricing_rules.bands` 差异；保留相同最低毛利和其他受保护设置。先用原 normalizer 核结构与数值，再核本次批准的研究边界。原代码允许范围不等于生产审批范围。
5. 用相同证据分别执行原 `calculate`；保持原完整平台集合，再按访问范围展示。即使研究问题仅针对PC，也列出共用规则对PS/Xbox的影响。
6. 独立保护对可信输入和输出做不变量检查。模拟中出现关停/在途状态可以列为执行阻断；不能把模拟可计算理解成可执行。
7. 保存带快照、policy、engine、候选、guard hash的模拟回执。标记 `write_performed=false`、`execution_authorized=false`。不生成 writer可消费的preview，不放入原生产quote目录。
8. 同输入幂等复用；源或基线已变返回冲突，重新引用新版本，不悄悄重算掩盖原草案差异。

严禁为模拟而临时保存 `automation.json` 再恢复；严禁调用 `writer(check_only=True)` 代替纯计算；严禁引入后台Cookie或浏览器。

### 7.3 候选范围与保护

首期候选是“当前四档折扣 min/max 的研究草案”，不修改档位分界、单位、赠送、固定毛利底线或平台联动。对新玩法/新商品/新优惠参数，能力目录返回 `unsupported`，输出研究建议但不假报计算结果。

独立预检至少核：可比较来源、成本资格、事实TTL与时钟、单位/赠送、底线、相对当前本店价格的涨跌幅、基线版本、PS/Xbox、未知写入及原系统状态。阈值从已批准配置读取；不存在则标“预检不完整/无执行资格”，不凭文档默认10%等数字补值。

独立指服务端、非模型裁决、不可由Agent绕过，并不要求再写一份完整定价算法。保留原 writer 的所有检查；新预检不是替代安全证明。

### 7.4 优惠策略处理

已有真实优惠字段可以分析新客/老客/未知订单的结构与实际折扣，但“新客订单标志”不是唯一新客人数，更不是可发券资格。交易净额已含折扣时不再二次扣减。

优惠计算仅在现有系统提供可验证的活动、叠加、适用商品、客户资格、币种、费率及计价合同后接入；否则本期完成建议、假设和复查模板即可。不得用 Coins 100K引擎对所有商品或券规则冒算。

### 7.5 退出

同一真实获准快照，基线结果与原引擎一致，至少一个候选产生可解释差异；越界、低毛利、成本缺失、策略变更、PS/Xbox等反例被正确处理；系统未触发采集和任何业务写。实际效果仍为未验证。

## 8. W5｜动作复查、UI 与业务对照

### 8.1 决策记录不是第二套生产策略主账

记录研究/模拟状态，引用原 FS policy 和原执行回执；不把草案直接写入生产参数表。建议、批准、实施与复查使用独立轴，见《03_数据与接口合同》。

对历史动作，先查实际执行证据。用户的文字记录可以成为核实线索，不能伪造系统执行ID。未执行/部分/未知时相应限制效果评估。保持执行回执来源和人工作业范围，不让模型通过“补记录”把提案变成事实。

### 8.2 观察窗口与因果边界

只有已执行动作进入结果观察。窗口从实际生效时间起算，按成熟程度判断；可比星期、平台、商品、流量范围、同期活动和其他调价都要保留。过短或混杂严重时结论为不足以判断。

历史回放仅证明在当时可得证据上新规则会产生什么参数/价格；不证明反事实成交量。未来试验须有独立批准和停止条件；本期不为了验收主动改价或发券。

动作暂停/撤销也应记录实际回执；仅代码回滚不能撤销已经发生的商品或优惠变更。

### 8.3 UI最小接线

现有AI运营顾问复用原导航，只增“策略与复查”“经验与方法”必要视图或子页。状态用业务语言：待补证、已模拟、待决策、未执行、观察中、可继续、需调整、证据不足。

功能未接通时不可显示假成功。普通经验只汇总批次和重大冲突，不为每条笔记创建弹窗；核心规则显示差异与影响范围，按现有身份确认。

### 8.4 对照方法

A=现有认可流程；B=V2相同模型与相同冻结证据，仅改变已记录的方法/经验；需要比较高推理配置时另做独立变量试验。先修传输或数据错误，再比较内容，不把工程缺陷误判为模型不行。

建议首批用12个不同业务问题，其中4个跨日期或平台重复检验稳定性；这是评测建议，不是日常任务上限或新增审批。评测集按时间留出，不能把参考答案先写进经验库。若反复调参使用了测试集，就更换新的独立留出集。

评分维度：主判断与数字、证据和反例、行动可执行、历史复查、读者理解、完成耗时与费用。模型评价可辅助，关键业务由吴律或指定负责人盲评；不以模型自评分替代。安全用例全通过只能证明已测范围，不承诺零风险。

### 8.5 退出

能从真实FS入口读取一份新报告、一份候选模拟、一条版本化经验与一个历史动作复查结果。内容盲评不低于认可基线，并明确哪些改善得到证据，哪些尚未通过。无真实动作证据时“策略效果闭环”单独未验，不拖累已通过模块，也不冒称整体完成。

## 9. W6｜发布、自然周期与回退

先局部静态/合同/隔离测试，再授权环境的真实手动任务，最后接现有自然调度。初期只对吴律的明确FC范围启用，新旧任务按自身冻结版本完成。不得双跑同一正式任务或覆盖旧run_id。

发布复用现有 publisher、锁与PR，代码和数据库变更相互兼容；不为本模块改全仓审批。按照下列层级分别回报：

| 层级 | 需要证据 |
|---|---|
| 文档与候选资产 | 文件与合同检查，不是已上线 |
| 代码及直接相关测试 | 实际提交、测试范围和失败/未覆盖 |
| 数据与模型接通 | 真实工具、有效输入、出站参数与调用回执 |
| 生产入口 | 实际任务、产物下载、版本与状态读回 |
| 业务质量 | 相同条件对照与负责人评价 |
| 自然周期 | 现有调度触发并完成/明确失败，不以手工替代 |
| 学习与效果 | 发布/撤销、独立问题泛化、真实动作效果分别说明 |

### 9.1 降级规则

- 学习链异常：暂停新增学习处理；正式任务使用上一个有效知识包。
- 候选经验不合适：撤销该经验或方法版本；不清空全部记忆和会话。
- 策略模拟异常：关闭新模拟入口；原自动采价、原writer不变。
- 模型/公共研究不可用：明确该研究失败或部分结果，不生成假新日报；原看板与价格引擎继续。
- 知识文件权限异常：修复批准发布副本，不递归修改共享home权限。
- 任务状态未知：按原ID核对，撤销未来工具权并隔离晚到产物；不能换ID盲重试。

### 9.2 回退保留项

保留任务/attempt/run、知识版本、候选、来源证据、草案、模拟与行动回执、历史报告、策略及账本。仅回退本次受影响的代码、配置和有效版本指针。不得回滚整库、删除未知任务、恢复僵尸publisher或重放已发生动作。
