## 修订选择：已实现的边界

调用方式：`archived_dataset(query, archive_root, publication=authorized_publication)`。publication 复用现有 `fs-users-weekly-publication-v1` 的 publication_id、flag_manifests（name/sha256）、data_version、cutoff、published_at；由既有授权的调用者传入已经选定的 publication。此读取层核内容摘要和数据边界，**不把摘要当权限凭据**，也不主动打开用户库或选择其他用户的 publication。

1. 仅读取所传 publication 的固定 manifest；后来出现、mtime 更新或 captured_at 更晚的其他文件不能替换它。旧 publication 可重复读取。发布者负责选择生效 publication，本包不另造发布流水线。
2. manifest／raw 哈希、原私有文件检查和 archive_access 锁沿用；已发布输入要求完整文件集合、日期覆盖、闭合日及 captured_at 不晚于 published_at。缺文件、变更、缺日、非法付款时间等明确失败，不转回最新归档，不触发导出。
3. `profile=FC27` 只是历史请求标签，不能证明 raw 的站点或游戏成员范围。固定分支只接受原 ALL 范围的 pin，返回 `site_verified=false`、`game_filter_applied=false`、`status_filter_applied=false`；未把 config.sites 冒充 raw 的站点列。后续 D1/D2 须按真实范围、身份桥和业务规则过滤。本包不会悄悄丢掉其他游戏行。
4. 同一 publication 中完全重复的行只保留一次，保留各 manifest 来源。19/21 与 24 同订单的共同字段全部一致、后者只是多列时，选取**整条**富字段 raw；无论 pin 顺序是 24→21 还是 21→24，缺列都不构成清空。没有逐字段 last-non-null 合并。
5. 若同一 publication 含不同金额、状态、身份或归因的同订单变体，不按捕获时间猜优先级。保留原始整行变体、`revision_conflicts` 和 namespace conflict，dataset 状态 partial，不能按行加总为完整经营统计。
6. 新 publication 明确 pin 到 24 列空值修订时，结果为真实 empty；原 publication 仍读原值。新 publication 只含 21 列时返回 field_absent，**不是清空指令**。本包不执行 Store upsert，因此不会把 absent 写成已知空值；后续持久消费必须保留这个区别。

**旧调用兼容边界：** 不传 publication 的原读取流程仍保留其捕获时间选择、TTL、容量和 UNKNOWN 行为，输出增加 `revision_selection=legacy_capture_unverified` 及范围元数据。它尚不是经发布认证的修订选择，不能用这个结果声称已对齐本阶段固定修订口径。D0 不擅自切换现役 P0 消费者；后续消费者接线须传其原可信 publication，不能只删掉状态标记。旧报表、缓存和 live/raw 的未公开字段尚未全量重投影。
