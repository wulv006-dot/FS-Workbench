# 1000K 及以上：按经营事实动态调价的最小设计

日期：2026-11-13。状态：设计候选；本文件不代表代码完成、发布或经营效果已经证明。

## 推荐结论

大额段以各平台本方实际经营结果决定保持、上调或回调。复用现有完整价表、采购成本、固定 A、三小时区组、真实价窗、订单归属和原 writer，补通“经营事实 → 候选偏好 → 学习反馈 → 分段采用”即可。无需新采集器、弹性模型、长期试验服务或监控框架。

本轮只做四处必要 patch：**把已有归窗结果送进原学习器；把订单最多选段改为配对级交替机会；给原 assignment 接上 policy/correction；采用 A 时只更新本段**。不新建逐轮模型定价，不增加通用策略框架，不层层重复财务或身份校验。下面的明细用于解释这四处所需契约，不是要求新增四套子系统。

1000K 价格是大额段控制点，后档售价＝1000K 售价÷1000×购买 K，再按原生分币规则编译；赠送 K 保留并计入交付成本。低于 1000K 的售价、原数量和赠送保持。PS、Xbox、PC 分开判断，不套用 PS 涨幅。竞品仅服务低段 100K；大段不读竞品价，也不从 100K 竞品外推。

18% 是平台主篮、近期篮各自的组合采购毛利底线，逐路径零线沿现合同；25% 是经营目标。已合法而低于 25% 不自动涨价，不新增每档 18% 或大段单独 18% 门槛。采购毛利额和率同时看，优先避免“率上升、全平台毛利额下降”的假改善。

## 一个决策入口，三类证据用途

| 用途 | 输入和判断 | 允许行为与边界 |
|---|---|---|
| 必要成本修复 `COST_REPAIR` | 同平台有效采购、真实购买＋赠送、FX、按[现行合同](HERMES-V61-CONTRACT.md)取 D-3 至 D-1 金额加权优惠；现价明确失守零线或平台组合 18% | 现有求解器寻找最小必要可写修复，不受普通 ±3% 限制；不要求先等经营样本。只改有依据的受影响段，不能借小段替大段补差 |
| 经营试探 `BOUNDED_TRIAL` / 保持 `KEEP` | 当前合法；固定篮子测算说明财务空间；真价窗订单、收入、毛利额/率和量额分布提供方向及不确定性 | 围绕该段固定 A 做 B/C 或合法中间步。证据弱可以保持或沿已有有界排程试探，不默认涨、不新增最低 N；不宣称已提高未来收益 |
| 经营正式采用 `BUSINESS_ADOPT` | 新增原订单/成本修订、确认价窗、可比结果、相对回合初始 A 的累计变化及明确判断理由 | 复用采用回执和证据去重。正式采用可标经营判断；只有符合既有成熟比较条件才称 `OBSERVED_WINNER`，两者不混称因果证明 |

合法性判断优先于普通偏好；未决写入继续原 ID 核账。缺证不能写成零成本、零销量或“现价合法”；已有合法探索不因尚无成熟赢家而停用。每 60 分钟 P0 采集、计算、归单与原自然轮继续。

**必要边界与观察信号分开**：当前/候选真实成本和必要财务证明未知、目标身份不明或原写入未知，沿原保护处理对应资源。订单分布、来源、新客、同钟点可比性、毛利成熟度不足，只使相应经营结论暂不可用，不额外阻断全部改价；有原财务证明的现价可保持，已有明确有界探索/回退继续。25%目标差额、样本数或辅助字段不得升级成第三道硬门槛。

## 输入只增加必要的分段聚合

沿既有冻结输入附加每个平台、每个回合和段的经营摘要，不复制全量 ES、不额外模型调用。已有字段直接投影/聚合，下面未具备的辅助字段标未知，不为它们增加采集任务或激活门禁。

1. **财务预测**：原主篮及近期篮的数量、订单数、金额权重，平台平均优惠留存、候选全档实交成本、预测毛利额/率、覆盖和版本。按本平台 D-3 至 D-1 同单优惠 USD 总额÷优惠前商品 USD 总额计算平均优惠，订单结构沿独立窗口。D-8 至 D-2 仅用于解读历史 V6 证明。
2. **实际结果**：绑定窗口 ID、完整实际 curve key、决策 key、平台、选中段、参考 A/episode、真实开始/结束及有效曝光小时；订单去重后收入、采购毛利、毛利率、订单/购买 K/赠送 K/交付 K。每个指标附同口径覆盖；分母为零时率为 unknown/not-applicable。
3. **结构解释**：沿原实际购买 K 分桶统计订单份额、收入份额、交付量、毛利额；展示大段绝对订单和金额，也展示平台合计。桶只用于分析，不增加独立控价段。混单无法可靠分配时留缺口，不将整单收入全部归 Coins。
4. **变动背景**：采购/优惠/目录版本、渠道与新老客可识别覆盖。客户或来源未知不删除其收入；不能把一次拆单后多笔订单当获客改善。已有无可靠访问/报价曝光分母，所有 `orders/hour` 均叫订单速率，绝不叫转化率。

固定篮子应同时输出主篮、近期篮，不把订单数占比直接当收入权重。高档赠送更高时实交成本可能增加，即使按购买 K 的单价相同，也不推断各档利润率相同。

实际比较先看全平台毛利额/有效小时及平台汇总率，再解释被调大段；订单数、收入、分布是共同证据。大额占比上升而平台或大额收入下降，可能只是小单减少或一笔大单占比变高，不能判需求走强。看绝对额、同钟点变化与单笔集中度；原成熟比较器已有集中度保护，不另加全局新门槛。

## 每轮选择、调幅与排程

1. 三平台独立计算当前和候选财务证明；当前已失守则沿既有必要修复。当前已合法进入普通经营选择。
2. 不再由“本小时哪段订单多”决定谁永远得到试验。复用三小时区组和既有同钟点配对，在**配对开始前**分配段，两半配对固定同段；选择顺序不得依赖刚发生的销量结果。
3. 推荐最小默认：以平台、episode 和配对编号确定两段交替的可重复机会；相邻配对交替 small/large，每个同钟点配对两半一致，未执行的机会不伪记曝光。订单金额分布用于解释机会价值、方向与风险，不能让低量大段长期饿死。此为待实施的公平排程选择，不是要求两段各贡献一半销售或每轮必须改价；按收入加权分配更多试验机会可留作后续业务选择。
4. 已有成熟结果/correction 优先决定本段保持、回到已验证 A、或继续优选候选；仅小段轮次消费 100K 市场偏好。小段市场变化不能每小时抢占大段机会；真实成本修复仍可优先。
5. 无成熟偏好时，继续现有 B/C 有界探索或保持，保留 `exploration` 原因。经营证据只支持某方向的弱判断时可影响下一可用区组，不把单个小时、一两单或低于 25% 本身写成涨价条件。不新增“低量一律 KEEP”。
6. 幅度复用固定 A 的 ±3% 和合法中间点搜索：财务空间不足自动缩到原生可表示合法步；没有合法方向则保持当前合法曲线。幅度不是当前价×1.03 连乘，也不按毛利目标缺口直接一次拉到 25%。更大普通经营幅度不在本最小方案内。
7. 候选全部调用现有完整证明和 writer。高段更新只影响该段价格；低段另一条临时试验现价也必须保留，不强行恢复它来凑“大段单变量”。比较器须把另一段曲线不同列为背景不匹配/不同层，不能把混合变化算大段单独效果。

这使“动态”体现为方向、合法步幅、保留/回调及采用随新事实更新，而不是每小时一定改变涨幅。已有成熟结果可提升优选候选机会；没有证据时继续既有探索范围，不自行扩大。

## 学习接线不能只补两个参数

最小调用链为：已确认 `actual_price_windows`＋已归属订单 → V6 区组聚合 → 既有 `assess`/policy/correction → `assignment(..., policy=..., correction=...)` → 固定 A 候选 → 原财务证明 → 原 writer/主站完整读回 → 更新原窗口。

必须同时满足：

- 学习键区分真实 plan ID、revision、平台、段、episode、reference 和实际候选 key；现 `_curve_preference` 的拼接 plan ID 只是随机种子用途，不能拿它与账本真实 plan ID 直接过滤，否则所有真实操作被漏掉。
- 保存 V6 assignment 的 epoch/block/slot/pair、请求标签、最终实际标签/曲线、policy/correction 来源和决策时间。候选经边界裁剪后以真实价格身份去重；“请求 C、实际 KEEP”不能算 C 的新曝光。
- 曝光从实际确认生效开始，在真实关闭或同资源变更时结束；计划三小时不等于真正曝光三小时。没有变价的 KEEP 可使用已有确认窗口，不为补样本额外 POST。
- `observed_blocks` 的 V6 路径匹配完整 curve 和 `decision_curve_key`，处理同窗口跨多个区组 continuation；不恢复 `base_prices` 比较。保留旧协议与历史记录原解释。
- 对照有效小时且同钟点配对，价格区间中零单但数据完整要保留为零；缺页/未归属/未成熟成本是缺口。完整窗口无订单不能被“无记录”过滤，从而只挑有成交的小时。
- 原订单创建时点及原价匹配确定所属价格窗；付款收入和成本成熟状态另记。采购或 ES 修订回算原窗，不能把新成本收入计到补录当天，也不能反向修改当时已冻结的决策输入。
- 既有“至少两个独立时段、每 arm 至少 10 单”等仅作用于宣布观察赢家，沿原比较器保留；不扩为排程、财务修复、普通经营判断或 P0 的门禁。观察赢家仍标 `causal_effect_estimated=false`。

## 分段固定 A 与采用：必须补的关联修复

当前 `confirm_adoption` 和 `_record_cost_repair` 都用整张已确认现价重设 A。若小段正在临时 B、大段获准采用 C，直接采用全表会把小段 B 一并变成新的 A；后续又降 3% 就产生隐性复利。这不是保存价表正确就能发现的问题。

推荐保留原平台级 state 和完整现场写入协议，最小扩展参考状态中的**各段采用来源**：

- `selected_segment`/实际受影响段必须进入采用提案及持久化；被采用段从原操作已确认完整主站价表取值，未采用段沿用原参考 A 及来源。
- 为每段记录其已确认来源 operation、readback、原 curve 和采用证据；合成的参考 A 明示是经营比较基线，不伪称它整体曾在同一时刻保存上线。下一次真正写入仍使用同轮完整 ALL/主站现态作底稿。
- 当前完整现场价、历史整张回执与“各段参考 A”分开。不得为了让参考 A 等于某张历史表而额外改小段、伪造 readback 或放宽原成功条件。
- 若改动采用时另一段只是临时价，采用结果不得更新那一段的参考；现有初始回合参照和累计变化保留。成本修复只重设修复段并以 `COST_REPAIR` 记录，不借重置洗掉回合前累计影响。
- 无需建第二张价格账本或独立定时器；可在原 metadata state 中存分段 reference 来源，候选生成按所选段取其 A。旧状态首次适配时，两段都引用原已核完整 reference，历史条目不改写。

`BUSINESS_ADOPT` 的新增证据不能只是采集时间变新。沿 `order_revisions`、成本语义修订、window IDs 和初始基线累计结果去重；同一证据不能重复支持连续上调/下调 A。业务采用与“已满足观察赢家条件”继续分开显示。若现有采用合同要求的新客累计字段无法证实，不能填零来通过；保持普通试验/保持能力，采用缺项单独标明并由原合同消费端处理。

## 权限与业务选择边界

**当前明确要求及现行合同已覆盖的落实范围**：取消大额竞品依赖；三平台独立；两段保留自动能力；按本方成本和经营数据判断；固定 A、有界 B/C、18%/25%、真实价窗归单、policy/correction 接线、防大段饿死和分段采用的必要修复。设计自身不调用业务写入。代码、发布、真实操作与自然周期由主控沿当前具体授权和原入口实施，不能拿本文件作新发布授权。

**不阻塞上述修复、也不擅自加入的业务选择**：将普通 ±3% 扩大、改变 18%/25%、改赠送或数量、引入新折扣、把收入/订单压过毛利额设为新目标、允许另一段补缺口，以及按销售额设新的试验配额。推荐本轮全部保持现状；未来确需时只问该具体变更。

两段交替机会是本设计建议的最小排程实现，实施者须将它明确记录为修复饥饿问题的分配规则，检查同钟点配对保持和现有学习能力，不把它写成用户曾指定 50/50 商业配额。

## 最小实施与验收

1. 保持当前 100K-only 在途载荷冻结，先独立核对最终合入差异；本设计不混入该批生产载荷。
2. 扩展原运行输入/区组聚合和 V6 assignment 持久化；接入原 policy/correction，替换订单最多选段。修改相关调用者和展示即可，不新建并行决策服务。
3. 扩展分段参考和原采用/成本修复路径；沿现有原 ID、CAS、完整主站回读与恢复。只改大段不得改变小段、原数量、赠送或共享模型消费者读取规则。
