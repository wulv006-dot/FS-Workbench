## 缓存和权限

- 内存键原样包含经校验查询；日期归档键补入国家、Admin-only 标识、授权域与新增逻辑筛选。合同升为 `admin-paid-order-labelled-supplement-v3-scope-repeat`，旧无范围证明／旧复购映射的缓存不冒充新合同。
- 既有 HTTP 登录检查和 nginx 替换 `X-Auth-User` 的信任边界保持。仅 summary 路由将可信调用者哈希放入缓存授权域，两个调用者不会互读同一条缓存；客户端不能通过查询参数声明授权域。现有聚合接口仍是原已登录聚合权限，不新增个人名单、站点 ACL 或权限扩张。内部已有服务调用使用独立 internal-service 域。
- 代价：跨调用者不再复用同一个 summary 缓存条目；原并发／速率／队列限制、旧拒绝传播与维护锁保持。实际消费者若后续已有更精确权限版本，须在既有权限层据实接入，不能用客户端参数模拟。
- 原日归档派生仍只加和可加指标，新增原生／本地复购和单日 scope 元数据不得混进多日结果。新增 Admin-only 查询不借无同范围 Order 的日合计兜底。

## 原生与本地复购

新增共享 `admin_scope.py`，由两条直接 Admin 适配器在既有 extract 之后调用。不复制或改写未核的生产 supplement_fields；测试用现有 `order-latency-20261010/source/supplement_fields.py` 验证真实提取器组合。原通用 supplement_reader 和定时 collector 的固定查询不改。

- `admin_repeat_rate_raw` 保存原 `repeat_rete`；`native_repeat_rate` 单位为 percent，分子／分母均为 null。`paid_payments` 继续作为原生付款人数，绝不反算为该率分母。原始 4.33% 不被本地结果替换。
- `paid_payments=0` 时原 raw 0% 和 raw_value=0 留存；展示值为 null、status=not_applicable。现有 `metrics.repeatRatePct` 保留名称／字段来源，按同一状态映射，不把空集合解释为观察到 0% 复购。
- `local_repeat_rate` 接收**现有** `user_replay_v1` 的 period_cohort 输出，不另建订单复购计算器。它沿用 Store 的 customer_id、有效订单、已选期间和原有身份／退款处理；声明 identity_basis 和 population，不等同于 ES buyer_id 样本，也不因 UID=0 去掉买家。仅期间完整、身份去重完整、原算法 available 且公式为期间至少两单时，返回原分子／分母及百分比；缺覆盖则不可得。
- 两条适配器都提供内部可选 `local_repeat` 输入。现役 HTTP summary 未自动接用户库；没有可信同范围本地结果时返回 local unavailable。真实消费者接线留在集成阶段，不把合成 13/280 变成线上结果，不触发明细导出或绕过私有权限。
- `reconciliation_status=not_aligned`；原生成员、公式和修订水位仍待核。4.33%、13/280=4.642857% 和排退款后的候选值不能用改分母凑齐。零／缺失原生率、身份覆盖不足的本地率各自保留状态。
