# ES 订单共享存储与更新合同

2026-11-13 用户明确要求：所有 ES 订单统一保存归档，一份共享订单数据库供 FC、D4 及其他任务按需筛选；每天补入昨日订单，每周复核一次当月历史订单，避免各任务反复拉取全游戏日期数据和各存原始全集。

## 统一行为

- 原始 ES 文件沿现有归档统一去重保存，订单级事实索引只维护一份。业务任务只持有日期、游戏、站点、数据版本及必要聚合结果，不复制全游戏原始订单集。
- 复用现有唯一采集、共享会话、原导出请求回执、归档锁与定时入口。每日按北京时间补齐昨日；失败续作仍沿原任务，不再生成重复导出。周复核覆盖当月月初至昨日，更新同一批订单及版本，不另存每游戏全月副本。
- 采集完整性按实际分页／工作簿文件集核实。业务订单按已核站点与订单身份唯一关联；来源没有站点字段时在统一入库时完成已有可信桥接，不能每次业务读取都重新扫描全部网站订单。
- 历史更正、退款及状态变化更新当前事实并保留可追溯修订；复核失败不删除原有有效事实，不把部分文件当完整月。月前个别已知争议可由既有按单查询核实，不扩展每周整段全历史扫描。
- 后端、MCP、看板、FC 及其他消费者沿原授权筛选读取同一数据版本。缺字段及覆盖不足明确返回，不各自退回全游戏导出。临时需要的真实单笔查询与 FC 每小时原生经营统计、竞品和报价能力保持，不把 ES 日归档频率套到其它 P0 通道。
- 图表、同单归因、码券／推广人关系及明细导出使用同一有效筛选和修订。允许有界、可失效的派生汇总缓存，不再保存各任务全量原始副本。

## 当前核对事实及迁移边界

现有 ES 工作簿归档位于 `/var/lib/fc27-es-exports`，按内容哈希保存，已有文件集合回执。用户库 `/var/lib/fs-user-analytics/customers.sqlite3` 目前主要是 Admin 订单及身份投影，不包含全部 ES 来源字段；渠道 `channel-day-v1` 还含码券、推广人关系。现状不能称为已经完成统一 ES 数据库。

先复用现有归档建立共同字段读取／索引和唯一更新入口，再把现有消费者接到它。原始订单不外传到知识页、日志或 Git。旧消费者切换须验证结果和权限一致，保留原在途导出请求及固定版本；已验证可替代后才停对应重复采集，不先删档案或削弱可用能力。具体装配、代码提交、测试、部署与自然批次验收另记。
