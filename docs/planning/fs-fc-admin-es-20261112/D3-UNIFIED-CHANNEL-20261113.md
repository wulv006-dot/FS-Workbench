# 渠道归因与订单优惠追踪

用户在 2026-11-13 确认，渠道归因应补充原渠道追踪。统一视图使用同一批按站点和原订单号去重的 Admin 付款订单，依次采用明确的后台归因渠道、可核订单来源、已有映射的推广人或折扣码。优惠券通过已核使用日志关联同一订单。关联的券、码和推广人可能重叠。

- 原后台渠道及 `归因来源明细` 保留。已有明确后台渠道时，图表使用该层来源明细，空值显示「未提供」。`google-FC27-PMAX-Coins-US` 是已确认的订单来源规则，可在后台归因为未知时补归 PPC。泛称 Google 不推断为 PPC。KOL、TikTok 按已核映射归引荐，SEO、谷歌广告沿用原映射，运营、分销和私域保留为辅助项目。优先层内的证据相互冲突时归未知，较低层记录仍可作为辅助查看。
- 全部渠道分母为筛选后所有已取得的去重订单，包含未知。单选渠道分母为该渠道下筛选后已取得的去重订单，包含来源未提供的订单。状态、国家、支付方式、推广项目、码、券模板或批次、关键词均先筛订单再算分母。某字段无法核实时，显示筛选覆盖缺口。
- 现有逐日归档用于补充同一主站、订单号、游戏和付款时刻的历史来源及券记录。某日无可信归档时该项保持未核。继续读取原 Admin 订单页、原固定发布 ES 和原成本来源，统一投影不发起第二次订单分页或新导出。SEO 和 FC 消费原后台归因字段，渠道看板单独消费 `effective_attribution`。
- 图表、数值表与汇总 CSV 取同一快照；CSV 保留同一筛选维度、分母和修订。URL 型来源只出主机名，完整地址、订单号、邮箱、手机号、券码及关键词不出现在聚合结果。管理员按需打开同范围订单分页或导出明细，服务端复核原管理员权限、操作者、全部筛选和快照 ID。明细从内存同一快照取数，过期时显示重新查询。原专项分析保留，MCP 继续只读聚合。

11 月 6 日至 12 日的原渠道逐日归档七日均记录完整订单与优惠券使用日志。直接只读核到 `google-FC27-PMAX-Coins-US` 原订单来源分别为 82、91、79、52、56、51、45 条。这些是原归档行级命中数。实际渠道结果须应用后台归因优先、Admin 当前付款成员和选定范围后验收。

## 当前验证和归档边界

本地原回归覆盖渠道、订单事实、来源投影和接口，90 项通过。两套本机 Chromium 回归覆盖全部渠道与单选分母、缺失、深色及小屏、同范围筛选、原专项分析、授权、同一快照分页和 CSV。最终生产与真实入口由本轮发布记录验收。

当前新增消费者只读原有归档。`customers.sqlite3` 保存客户分析用订单及修订，固定 ES 工作簿保留后台归因字段，`channel-day-v1` 已有缓存提供主站券日志及历史订单来源。共享 ES 订单库按日期、站点和游戏读取的接线为后续统一源工作。本批没有增加原始文件、独立数据库或采集定时。
