版本 `fc_v6_d3_d1_amount_weighted_discount_v1`。本合同落实本线程总施工方案及 2026-11-14 用户最新决定；完整策略、固定 A、账本和归单细则见 [MASTER](MASTER.md)。正式知识索引的稳定 ID 继续复用 `fc.pricing.constraints` 和 `fc.pricing.v3`，不因此另建执行器。

业务决定、代码、部署和激活分别记录。生产计划仍使用旧 scalar 协议时，不能把本合同当成 V6 已激活；历史操作继续按原协议、原 ID 对账。新 `fc27_curve_v6` 操作采用下列口径，不再套用旧 100K 双20、八日优惠或逐券完整路径门槛。旧运行合同只负责未迁移计划和历史回放。

## 财务、竞品和地区

PS、Xbox、PC 分平台建曲线、核成本、计算优惠和经营结果。主站以 MMOEXP 为基准；用户确认卫星站默认跟随 MMOEXP、不独立定价，共用商品模型的 ALL 保存允许影响继承站点。技术传播结果仍按原回执和目标读回核实，不把授权当成传播成功。

### 三日平均优惠与午夜归档

- 优惠窗为北京时间业务日 D 的 **D-3 至 D-1**，首尾包含，共三个完整自然日。主订单结构及历史采购成本仍取独立的 D-7 至 D-1，近期订单结构沿原窗口和回退规则。此前 D-8 至 D-2 的优惠证明保留在历史回执。
- 午夜换日后，新的 V6 自动改价轮以共享 ES 发布中可读的昨日主站 FC27 切片为准。未发布时原任务等待，数据发布后用当轮新证据续跑一次。已有写入的对账、读回和监控继续运行。
- 写前按同一优惠窗复核日期、归档修订和平台金额，证据变化先重新采价，跨日旧证明不可写入。
- 本平台平均优惠率＝同范围去重原订单的 ES 实际优惠金额 USD 总额 ÷ 同单优惠前商品金额 USD 总额；留存比例＝1−平均优惠率。按金额加权，不按每日率或订单百分比等权，不借用其他平台比例。
- 优惠前商品金额取已核 Admin 商品金额字段；不能把包含支付附加层的客户实付差额当优惠。绑定共享 ES 固定版本、订单身份、日期、平台和原始修订。缺少必要金额或身份时保留缺口，不补零。
- 当前与候选曲线按本平台留存比例估算净收入。`pricing_assumption`、`domain.version` 和 `average_discount` 采用本合同版本；`receipt_status=forecast_under_average_discount` 明示经营估算，不冒充逐单实收。
- 用户要求不再逐券、会员、积分、混单精算：这些路径未逐一证明不再单独阻塞本方案激活；保留已有明细供分析。合法单笔优惠仍可低毛利或亏损，不能把平均假设的通过说成极端优惠组合必然保本。

### 利润约束和成本

V6 零线按本方案平均优惠假设及原生可表示价表评估；主／近期两个实际订单结构篮子分别核组合利润率 18%，25% 是经营比较的软目标。不得恢复旧 100K scope、双20、daily30 或固定赠币比例，也不把软目标变成额外硬门槛。

采购使用同平台的有效普通采购事实、实际交付数量与币种换算。购买 K、赠送 K 和交付 K 分开，赠币成本只计一次；自定义量必须保留真实购买 K，报价或赠送采用估算时标出原生区间与保守假设，不能将其变成实测事实。用户已确认商家不承担支付／履约费率，并明确忽略偶发退款和追回对新售价预测的影响；原历史记录保留，预测仍不称扣除所有损失的净利润。

### 原生 ALL 价表和市场比较

读取对应产品模型 ID 的 ALL 完整价表作为修改底稿。用户最终确认分为低于 1000K 和 1000K 及以上两段：大段按 1000K 售价／1000 得出单价，再乘后续各档数量生成完整售价；只改大段时低段原价不动。两段保留独立自动调价能力，不另设 2000K 控制段。以各档前台售价为定价依据，不从折扣字段反推目标价格；原数量、赠送及其他商品字段保留，金额按后台分币舍入，不为几分钱差异改全局单价。

V6 的售价只通过 Admin 保存接口提交完整目标价表。以本次明确成功回执及重新读取 MMOEXP 主站完整价表核对实际生效；ALL 写后回读不代替主站验收，全部卫星站写后读回不作为新保存成功的前置。V6 不同步 Order 售价。原请求超时、拒绝、部分传播或未知仍沿原编号核对，不盲目重放。此更新不改写已发生操作的历史合同与证据。

使用同轮 Admin 完整 Goods 作为自身价表事实；公开页／购物车属于独立报价诊断，不能标作已成功实测，也不能将单独的公开自身页不可用等同于 Admin 价表不可读。普通成本、FX 和竞品有效性仍按各自真实来源核实。

Lootbar 是直接竞品，U7Buy 提供品牌价格参照，Arab-UT 补充观察市场变化。ItemD2R 保留历史记录和独立查询能力，退出 V6 当前轮的自动采集和选价。竞品采集及比较仅限每个网站、每个平台的购买 100K 报价，保留实际赠送、交付量、优惠资格和交付方式。Lootbar 无券价按实际交付量与我方 100K 无券价比较，我方平均优惠用于经营测算。我方 1000K 及以上大额段按实际成本、优惠和利润独立核算，不使用竞品大额报价或从 100K 竞品价外推。

固定参考 A、候选选择、双向试验和最小可表示修复遵循 MASTER。不能用不断重设 A 制造复利式漂移；需要提高售价满足真实财务约束时，可使用已证原生控制，不生成不可写的理想价表。

## 执行、恢复和学习验证

V6 沿现有 Admin writer 每平台一次保存 ALL 完整目标价表，写前绑定同轮事实、目标版本与操作身份。写后用本次 Admin 成功回执及 MMOEXP 主站（site 266）全档读回确认。Order 的订单、采购和利润只读继续使用。旧标量操作保留原协议、原回执和原 ID 核账。

UNKNOWN／PARTIAL 先沿原 ID 核已发出状态、原回执及目标，不盲目重发、换 ID、清锁或释放未决资源。旧失败不成为永久禁令：复用原恢复和明确纠偏入口，完成核账后继续合法新处理；仅当前价格恰好一致不能伪认旧操作成功。

数据时效、请求超时、整段任务期限和操作授权期限各自记录。不能把短网络 timeout 当业务报价有效期，也不能因新行情过期拒绝对既有写入核账。任何时效调整均依据真实全轮耗时和业务决定，不凭几轮失败样本随意定值。

沿共享 ES 数据库按需读取，不复制 FC／D4 全游戏全集；缺一天或字段时复用原档及原订单 ID 精准补充。每日补昨日、每周复核当月历史，保留旧固定版本和修订链。

Hermes 继续消费既有 `pricing_review_v3` 与真实 actor/session 边界，不覆盖其他项目、周报或经营管理台配置，不恢复已暂停日报／月报。报告区分实际执行、平均优惠预测和自然经营效果；24／72 小时观察按原时点进行，不为凑验收额外改价或持续空转。

正式索引、部署装载、实际预览、首次激活／写价及自然周期分别验收。具体状态以本任务 CURRENT-EXECUTION、DELTA 和原发布回执为准；本文件不声称它们已经完成。
