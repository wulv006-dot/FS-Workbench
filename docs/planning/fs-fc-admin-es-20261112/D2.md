## 输入与信任边界

入口：`build_order_facts(admin_orders, attribution_rows, deliveries, *, sites, scope, source_coverage, complete_cost_orders=())`。它是纯内存投影，不是用户可直接调用的取数／授权接口；调用者必须先沿原权限和发布记录选好同一范围及修订。

| 输入 | 必须具备的事实／行为 |
|---|---|
| admin_orders | 原销售订单的 `site_id`、原 `order_no`、订单级 `amount_usd_format/amount_rmb_format`、状态、付款时间等。商品明细可以重复带出同一个父订单，但金额必须仍是订单级字段；不能把商品行金额冒充整单实付 |
| sites | 经原站点目录验证的 `{Admin site_id: Order source/full_title}` 精确映射。重复名称映射明确拒绝；不能靠域名相似、profile 或唯一订单号猜站点 |
| attribution_rows | 原订单号与可信 site_id 的桥接记录，携带新三列或 D0 marketing_attribution。仅有 D0 订单哈希不能反解或当原单号使用；没有已核桥接则保留为 unlinked |
| deliveries | 原 `delivery_id/source/sn/genre/cost_total/sale_total` 等。只将订单发货角色关联为采购事实；不同真实 delivery_id 均保留。同站同 ID 的完全一致投影去重；冲突修订明确失败，不按抓取时间选赢家 |
| complete_cost_orders | 已有证据确认全部实际采购记录覆盖的 `(site_id, 原订单号)` 集合。默认空；有一笔发货不证明整单成本完整，完整发货时间窗也不自动证明每单全部成本齐全。该集合不能由前端提交充当证明 |
| scope / source_coverage | 原调用者的选定范围、期间、修订和覆盖依据。原样保存为 input_scope/source_coverage，不在此重新宣称范围过滤已验证或授予权限 |

本函数不重新过滤整个源数据集；调用者负责同范围、同修订、已授权输入。输出 private 标志只描述数据性质，**不替代权限校验**。原单号和成本记录留在私有对象，未连接公开接口。

## 身份、去重与未知

- 主键为 `(site_id, 原订单号)`；同号跨站是两个订单。Order source 精确映射到 site_id 后再按原单号关联；同 delivery_id 跨站也不合并。
- 一个父订单的同值多行只记一次收入；商品行差异不会倍增父金额。父级金额／状态／时间／游戏有冲突则 `admin_order_revision_conflict`，同成本记录有冲突则 `cost_record_revision_conflict`，都不吞错或静默选新旧版本。等值金额格式如 350 与 350.00 不构成冲突。
- 缺站点、缺原单号或无法对应输入订单的记录保留在 `unlinked_admin_rows/unlinked_attribution_rows/unlinked_cost_records`；不因为总数相同或同号唯一而猜关联。已链接订单汇总不混入无法安全去重的 unlinked 行；未知 Admin 身份使总体状态 partial。
- 新三列／D0 namespace 是主渠道来源。Direct 不因旧 google 改为 PPC；空、缺列、未识别或冲突归因为 unknown。旧优惠码和推荐人不强行分配主渠道；原归因证据／变体保留。

## 金额、成本和覆盖

金额以十进制定点字符串或 null 输出，不用浮点 join 加总，不换汇；原币种／金额角色保持。Admin USD／CNY 来自既有原订单字段，不是退款、费用扣除后的净收入，也不拿 Order 销售额覆盖 Admin 实付。

每单分别输出：

- `admin_paid_usd/admin_paid_cny`：原 Admin 订单金额，只记一次；缺金额为 null。
- `cost_records`：去重后的实际发货记录，保留原成本、Order 同记录销售 CNY、时间、数量、赠送及状态；不同真实发货全部保留。原 quantity_unit 未核为 K 时不猜数量基准。
- `observed_cost_cny`：目前已读到、可用非负成本记录的已知小计。没有记录时的小计 0 **不等于实际成本 0**；必须同时看记录数和覆盖。
- `actual_cost_cny`：只有非空记录集合、各金额可用、记录身份完整且该订单已有完整成本证据时才给值。否则 null，cost_coverage=missing/partial。真实零成本记录可保留 0；没有记录、缺金额或负数角色未核不会填零。
- `procurement_gross_cny`：通过已有 accounting_row 的已完成／非退款状态规则后，按同单 Admin CNY−完整 Order 采购 CNY 得到。投诉／追回等状态和原金额、实际成本继续保留，但不因有成本便认证成熟毛利。它不是净利，也不是 Order 发货口径毛利。
- `fee_coverage=unknown`、`known_fee_contribution_cny=null`：本包没有费用证据，不把缺费用当零。

`totals` 与每个 `channels` 项都从同一份去重订单对象汇总：订单数、Admin 已知收入小计、唯一成本记录数、观察成本、成本覆盖收入和缺成本收入守恒。已知收入小计必须与 missing_admin_*_orders 一起使用；缺金额不会被认证为零收入。

`covered_revenue_cny` 是有完整成本且有 Admin CNY 的成本覆盖收入；`gross_covered_revenue_cny/gross_covered_orders` 另列满足原核算状态的毛利子集，不把争议／退款强混入成熟毛利。`unknown_channel_orders/attributed_revenue_cny` 为这次去重订单集合的覆盖，不复用历史 raw 空值率；不计算或相加跨渠道人数。

顶层 available 仅表示声明完整的 Admin 输入成功关联；成本、归因和费用仍看各自覆盖。不能只凭顶层状态宣布成本全覆盖。
