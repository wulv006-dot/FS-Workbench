# FC27 自动改价与 Admin/ES 收尾复盘

本记录回答用户收尾九问。当前事实来自部署源码、原账本、实际读取和定时任务回执；未来经营效果不提前认定。发布与测试版本见 [交付记录](DELIVERY-20261113.md)。

## 运行逻辑

60 分钟自然轮采集当前采购成本、D-3 至 D-1 金额加权平均优惠、主站完整价表和竞品购买 100K 报价。北京时间午夜后如昨日 ES 尚未发布，自动轮等待并在发布后续跑原任务。小于 1000K 与 1000K 起分开试价，同段按锚点单价联动，原数量与赠送保留。竞品信号只用于小额段。现行口径见 [V6.1 合同](HERMES-V61-CONTRACT.md)。

价格不是看到竞品便自动压低：策略使用当前价、固定参考价及有限上下试价候选，并结合可比销量、收入与采购毛利判断。候选先做财务和完整价表证明，符合条件才交给唯一写入链。Admin ALL 保存后重新读取 MMOEXP 主站完整价表；成功确认后触发 Players 原分类同步，Admin 自行计算。

## 防错与恢复

- 写前核商品、平台、币种、K 单位、规格、数量、赠送及当前价表；与预览不一致则拒绝，避免覆盖别人刚改的内容。
- 组合采购毛利 18% 为底线、25% 为目标，同时保留逐档保本校验。平均优惠是估算口径，不能保证每笔订单或每个小时都达到目标，更不是净利润保证。
- 同一操作编号、单写入者和持久队列避免重复执行。网络超时后先查原回执及实际状态，不换编号再发一次。
- 写后核对主站完整价表。部分成功、未知或不一致保留为未决，不伪装完成；对账沿原操作补读。
- 已有完整价表恢复入口：从原操作写前表预览，用当前成本与优惠重证，再沿同一受控写入链恢复。生产只读预览已验证，实际恢复写入已做合成回归，没有为验收故意制造线上错价。

目前不能宣称任何错价都会被自动覆盖。自动无脑覆盖可能把刚发生的合法人工调整或新的成本变化一起覆盖。合理方案是先识别真正的当前错价、核对原操作，再在当前条件合法时执行有界修复；不能确认的部分保留报警与人工接管。当前已有自动对账及成本底线修复，完整历史价表恢复仍是显式入口。

## 小故障恢复与仍需人工介入

已有持久任务队列、依赖失败重试、原编号对账和完成后续办；不需要每次短暂网络问题都人工重新点执行。本轮 Players 已沿原队列确认四笔后续同步，是实际恢复证据。无法确定请求是否已写入、商品规格冲突、真实错价等高后果问题不会靠盲重试掩盖。Evolutions 旧任务仍为 needs_review，说明自动恢复有边界，后续需针对原商品和原请求核清，不能清锁冒充修好。
