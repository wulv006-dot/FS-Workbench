# 每日新增与每周月度复核

**Goal:** 每日补新、每周复核三个自然月，成功归档后清理已被承接的多余文件。

**Architecture:** 复用现有用户分析任务、ES异步导出及SHA归档、Store修订与冻结结果；采集、发布、清理沿原状态顺序恢复，不另建调度器。

**Tech Stack:** Python、现役Admin/ES接口、SQLite、现有私有文件归档与原发布器。

**Spec:** 本聊天2026年11月5日用户对复核周期、三个月范围、清理与不备份的明确确认。

用户2026年11月5日明确确认：每日补新；退款、争议及状态变化每周集中复核，范围为当月及前两个月；复核通过后清理多余副本，不为这些副本额外备份，保留正式完整版归档。

## 实施口径

- 每日：补昨日及实际未完成的新日；按订单主键幂等入库。历史完整日不因日更而重复拉取。
- 每周：沿现有周一晨窗，按三个自然月复核。当月仅到昨日结束，前两个月取完整月；不是固定90天，跨年和31天月份均按自然月计算。
- 取消新流程每天复核已完整旧日的轮巡与重复旧单查询；周度全月复核覆盖的订单，不再额外重复逐单查询。历史首次缺口补齐及原在途任务恢复保留。
- 逐月检查来源、日期覆盖、订单唯一键、付款/退款/状态和身份字段；来源接口分页/日期上限按其实际合同分段，不把一次请求成功视为全月完整。
- 完整且核验通过后更新正式归档；失败保留上一份正式可用归档与原任务状态，不公布虚假的新截止。
- 只清理已被正式归档完整承接且无读取依赖的重复下载件、临时件与重复副本；不删除唯一订单事实、有效冻结引用、未完成任务输入或其他业务的共享数据。正式月归档承接日文件时同步更新读取与索引，不以保留无限重复副本代替实现。
- 不恢复每日整库备份；本次“不要备份”针对多余数据副本，代码发布回退仍沿原发布器。

## 受影响范围与验收

复用用户分析user_weekly/user_jobs、原ES归档与Store及FS/Hermes读取，不新建第二套采集或归档系统。调度和档案清理分线核查，主控统一检查数据完整性与现网版本。

必须覆盖：月边界/跨年、同日幂等、缺日重试、全月部分失败不发布、不清唯一数据、清理后原FS/Hermes查询和冻结引用可读。已上线PR830仅为原日更版本；本页新月度策略未因文档落盘而上线。

## 跨日复核与发布顺序

周月复核可能跨过一个晨窗。新策略必须优先补新日，不能让周一复核的旧截止阻塞周二、周三日更。沿同一个任务、同一写锁保留周复核的固定截止与游标；每日发布截止独立前进，月复核完成后也不能写回旧截止。未完成月复核只标进行中，不进行归档清理。

最小回归包括：周一中断后周二补新成功、原复核不换ID续跑；周复核完成后日截止不倒退；来源失败/部分月份不完整不清理；正式月只覆盖到周复核截止，之后新日文件不被误删。

## 已确认的关键依赖

现役Store的recipe-v1保存固定订单版本和新老客标记，旧快照重放不直接依赖原ES表格；当前publication用于新查询时仍按manifest与文件SHA读取。因此不能在新publication完成前覆盖或删除当前引用文件，也不需要为此迁移全部历史客户快照。

## 候选实现与隔离验证（2026-11-05）

- 现役timer的唯一入口仍为`user_jobs tick → wake(cadence='daily')`。新日任务写入`calendar-months-v1`；旧无此标记的在途任务继续按原ID及原合同收尾，不迁写旧快照。
- 周一固定复核截止、开始时间和游标，原始发布截止单独持久化，避免日更推进后把较早缺口误判为越界。每次Admin同步仍为一天，底层28日上限及原分页完整性校验不变，未使用仅已付款状态筛选。
- 同一jobs锁内先补新日、确认coverage/ES标记后发布，再续月复核。月复核错误不自动重试永久错误；独立的新日可继续。月完成按最新已发布日截止生成结果，不写回旧截止。
- 正式月结果发布后才调用原归档清理的dry→apply。失败保留原计划hash；明确引用或库存CAS变化时，先核原回执及剩余文件再形成新候选。清理权限/合同错误暂停该清理，新日仍可推进。未创建副本备份或新的定时器。
- 现有页面状态行区分新单更新、月复核和归档整理。只有已发布截止达到本日零点且无新日错误，才显示“新单正常更新”；保留所选旧快照自己的日期。
- 两线候选在183 Python 3.9.18、CI同版lxml 6.1.3隔离环境完成66项归档、313项用户分析、81项渠道回归，共460项通过；包含真实临时归档删除中断后，下一日发布改变引用再核原剩余文件的恢复测试。UI另有4项日期和7项状态语义检查通过。
- 另以现役Store叠加身份补充、现役查询叠加短锁与状态字段的实际待发布组合完成438项回归；仅排除未上线索引专用测试。跨日完成回执按最新publication截止返回，并单列review_cutoff保留周复核原截止；这一最终调整在main与实际混合组合各补跑59项weekly回归通过。
- 上述为候选与隔离结果，不代替正式CI、生产发布、真实入口和自然周期。发布载荷仍须与已核现网基底核对，不能顺带部署main未上线的索引能力。
