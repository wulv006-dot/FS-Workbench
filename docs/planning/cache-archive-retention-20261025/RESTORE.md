# 恢复与回退

业务读取继续使用原入口。历史核算/同比按原清单定位文件；热路径缺失时从.cold按同一SHA恢复原字节再解析，不重新导出、不换数据期间、不补旧价。计算缓存读取经原SnapshotStore恢复7天回收区中的原版本，saved_at保持，过期仍按原数据时效判断。

人工恢复由维护人通过原Invoke-Server187.ps1执行已上线读取器的excel_path或SnapshotStore.read；仅接受原哈希文件名，恢复后核哈希及原清单。单独恢复不等于重新采集、报价或价格写入。损坏/缺档应保留失败并报告，不删除回执或尝试新的导出ID。

每小时任务只回收过期、未被当前索引及持久证据引用的计算缓存。原Excel、清单、attempt、失败和UNKNOWN不永久清理。恢复过的Excel保留热目录24小时，近期31日清单需要的原件继续热存。

查看/复跑使用原fs-cache-retention.service及其日志，自动状态保存在source-snapshots/.retention-status.json；原件转移回执在fc27-es-exports/.cold/index.json，压缩回收回执在source-snapshots/.recycle/index.json。引用覆盖、权限、完整性或查询检查失败会退出，不把失败写成清理成功；发现业务在途则deferred，下小时再检查。

回退必须先停新增维护定时器，使用当前兼容读取器恢复全部冷原件和回收缓存并核原哈希；将冷区连同回执完整保留到私有备份，确认旧读取器看到的热目录格式恢复后，才沿原publisher/CAS回退代码和Admin镜像。不得只回退旧镜像而留下旧读取器无法识别的.cold目录。已经永久到期的无引用计算缓存副本不凭空恢复；财务原始Excel始终留存。

归档是同磁盘保留原件，不能代替异地备份；容量不足、损坏或实际恢复失败需要人工处理。没有把归档文件变小误称为解决解析内存；流式解析和服务资源边界继续有效。
