# 计算缓存清理与Excel可恢复归档

用户已授权实施：先回收过期且无引用计算缓存，历史Excel可恢复归档，自动清理及按需恢复，保护历史核算、去年同比、FC自动改价。原价格、会话、采价/模型周期、UNKNOWN及长期暂停不变。

计算缓存：扫描持久工单/报告/证据和当前索引引用，覆盖不足或读取失败则停止清理；仅过期且未引用版本进入压缩回收区，原字节/哈希不变，保留7天。到期前重新核引用，仍无引用才删除可重建缓存副本；原Excel没有永久删除路径。读取缺失版本时由原SnapshotStore按原哈希恢复，旧时间保留，不能把过期值标成新鲜。

Excel：保留全部原始清单、哈希和文件内容，近31日范围及恢复后24小时内的原件保留热目录（覆盖近七完整日自动定价依据）。其他原件经复制、落盘、全量哈希核验及回执后移至同私有挂载的.cold目录，原查询按清单自动恢复到原路径。主服务及现有Admin容器都要支持，旧容器不能因新增目录/缺失热原件失去能力；镜像只改原ES模块，复用原30分钟持久会话检查点、原身份与挂载，不重新登录。

自动维护：独立512MiB、低优先级服务，每小时检查一次；发现FC或Hermes在途/待核任务先延后。它不采集、不调用模型、不改价、不重放导出，不恢复暂停的故障跟踪，不改变每日07:30业务监控或原价格调度。首次清理先预览，逐项保留可恢复记录；冻结的原导出attempt/失败/UNKNOWN、财务原件与原报告不删除。

完成条件：本地/正式CI、服务器引用预览、两套实际读取环境的历史/同比恢复前后摘要一致、原近七日优惠/成本只读核验、首次清理回执、原身份持久化不增登录、后台健康及定时器读回。代码/合并/上线/真实入口/下一自动维护自然触发分别记录，不能以计划或模拟验收冒充实际完成。
