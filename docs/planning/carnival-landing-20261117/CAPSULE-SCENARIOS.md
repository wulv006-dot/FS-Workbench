# 狂欢盛典扭蛋（累计消费档位券）验收场景

2026-11-17 整理，同日按主站《外部对接-API文档》改定。这份文件是 FS 页面接入后的验收表。

可执行版本：
- `releases/fs-dashboard/campaign-analytics-20261023/app/tests/carnival-capsule-scenarios.test.mjs`：参考模型；
- `tests/carnival-page-browser.mjs` 中的 `capsule:` 用例：页面加模拟主站，接口形状按 API 文档。

## 规则

- **累计消费**：主站 `/ajax/carnival/user` 返回的 `spend_amount`，按以下条件计算：
  - 本站订单，`status=101`（已完成），`del=0`；
  - `paytime` 落在活动起止时间内；
  - 取 `amount` 合计。
  - 已付款但未完成的订单不算。
- **退款**（用户 2026-11-17 确认）：
  - 统一以已完成订单为准。退款后订单不再是已完成，累计金额随之减少。
  - **已发出的档位券不自动收回**，由运营在 Admin 手动取消其使用权限。
  - 页面不记账，只看主站返回的 `unlocked` / `claim_status`。
- **档位与券**（Admin「档位配券」已配）：

  | 门槛 | 券 | 面额 |
  |---|---|---|
  | $1 | 1501 | $1 |
  | $100 | 1503 | $5 |
  | $300 | 1505 | $12 |
  | $500 | 1507 | $18 |
  | $800 | 1509 | $25 |
  | $1000 | 1511 | $50 |

  门槛含等于。
- **领取接口**：`POST /ajax/carnival/claim`，参数 `slot=capsule`、`coupon_id`，一次一张。
  - 主站校验消费。未达标返回 `locked`。
  - 重复领取是幂等的：返回 `code=1`「Coupon already claimed」，不会发第二张。
- **页面行为**：点一次「抽扭蛋」，从低到高逐张领取「已解锁且未领过」的全部档位券，弹窗展示本次领到的券。
  - 页面读取 `coupon?slot=capsule` 列表，按 `required_spend` 对应到档位，不写死券 ID。
  - 抽奖只在 Cyber Monday 阶段开放（11/30 00:00 ET 起）。内部测试模式下不开放，因为档位券是真实减免。
