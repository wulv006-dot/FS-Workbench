# MLB 后台「新增模型」通道逆向结论（2026-10-12）

> 起因：老大质疑「MLB 是不是跟 FC 不同的单独通道」。
> **结论：老大的直觉方向对，但更精确的答案是 —— 不是"两个系统的两个通道"，
> 而是「同一个『产品模型管理』页面里，有两条写入路径，其中『批量导入』是 FC 专属的。」**

---

## 一、一句话结论

| 写入路径 | 后端接口 | MLB 能用吗 | 证据 |
|---|---|---|---|
| **批量导入**（网页「导入 Players」按钮） | `POST /admin/goods.GoodsMould/importPlayers` | ❌ **不能** | 前端硬编码 `[833,1327]`；后端返回 `msg='仅支持 FC26/FC27（gid=833\|1327）'` |
| **逐条新增**（网页「添加」按钮） | `POST /admin/goods.GoodsMould/add` | ✅ **能** | 空 body 探测返回 `msg='Parameter can not be empty'`（**只缺参数，无 gid 限制**） |

**⇒ MLB 完全可写，只是不能走"一键批量导入"这条 FC 捷径，得走通用的"新增/编辑"通道。**

### 2.3 「添加」通道是通用 CRUD（`index-b61e4612.js` 原文）
```js
const e = new W(new Q("/admin/goods.GoodsMould/"), {...})   // baTable CRUD，前缀 = 控制器 URL
```
而 `baTableApi`（`entry.js` 原文）：
```js
class baTableApi {
  constructor(r) {
    this.controllerUrl = r;
    this.actionUrl = new Map([
      ["index", r+"index"], ["add", r+"add"], ["edit", r+"edit"],
      ["del", r+"del"], ["sortable", r+"sortable"], ["copy", r+"copy"], ["gameDes", r+"gameDes"]
    ]);
  }
  add(r){ return createAxios({url:this.actionUrl.get("add"), method:"get", params:r}) }
  postData(r,t){ return createAxios({url:this.actionUrl.get(r), method:"post", data:t}) }
}
```
**⇒ 「添加」= `POST /admin/goods.GoodsMould/add`，是**通用**接口，代码里没有任何 gid 判断。**

## 三、这对 MLB 意味着什么

### ✅ 好消息
**MLB 可以自动化写入后台**，路径是 `POST /admin/goods.GoodsMould/add`（逐条）。
不需要等运维放开 `importPlayers` 白名单。

### ⚠️ 代价
| | 批量导入（FC 走的路） | 逐条新增（MLB 可走的路） |
|---|---|---|
| 请求数 | 1 次 | N 次（N = 新卡数） |
| 速度 | 秒级 | 每卡 1 次 POST |
| 可靠性 | 后台分片处理 | 需自己做幂等 + 失败重试 |
| 图片/关联产品 | 后台自动按模板生成 | **需确认是否自动；可能要额外步骤** |

### ⛔ 关键未知项（必须先验证，不能想当然）
1. **`add` 成功后是否自动生成 PS/PC/Xbox 三平台产品？**
   - `importPlayers` 的说明写明「每行创建一个模型，再按 PS/PC/Xbox 分区分别上架商品」
   - `add` 是否有同样副作用 —— **未知**，需实测一条才敢批量
2. **`add` 对 MLB(927/8233) 是否真的能成功**（还差"填对字段真跑一条"这一步）
3. **图标/图片**：`icon` 字段是附件 ID（如 `16274653`），走的是另一套上传接口

## 四、建议的下一步（等老大点头）

**最小验证 =「单卡试写一条」**（一次 POST，可回滚：`del` 接口存在）：
1. 选一张 MLB 新卡（如 Dennis Eckersley）
2. 按 §2.6 字段集构造 body（gid=927/cid=8233/title/price/…）
3. `POST /admin/goods.GoodsMould/add` → 看返回
4. **立即回读** `GET /index` 确认模型生成 + 是否有 3 个关联产品
5. 若成功 → 写批量脚本（带幂等 + 逐条回读）；若失败 → 拿到确切错误再定方案

⚠️ **这是生产写入，按项目铁律需老大明确授权后再做**，且必须先备份/记录可回滚范围。
