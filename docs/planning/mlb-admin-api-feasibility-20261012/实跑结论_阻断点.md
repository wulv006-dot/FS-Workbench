## 三、三个被实测推翻/修正的认知

### ① 查询参数必须 axios 括号格式（已修）
```
✗ search=%5B%7B%22field%22...%5D          → total=0（后端忽略）
✓ search[0][field]=gid&search[0][val]=927 → total=270（正确）
```
修法：移植 `fc27_players_cloud/球员维护工具/admin_client.py` 的 `_query_pairs()`。

### ② 上传文件扩展名必须 `.xlsx` / `.xls`
`.xlsm` 直接被拒（`仅支持 xlsx、xls`）。内容相同，改扩展名即可；
但**后台只认扩展名**，所以交付给导入链路的文件要用 `.xlsx`。

### ③ ★ 最关键：`importPlayers` 不支持 MLB
```
code=0  msg='仅支持 FC26/FC27（gid=833|1327）'
```
后台在 `gid` 维度上**显式白名单**。MLB 的模型（270 个）**不是**通过这个接口生成的
—— 是运营在后台**手工导入**（或用另一条前端路径）产生的。

⇒ **"执行器不给我写入"的真正原因，不是执行器没实现，而是后台这条路对 MLB 是封死的。**
