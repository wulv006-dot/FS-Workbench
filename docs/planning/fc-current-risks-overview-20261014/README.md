## 行为与定义

FC 总览原有四个核心指标保留。在现有“运营关注”里显示三项，并复用当前池订单抽屉。原关注提示收在“其他关注提示”中。

| 项目 | 定义 | 缺失与边界 |
| --- | --- | --- |
| 当前问题单数 / 涉及金额 | Admin 当前未结案池中现有 `issue` 标志为真的订单，含现有资金异常口径；金额为 USD 订单额 | 缺金额时完整金额为 null，仅显示已知金额和缺失单数；不是财务损失 |
| 待交付等待至少 24 小时 / 账龄 | 现有 `backlog` 标志为真的待交付订单；资金待处理不计待交付。以源快照 `as_of` 减付款时间；付款时间缺失才回退下单时间 | 精确未取整时长判定 24/72 小时。时间缺失、无时区、无效或未来时间进入未知；显示已知计数及未知单数。账龄分为 <24、24–72、≥72 小时及未知，并列回退数 |
| 高金额未结案单数 / 涉及金额 | 当前未结案池中整数分金额 ≥ 既有 `attention_amount_usd` 配置（当前 $300）；含资金待处理 | $299.99 不进入，$300.00 进入。缺金额订单无法判定门槛，完整数量/金额为 null，显示已知小计和未判定数 |

三组可重叠，不能相加或除以所选历史销售额作为风险占比。当前状态不受所选支付日期截断，仍受现有站点、平台等筛选；不是所选历史日的日末快照。页面显示 Admin 读取时点。既有 `slow_orders` 使用当前查询时钟、包括全部未结案状态；新增 `waiting24` 使用源快照时点、只含待交付，两者不可互换。

汇总在后端完整池上计算，先按现有 ID/更新时间去重，再排除终态；不依赖页面 10 条分页。只有显式 `coverage.backlog_status=available` 且没有失败组才给汇总。缺完整性标记、分页失败或失败组矛盾时，新字段为 `not_available`，不提供任何三项合计；旧后端未提供新字段时前端同样显示暂缺。已验证完整空池才显示零。
