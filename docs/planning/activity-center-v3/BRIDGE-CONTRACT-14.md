## 字段保值与范围

已观察原生编辑采用完整 28 字段 JSON、原共享会话、`server:true` 和 `think-lang:zh-cn` 请求头。代码只从受信任 Admin 详情取得完整行；浏览器不得提交快照或原生字段集合。当前合同只授权修改 title/brief；不把其证据扩展为启停、发券、新建或其他业务字段验证。

字段名、类型、零值、金额字符串、空时间及范围均保持原样；未识别字段或类型应拒绝，不猜测或用表单默认值补齐。每次操作绑定请求摘要与最新完整行摘要；派发前再次读取比对。原生接口没有已证实的服务端条件写入，因此客户端读取与 POST 之间仍存在外部并发窗口。对象锁只能协调本 FS 账本，不能锁住原生 Admin 或其他系统；现场写验证仍须独占测试对象和无并发操作。

## 回执、账本和未知态

- 原操作 ID 与请求内容永久绑定；重复请求读取原记录，不派发第二次。同一对象存在 pending/unknown 时，新 ID 不得绕过锁。
- 原始/预期完整行仅保存在服务端私有状态中，绑定原请求摘要；公开结果只能返回安全状态和引用，不暴露快照。Git 用纯合成数据测试。
- POST 不重试、不跟随重定向；底层重试配置必须确证关闭。获得响应后先持久化脱敏业务码、响应摘要和传输状态，再进行独立读回。
- 只有 HTTP200、精确整数 code=1、原操作匹配的持久回执/完整提交快照和独立字段读回均满足，才确认成功。HTTP200/code0、字符串码、畸形响应、超时或审计保存失败均不能判成功。
- 旧 UNKNOWN 不迁移为成功。缺少原成功回执或完整快照时，即使当前标题与期望相同也维持未知，只查原操作、不重新 POST。
- 进程中断后只读对账；同一操作的成功回执足够但读回暂失败时，可恢复查询。历史失败与 UNKNOWN 原记录保留，不以本轮测试重新解释其终态。

## 恢复合同

管理接口：`action=benefit_restore`，携带 site_id、kind=coupon、native_id、operation_id、before_hash 和 `restore_of`（原 benefit_edit 操作 ID）。沿原管理 POST/鉴权/CSRF 边界处理，读接口拒绝此动作；不增加公开端点或自动恢复按钮。请求不能包含客户端快照、恢复文本或 enabled。

恢复必须引用原成功文本编辑操作，不能恢复未知请求、状态切换或任意客户端快照。成功准入派发后，原编辑仅绑定一个恢复操作 ID；unknown/confirmed 保留绑定，后续同源不同 ID 不得重复补偿。前置验证失败或明确未派发的拒绝不消耗合法恢复机会；不能凭超时释放绑定。

恢复时重新读取最新完整行：原标题/说明从服务端原快照取得；当前文本必须仍与原编辑预期相同，站点/对象范围及领取使用条件必须合格。仅覆盖标题/说明；用户后来填写的时间、状态及其他合法非文本字段原样保留，不从旧整行恢复。恢复同样执行新快照、派发前比对、一次 POST、业务回执和独立读回。任何冲突/未知都停止自动写入，不循环恢复。

代码通过不等于 FS 实际写入接通。对象归属、原生写入合同和 FS 桥现场验收证明由服务端私有配置管理，不能由浏览器开启；本轮不设置任何真实对象证明。能力仍默认关闭。
