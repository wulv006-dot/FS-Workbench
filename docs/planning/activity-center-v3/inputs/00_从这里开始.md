# FS 双活动上线 从这里开始

本执行包采用老D负责监工、本地Codex工程主控负责施工、子Agent按需开发与审查的方式。187保持既有IP白名单；所有187操作由实际能连接它的用户电脑通过原SSH通道执行。纯开发与测试可以使用合适的本机或已配置云端环境。

## 开工前先验证本地通道

1. 在实际能SSH到187的电脑上打开ChatGPT，进入老D资料页，在Computers中找到Your computer并允许访问。Dot电脑授权与Codex连接、Work Sync分别核对。
2. 把本执行包交给老D，同时提供两个原任务的完整本地目录或源文件包，以及已接受设计版本。两个任务是「策划 FC 活动与落地页」「设计 MMOEXP 限定活动页」。Matchday、竞猜和竞猜奖励排除。
3. 发送02文件中的指令。老D先确认目标电脑连接；有合适的本地Codex任务则续用，否则创建本地工程主控。不能将云端旧任务当成已经迁移到本机。
4. 取得真实任务入口、实际执行主机、仓库路径、Git版本、原SSH到187的最小只读结果，以及老D向同一任务续派一次只读要求的结果。
5. 这些证据进入04开工回执后，按完整方案推进G1。开工期间电脑保持在线，ChatGPT应用保持打开。

如果老D不能自动创建本地任务，用户可以在本机Codex手动创建一次，粘贴03文件，再把准确任务入口交给老D。仍须验证老D能否继续该任务；未通过则标记自动派工尚未打通，由用户转交阶段指令，不把任务已启动等同于自动监工闭环。

## 两个交付节点

G1：完成FS和187活动侧工程、两个原任务页面、必要真实后台接入、验证审查、部署读回及主站技术交接包。主站交易未接通时如实保留待适配状态，不能以模拟宣称购买已经可用。

G2：主站适配就绪后续派同一工程主控，分别完成两个任务的真实购买、允许的优惠叠加、支付、Admin/Order读回和FS活动归因。Codex出具技术证据，老D核对范围并统一向用户交付。
