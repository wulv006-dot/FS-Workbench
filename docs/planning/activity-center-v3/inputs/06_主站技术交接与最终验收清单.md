# 主站技术交接与最终验收清单

先完成G1活动侧工程与技术包，再由主站完成正式接入；G2验证两个任务的实际交易。工程证据由Codex主控汇总，老D统一向用户交付。

## 14 先固定哪些业务和接口约定

| 约定 | 需要落实的内容 |
|---|---|
| 商品 | 站点、游戏、模型、商品ID、SKU/变体、平台、规格、数量与数量单位；由实际模型和购买页核实 |
| 活动 | 活动和页面标识、有效时间、语言、素材、SEO、发布版本与状态 |
| 优惠 | 主站可识别引用、适用商品行、叠加规则、有效区间及对应品类利润规则 |
| 报价 | 权威来源、币种、金额、优惠拆分、有效期和价格变化处理 |
| 购买交接 | 商品行、活动/优惠版本、操作唯一标识、原主站会话和交接结果 |
| 订单归因 | 实际使用优惠、有效付款状态、站点与订单号、退款及可获得的商品行分摊 |
| 能力状态 | 哪些是真实接通、哪些为模拟、哪些待主站适配；决定页面实际可用操作 |

FS作为统一运营配置入口，主站执行最终价格和支付校验。活动商品与普通商品混合购买时，只对适用商品行应用活动规则。

金额验收可使用既有合同样例：100美元商品活动九折后，再叠加允许的5%优惠码，顺序计算为85.50美元；实际优惠顺序、定额券、积分和互斥以已确认合同为准。各品类使用自身批准的利润规则。

不同活动要有可区分的优惠引用；同一优惠被多个页面共用且没有额外标识时，只归因到可证明的活动组。用券日志没有付款信息时须与真实订单付款状态关联；不能将领券、点击或加购等同成交。

### 主站技术接入清单

| 项目 | 主站负责 | FS/187侧先准备 |
|---|---|---|
| T01 正式入口 | 域名、HTTPS、入口链接或代理 | 可配置域名/路径、构建与公开服务说明 |
| T02 报价与购物车 | 权威报价、购物会话、正确入车和幂等 | 商品参数、选购意图、适配器与失败用例 |
| T03 优惠执行 | 活动与通用券/码/积分组合、最终金额 | FS规则、主站优惠引用和金额用例 |
| T04 订单追踪 | 必要的实际优惠/活动标识 | 绑定表、读取和归因逻辑 |
| T06 后台缺口 | 仅补现有接口确实缺失的动作 | 已有能力复用和精确缺口清单 |
| T07 结果通知 | 可选的即时通知 | 现有后台拉取对账，基础上线不依赖通知 |

竞猜专用T05不进入本次。正常购物登录与会话属于T02；原任务如确有其他会员功能，按已接受原需求处理，不自行加入竞猜身份工程。

## 15 验收与最终交付

| 验收内容 | 技术证据 | 老D核对重点 |
|---|---|---|
| 原任务范围 | 页面/功能清单、接受版本、部署映射 | 两个原任务是否完整，是否误加Matchday |
| 商品与配置 | 实际模型、规格、FS保存与回读 | 展示和购买参数是否一致 |
| 优惠管理 | 创建/调整/停用等必要动作及回读 | 活动规则与主站引用是否对应 |
| 页面发布 | 构建、候选提交、187运行版本及地址 | 实际发布是否等于被审查版本 |
| SEO与素材 | 正式URL、标题描述、素材和构建结果 | 是否沿用原设计并可维护 |
| 购物车与金额 | 真实商品行、活动优惠、允许叠加的通用优惠 | 是否只对适用商品生效 |
| 异常与重试 | 重复请求、失效报价、价格变化、活动到期用例 | 用户流程是否真实可用 |
| 付款与归因 | 实际订单、付款状态、优惠和FS结果 | 不以模拟、领券或点击替代成交 |
| 退款及统计 | 实际状态更新或可复现的相关验证 | 金额范围和净结果是否说明清楚 |
| 维护与回退 | 配置入口、日志、版本、回退说明 | 上线后谁维护、如何继续操作 |

项目报告固定保留四种完成状态：**界面完成、真实后台数据读写接通、187部署并读回、主站真实交易与活动归因接通**。代码提交、PR合并、模块发布分别记录，不相互替代。

每个原任务至少有自身的购买闭环证据，其他平台/规格和异常情况采用与风险相称的相关覆盖。原业务施工方案中仍适用的验收场景继续执行，Matchday项标记不适用。

最终给用户一个统一交付包：两任务正式入口、FS管理入口、版本与PR清单、技术验收报告、Q复核、商品和优惠映射、订单归因证据、主站接入说明、运维与回退、剩余事项。

**Codex工程主控负责技术验收；老D负责对照业务目标签收证据并统一向用户交付。** 用户无需收集各子Agent的独立报告。
