# Seasonal 模型优惠、玩家规格与许愿池合同纠偏

2026-10-26，覆盖旧参考中“固定服务器商品快照价作为卡片统一售价”的设计。RELEASE39仍为现役，以下是本地候选与主站待对接合同，不代表已部署。

## 已核实差距

用户现有Chrome标签 `/events/seasonal/index.html?theme=halloween` 实际卡片显示固定平台/区服、SKU及SIMULATED金额。源码event.js用priceCents本地计算折扣价，弹窗options仅为source.platform；runtime-bridge.lines取source.quantity及空attributes，未使用用户区服选择。已查看当前真实像素；浏览器当前有翻译呈现，不能据其中文证明服务器源文案是中文。本轮不更改浏览器翻译设置。

## 业务对象

运营选商品模型及版本化活动优惠规则。卡片表示该模型的优惠机会，不表示某一区服商品的统一价格。保留随机池、固定优惠区、锁卡、邀请刷新；旧快照仅作迁移来源，不自动把goods_id当model_id。

玩家选择此模型实际允许的区服、平台、规格与数量。只有组合完整、实际商品关联唯一且有效、主站合同可用时，才能请求该组合的权威最终价。展示优先为模型信息和优惠力度；演示折扣仍标DEMO，不启用正式规则或虚构最终金额。真实选项未知时显示“Model options unavailable”，不复制另一模型选项或预选唯一快照区服。

锁卡锁定模型优惠及规则/权益版本，不锁区服售价。允许换区服的范围、锁定期限及活动结束前后规则由主站明确；每次改变区服/平台/规格/数量使旧报价失效，必须重报价。过期、规则变化、旧异步响应和上下文不符的报价不得恢复可购买状态。订单仍以主站最终校验为准。

## 许愿池 Wishing Pool

既有偏好设置在抽取区上方明显展示，让用户先选择偏好再抽。复用原状态、游戏集合和抽取算法，不新增概率、次数或正式参数。偏好不保证抽中；当前仅本地DEMO。已锁定卡片、固定区及邀请刷新语义保留。

建议主站接收：主体可信会话、activity_id、rule_version、pool_version、偏好游戏ID集合、稳定operation_id及原状态revision；响应实际接受的偏好版本与生效轮次。该命名是建议，不是已存在API。服务端校验允许范围，偏好影响下一次抽取，不追溯重抽当前卡，不把点击/分享当有效注册。实际权重映射由已有正式规则确认，客户端不提交任意权重。

## 必须对接而非猜值

1. 模型目录：site_id/game_id/model_id及真实模型名称、允许选项和条件依赖、catalog_version、选项有效期；服务器/平台/规格ID属于原命名空间。
2. 组合解析：完整选择→goods_id/可选SKU、原生购买参数、数量单位/步长/范围、状态；跨模型/站点组合必须拒绝，不用展示标签做主键。
3. 权威报价：稳定请求/意图、模型/组合/数量指纹、活动优惠及规则版本、锁定优惠引用、currency/scale、实际优惠拆分、应付和expires_at。价格由主站根据所选区服计算，页面不能从旧priceCents生成。
4. 交易与订单：原会话购物车、幂等及unknown查询、最终重验；订单保存真实模型/组合/活动调整/付款与退款事实。
5. 当前FS公开snapshot尚无Seasonal模型选项真值服务；新增客户端合同与合成样例不等于服务端接通。原后台FC三平台模型解析仅限FC，不能直接用于RPG区服。

## 配置迁移边界

既有product_keys和原始快照/审计保留，不在读时自动写新模型配置。后续运营字段应是模型引用+优惠规则引用，真实模型关联通过既有合法Admin只读合同核实后才能迁移；不要求运营填写服务器SKU作为统一卡片。未知映射保持不可报价。唯一products入口和数据分析功能不重建；本轮不保存线上草稿、不迁移业务数据。
