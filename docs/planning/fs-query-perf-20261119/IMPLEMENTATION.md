# FS 跨模块查询提速

负责人 Codex。基线 `b82875edfb170a7eb9bc9299b3cb51908dc0f1f0`。本轮优先让 FC 查询直接使用已发布订单与已有发货证据，其次缩短采集、经营首页与活动草稿的等待。

## 实施顺序与验收

1. 从已登录 FS 和现行连接器按原调用者读取。专项查询按北京时间最多三个已结束自然日汇总固定发布的付款群体；返回站点、平台、数据修订、实际同单成本覆盖。对同一笔完成订单，用已核实的人民币收入计算采购毛利率，按总额相除。已经在经营看板使用的 Admin 原生付款数及 Order 发货日毛利各按原口径展示。
2. 保留原有共享 Order 采集、锁、同轮来源和截止范围。比较原生请求数、等待时间、样本数量和单位成本；使用同一冻结输入对照平台候选及最终价格。读盘、Order 源采集和端到端耗时分别计量。
3. 经营首页独立加载有权限的数据，活动编辑器重叠脚本与配置加载。草稿回执、发布和失败后核对均通过现有业务入口。活动打开计时到草稿可用，搜索计时到真实结果，保存计时到同一操作读回。
4. 发布采用各模块已有发布器、目标哈希、服务保护和备份。使用同一身份和范围对照前后。记录首次、再次与多人请求，取第 95 百分位。FC 三天和工具完整响应目标为 2 秒，经营首页首批有效数据为 1 秒。等待响应、页面外壳和权限拒绝单列。

## 批量取数与真实样本

11 月 18 日，Admin 已有订单接口按 FC27 主站相同条件一次返回 207 笔，用时 1.279 秒。207 笔的 purchase_price 全为零，同号比对有 169 笔在 Order 发货数据中存在正成本。Admin 原生订单接口可供订单查询，不能拿该字段代替实际采购成本。

使用 Order 原客户端有效会话，同一小时发货列表普通请求返回 HTML，用时 1.858 秒。使用页面常见的 AJAX 读法时返回 application/json，但解码得到的是整份 HTML 字符串，长 146214 字符，用时 3.384 秒。已核入口可按时间筛选和分页，尚未确认服务端提供结构化批量详情。供应端如果能提供只读批量明细，需包含稳定发货行 ID、商户订单号、平台商品、购买/赠送数量、单位、采购金额、履约状态和可追踪的更正/撤销，才能分别服务于经营汇总和定价核查。供应端可按日期批量发出的数据与 FS 读取既有归档是两种不同的性能指标。

187 独立加载候选代码，用同一份已发布业务数据按窗口各读 20 次。11 月 16–18 日首次 0.334 秒、P95 0.066 秒。固定版本的 699 笔已付订单共 44857.88 USD，已完成且可核 576 笔、待完成 121 笔、排除 2 笔。576 笔合计人民币收入 255128.07、实际成本 163899.94、采购毛利 91228.13，毛利率 35.7578%。11 月 15–17 日首次 0.061 秒、P95 0.082 秒，807 笔已付订单中有 670 笔已完成，409 笔可核，261 笔空缺保留。这里计时包住服务器查询，不含正式 HTTP、浏览器或连接器转发。

Order 原客户端同四笔详情的一次顺序和两笔并发对照为 3.543 秒和 2.035 秒，四笔的原始校验结果一致。渠道采集仅在一次成功发布后复用当次已加载的发货归档。自然改价、正式活动页、三日快查及共享成本的上线测量见[正式验收记录](ORDER-ARCHIVE.md)。第三方工具完整往返尚无同入口样本，按用户选择使用正式看板计时。

### 大批量读取试验

187 在内存中为已采集的 67432 条普通发货行按网站和商户订单号建立 SQLite 索引，覆盖 52386 笔不同订单。读取现有归档、解码、建索引共 0.480 秒。各选 100、1000、5000 个分布在归档内的订单，各测 10 次，计时包含填充订单集合、查询和 JSON 编码。对应返回 126、1311、6503 条发货，中位耗时分别为 0.78、7.33、35.70 毫秒。5000 笔最慢一轮 42.97 毫秒，编码 528560 字节。三组发货身份、交易时间和原成本值均与同一归档逐行一致。试验没有持久化索引，未计正式接口鉴权、网络或首次采集。无法关联原单的补发及最终结算未纳入。

## Order 原生批量导出

本机已登录 Order 的「订单管理 → 发货记录 → 下载表格」在选中两笔 FC 发货后，向 `/order/admin_delivery/download.html` 提交当前日期、游戏、类目和发货记录集合。生成与领取均返回 HTTP 200、业务码 1，两次收到响应头分别为 54.482 和 52.539 毫秒。两次人为操作相隔约 53 秒，实际生成耗时未知。Chrome 屏蔽了此次下载，Edge 取得两笔共 22 列的原生 Excel，采购总额、数量、赠送等九项与发货网页逐行一致。更大批次的导出吞吐仍待实测。线上消费者复用共享归档。详见[发货样本与正式读法](ORDER-ARCHIVE.md)。

定价回放使用同一批 PS、XBOX、PC 的 45、8、15 条输入。旧实现与候选三平台平滑采购成本逐项一致。隔离运行实际 PS 定价计算，低成本两版均保留 10 / 95 USD，高成本两版均得到 10 / 109.25 USD 的候选价，完整价表及财务证明一致。没有触发正式写价。
