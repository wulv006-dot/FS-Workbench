## 订单身份、截止与修订

1. **付款父单唯一。** 主键是经站点目录核实的 `(site_id, 原商户订单号)`，保留 Admin 原生 ID 作为核对证据。商品独立保存原行 ID 或现有行签名，整单实付只计一次。同号跨站分别计数。未能证明完整归属或混合平台的订单保留在未知组。ES 哈希只用现有可信身份桥接。 [FC 看板整单归属](../fc-dashboard-category-20261106/CONTRACT.md)
2. **发货行唯一。** 能证明原生发货 ID 在来源内唯一时，用 `(来源命名空间, 原 delivery_id)` 作为稳定身份。只有站内唯一证据时沿原站内键，跨站冲突保留待核。按 `(site_id, 原商户订单号, 交易时间)` 建归属和批读索引，站点继续约束访问。来源证实站点或原单号更正时，事务内撤下旧关联并建立新关联，保留前版，防止跨站重复入账。分批发货按不同原行计成本。保存原类型、原单或父发货引用、平台／商品、购买量、赠送量、单位、采购金额、币种、交易及更正时间、撤销和可得结算状态。缺站点或父单的记录保留原类型、来源 ID 和未关联原因。全站声明须有原生范围及完整分页证据，闭日主站数据沿原主站范围。
3. **普通发货、补发和结算按源证据处理。** 当前同单快查只覆盖 `genre=1` 且可按同站、原单号关联的普通订单发货。导出可提供的销售补发单列实际类型和原关联。只有明确原单或父发货引用且经原源验证才归属，财务是否纳入依对应合同。缺字段、缺身份或冲突继续显示未知。最终结算须有独立来源证据。
4. **按固定来源声明覆盖。** 每批写入来源、契约版本、网站／游戏／类目、北京时间半开范围、原回执、源生成和取得时点、原件哈希、实际与预期的页／文件／行数。付款日和发货交易日各有截止，当日开口、晚发、缺页或状态更正分别标示。采购毛利只对已核完成且未退款的订单计算，分母为同一群体的 Admin 人民币收入，成本为同角色发货实际采购合计。完成状态使用已有客户采集回执及当时订单修订核实。匹配一笔发货或列表完整本身不足以证明整单成本。真实零成本和缺成本分开，金额小计与覆盖分母一并返回。 [同单事实合同](../fs-fc-admin-es-20261112/D2.md)
5. **增量按原证据发布。** 按回执、范围及内容哈希识别重复。私有临时区先核日期、筛选回显、行 ID、金额和完整性，成功后同一事务更新发货索引、旧值／撤销及发布指针。只在同来源同范围的完整重读中将范围内已撤回行退出现行结果，近期优先采用本次已证明完整重读的原生窗口。补抓只更新被证实的记录。无可核修订顺序的冲突隔离，待原源确认。79 个闭日档和滚动档的历史重叠中已发现 36 条采购额和 1 条发货售价存在差异，已有数据中还观察到 94 条交易日期更正字段。固定版本同时引用当期 Admin／ES、Order 批次和状态回执。晚发与更正反查受影响的付款日和交易日，只让覆盖范围内派生结果失效。固定历史、历史改价证明及在途操作继续读取其原修订。

拟在现有私有发货目录放一份 Order SQLite 索引，包含采集批次、现行发货行、受引用的修订差异及发布指针。生产任务沿原锁协调写入，在一个事务内检查前版并发布。读方在同一读取事务固定发货版本和它引用的付款发布 ID。金额采用十进制定点或经确认的币种最小单位。以稳定游戏标识映射 Admin、Order 原生 ID，各保留来源范围。D4、RS 等消费只接已核业务来源和相应权限。

## 原件、容量与故障恢复

- **XLSX 最小化留存。** 在仅原服务账户可读写的临时区领取原文件。校验文件类型、页／行、大小和压缩展开界限，再流式提取允许列，不计算工作簿公式。现场已见的收款姓名、方式和账号，以及表中可能出现的手机号、邮箱、地址与操作员身份都不进通用索引或日志。必要的原单 ID 仍留在原私有权限。发布后保留哈希、源回执和用途所需字段，只清理 FS 本次作业的本地临时原件。Order 服务端导出留存继续标未知，清理须经源端授权。已留存的 ES 原件和财务证据沿原归档合同保存。
- **容量有界。** 187 已核 79 个连续闭日（9 月 1 日至 11 月 18 日），约 22.94 MB、102,673 个独立发货 ID，全部属于 MMOEXP 主站 `genre=1`。滚动文件约 19.73 MB、67,464 行，其中本次可证明原生完整分页的只有 11 月 18 日 00:00 至 11 月 19 日 21:00:59 的 1,363 行。滚动保留旧记录需看原版本。按主站闭日样本估算 90 日约 11.7 万行、26 MB 原 JSON。全站量尚未量测，按 5,000 行／日压力情景，90 日约 45 万行。用 0.6–1.2 KB／行预算精简事实及索引约 270–540 MB，另测 WAL、修订、备份和解压峰值。磁盘增长取决于真实新增发货、修订和留存期限，同版重复查看只读。现有三个月是自动回填范围，旧的 Order 发货文件当前未纳入通用清理。拟沿该范围建热索引，冷历史按清单及引用查回。空间不足先延后新回填和压缩，保住原采集、热读和已引用证据。 [现有恢复规则](../cache-archive-retention-20261025/RESTORE.md)
- **回退和续作。** 源慢、缺页、损坏、资源不足或版本不符时保留原请求和失败状态。允许的查询可读上一确证版本，显示时点和缺口。价格继续用其原时效和失败策略。阶段性切回旧读法时保留新索引、来源文件、版本、锁、作业回执和账本。在并行验收通过后才停对应重复采集。不以 2 秒的空响应或缺数认定达标。

## 实施顺序与验收

1. 在 183 隔离环境用原档建立索引，做同 ID 更正、补发、撤销、重复和失败回放，再在 187 只读核对。按固定版本选 100、1000、5000 单核去重、跨站不串、分批守恒、已知小计及未关联。
2. 在已核的双笔 XLSX 基础上，用原授权入口扩大真实样本。分别抽核全站、主站、普通发货与销售补发，与同范围分页／原生统计核对行数、ID、金额、单位、时间和晚发。测请求到工作簿完整落地、解析和发布的各段耗时。字段或范围无法证明时沿原分页并标缺口。
3. 登录正式 FC 看板、HTTP 及原连接器，读取同一三日已付群体和采购毛利，三端核对版本、账号权限、范围、覆盖以及金额。目标为有效业务响应 P95 不超过 2 秒，冷、热、并发分别计时。渠道、分类及经营主卡分别与原口径对照，验证缺日、拒绝和旧固定版本。
4. 用相同冻结输入对照 PS、Xbox、PC 的成本和价表，比较完整财务证明。再按原授权验自然轮的请求数、来源新鲜度、写价和 Admin 回执。隔离索引试验、正式入口切换及真实自然轮分别记录。

## 本轮实测与发布

提速版已随 PR #1280 合并。原发布器已切换 FC 查询、Order 成本采集、经营首页、活动编辑器和连接器。正式浏览器“全站近三个完整日”从点击到显示真实 576 笔已核成本，连续十次为 505–679 毫秒。首次打开整页时，快查请求用时 2.231 秒，数据在导航后约 5.373 秒到达。活动编辑器从刷新到读到草稿，三次为 6.542–6.911 秒；同范围基线为 6.673–8.840 秒。首屏、鉴权和取数分别计时。连接器镜像已切换，仍待真实 OAuth 调用者从工具读回并计时。

用同一真实两行 XLSX 重复导入内存数据库，第二次没有新增或更新；随后读取 1000 次仍为两行、两个内存页。合成一笔更正只修改一行。这个试验验证重复读取不导致事实表增长，实际长期存储还要计入新业务、修订、索引、临时文件和备份。
