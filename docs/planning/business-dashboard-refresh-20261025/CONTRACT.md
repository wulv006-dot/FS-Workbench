# 经营看板展示与刷新规则

现行口径：2026-10-30 用户确认的 Order 发货统计毛利；2026-11-07 确认昨日首页与汇总优先展示。已废弃的逐单毛利主展示、旧会话端口和旧定价规则不再列入本合同。历史决定、部署及回执保留在 Git 历史和原审计记录。

## 首页与主展示

首页默认北京时间昨日完整自然日，展示 MMOEXP 主站订单数、销售额和原有预估利润，注明日期和来源。预估利润不是净利润；Order 暂不可用不隐藏已取得的 Admin 销售与订单，未知不填零。

经营看板默认八张大卡：销售额、订单数、毛利（¥）、毛利率、新客人数、复购率、新客占比、客单价。销售额和客单价为 USD，毛利为人民币；补充指标与详细来源收起。负值保留。

销售、订单、客户字段优先使用同范围 Admin 原生汇总。订单客单价（AOV）=同范围已付款销售额÷已付款订单数；零分母不计算。原生 customer_price 是付款客户均额（ARPU），不冒充订单 AOV。新客、复购率、新客占比保留原生定义和真实来源范围；人数和比例不能跨日相加。

主毛利来自 Order「统计管理→发货统计」，交货类型=订单发货，按所选交易时间、Order 游戏 ID、网站及原生类目/区服筛选。毛利（¥）=同一响应人民币销售总额−采购总额；分游戏毛利率取该行原值，全局按总毛利÷总销售额，不平均游戏或每日比例，不用 Admin 美元销售额乘率。零销售额率不适用，缺成本/缺日不补零。该口径没有排除全部退款、申诉和欺诈损失，不是净利润。

发货交易群体与 Admin 付款群体独立；每日曲线使用完整北京自然日，缺日留空。今日区间卡注明截至读取时间。主视图不自动请求 actual-profit，原逐单核算接口、覆盖证明、归档与 Hermes 按需能力保留。

FC 全部商品、平台、客户及金额档，在网站、日期、已付款池均一致时，销售/订单/客单价和发货毛利主卡直接展示原生汇总，不等待 fc-detail。细分商品、平台、客户、金额档、分类趋势和导出仍使用[商品整单归属合同](../fc-dashboard-category-20261106/CONTRACT.md)，不能借全游戏总数补细分缺项。

## 读取、归档与刷新

同一权限、网站、游戏、类目、区服、时间和口径的旧值先展示，顶部提示刷新，完成后替换。切换范围不带入旧范围值；权限拒绝清除对应数据；失败保留同范围最后成功值并显示状态，不拼接缺项冒充完整结果。

读取顺序：同合同完整区间归档 → 原生汇总缓存/查询 → 原生尚不可用时的合法每日归档派生。Admin 已可用时不因 Order 尚未返回而重读每日文件或用旧派生总数覆盖。人数、比例与不完整毛利不得通过简单日合计伪造。

现役 summary 缓存为当日 600 秒、历史 604800 秒；历史数据仍可能更正，手动更新保留原锁、冷却和任务接续。归档按查询范围、网站、游戏及来源合同隔离；定时预热须匹配页面的显式站点/发货口径，同时保留首页与其他现有调用方。归档存在不等于当前查询命中，不同站点不能借用。

归档保留规则、定时预算和原有补齐能力继续有效；不为提速降低 FC P0、Order/Admin 依赖、分类查询、履约实时状态或自动化频率。报告、原始快照、订单账本及 UNKNOWN 回执保留原版本，新读取形成新版本。

## RS 筛选与当前积压

网站与商品类目可见，区服置于“更多筛选”；保留键盘、焦点、深浅色及窄屏交互。当前积压独立于历史付款区间，使用现有独立 5 分钟缓存，不冻结为历史状态。

问题单只计经原生明细核实的 status=91、已支付 RS 订单，按订单 ID 去重。待支付须核实 pay_status=0 及真实未付款/待支付状态，不能把已支付待交付数量替代。完整分页、游戏/网站与状态验证后才发布数值，失败/未知不补零；旧筛选冲突记录不是已恢复来源的证明。

## 执行与验收

沿当前 Admin 直接 API、Order 共享会话与各模块现役入口，不恢复退役 OCR/会话回退。价格、成本、权限、自动计划与原 ID/CAS/UNKNOWN 保护保持，定价规则只见其现行合同。

发布使用原 publisher、准确目标、CAS、备份、原锁与读回。代码、CI、合并、上线、真实入口和自然周期分别记录；本合同不冒充部署证明。
