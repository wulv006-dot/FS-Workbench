# 活动专属码付款收入

用户确认以活动专属折扣码归因收入；不等待逐访客付款事件回传。本次只读 Admin 8912，复用原 campaign backend 与 FS 登录保护，不修改订单、优惠码、活动配置、权限或定时器。

## 口径

- 站点266，十二个专属码及其原 native ID 固定绑定当前万圣节活动；排除临时共享码 LOH8/d4e 和旧 WoW 码。按码忽略大小写、去外围空白；读取原码目录核唯一原ID，不以推广人UID匹配。
- 页面日期仍为UTC付款日期，读取端精确换算为 Admin 北京时间，最长31日拆成不超过28日的窗口；完整分页、范围和重复订单冲突校验后才显示。
- 原 pay_status=1/2 都保留付款观察，2单独列含退款订单；0排除，未知状态拒绝。按订单号去重，不按商品行或事件重复计数。
- 展示原 Admin `amount_usd_format` 付款订单美元口径和 `pay_money_format2` 后台付款显示金额，不再扣同一折扣，不自行换汇。混合购物车金额是活动码关联整单金额，不是活动商品分摊收入。
- 退款金额、退款后净收入、商品分摊、逐访客转化率保持未知；不根据当前退款状态伪造退款金额。
- 收入独立于PostHog、统计授权及浏览器事件。只按日期和游戏筛选，不随访客设备/渠道改变；测试模式不读取正式订单。原访客与加购统计保留。
- 600秒内存缓存，同窗口并发合并；参数/权限/来源错误不缓存为零，界面显示未完成。更新分析以refresh=1强制更新，自动检查仍按现有60秒检查、600秒到期读源，无新增timer。

## 原币与付款显示币种（2026-11-02用户纠正）

沿[业务基准](../fs-business-baseline-20261021/BUSINESS-BASELINE.md)区分订单USD金额、USD折扣和实际支付原币。`currency_code`是原币字段，`pay_money_format2`必须按数组自身的币种与金额成对读取；后台可以将付款金额折算为USD显示，不能要求两个币种代码相同，更不能将USD显示值贴成PLN/BRL实付金额。本模块保留原币代码和显示币种各自的严格格式校验，按显示币种分列；不计算汇率、不把显示金额称为原币实付，不改变主卡既有`amount_usd_format`口径。退款后净收入仍未核实。

本次已核原00/08/16北京时间计划每日正常执行，失败原因是错误的跨字段币种相等判断；修复后沿原锁、有限重试、固定快照槽和日期/身份隔离刷新。不新增每日任务或历史全量副本，也不降低原有自动刷新能力。发布后先实际读回，再观察后续自然计划；一次手动刷新不冒充自然周期。

现场另核HWAION15仍为原native ID6033、同码目录无额外ID，但适用站点已为全站0。既有绑定原ID的全站配置可以用于读取站点266的历史活动订单；码目录仍只允许固定12个原ID、原码值和站点0/266，新增同码ID或其他站点配置继续拦截。订单查询和逐行核对仍严格site_id=266。此兼容只影响报表读取，不修改优惠码适用范围或纳入其他网站订单。
