# FC27活动页周更运营台

## 目标与本次授权

在 FS 主站活动区管理 Player Trio、Weekly Scout、SBC Core 每周选品、素材文案、真实商品映射、优惠校验、审批与复查。用户于 2026-11-09 授权设计、实现与功能验收，可分派子代理；真实发布、优惠券写入、定时启用和回退必须另等人工批准。当前修正尚待部署；此前已批准部署与启用计划的记录单独保留，不重置原计划。不发送社区消息、不提交订单或支付。

同日最新要求见WEEKLY-RULES.md：每周日北京时间12:00自动更新，保留手动触发及管理台自动/手动读取状态；SBC取最新9个SBC Players，Sol各配2个普通Player且全局18人去重，每核心共享2首选＋16备选；Scout按主站Popular推荐优先顺序过滤普通版后取前三，Trio从Newest标签的普通Player完整候选池，结合市场热度、公开社媒与垂类资料由Sol选择三人。Hermes获准使用用户身份，验收允许真实模型进行页面商品更新测试。人工请求仍验证当前FS会话，自动执行使用该会话授予的可撤销限定委派，不固定冒用owner或保存Cookie。生产代码部署、活动对外发布、券写、定时启用和回退仍遵守原审批边界。

## 实现选择

沿用 `releases/fs-dashboard/campaign-analytics-20261023/app/analytics/` 的现有 Node 服务、FS 登录/管理员/CSRF、活动中心和版本记录。增加 `weekly.html` 及同服务 `api/weekly`，周更计划存于活动中心目录。没有另建服务、数据库、账户或模型后台。素材、文案、商品配置仍由现有 `products.html` 编辑；发布仍由原活动中心及原 publisher 执行。

独立后台会重复权限、商品与回执，纯静态看板无法持久保存周次及人工审核，因此采用原后台内的周更记录扩展。

## 数据与证据

- 周次键：ISO 周次 + page_id，各页独立，允许同周分别审批。沿用 `fc27-trio`、`fc27-weekly`、`fc27-sbc`，不新建消费者页面身份。
- 当前商品、页面绑定、活动 revision、发布指针来自现有 center；周更账本只保存工作单、审核、证据引用、辅助建议及操作记录，不复制出第二份权威商品配置。
- 写入使用 revision/CAS 与 UUID operation_id；同 ID 同请求返回原结果，同 ID 不同内容拒绝。未知结果先原 ID 核对，不新 ID 重放。
- 规划、代码实现、测试可用、生产验证、部署读回、自然周更、待核实、证据缺口分开显示。人工填写的证据仅为报告/待核，不自动成为可信生产证明。
- 商品身份按站点266、游戏1327、模型/商品/SKU、平台与区服核对；有目录身份不代表可售。价格需金额、单位、币种与有效期；券需范围、平台、时间、金额和实际应用证据。缺项保持未知，不填零、不从旧万圣节结论推定本页成功。
- 审批绑定具体活动版本与动作，版本变化需重新核对。批准只代表人工决定，不代表已派发、已发布或自然运行。

## Hermes 与 SBC

Hermes 是独立开关的候选生成及任务编排层，可在已批准委派内定时生成草稿，不自行启用计划、对外发布、写券或回退。SBC任务明确请求 `gpt-6.1-sol`，不改其他 Hermes/周报/经营/定价模型路由。新生成只经顶部统一取品与草稿入口，自动冻结当期目录、来源及配置revision；旧独立SBC生成表单已删除，历史任务仅保留读取与原ID核对。输出只能引用输入内真实商品；平台不符、身份歧义、可售/价格未知列缺口，不将模型建议当验证。

活动服务通过当前请求的登录会话调用现役8931宿主的 campaign_recommendation_v1 入口；宿主重新验证原FS管理员会话，沿既有Hermes任务、Grants、Proxy、模型额度及用量账本调用Sol。独立campaign任务不借用报告或定价身份，不授予业务工具，不新增服务、凭据或模型配置。异步请求先保存原ID，查询只核对原任务，断网或未知不自动重派。

新取品流程复用原backend-read与真实目录身份：动态读取SBC Players、Player及Popular/Newest标签，保存排序与分页覆盖，不把一页搜索当全库覆盖。素材、商品卡与真实映射优先参考万圣节FC专区的native_catalog/model-options链。原SBC核心/两搭档下拉及多备选直接复用，实际写入fc_layout.routes；Trio按最新规则允许跨卡系列。来源、可售或价格尚未核实时保留缺口，不把模型导入预览当可售。

自动和手动共用prepare→公开证据→Sol→原center草稿流程；原center保留单一写入者，宿主通过固定本地桥调用，不新增网络后台。批准定时后沿现有Hermes宿主tick运行；辅助关闭和授权撤销仍能阻止新模型/草稿写入。自然周更只有真实计划的一轮运行才能验收，手动测试不替代。原发布、优惠券和结账链不由该草稿流程自动执行。

## 实施与验收

1. 后端：周次持久化、CAS/原ID、审批与证据、当前来源校验；单测覆盖冲突、未知、伪证据、过期和故障隔离。
2. 页面：三页概览、周次筛选/对比、工作单、检查、审批、异常、Hermes、效果入口；复用FS主题，覆盖加载/空/失败/只读、窄屏与键盘。
3. SBC：复用现有输入契约，严格候选过滤，provider失败不破坏记录；测试显式使用替身。
4. 总控：审查调用链，执行受影响模块既有测试，记录可复现结果及缺项；准备具体发布清单供人工审批。
