# FC27活动页周更运营台

## 目标与本次授权

在 FS 主站活动区管理 Player Trio、Weekly Scout、SBC Core 每周选品、素材文案、真实商品映射、优惠校验、审批与复查。用户于 2026-11-09 授权设计、实现与功能验收，可分派子代理；真实发布、优惠券写入、定时启用和回退必须另等人工批准。本批不修改生产配置、不发送社区消息、不提交订单或支付。

## 实现选择

沿用 `releases/fs-dashboard/campaign-analytics-20261023/app/analytics/` 的现有 Node 服务、FS 登录/管理员/CSRF、活动中心和版本记录。增加 `weekly.html` 及同服务 `api/weekly`，周更计划存于活动中心目录。没有另建服务、数据库、账户或模型后台。素材、文案、商品配置仍由现有 `products.html` 编辑；发布仍由原活动中心及原 publisher 执行。

独立后台会重复权限、商品与回执，纯静态看板无法持久保存周次及人工审核，因此采用原后台内的周更记录扩展。

## 数据与证据

- 周次键：ISO 周次 + page_id，各页独立，允许同周分别审批。沿用 `fc27-trio`、`fc27-weekly`、`fc27-sbc`，不新建消费者页面身份。
- 当前商品、页面绑定、活动 revision、发布指针来自现有 center；周更账本只保存工作单、审核、证据引用、辅助建议及操作记录，不复制出第二份权威商品配置。
- 写入使用 revision/CAS 与 UUID operation_id；同 ID 同请求返回原结果，同 ID 不同内容拒绝。未知结果先原 ID 核对，不新 ID 重放。
- 规划、代码实现、测试可用、生产验证、部署读回、自然周更、待核实、证据缺口分开显示。人工填写的证据仅为报告/待核，不自动成为可信生产证明。
- 商品身份按站点266、游戏1327、模型/商品/SKU、平台与区服核对；有目录身份不代表可售。价格需金额、单位、币种与有效期；券需范围、平台、时间、金额和实际应用证据。缺项保持未知，不填零、不从旧万圣节结论推定本页成功。
- 审批绑定具体活动版本与动作，版本变化需重新核对。批准只代表人工决定，不代表已派发、已发布或自然运行。

## Hermes 与 SBC

Hermes 是独立开关的候选生成及任务编排层，不拥有发布/券写/开定时/回退权限。SBC任务明确请求 `gpt-6.1-sol`，不改其他 Hermes/周报/经营/定价模型路由。每期输入应携带游戏更新/SBC来源、本期ID、当前目录与配置revision，输出只能引用输入内真实商品；平台不符、身份歧义、可售/价格未知列缺口，不将模型建议当验证。

保留注入真实 provider、测试记录、发布回执、差异及自然运行结果的接口。未配置 provider 明确不可用，测试替身不冒充真实模型调用。定时启用待批准，手动候选、人工配置和原页面不依赖 Hermes 在线。SBC身份匹配与阵容/关联推荐是不同步骤，不把现有身份解析说成已有完整SBC推荐。

## 实施与验收

1. 后端：周次持久化、CAS/原ID、审批与证据、当前来源校验；单测覆盖冲突、未知、伪证据、过期和故障隔离。
2. 页面：三页概览、周次筛选/对比、工作单、检查、审批、异常、Hermes、效果入口；复用FS主题，覆盖加载/空/失败/只读、窄屏与键盘。
3. SBC：复用现有输入契约，严格候选过滤，provider失败不破坏记录；测试显式使用替身。
4. 总控：审查调用链，执行受影响模块既有测试，记录可复现结果及缺项；准备具体发布清单供人工审批。

## 发布与恢复边界

本批开发基线为 `origin/main` 的 `2b0f735`，独立分支 `codex/fc27-weekly-console-20261109`。主目录的 Hermes 分支不改。工作树没有 `.codegraph/`，不自行建立索引。当前 main 不含主目录提及的 graphify-scope.json，不凭历史文件新建全仓图范围。

批准后先读取实际生产文件/版本/CAS，再由原publisher准备精确载荷，不覆盖运行数据、旧账本、未知操作或其他页面。周更数据保留，回退仅回本批代码并另经批准；原消费者结账文件本批不改。自然周更只有在真实计划启用后观察完整一轮才能验收。
