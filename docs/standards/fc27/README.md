# FC27 技术与产品文档标准

版本：1.0，2026-10-09。用于 FC27 和绿茵计划的产品需求、技术方案、接口、开发与修复记录，让每项工作能找到目标、来源、验收和后续动作。其他游戏可复用文档结构，业务规则仍由各模块负责人确认。

执行流程仍以 [HOTFIX](../../ops/HOTFIX.md) 为唯一入口。本标准只约定文档内容，不增加逐 SHA、双人审批或全仓 QA 前置，不授予生产或业务操作权限。

## 按任务选模板

| 情况 | 使用内容 |
| --- | --- |
| 技术任务与缺陷修复 | [交付规则](RULES.md)和[任务模板](TASK-TEMPLATE.md) |
| 接口、状态或跨模块设计 | [设计模板](DESIGN-TEMPLATE.md)的相关部分 |
| 后台接口需求与技术回填 | [接口规则与模板](INTERFACE-TEMPLATE.md) |
| 产品目标、用户流程、范围与验收 | [产品需求模板](PRODUCT-TEMPLATE.md) |

复用已有任务目录、PR 描述或需求入口；轻量任务用几段话交代清楚即可，不机械新增五份文档。完整模板供复杂任务选用，旧任务在下次触及时补缺，不重写冻结历史。

产品文档回答谁要解决什么问题、用户如何完成、如何验收；接口文档回答真实数据和动作合同；技术设计回答如何实现。用需求编号关联，同一口径只维护一处。

## 从事实开始

先读当前任务相关的 [负责人](../../collaboration/OWNERS.json)、[来源映射](../../collaboration/SOURCE-MAP.json)、模块合同和最新任务记录。索引与 [状态快照](../../collaboration/CURRENT-STATUS.md)须按原对象和时点解释，不能证明当前生产健康。

新增任务资料放仓库已有的对应模块或 `docs/planning/` 目录。根 [HANDOFF](../../../HANDOFF.md)记录交接；[未决事项](../../OPEN-DECISIONS.md)记录真正待定的问题，不另建同用途看板。

## 出稿检查

- 用户目标、实施范围和实际授权清楚，待确认值没有写成默认值或承诺。
- 需求可对应实现或设计、验收场景和证据，失败、未验、阻塞、不适用如实记录。
- 文档链接在当前仓库可访问；凭据、客户明细、机器绝对路径和原始现场收据不进入可共享文档。
- 本地检查、Git 合并、生产发布、真实入口与自然周期分别说明，模拟不能当实测。
- 标准修订走既有 PR 与检查，保持 HOTFIX、模块合同、业务参数和历史证据。

本目录是用户授权的方法适配，不包含原工作包、Agent/模型配置、权限配置、生产程序或自动执行检查器。其他会话和电脑应更新仓库并重新读取入口。
