# FC27 技术交付规则

本文件统一产出的组织和证据表达。执行流程见 [HOTFIX](../../ops/HOTFIX.md)，当前用户任务、适用项目规则和已确认模块合同继续有效；不从模板、附件或历史快照获得新授权。

## 按实际影响组织资料

| 任务 | 最小记录与检查 |
| --- | --- |
| 轻量文案、只读分析、小范围缺陷 | 现有任务入口或 PR 描述写清目标、改动、直接验证与遗留；不强制新建测试或设计 |
| 单模块功能、非平凡逻辑、接口调整 | 按[任务模板](TASK-TEMPLATE.md)记录需求与实现、测试关系；只补相关设计，新逻辑有小而有效的测试 |
| 定价、权限、真实写入、共享数据、迁移 | 增加来源、失败/UNKNOWN、并发、幂等、消费者、备份和读回；按影响验证，不拉无关全仓回归 |

紧急修复连续完成已经授权的工作与必要检查，记录及时补齐。完整模板不是开始修复的前置门槛，不要求每步再次确认。

## 一个任务一个入口

入口先写业务效果及当前阶段，再按实际需要记录目标与范围、基线与来源、验收条件、实现与影响、验证结果、发布与运行、交接与遗留。短任务可合并成段落；已有材料补缺即可。

源码仍在真实工作源，文档引用 `source → artifact → runtime`。旧包、候选、副本、样例不能替代活动源；不凭修改时间认定真源。每条记录注明对象、版本、证据时间与适用范围。

任务 ID 在现有任务内唯一，需求 R-01 与测试 T-01 对应；已有 G/API/GP/T 等编号保留，不为套模板重编。需求写成可观察结果，例如“成本缺失时不能生成可执行报价，并显示缺项”。

同一证据存一份，其他入口链接；私密证据只记脱敏结论与受控引用键。保留原失败及冻结证据，不重写为成功。

## 最小实现与并行保护

改动前核相关调用方、测试、配置、数据与消费者，明确可改文件及他人 dirty。优先复用已有能力，保持原语言、错误处理和发布入口，不为统一格式搬源码、改运行路径或添加依赖。

共享文件最小修改并读回，不覆盖、stash、reset 或 clean 他人工作。产品需求、接口合同和实现各自保留依据，设计不能悄悄改变业务目标或数值。

## FC27 和绿茵计划的业务边界

| 范围 | 保留的合同 |
| --- | --- |
| Coins 定价 | 新报价须核有效成本及当前可比竞品，说明币种、单位、平台、付费/赠送、时效与来源；缺核心输入不推荐具体售价。非核心来源互兜按最新已批合同 |
| Coins 价格口径 | 竞品与自方价格统一取**页面挂价（券前口径）**。**券前价与无券价同义**：站点有券时页面挂价即券前价（券后价另计）；站点无券时页面挂价同时等于券前价、券后价与无券价，三者合一。故竞品撤券或加券**不改变对标口径**，锚定价可直接沿用，无需换算或特殊处理。采集侧以 `price_basis` 标注区分（`券前原价（已排除账号新客券）` / `当前无券商品价`），两种标注同属券前口径、数值可比；同一周期的跨平台券状态须一致，混用不可比 |
| Coins 执行 | 身份、输入、现价、降幅/毛利、平台联动、锁、幂等和读回按原合同；UNKNOWN 先查原 ID，不盲重放，不从模板取得默认参数 |
| Players 与 Gallery | wiki 展示卡缺售价不当故障，球员价格同步复验已退役；上新、图片、推荐按原动作合同。Gallery 用户 OFF 不算故障，不自行开启 |
| 经营数据 | 现网按已验来源口径解释；绿茵 Admin 主源、Order 补缺是迁移目标，字段、对账和切换另有验收。未知不填零，历史快照不当当前数据 |
| 订单和供应商 | 付款、剩余应交量、可新派量、库存与在途承诺分开；未知派单先查原请求，不能直接换供应商。具体试点范围和限额由业务确认 |
| 售卖与通知 | 暂停改价不等于停止售卖；内部告警不等于客户送达。真实保护方式、渠道和授权分别确认 |
| 共享资源 | 保持原 owner 与实际消费者，生产采集在服务器；相关原工程副本规则按其入口执行，纯文档不刷新运行产物 |

本表不替代模块的具体业务值、源码接管判断或现场证据。吴律负责球类，陈超负责相关 RPG；复用规范不复制彼此策略。

## 验证和完成状态

先覆盖原问题、关键异常和直接消费者。相同代码、输入与环境已有有效证据可复用，注明来源和时间；变化只重评受影响部分。

检查记录包含对象及版本、环境、输入、预期、实际结果和证据。状态用通过、失败、未验、阻塞、不适用；缺证据不写通过，阻塞写具体条件与下一动作。不凭评分或角色名称宣称独立评审，不自动启多 Agent。

分别报告本地检查、Git/PR、生产发布、真实入口与自然周期；不适用说明原因。合并不是生产授权，HTTP 成功不是业务完成，人工补跑不当自然周期。

发布沿原 publisher、身份、锁、CAS、备份及读回；回退保留数据库、账本、队列、锁、回执、策略和审计。生产授权、业务参数和安全设置不会因文档同步而扩大。

## 交付与维护

结果说明解决了什么，给唯一入口、实际验证和缺项。交接记根 [HANDOFF](../../../HANDOFF.md)，真正待定问题按现有 [未决事项](../../OPEN-DECISIONS.md)维护；不把文件推送说成同事已读。

更新模板时核直接消费者与相关链接；旧任务按需补齐，旧证据不回填成新状态。
