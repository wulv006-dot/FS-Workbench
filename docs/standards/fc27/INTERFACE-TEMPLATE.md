# 接口文档规则与模板

用于需求提出、后台能力回填和联调验收。需求编号不等于真实端点，历史调用和合成样例不证明当前支持。执行与权限仍按 [HOTFIX](../../ops/HOTFIX.md)及原模块合同。

## 编写规则

1. 分开需求、正式协议和历史线索。真实 host、path、method、版本、scope、开发人、交付日由提供方确认；未知写待确认。
2. 字段说明类型、必填或出现条件、默认、枚举、单位、精度、空值、权威来源和版本。模型、SKU、订单行、价行分开；不猜 ID 映射。
3. 金额与数量精确表达，写清币种、付费与赠送、量纲和舍入；时间说明时区、业务含义及区间边界。既有已确认口径优先，不凭模板更改。
4. 区分明确 0、未提供、null、不适用、源不可用。故障、权限不足或空列表不能静默触发另一后台整份替代；数据迁移目标与现网分别标记。
5. 按实际副作用划分读写；说明分页快照、排序、完整性、增量水位、删除、迟到、重放和过期恢复。
6. 写动作说明预览、版本、幂等作用域、内容摘要、持久回执、真实执行方和原子边界。受理、实际写入、同步和公开生效分别取证。
7. 批量给逐项稳定身份及原子性。成功不重放，UNKNOWN 查原 ID；确定无副作用的失败项只有在正式合同允许且新计划有效时才能重提。
8. 订单“未履约”不等于“可新派”。在途承诺、订单预留、供应库存分别说明，提交时服务端原子核量；撤单未确认不提前释放或改派。
9. 错误需同时说明 HTTP/业务码、确定性、副作用和下一动作。限流、5xx、网络断开不直接证明写入未发生；性能、配额和保留期不填虚构承诺。
10. 字段、类型、单位、枚举、状态、默认值变化都核消费者；新增枚举也可能不兼容。写清版本、生效/废弃计划和回退。
11. 真实接口、合法环境和业务范围签收分别记录。文档检查、模拟、真实联调与生产验收不可混用。
