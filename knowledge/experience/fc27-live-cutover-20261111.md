# Evolutions：保留历史未知结果，凭当前实态恢复原自动任务

记录日：2026-11-11。层级：experience；状态：已验证的条件性工程经验，不是新的业务规则或经营赢家结论。本条是该案例的唯一知识原文；现行业务规则仍从 current 条目读取。本条入库与发布、模型实际使用分别验收。

## 结论与适用场景

已结束的历史写入结果未知，不必永久阻止后续业务；但解除当前阻断需要独立、可追溯的真实商品现态，不能靠理论报价、现价碰巧相同或重发旧目标。本案例在用户明确授权下，将原 UNKNOWN 结果保留，另记录一次成功刷新取得的 Admin 商品现态覆盖，随后原自动任务自然恢复。

适用于原任务已经终态、没有在途写入、商品身份可核、正式来源可读的历史阻断。它不授权清除所有 UNKNOWN，也不授权绕过其他模块的锁、权限或写前校验。新的未知写入仍独立阻断。

## 已发生的事实

2026-11-10，Evolutions 旧 Admin 客户端的真实刷新返回 `AdminAuthRequired`，不是有效预览。适配使用已部署的正式 Admin Session，保留原 Order 取价、平台身份、完整商品字段、配置 CAS、唯一 writer 和单次写请求保护；没有新增身份或改用旧登录回退。

另有历史 operation `36e7fdf4-5479-4273-91d7-44480263cd55-186204551`，原 job 已终态，但账本没有明确写入成功回执。用户要求已被后续有效现态覆盖的历史未知不再卡当前，故本轮采用以下有限处理：

- 成功 refresh 取得真实 Admin 目录，核对原商品 id、model、平台、site 等身份及现价、单位价、折扣，并记录真实读取起止时间；原 job 完成时间须早于本次读取。
- 原 operation 只追加 `current_state_coverage`，绑定新 refresh 和来源；原 unknown、目标、写前内容和原 job 回执保留，不改写为旧 POST 成功。
- 缺商品、身份不符、原任务在途、金额缺失或读取不新鲜时，仍保留当前阻断。覆盖一经有效成立，作为历史事实保留，重启或经过一小时不会让旧阻断复活；未来每次新写仍须重新取数并执行原校验。

## 为什么保留 36 项跳过

26 个模型各有三个平台商品；16 个模型启用、10 个禁用，对应 48 个启用商品和 30 个禁用商品。目录包含禁用品是原完整读取合同，执行阶段跳过，不是多采或重复写入。

另两个启用模型 `45528449`（Ice Cold）、`45528451`（Blue Fire）在 Admin 列表及逐条编辑读取中 `unit` 都为空字符串，且没有单品金币覆盖，合计六个商品未计算。空值不等于 0，也不能推断免费；模型已有售价、buy_price 或其它非金币字段不能代替金币数量。当前消费层按原合同读取 Admin unit，没有证据表明本次 Session 适配丢失有效值。建模时原 Futbin 载荷未取得，因此不能归因为上游字段变更。

本轮没有补金额、启用禁用品或为了全绿捏造金币数。后续若核实数量，可经原模型字段或现有单品配置更正；该后续不属于这次验收事实。

## 比较过的处理方式

| 方式 | 本案例的判断 |
| --- | --- |
| 所有历史 UNKNOWN 永久阻断 | 原任务已结束且可以取得后续实态时，会把历史证据不足变成当前自动化不可用；与用户本轮明确目标不符。 |
| 重放原目标或更换业务请求 ID | 旧 POST 是否成功未知，可能重复执行；不采用。 |
| 仅凭现价相同把旧记录记成功 | 不能证明原请求成功，且旧 reconcile 还会写账本、清缓存；本轮未调用。 |
| 保留旧结果，另建本次真实现态覆盖 | 既保留不确定性，又在严格身份和终态条件下恢复当前任务；本案例实际采用并验收。 |

若原任务仍在途、商品身份发生变化、正式来源不可用、无法证明读取发生在原任务结束之后，或出现新的 UNKNOWN，本经验不能用于解除阻断。若未来后台字段或执行契约变化，应按新事实重验，不能照抄本条的价格、时间或 ID。

## 同轮反例：文档发布不应抢正常成本读取的锁

本轮另一次纯知识同步，旧适配器两次因 `collector.lock` 忙而在任何目标写入前退出。原进程当时正在正常成本读取；“锁忙”不证明采集故障，也不构成停用或重启业务服务的理由。

[PR #981](https://github.com/wulv006-dot/FS-Workbench/pull/981) 的原 publisher 适配修复，仅对精确知识载荷复用既有 reader-entry 与任务 DB 发布协议，保留正常成本读取和原保护范围，没有新增发布器或服务重启。真实发布后读回 **38 个目标、83 个保护项、8 条既有知识选择路由**，原 `fc.read_skill` 入口读取的规则与确切版本相符。同步前后 `fs-business-range` PID 9350、`fs-hermes-fc` PID 9220 保持，原业务进程未因文档同步重启。

这个结果证明文件、选择器和真实读取入口可用，不证明模型已在自然任务里采用这些知识，也不证明经营收益。它只适用于原 publisher 识别并校验过的知识范围；不能据此取消业务写入锁或扩大普通代码发布的免重启范围。
