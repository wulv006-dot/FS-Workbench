# 用户生命周期与 FC27 客户维护

## 用户分析 v4

- 使用 MMOEXP 主站 266 的有效订单投影，按已核 Admin 主邮箱识别客户。站内首单从覆盖起点 2026-01-01 判断，首单上的 ES 标记决定新客、老客或待核。老客批次按覆盖期首次观测月份归属，待核只进入全部客户与待核统计。
- `game=all` 使用全部游戏；`game=series:FC` 合并 FC26、FC27；单款用具体项目 ID。确定批次时先找站内首单，再判断是否属于所选游戏范围。复购使用同范围、距首单至少 24 小时的不同有效订单。观察窗 `N` 不含首单加 `N` 日的端点。只有时间已满且覆盖完整的客户进入分母，观察中和覆盖缺口分别列出。
- `cohort_type` 选批次人群（new、old、all、compare）；`customer_type` 仅过滤客户阶段。指定游戏以该游戏末购计算阶段，FC 系列按现行配置使用 FC27 阈值。数据截止和配置版本以响应为准。
- 同范围复核使用 `users.summary` 或 `analytics.user_section` 的 `snapshot_id`，Hermes 用 `fs_query_user_analytics` 读取同合同。返回 202 时只带原 `query_id` 续查，分节接口另带 `section`。旧快照按原版本追溯，v4 入口会明确拒绝旧版本 ID。名单和导出受各入口原权限约束。
- 默认窗口为 30、90、180 天，月份到上一个完整月。PR #1352 的预计算和磁盘归档随原发布截止更新，历史补正、证据变化与临时缺失按原数据重新核算。生产是否支持新筛选与归档，以运行版本和实际读回为准。

## FC27 阶段维护

- 维护范围为 FC27（1327）。有效消费按已核 FC27 订单的累计 USD 金额分档，阶段按该游戏末购和最近完整观察日计算；配置版本、缺口和人工展示档位随原响应保留。
- 「处理与查看 → 分组名单」可按价值档、阶段及新老客选择整组。维护管理员可查看邮箱、人数和页码；FS 连接器方法 `customer_tracking.stage_groups` 使用同三个分组字段与 `next_offset`。阶段项目跟进、原客户观察，以及券的复核和执行各走适用合同。

业务公式、页面和消费入口见[项目合同](../../docs/planning/users-cohort-maintenance-20261124/README.md)。

## FC27 客户追踪候选：Buyer ID 与 ES 金额

2026-11-10 吴律确认以下候选筛选口径；软件发布、历史重扫和自然周期分别按真实回执验收。只适用于原 FC27、主站 266、Coins/Items 客户追踪池，不改用户分析主键、其他游戏或客户价值报告。

- 复用所选北京时间日期已有的完整 ES 导出。候选订单仍须符合当前配置的商品、新老客标记、折扣严格小于上限；**订单金额严格大于下限以 ES 原表“订单金额（美元）”决定**，缺失或无效金额不能补零。实付金额和币种另存，不混为美元订单额。
- 有效 Buyer ID 在主站范围内作为候选分组键；同日多笔合格订单且 Admin 邮箱相同，只显示一位候选客户和一笔代表订单。日期范围名单对同 Buyer ID、同邮箱再去重。Buyer ID 缺失、无效或历史文件未提供时，继续按订单号和 Admin 邮箱处理，不丢旧候选。跨站唯一性未经核实，不跨站合并；UID=0 不代表无客户身份，也不借 UID 合并不同 Buyer ID。
- ES Buyer ID 是私密的稳定关联标识，不作公开输出。开发通过用户说明其与下单邮箱存在固定哈希映射；这不等于可以从 ID 反推出邮箱。邮箱仍由原受控 Admin 查询取得。同次扫描若核到同一 Buyer ID 对应不同邮箱，保留冲突证据，不自动归为一人或加入追踪；只抽查一笔代表订单时无法证明该 Buyer ID 所有订单邮箱一致。
- 每个有效 Buyer ID 先选一笔符合条件的代表订单；无 Buyer ID 则按原订单号。以订单号小批量向 Admin 核实原订单、游戏、主站、付款状态、付款日和邮箱；代表订单未查到时尝试该 Buyer ID 的下一笔。返回行逐笔精确匹配。Admin 与 ES 金额不一致时，候选条件仍按本条 ES 金额判断，并显示差异供核对。后台忽略订单筛选时回到原完整日读取；失败、缺页、拒权不当作空客户或已完成扫描。
- 不新增原始订单文件或整库副本，复用现有私有 ES 归档、容量预留和发布后清理。按日处理，完整文件集与哈希核验、原任务编号和 UNKNOWN 恢复保护不变。
- 加入追踪后的首次付款日仍取同邮箱 Admin 主站跨游戏完整已付款历史；7/14/30 阶段、每日更新、人工停止和手动全池报告规则不变。已存候选、旧快照及订单记录不因新口径被静默改写；需要新结果须用新的原扫描回执核验。

实现范围及验证见 [2026-11-10 改造记录](../../docs/planning/customer-buyer-tracking-20261110/IMPLEMENTATION.md)。
