# 经营报告创作方法 · 1.5.11（经营者判断优先）

## 所有报告的核心逻辑 · 用户2026-10-25明确纠正（优先适用）

报告首先服务读者判断和行动。先给全局主判断、问题主次、价值取舍与建议方向，再用关键事实和直观图表解释理由，最后落到行动与复查。不是越深入、越长或越多限制说明就越好。本规则适用于日报、周报、月报、专题、定价研究及其他报告，不只FC。

- 有依据就承担判断：现有优先数据方向一致、影响量级与排序足够清楚时，明确说“我判断/更可能/建议优先”。工作判断不等同学术因果证明；允许方向性推断和价值性建议，不把所有事项都退回待验证。
- 用重要性决定细查：只有差异可能反转主次、行动方向、关键金额量级或造成实质误导，才继续补证；小口径差异、未完全核平、归因未成熟或缺精确单价，不自动取消有效趋势、风险、结构与优先级判断。必要范围限定一句即可，细节进附录。
- 用人的语言组织：判断→理由→业务意义→下一步自然连起来。标题讲业务，文字解释图的含义，少复读数字；不机械给每项套反证/缺口矩阵，不反复写“不能证明/不能排除”把自己的结论撤空。
- 可视化按需使用：不需要图表或HTML的短答复/分析直接用文字，不凑图造页；核心逻辑不变。需要可视化时认真打磨首屏、图表、标签、对照、单位、留白、字号与切换反馈。重点默认可见，原值/计算/技术限制按需展开。图表、手机阅读、目录和主题实际看，不以HTML结构通过代替好读。
- 内部全维、前台重点；行动给推荐主次、理由与主责，不能只留“再查清单”。建议不冒充已执行。数据不编造，重大对象/币种错误仍改，财务公式、实际价格/预算/权限及UNKNOWN保护保持；用户明确要审计/论文时再按相应目的深入。
- 23号用户指定报告是阅读和可视化参照，不继承历史数字。24号旧补报已被用户否定，不把它当认可范本。后续审核同样先看决策价值、逻辑通俗，再查视觉交互与真正影响方向的数据问题。

历史逐字段条款、纠错示例和教材按上述重要性用于内部取证，不机械扩成报告前台或阻止方向判断。完整例解见 references/operator-report-core-20261025.md。


本版来自用户2026-10-17的明确纠正：旧产出的质量不合格，报告方法重新建立。只替换报告创作方法，不删除业务事实、历史决策、来源合同、失败记录，也不扩大业务写入权限。报告方法的唯一正文是本技能及随附 METHOD.md；旧报告技能改为指向本技能的简短入口，不再同时提供互相冲突的写法。

## When to Use

- 需要经营日报、周报、月报、区间复盘、专项分析或简短经营问题解读。
- 用户反馈旧报告质量、理解或排版问题，需要重新分析或调整呈现。
- 需要把真实证据转为易读图表、关键分析、建议或简洁回答，具体设计自主。

管理层报告每个重点先用一至两句话解释判断、业务意义与有线索的推断，图表提供依据，行动写清建议负责人/协作方、交付与验收及反证。精简重复报数和推导，不删成纯图表；全业务在内部检查，无结论或重要线索的模块不硬塞。用户认可的报告优先局部调整视角和行动，不按图表数、字数减少比例证明质量；具体视觉与正常自动化保持自主。

## 按问题选择方法与输出

1. 历史examples只在有助于本次问题时按需参考，不是每次必读的前置条件，也不继承其数据或旧结论。用户2026-10-18已明确放开报告视觉：配色、字体、布局、图表及阅读顺序自主，FS只作宏观建议；旧“必须复刻/必须使用FS样式”的要求被替代。此例外仅限报告HTML。
2. 按本次问题采用METHOD.md和ACCEPTANCE.md的适用要求；复杂报告参考读者视角、场景覆盖、图表密度与互动指南，简短问答不套页面施工流程。历史施工脚本仅供阅读，不执行其旧路径或旧数据。assets中的FS样式可作参考，不是报告必选依赖。计算说明见references/example-notes.md。
3. 为本次报告建一份经过核对的事实对象：期间、对照期、采集时间、游戏、来源、原值、单位、分母和缺项。正文、卡片、图表、原值表都由这一份对象生成。历史示例只教方法，不能成为未来期间的事实。
4. 按问题明确本期情况、值得处理的事项和可行动方向，再选择阅读顺序；不固定句数、问题数、动作数或章节，简单问题可直接回答。
5. 简单问题直接返回简洁文本；复杂分析按需选择完整 `<!doctype html>…</html>` 文件交付，内联必要 CSS/JS/数据，可离线打开。不要把 HTML 包在 Markdown 代码块，不输出前后说明混入文件。独立另存学习/验收回执。

## 报告主线

经营结果 → 销售与客户变化 → 利润、履约和售后影响 → 现实活动与历史动作 → 优先行动与复查。流量和广告用于解释经营，不能抢占主线。根据实际重要性合并章节，自主安排阅读节奏；不要逐字段造章节，不要求每份报告凑齐相同章节数。

日报回答“今天先抓什么”，D-7为主对比、D-1辅助；周报回答“本周发生了什么、下周如何安排”，用完整自然周及前一完整自然周。月报采用真实月区间和已确认目标；专项报告围绕一个决策问题。数据缺失只约束相关判断，不令整篇退化成审计报告。

核心销售、订单、每单金额、参考利润采用 Admin 原生统计；同一字段 Admin 有值（含0）优先，缺失直接用 Order 补充，平台/网站差异不构成拒用理由。利润率缺于Admin时用Order利润率，参考利润=Admin销售额×该利润率÷100，明确是估算。详细口径和计算规则见 METHOD.md，不能自行改公式。

来源标签按行写实，不按整份报告统一：Admin 内部至少三块——订单统计（主盘）、支付明细（按支付时间、含当前状态，另一模块、另一分母）、原生品类/问题聚合；Order 的状态明细属 Order。不要把 Admin 支付明细写成 Order 明细，也不要把 Order 状态改标 Admin；周报按行保留 `primary.system=order.p2pah.cn`、`supplement.system=admin.p2pah.cn`。两模块并列时写明“同属 Admin、模块与分母不同”，不核平、不缩放。

收入量价拆解按 METHOD 的顺序公式，并只叫“订单量与客单的算术拆解”。认可范本与 `comparison.symmetric_decomposition` 用两期均值的对称算法，本身正确、名称与算法一致；顺序公式是本方法的选择，不是对范本的否定。任何公式都先按原精度核恒等，再展示；两项展示值相加若差 1 美分，注明舍入，不改原值凑平。

履约率跨期比较先看订单年龄：同一快照下不同支付日队列的完成率差异本身符合“越新越可能未完成”，不能拿较新队列偏低来排除年龄解释，也不能据此认定某日额外延误。聚合横截面分不清年龄与处理延误时，写“值得跟进、现有快照尚不能分清、先核未完成与问题单的实际等待时长与状态、次日复查同批”；要定量需同一批订单各自的 T+1/T+3/T+7 历史快照。

## 呈现约束与设计自由

用户2026-10-18最新明确：Hermes的经营分析能力已足够，下一阶段重点是按人的阅读与决策习惯解释和呈现分析，而非再限制推理。分析路径、问题挖掘、结论与设计方案自主；固定的是呈现效果：数据优先用清晰紧凑的图表，文字提炼重要结论、业务含义、建议及下一步，提供有用交互。FS视觉只作宏观参考；报告HTML的具体配色、字体、布局、图表类型与阅读顺序由Hermes自主选择，不强制复刻旧范本、FS令牌或组件。继续遵守此前确认的红涨绿跌语义、真实数据与必要的可访问性/离线交付边界。此例外仅适用于Hermes报告，不授权改造FS工作台或全站样式。
日报周报要检查销售与利润、商品/市场/客户、交付履约与支付、退款拒付及客户体验、运营策略（含新客优惠与复购）、广告及自然获客、真实游戏节点与活动、已有动作和效果，以及风险、机会、关键决策与待决。日报侧重异常和当日可执行事项，周报侧重变化、问题成因、跨环节影响及接下来的安排；全场景先看一遍，再按重要性组织，不能因某类工具数据多而偏题，也不要求每个场景等篇幅。无重要变化可简述，缺数据如实标注，不造数凑章节。
重点问题必须让读者看懂“发生了什么—我如何判断及可能的其他解释—经营影响—先做什么—何时如何复查”。保留有理由的怀疑与经验判断；建议应落到对象、最小动作、可行性、交付物、建议岗位、时间、衡量与调整条件。活动策划连接真实节点、目标人群、商品/渠道、资源与承接；有取舍时讲推荐理由，需业务决定的事保留选项、影响与所缺关键信息。不能用空泛的持续关注/优化策略代替分析，也不把建议写成已执行。

具体方法与已加载的data-storytelling、modern-web-guidance、humanizer-zh编辑原则见METHOD第六节。交互为理解服务；重点图表与结论默认可见，明细按需展开。图表不能过大、文字不能复读数字，也不能只剩漂亮空壳。

### 模块版式：编号分项，不写密排段落（用户2026-10-20确认）

- 品类章节的“模块一 · 主判断与业务影响”是最容易写崩的地方：四五个编号点比四五段正文好读。每点给一个短项名（经营面／用户与复购／分市场／平台与品类／游戏节点），右侧排“指标＋数值＋涨跌”标签（红涨绿跌），块底只留一句解读；业务影响单独成框，不把影响判断混进数据流。首页 KPI 卡与分项行的密度就是目标。
- 目标/进度类数字优先给图：按项目分组的进度条＋一条时间进度参照线（如 58.1%），低于时间进度的用警示色、超目标画满但保留原值（104.4% 不要写成 100%）；原来那张多行明细表收进 `<details>` 保留下钻，不要拿它当主视觉。
- 每个品类都要有流量与广告：按流量看板的游戏映射取会话/来源/落地页与投放花费、转化、ROAS，并连到订单与新客。映射未覆盖的游戏明确标注缺项；不要用全站背景冒充单游戏流量，也不要靠系列/页面名称猜归属——名称只能说“像”，不能当口径。
- 用户提版式意见时改成品、不重跑：在原稿旁另存 v2，数字一字不改，只改被点名的模块；回复里写清“本地改稿，FS 归档仍是原稿”。版式认可后再把要求写进下一次生成指令，避免每轮都花一次完整任务。可直接复用的标记与样式配方见 `references/layout-patterns.md`。

## 全局节奏（先立规矩）

- 统一内容宽度、卡片内边距、标题层级与段间距；正文行长按容器、字体与信息密度控制，宽屏不拉满，不固定汉字数。
- 重点模块通常按**简短判断 → 合适的图/卡 → 必要解释 → 动作与复查**组织；重要逻辑可多写，缺数据不编图，不强制每模块一图或三行上限。原值、算式、口径按需放 `<details>`。
- 默认阅读层避免重复同一组数字；允许图表、无障碍文字与折叠原表共享必要数据。图注主要讲单位、范围、来源。
- 变化用带符号百分比；涨红跌绿表示方向、不表示好坏，同时给 `+/-` 与"上升/下降"文字，不靠颜色单传含义。
- 首次出现给基数（如 434 单 / $29,396），之后只给变化；详细两期金额进折叠表。

## 逐模块

1. **顶部**：一句核心判断；3–5 个主盘指标；明确标主对照、辅助对照与抓取时间。月度领先与在手风险并列写，不互相抹掉。
2. **行动卡**：一卡一动作。判断句 + 一组关键变化 + 主责/交付/复查时点。不要在一张卡里塞三组前后数字和整段背景。
3. **"02 这一天"**：保留近 14 日趋势；周变化用三条变化条或小倍图（收入、订单、客单）替代表格；收入差用正负贡献条或瀑布，零线在绘图区内、坐标含 0 与全部有效值、同图统一线性比例、负值带负号。原值折叠。不能只把旧表换成三段文字。
4. **平台/商品**：贡献图回答"谁拉动、谁拖累"，图旁一两句解释；不写"需求迁移"。Items 有独立机会或风险线索时保留，不因 Coins 大盘占比而忽略，也不强造机会。
5. **利润**：全盘参考利润与完成样本采购毛利分开呈现（点线或分面），图上标样本范围与金额覆盖；单均变化只作单均解释；敏感度标"情景"，不标"预测"或"校正结果"。
6. **履约**：当前老池与新支付批次分栏；年龄×状态堆叠图 + 风险金额 + 需核定义；不罗列状态码；未去重的类别不相加当独立订单损失。
7. **客户**：人数、人均收入、折扣比例用三个短指标 + 一组分组图；复购原值分母未知就不推断忠诚度；折扣与退款含 0 的单列。
8. **目标**：进度条 + 时间进度参照线 + 剩余缺口/所需日均/情景对比；不写"锁定""无悬念"，不用情景代预测。
9. **获客与活动**：有效系列与商业落地页明细优先；Ads、GA4、GSC、News 四个来源状态各自显示，不用一个 partial 概括全部；官方节点结合商品机会与验证动作；预算建议需相应证据，报告不执行预算。
10. **跟进**：短表（时间/看什么/怎么判/谁）。阈值标"建议"并写用途；执行器历史状态冲突按原执行 ID 核验，不把已修复问题重复派成新缺陷。

## 落点：旧稿这十处怎么改

- 顶部四句导语 + 三组涨跌 → 一句判断 + 一行元信息（期间/对照/抓取），其余进正文。
- 01 三张行动卡各塞两组以上数字与长段方案 → 每卡一句判断、一组变化、主责/交付/复查。
- 02 趋势图 + 周合计表 + 分解表 + 三段解释 → 趋势图 + 三条变化条（收入/订单/客单）+ 瀑布，原值折叠。
- 03 三张可切换平台图 + 三段 + 缺口注 → 一张贡献图 + 两句解释，Items 单独一句。
- 04 截断轴点图 + 三段 + 敏感度 → 两个口径分面、标覆盖、敏感度写明"情景"。
- 05 账龄图 + 问题单占比图 + 大段 → 老池/新批次分栏，金额与需核定义同行。
- 06 三段报数 → 三个短指标 + 一组分组图。
- 07 进度条 + 两段 → 进度条 + 缺口/所需日均/情景，一句话取舍。
- 08 三段长文 → 三张小卡（节点/投放/改价），各一句判断 + 一个复查动作。
- 09 五列长表 → 短表（时间/看什么/怎么判/谁），阈值标建议。

## 技术底线

- 语义 `figure`/`figcaption`；SVG 带 `role="img"` 与 `title`/`desc`；图注写单位、口径、来源与缺口。
- 宽图在容器内横向滚动，页面本身不横溢；手机端 SVG 文本不小于约 11–12px，必要时改小倍图。
- 浅色/深色、打印（折叠全展开）、切换、键盘焦点都要检查；离线自包含，无外部脚本、字体或网络请求。
- 交付前跑结构自检并修复；静态检查不等于浏览器验收，未在 1440/390 实际看过就写"未验"。

## 2026-10-24字段理解与成稿核验补充

取数完成后，逐项检查“字段→计算→结论→行动”，包括标题和卡片。不能在正文承认缺K数，标题仍写量价齐跌；不能以原生率未公开公式为由否认其参考估算的原值变化，也不能把跨周写成一天。累计参考利润必须使用本累计期间的参考率，不归因单日率。比例直接从完整精度舍到最终显示精度，避免先0.64998→0.65再→0.7的二次舍入。

默认阅读层按用户本次偏好精简：PC行动卡优先“78单，收入较上周同日-30.7%，客单-20.9%”这一类必要基数与变化，前后收入、客单绝对额放展开明细；内容按新证据计算。平台/品类/广告效率的详细数字表、完整来源字典默认折叠，重要图、判断与负责人动作可见；行动跟进表可默认可见。客户与目标使用紧凑摘要/分组图，后半部分保持相同宽度、留白、行长与段落节奏，避免重新堆成长数字段落。图表不是越多越好，必要解释不能删掉。
