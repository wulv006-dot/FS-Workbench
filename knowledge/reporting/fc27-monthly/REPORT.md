# FC27 月报：从经营问题到行动

按[审核核心](../../../docs/planning/operator-report-review-20261025/REVIEW-STANDARD.md)执行：先主判断与价值取舍，再关键事实、解释和行动。优秀月报是组织与表达参照，不是固定章节数或历史数字模板。

| 报告频率 | 主要决策 | 比较与展开 |
|---|---|---|
| 日报 | 今天优先处理哪个异常 | 昨日完整日对前日/上周同星期；当日注明截止时刻，突出1—3项实际动作 |
| 周报 | 哪些变化持续、资源怎样调整 | 明确连续七天/自然周对前等长周，结合星期结构、活动节点和归因回补 |
| 月报 | 全盘增长质量及下月重点 | 完整月同比/环比，再月内周趋势、品类/游戏贡献与下月资源取舍 |
| 专题 | 用户当前要决定的具体问题 | 围绕问题选择同范围可比窗口，不强套全盘章节 |

## 形成主线

先问本月增长有没有留下采购毛利、月底趋势是否延续、下月最值得投入什么。取得Admin付款销售/订单、Order发货采购毛利和主要获客数据后，列出变化贡献最大的对象，再补能改变优先级的少数证据。内部全维检查，正文按主次展开；不要把每项字段都变成一章。

1. 全盘先区分规模与质量：销售、订单、客单、毛利额/率，新业务天数及月内趋势。完整月环比不能掩盖月底转弱。
2. 分解主要矛盾：订单需求、套餐/平台/国家结构、有效获客、商品承接、采购履约和复购。销售=订单×客单是算术分解，不直接证明价格因果；Coins要有实交K才能拆单位价与数量。
3. 广告与自然分别判断：广告看费用/平台效率、真实广告新客CAC、成熟客户价值/回本期及国家取舍；自然看搜索曝光/点击、精确商品页浏览、自然入口购买信号与语言优先级。
4. 用业务结果解释商品与履约：Players/SBC的真实成交与可售性、Coins交付/验证问题及长尾等待；自动化记录只证明执行行为，不凭上线时间虚构增量收入或工时节约。
5. 给下一月2—3项优先工作，写清建议主责职能、动作、所需资源/依赖、复查日期与何种结果改变判断。未知预算或目标保留待定，不编执行记录。

## 对照与解释

同比先核发售阶段、经营天数、网站/游戏映射和同源窗口。FC26与FC27的Admin/Order游戏ID不同，不能只换名称；详细历史映射见[业务知识](BUSINESS.md)。国家、语言、币种、下单设备与游戏平台分别解释。

每个重点串起“我判断什么 → 哪些事实支持 → 对业务意味着什么 → 下一步”。依据足以支持方向就承担判断；主要竞争解释与关键未知各用必要一句说明。只有会反转主次、行动方向或重要金额的缺口才继续下钻。精确因果份额、实验收益和执行成败须有对应证据，不能用观点补成事实。

## 报告表达与体验

- 首屏给主判断、最重要的变化和行动，不用来源矩阵或技术过程挡住结论。标题表达业务含义，文字解释图而不重复读数。
- 付费与自然先分模块，在各自模块内展开；核心事实默认可见，原值、计算、来源和详细边界按需折叠。业务正文和折叠附录均不展示内部修稿、抽样教学和核验过程。
- 多指标或期间切换同步更新标题、单位和比较对象；不同量纲分开，非零图元可见。内部图涨红跌绿并保留符号，主题、键盘焦点和状态可读。
- 沿用成品或现有项目设计；文字答复无需强造HTML。需要HTML时检查桌面/手机宽度、页签/锚点/键盘、深浅主题、打印和无脚本可读性，证据绑定最终成品版本。

## 交付与复用

成品先交结论、判断和行动；必要来源与限制轻量呈现。内部同时保留可重算数模、来源/筛选、请求回执、版本、未覆盖项和最终验收。报告负责人不得将方法文件保存、Git合并或某轮模型复述当成业务验收。

报告完成后按[维护协议](MAINTENANCE.md)提炼本次真正改变未来决策的方法、接口故障经验和用户新确认口径。历史事实留原报告，稳定方法更新唯一原文；没有新增可复用知识就记录无需更新，不制造新规则。
