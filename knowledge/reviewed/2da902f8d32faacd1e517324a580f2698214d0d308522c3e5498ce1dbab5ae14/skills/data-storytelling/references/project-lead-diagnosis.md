# 项目负责人经营诊断方法

适用：由销售额、订单、利润或复购异常出发，检查整个项目，提出跨部门改进与活动方案。项目负责人负责问题排序、资源取舍、部门协同和结果验收；专业负责人负责本职方案与执行细节。业务规则与操作权限沿当前项目基准，本方法不授予生产写入权限。

## 1. 从结果建立问题树

先确认比较窗口、站点/游戏、币种、订单状态、数据成熟度与真源。能复用的完整证据直接复用。销售额可在同一订单集合内拆为订单数×每单金额；Coins进一步区分交付数量与单位成交价，缺数量时保留两种机制。不要把不同来源的访问、订单和金额拼成精确漏斗。

随后沿业务链检查：市场需求与竞争 → 获客 → 商品与承接 → 下单支付 → 供给履约 → 满意与复购；财务、风险、数据和跨部门协同贯穿全链。产品、平台、客户、国家是定位切面，不能相加当独立原因。

## 2. 全面覆盖，集中推进

按业务实际检查以下模块；不适用时写明理由，缺数据写“待验证”，不将未检查写成正常或失职：

| 模块 | 负责人层面要回答的问题 |
|---|---|
| 市场/版本/竞品 | 购买需求、替代方式、内容节点、竞争力是否变化？ |
| Ads与SEO | 高意图入口和真实成交哪里变弱？获客与金额结构怎样区分？ |
| 内容/KOL/社媒 | 发布、触达、商业引导、匹配成交是否衔接？ |
| 分销/伙伴/私域 | 合作活跃、有效引流、触达与归属规则是否变化？ |
| 商品/定价/优惠 | SKU、平台、数量、到手价、优惠资格与组合是否影响购买？ |
| 网站/设计/本地化 | 主要商业路径是否让对应客户顺利理解并购买？ |
| 支付/风控 | 匹配的支付尝试与失败证据是否显示阻塞？ |
| 供应/交付/客服 | 库存、交付时长、问题积压与客户反馈是否恶化？ |
| 客户生命周期 | 新客是否减少或变小？同龄客户是否少复购？ |
| 财务/经营风险 | 净收、实际成本、采购毛利、退款拒付及可归属费用如何变化？ |
| 数据/项目协同 | 统计变化、漏项、反馈闭环和部门间依赖是否妨碍决策？ |

覆盖检查不等于每个模块都要深挖。先提出全景判断，再集中2—3项最可能改变结果的工作。优先级综合金额影响、证据强度、紧迫性、可控性、执行成本与跨部门依赖，不用虚构精确评分代替判断。运营风险可先处理，但不要因此认定它已造成本次销售下降。

## 3. 核心判断的最小交付

管理层报告中，每个重点先用一至两句话讲清判断、业务意义及有线索的推断，再用图表支持，并说明负责人动作与反证。精简的是重复数据和推导过程，不能删到只剩图标题或指标；不以字数减少或图表数量作为质量证明。全业务检查在内部完成，前台只展示有判断或影响决策的重要待核项，不强塞模块。用户已认可的报告优先局部调整视角与行动。详细计算、竞争解释与学习复盘留内部，必要口径按需展开；缺数据不编图。

每项包含：**直接判断 → 数据/图表与范围 → 竞争解释 → 责任接口 → 最小核对项 → 反证条件 → 若成立/不成立分别怎么推进**。分清事实、分析者判断、用户提供的信息与待验证推断。对部门提出需要回答的业务问题，给足验证方向；通常无需代其研究出价、素材组、代码修复或逐单交易细节。

补查前问：结果会不会改变问题排序、负责人、资源取舍或下一行动？会则查最小必要证据；不会则把线索交负责人、继续扫描其他模块。发现数据身份错误、结论可能反转、重大支付/履约风险或关键决策无法作出时，可深入到足以判断的层级。用户明确要求专项审计时再进入专业执行深度。

## 4. 将判断转成计划和活动

每项行动记录ID、目标问题、建议主责/协作方、依赖、相对截止、交付物、业务验收、反证后的替代动作、状态和下次决策点。负责人未指定具体人名时标建议职能，不能假称已派单。计划完成、执行完成与业务改善分别记录。

活动必须针对已识别机会：目标客群与使用场景、客户阻碍、活动机制、渠道组合、部门分工、上线依赖、可支配资源、主要指标、退款/履约/利润约束、比较方式与继续/调整/停止条件。未知预算、价格、折扣和预期增量保持待定，不造ROI；具体新报价须核有效成本与当前可比竞品。优先复用现有能力，以一个小范围试点验证后再扩展；随机对照可行时优先采用，观察性比较要写明同期干扰。

## 5. 复盘与学习

复盘记录当时预期、实际结果、证据、错在范围/数据/机制/执行的哪一层、下一次改变什么、何时复验。规则写入、真实加载、给过提示后的应用、未见真实任务、长期稳定分别记账。对原题修复或事后解释正确，只能说明收到并理解，不能充当独立迁移。保留失败与撤回理由，在后续真实业务任务中观察是否反复用对。

方法借鉴原作者公开资源：phuryn/pm-skills、coreyhaines31/marketingskills 与 wondelai/skills；采用结果树、业务覆盖、决策指标、协同行动与复盘。现行业务基准与用户指令优先。
