# 经营报告：读完能判断和行动

先回答最需要判断的问题，给有主次的结论和取舍。正文说明为什么、影响什么、下一步做什么；数据和图表提供依据。不要把报告写成代码审计、字段清单或层层免责。允许有依据的宏观判断与推断，只有可能改变经营方向的重要缺口才占正文。

本入口2026-11-02整合此前用户已认可的阅读、图表和交互要求；未减少分析覆盖、工具或自动化。用户最新指令、当前业务基准和`data-storytelling`当前入口优先。旧`METHOD.md`、`APPLICATIONS.md`、范例与历史参考保留供按需查阅，其中旧“Admin销售×参考率”主毛利、固定优惠或历史版本状态不能覆盖当前Order发货统计及实际证据。

## 先形成一份事实对象

取数、口径和公式按`data-storytelling`及其团队规范参考。统一事实对象保存期间、对照、时点、范围、来源、单位、分母、原值和缺项；摘要、图表、原表从同一对象产生。Order发货采购毛利不称净利润。

日报突出今天先抓什么；周报突出整周驱动、转折、动作反馈与下周安排；月报先全盘贡献和增长质量，再逐组解释；专题围绕决定。全维内部检查，前台按重要性合并，不逐字段造章节，也不把后半各游戏章节写成密集文字和数据表。

## 阅读顺序和图表

- 首屏给主判断、关键指标和优先行动。重要线索按判断→图/对照→业务意义→动作与复查组织，不逐数复读，也不删成纯图。结构、配色、字体、图型和布局自主。
- 趋势看变化和转折；贡献图看谁拉动/拖累；分组图看平台、商品、国家、新老客和让利；获客看规模、成本、成交效率与实际业务贡献。多维比较适合切换和紧凑分面，表格作原值下钻。后续FC/ARPG/综合等每组有实际对照图，不能只重复全盘图形而缺组内分析。
- 先看经营结果，再解释投入、获客与承接，之后看供给履约和风险。FC周报沿用户认可日报的阅读质量，把重要Ads/流量线索放在履约前；不机械照搬旧数字、八章结构或固定图数。短答不凑HTML或图表，用户明确要求HTML/PPT的正式交付要完成。
- **内部涨红跌绿，同时显示正负号/文字；涨跌方向不等于好坏。** 带正负变化的条/柱图共用绘图区内真实0线、统一线性比例和单位。正值从0向右/上，负值向左/下；保留负刻度，不取绝对值画成同方向。不要求零线居中，数值范围含0及有效极值并留标签空间。0不造最小柱，金额、百分比和百分点不混轴；总量/构成图按表达目的选坐标。
- 目标图给真实完成率、时间进度与剩余缺口，超100%保留原值；跑速外推标情景，不说锁定。不同来源/状态/覆盖的利润、广告和履约分面，不用一个partial把可用子源全隐藏。

## 交互与布局

重点判断和必要图表默认可见，原值/公式/一般限制按需展开。切换期间、游戏、国家、平台或指标时，标题、单位、基准、图元、解释和来源一并更新；切换不创造可比性。折叠后仍能读懂结论，不藏重要风险。

统一宽度、字号、标题、卡片和间距；图大小适当、标签不拥挤、手机可读，不固定段落句数。行动卡讲一个动作、关键理由、主责/交付和复查时点；避免无结论大表和满页警示色。

目录在FS嵌入页实际定位正确，不能只改hash；按钮和切换给明确当前状态，键盘可用、焦点可见、字号对比足够，不能只靠颜色传递。语义figure/figcaption，SVG提供title/desc及可访问说明。空、缺失与真正0分开，失败状态保留可用内容；不画假零。

## 文件与验收

正式HTML为可独立打开的完整文件，内联必要样式、脚本和数据，不把源码代码块当成品。PPT按用户要求另交付，与HTML同口径；适用时优先可编辑图表。不要把学习、修订和审核过程塞进经营正文。

文件自查后，在可用浏览器看宽屏与窄屏、浅暗主题、切换、展开、目录、键盘及打印；下载/另存后重开。检查真实图元和截图，混合正负共用0线、比例正确、无重叠/越界，切换和窄屏后仍成立。校验绑定被验文件SHA；改后复查受影响部分，不复用改前通过。浏览器不可用如实写未验，不冒充效果通过。

认可报告按要求局部修改，不因版式反馈重采全部业务；版本、归档和验收状态写实。授权内继续完成；UNKNOWN先核原ID与回执，不盲重放。
