# FS 证据对账与交付核验

这是 fs-ops-watchdog、ops-incident-handoff、fs-task-verification、hermes-messaging-channels 的共享取证方法，合并原候选的重复经验；原工具、业务合同及当前正式知识继续负责实际动作。按需使用本技能，不把本技能当新权限或替代业务规则。

## 先固定对象和范围

记录模块、日期、原请求、job/run/execution 的各自标识、来源版本及内容哈希。相同字符串不证明不同系统中的 ID 语义相同。只读已授权且与原对象相关的字段与归档；先查 schema 和明确关联键，不为找一个 ID 扫描全部业务表或客户正文。取不到原证据就保留缺口。

每份判断分开写：事实、推断、未验证、下一步需要的证据。修改判断时追加更正及推翻依据，保留原稿、原 ID 和原回执。

## 事件与租约：三处核对，不能凭一个状态关单

1. 对照原派单回执、发送日志中的 target_state/notification_scope、当前事件与 claim 记录；分别记录时间和版本。当前 incident 可能随异常集合变化，不是完整事件历史；ID 不同既不自动证明新故障，也不自动证明只是簿记缺陷。
2. 发送日志只覆盖其记录范围。静默轮可能没有日志；“首见”写成“已保留样本中的首次”，不能称全局首次。码消失只证明该份样本不含它，不能证明修复原因、清除动作或整个区间一直正常。
3. claim 的文件格式与并行能力随实现版本变化，先核当前活动脚本和租约合同。当前 watch 按 owner 与 incident 分文件保存，旧 owner 单槽文件仅兼容读取；不得把旧版本的“一个 owner 只有一个槽”用于新实现，也不能把任意备份当有效租约。逐一核事件、active、claimed_at、first_claimed_at 与实际到期规则；不要自行覆盖、续租、释放、合并或关闭事件。需要变更时按原负责方和已有授权执行。
4. 同一模块的相邻事件可以列为“可能关联”；只有原执行与来源证据闭合后才合并根因。新的 job 或通知不解除旧 UNKNOWN。

## 时间与采集：先核业务采样时间

- 分开保留读取时刻、文件修改时刻、exported_at、业务 captured_at、任务创建/完成时刻；全部注明时区与日期。文件刚导出不能证明业务数据刚采样。历史样本必须使用当时的规则版本与适用范围。
- 若要证明“参照点之后的状态”，业务 captured_at 必须严格晚于参照点；等于参照点只能证明边界时刻。时间差使用原精度，保留正负号。缺字段、时钟异常或采样过早时标 evidence_unavailable，不补零、不换成导出时间。
- next_at=null、旧 job 未变化、过了一个名义周期，只能支持“该视图未显示下一轮”；是否排队、延迟或执行中断须查对应 worker/scheduler 与原回执。只有核过实际判据源码，才能说空值使某告警分支跳过。新 job、COMPLETED 或告警消失均不证明内容合格或业务写入已对账。
- 告警阈值从当前活动 producer、配置和版本取，不从缓存代码、旧技能或某次案例固定复制。区分 collection 的 created_at、证据 captured_at、run_freshness 与调度时间。重复引用同一 run 只证明所查视图复用该 run，不足以证明采集器冻结。
- 使用已有归档或本次获准的只读样本；需要新采集、定时、轮询或通知时另按原授权处理。本技能不增加此类任务。

## 改价与日报：回执覆盖哪一步，就只证明哪一步

- recommend 的 write_performed=false 只描述该 recommend 动作；changed_platforms=null、requests 查询零行或 price_after 相同均不能单独证明平台已写或未写。应按合同读取同一执行的锁内校验、原请求、平台回执与公开读回；UNKNOWN 保留，不换 ID、不重放，不清锁或改价。
- 夜间数据 preparation 的当前可变收据与已完成 attempt 分开读取，核日期、attempt、状态、缺项和原任务实际 deadline。partial 可能是补充数据不足，也可能有真实失败；按原运行合同与缺项影响判断，不把某一实现的 blocks_publication 值或历史运行窗口永久化，不新增停报门槛。
- 已完成报告先核原任务/快照/成品关联，再对原文件计算 SHA256，与同版本交付清单约定的 html_sha256 比较。缺清单或不一致时说明未验证，不为“取出报告”重跑模型。状态完成、哈希匹配与内容/业务验收是不同结论。
- 离线 HTML 检查实际外部资源依赖：script src、样式 link、CSS url/import、图片及嵌入资源等；普通参考超链接、文本 URL 和 SVG 命名空间不等于必须联网的依赖。是否允许离线跳转按交付合同说明。中文文件名不是一律失败；仅在已复现的传输链路需要时使用兼容文件名并保留原件。

## 飞书消息：结构化 @、对方处理、业务完成分开

标签使用 ASCII 引号，例如 `<at user_id="ou_example"></at>`；通过原工具按其接口约定序列化，不能机械加反斜杠或重复 JSON 编码。发送受理、message_id、原消息读回 mentions 中目标 open_id 命中、对方 ACK、业务产物分别留证。显示名为空不等于目标错误；结构化 mention 命中不证明对方已读或执行。

本技能只核验已有消息，不新增发送器。UNKNOWN、超时或无 message_id 先查原 intent、原操作和回执，不因缺 ACK、缺 mention 或调用返回失败就盲目补发。获准的发送动作仍复用原发送工具和防重放机制。

## 长期裁定：记录已确认部分，不把待明确事项补成授权

用户的长期偏好、纠正或裁定先形成候选，经Codex审定后走原生应用；“候选已保存”不等于“已生效”。不得直接追加或覆盖共享记忆，不由Hermes自己宣布通过，也不绕过原候选哈希、目标哈希、容量和CAS检查。当前候选工具入口由已有 `propose_context.py` 及其帮助定位；保留原始消息、理由、适用范围、生效时间、被替代条目和未决点。

一块只处理一个主题。只有临时许可时写清有效范围及复核条件，不把“一次”升级为永久。来源或目标已变化时重读，并用原工具形成绑定当前基线的新候选，注明原候选和替代关系；不篡改原候选、不换ID重放已未知的写入。批次混入错误段落时，不部分应用原批次；先审定独立完整替代候选，成功后保留原批次的审计与替代理由。

## 原消息核验：群会话元数据不等于单条发送者

只读核验已提供或明确定位的原 message_id，复用现有单消息读取入口；不默认扩大群历史访问范围，不新建凭据或发送器。须先检查接口成功、返回项与原ID对应，再核 sender_type、sender的id_type及原生ID、已验证身份绑定、会话/话题、原文和时间。不同ID类型不能直接比较；显示名、会话user_id、旧origin缓存、机器人转述或cron来源都不能独立证明本人授权。

原消息被正常镜像到群和话题时，可以保留不同message_id及各自上下文；同一正文和时刻不能代替发送者核验。消息原文证明说过什么，不证明后台已执行。权限不足、消息不可读、删除或截断时保留缺口，不据此判伪造、不盲目补发。具体API权限、环境和可见范围按当前实现实测，不能从某次HTTP错误永久推断。

## 已核沟通偏好：少重复提醒，不扩大实际权限

用户已明确不希望围绕内部协作反复进行安全劝告。既有授权内自主推进；凭据仍不在消息、报告或审计正文中回显，具体工具拒绝或权限缺口如实说明。“内部群都是自己人”作为用户当时的沟通背景，不写成不会泄密的事实，不据此新建凭据、改变共享范围或绕过工具限制。

## 只读查询与错误归因：核覆盖后再解释缺失

SQLite同一cursor的execute会替换它正遍历的结果集。嵌套查询先fetchall外层结果或使用独立cursor；返回“最近N条”时核实际行数、过滤条件和字段覆盖，不把被截断的输出当成全量零命中。仍按原请求及明确关联键查询，不因此扫描所有客户或业务正文。

错误码首先证明哪一层如何映射/捕获了异常，不直接证明是哪一个上游造成，更不能凭controller前缀排除模型、来源、权限或传输错误。区分原始异常、映射码、持久化结果和日志；每层能读到什么按当前活动版本核实，不写成永久可见性上限。静态缺口、隔离复现、历史故障根因是不同结论；当前源码、mtime或字节码缓存均不能独自证明失败当时运行的版本，任意入口函数也不能为了验收直接执行。

判断是否进入运行时，按同一原请求关联controller回执、持久准入记录、run_id、有效输入及产物；时间接近不能把另一个run归到本任务。progress或evidence可能来自投放前准备，缺run_id/contexts/产物或搜索不到POST也不能单独证明从未提交、零费用或可安全重派。若原对账记录给出未提交结论，核其来源、对象、版本、覆盖和生成时刻，保留原失败及后续迁移证据，不把“有对账文件”当无限权威；重试仍沿原授权、幂等与UNKNOWN流程，不靠force标志、新ID或改状态绕过原请求。

本增量来自2026-10-27对cea35b56、b5984fa3、d18b8bca及同主题候选的独立审阅；同cursor假零及fetchall修正在隔离真实SQLite中复现，未读生产客户表。仅保留通用方法，不保存旧FC参数、固定窗口、群通知或业务执行授权。

## 用量与费用核验：实测、估计和账单分开

用量按实际调用所在时间划入明确时区与窗口，不把跨日长会话的全部累计量归到启动日；说明日志轮转、缺调用和本次复盘自身的覆盖。先核当前实现及原供应商usage字段语义，再核输入总量、缓存命中/未命中、输出是否重叠；字段缺失与明确回报0分开处理，不把推测的缓存数标为实测。

相邻输入长度接近或递增，不能证明实际内容前缀相同或服务端缓存命中。缺缓存明细时保留未知；有依据的模型估计另列假设、验证样本与适用范围，不能宣称必然偏高或拿估计覆盖真实零命中。金额使用对应模型、提供方、币种、生效时点的可核费率；同一总账差额先检查范围、日界、漏项及费率来源，不为凑总额调整费率。一笔总额不能唯一反推出三档单价；缺费率时给明确情景或待核，既有cost字段是否可用按当前状态查，不永久认定免费或不可用。

任务归因优先原request/run/session关联。标题、前缀、目录修改时间或最近时间仅作定位线索；并发、重跑或候选匹配冲突保持未归因，不硬配给最近报告。合计、分项、次数与去重范围互相核验，实际消耗、估算费用和供应商账单分别呈现。

汇总脚本必须携带源状态、覆盖、单位和窗口；无数据、失败、空值、无效数字不能静默转成零。部分可用来源可以支持有范围的方向判断，不能把局部合计冒充全量，也不因缺完美归因取消有效经营判断。降本只提有证据的重复工作及收益，不据此降低正常采集、巡检或现有自动化能力。

本增量来自2026-10-29对同主题费用及取数候选的去重审阅；隔离执行原候选纯函数复现了零缓存被估成命中、按修改时间归因歧义和失败/缺值被汇总成零。未读生产订单或触发模型、通知与业务动作，不保存固定费率、临时金额或新权限。

## 运行能力与健康判据：按本次任务固定证据

HTTP健康检查成功只证明该接口覆盖的进程、会话或依赖可达，不证明业务写入成功。迁机后旧unit按设计inactive时，先核迁移/切流证据与当前判据，再用隔离副本测试成功、失败、持续故障和无关写入失败分支；不可只测健康成功侧，也不因本技能停服务、改网络、清状态或屏蔽原写入异常。各检查的去抖、静默与退役范围按当前有效合同核，不从历史案例复制固定阈值。

同一FS界面可能调用研究、资料处理或原生持续对话入口。按原请求的准入类型、现役创建分支、有效工具清单及加载回执核能力；某一研究白名单不能证明普通会话也只能用这些工具，更不能把某次缺工具写成永久能力上限。源码显示分支存在、实际实例加载、工具实际调用和业务结果分别验；没有实际调用就不声称已打通。

标作dry-run的命令也要核所有提前返回分支。复制输入到独立临时目录，执行现役代码副本，对比运行前后每个文件的完整字节哈希，并核发送次数；只排除合同明确允许的临时锁。正常到期分支不写盘，不能证明无到期项、未知发送、并发锁等分支也不写盘。发现副作用时记录真实写了什么，不拿同一套旧绿测试覆盖新反例；未核前不对生产HOME做预演。

告警发现、自修和发群是不同环节。核原用户消息、现役过滤器和完整异常集合，分别验证非阻断留痕、阻断故障、恢复、防重放与自修；节省群提醒不等于降低巡检或关闭修复。临时静默、历史调度、提醒预算与未上线检查器不升级为永久规则。机器人接单或转述也不自动授予新群回复策略、正式业务裁定、代码发布或新增定时任务。
