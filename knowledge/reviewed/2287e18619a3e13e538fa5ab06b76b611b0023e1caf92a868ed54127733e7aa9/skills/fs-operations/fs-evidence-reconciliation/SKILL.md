# FS 证据对账与交付核验

这是 fs-ops-watchdog、ops-incident-handoff、fs-task-verification、hermes-messaging-channels 的共享取证方法，合并原候选的重复经验；原工具、业务合同及当前正式知识继续负责实际动作。按需使用本技能，不把本技能当新权限或替代业务规则。

## 先固定对象和范围

记录模块、日期、原请求、job/run/execution 的各自标识、来源版本及内容哈希。相同字符串不证明不同系统中的 ID 语义相同。只读已授权且与原对象相关的字段与归档；先查 schema 和明确关联键，不为找一个 ID 扫描全部业务表或客户正文。取不到原证据就保留缺口。

每份判断分开写：事实、推断、未验证、下一步需要的证据。修改判断时追加更正及推翻依据，保留原稿、原 ID 和原回执。

## 事件与租约：三处核对，不能凭一个状态关单

1. 对照原派单回执、发送日志中的 target_state/notification_scope、当前事件与 claim 记录；分别记录时间和版本。当前 incident 可能随异常集合变化，不是完整事件历史；ID 不同既不自动证明新故障，也不自动证明只是簿记缺陷。
2. 发送日志只覆盖其记录范围。静默轮可能没有日志；“首见”写成“已保留样本中的首次”，不能称全局首次。码消失只证明该份样本不含它，不能证明修复原因、清除动作或整个区间一直正常。
3. claim 的文件格式与并行能力随实现版本变化，先核当前活动脚本和租约合同。当前 watch 按 owner 与 incident 分文件保存，旧 owner 单槽文件仅兼容读取；不得把旧版本的“一个 owner 只有一个槽”用于新实现，也不能把任意备份当有效租约。逐一核事件、active、claimed_at、first_claimed_at 与实际到期规则；不要自行覆盖、续租、释放、合并或关闭事件。需要变更时按原负责方和已有授权执行。
4. 同一模块的相邻事件可以列为“可能关联”；只有原执行与来源证据闭合后才合并根因。新的 job 或通知不解除旧 UNKNOWN。

## 时间与采集：先核业务采样时间

- 分开保留读取时刻、文件修改时刻、exported_at、业务 captured_at、任务创建/完成时刻；全部注明时区与日期。文件刚导出不能证明业务数据刚采样。历史样本必须使用当时的规则版本与适用范围。
- 若要证明“参照点之后的状态”，业务 captured_at 必须严格晚于参照点；等于参照点只能证明边界时刻。时间差使用原精度，保留正负号。缺字段、时钟异常或采样过早时标 evidence_unavailable，不补零、不换成导出时间。
- next_at=null、旧 job 未变化、过了一个名义周期，只能支持“该视图未显示下一轮”；是否排队、延迟或执行中断须查对应 worker/scheduler 与原回执。只有核过实际判据源码，才能说空值使某告警分支跳过。新 job、COMPLETED 或告警消失均不证明内容合格或业务写入已对账。
- 告警阈值从当前活动 producer、配置和版本取，不从缓存代码、旧技能或某次案例固定复制。区分 collection 的 created_at、证据 captured_at、run_freshness 与调度时间。重复引用同一 run 只证明所查视图复用该 run，不足以证明采集器冻结。
- 使用已有归档或本次获准的只读样本；需要新采集、定时、轮询或通知时另按原授权处理。本技能不增加此类任务。

## 改价与日报：回执覆盖哪一步，就只证明哪一步

- recommend 的 write_performed=false 只描述该 recommend 动作；changed_platforms=null、requests 查询零行或 price_after 相同均不能单独证明平台已写或未写。应按合同读取同一执行的锁内校验、原请求、平台回执与公开读回；UNKNOWN 保留，不换 ID、不重放，不清锁或改价。
- 夜间数据 preparation 的当前可变收据与已完成 attempt 分开读取，核日期、attempt、状态、缺项和原任务实际 deadline。partial 可能是补充数据不足，也可能有真实失败；按原运行合同与缺项影响判断，不把某一实现的 blocks_publication 值或历史运行窗口永久化，不新增停报门槛。
- 已完成报告先核原任务/快照/成品关联，再对原文件计算 SHA256，与同版本交付清单约定的 html_sha256 比较。缺清单或不一致时说明未验证，不为“取出报告”重跑模型。状态完成、哈希匹配与内容/业务验收是不同结论。
- 离线 HTML 检查实际外部资源依赖：script src、样式 link、CSS url/import、图片及嵌入资源等；普通参考超链接、文本 URL 和 SVG 命名空间不等于必须联网的依赖。是否允许离线跳转按交付合同说明。中文文件名不是一律失败；仅在已复现的传输链路需要时使用兼容文件名并保留原件。

## 飞书消息：结构化 @、对方处理、业务完成分开

标签使用 ASCII 引号，例如 `<at user_id="ou_example"></at>`；通过原工具按其接口约定序列化，不能机械加反斜杠或重复 JSON 编码。发送受理、message_id、原消息读回 mentions 中目标 open_id 命中、对方 ACK、业务产物分别留证。显示名为空不等于目标错误；结构化 mention 命中不证明对方已读或执行。

本技能只核验已有消息，不新增发送器。UNKNOWN、超时或无 message_id 先查原 intent、原操作和回执，不因缺 ACK、缺 mention 或调用返回失败就盲目补发。获准的发送动作仍复用原发送工具和防重放机制。
