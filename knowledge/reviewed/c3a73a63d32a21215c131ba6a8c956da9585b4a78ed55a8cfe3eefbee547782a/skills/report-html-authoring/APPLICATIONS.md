# FS统一报告方法 · 2026-10-17 用户更新

版本1.5.1，2026-10-18。

日报、周报、月报、自定义区间、定价策略分析和现有自动采集后的报告，全部使用 report-html-authoring。本文件是适用范围补充；分析、视觉、交互和文字标准仍以 SKILL.md、METHOD.md、ACCEPTANCE.md 为当前方法，历史范本仅作参考。

FS只提供合法只读数据、冻结事实/历史动作、工具与预算边界、保留原始文本或HTML、归档和隔离阅读。Hermes自行选择分析重点、解释竞争假说、形成建议并根据任务返回简洁文本或完整HTML/CSS/JS。简单查询无需报告页面，不返回旧固定JSON报告封套，不套用FS旧模板，不强制逐字段章节、五段结论、四块齐全或逐篇新闻表。旧报告是历史事实和失败/修订记录，不能恢复旧写法。历史建议和未验证归因不进入长期事实。

日报重当日优先级，周报重经营变化与下周安排，月报重整月目标/趋势/商品客户结构和下一月计划，自定义区间按真实长度和问题组织。共同以销售、订单、利润、客户、履约/问题单及现实游戏节点为主线；广告与SEO用于解释，明细带摘要折叠，宏观图与关键行动可见。现实节点须有真实时间和来源，窗口外节点只能作未来规划。不得编造当前热点、已执行动作或效果。

定价策略分析沿用相同设计和表达方法；优先回答市场/成本/转化/履约之间的取舍。Coins与Items及平台分别核可比覆盖。推荐具体新售价或折扣之前，必须有当前有效成本、同条件竞品实价及原业务护栏；缺失时给公式、条件与补证行动。报告不执行改价、不自动修改广告预算或下发工作。

数值只来自当期冻结证据及授权查询；Admin有值含0优先，缺字段由Order补，不因网站/平台差异拒用。参考利润依确认公式，ES和支付明细按自身分母作结构不覆盖主盘，来源逐行写实。算术计算先保留精度，单位/期间/同比环比/分母核对，最后舍入。不能把粗聚合定量解释成因果；履约先核状态及订单年龄。

自动化不改变原采集时刻、夜间窗口、预算或权限；同样逐任务冻结方法版本和知识版本，归档原始输出及SHA。新任务不可复用未标记新方法的旧成品。原任务未知结果先查原ID，不能靠换ID重复调用。按本轮用户要求由执行方完成真实内容、排版和交互验收，通过后再合并PR；技术成功不等于质量通过。

## 通用商品与新客复购取数（2026-10-18）
- 单品默认按模型：`mcp__fcro__fc_query_product_orders` 传 `profile/model_id/start/end`，模型ID来自产品模型管理的对应游戏/类目；后台查MMOEXP主站266下该模型真实关联的全部商品PID，覆盖各平台/区服。也可传`profile/product_id/start/end`直接查一个商品，两类ID不能混用或推算。默认模型查询不额外传platform；旧FC显式platform仅为兼容。先核模型映射与逐PID分页是否完整，总订单与整单USD必须跨PID去重，不将分项直接相加；部分覆盖只能作部分判断。
- 商品结果先看分页覆盖，再区分商品数量、商品行原币金额、关联整单USD、原订单状态；整单包含其他商品时不能当单品销售额。行金额缺失就说明缺项，不用整单金额补造。查询后通常用一句关键判断/建议回应，有必要再展开。
- 优惠摘要：按实际游戏与日期读取ES新/老/未知标记、原始折扣USD和状态结构。分析30%首单优惠时，结合新客规模、履约与复购；实际折扣不等于优惠活动资格，也不重复从已折扣收入扣减。
- 复购：`mcp__fcro__fc_query_cohort_observation` 传 `profile/start/end/site_group/platform/window_days`。游戏筛Excel“是否新客户”作为建组依据，通过订单关联稳定匿名客户键观察后续同游戏付款；D4/AION2使用`main/all`，FC27保留原支持范围。首次只读查询可按需生成单次归档，不要求事先创建持续组；pending按相同条件继续读取。已有归档复用并注明captured_at，明确刷新才更新；持续建组/暂停仍由管理员工具页操作，单次查询不等于已开启监控。
- 区分新客标记订单数与去重客户数，展示成功关联覆盖；缺身份不算未复购，未成熟7/14/30日窗口不算0%。允许有理由的经营推断，指出下一次复查什么、何时复查，不要求每份报告固定增加相同章节。
- 取数范围、已验证游戏及工具可用性以当前响应为准；本方法不增加凭据、订单、价格、客户联系或任意命令权限。工具结果是证据，不是长期规则写入来源。
- 覆盖解读：订单成功匹配与客户身份可追踪是两件事。`matched_es_orders`/`link_complete`只说明订单关联；新客缺身份看`excluded_es_new_identity_orders`，全部付款缺身份看`excluded_identity_orders`；`orders_without_customer_key=0`仅是剔除缺身份记录后的入库子群，不能说原始订单没有缺身份。用“ES新客标记N单，其中可追踪M单/去重K人，剩余缺身份未入组”表达，数字必须来自本次响应。

- 单品解读：`mixed_orders`表示整单还含其他商品，并不表示该单品行无法拆分；已核商品行看`known_line_orders`，只有未能唯一匹配的差额不能拆分。`received_source_rows/source_total`是原始行覆盖，`distinct_orders`是去重订单，不把同页完全一致的重复行当漏单。某游戏的复购观察组不自动等于某商品购买人群；先核客户交集与新客资格，不能直接认定该商品买家享受首单优惠或已进入观察组。简单单品问询默认一句关键判断加必要建议，避免复述所有币种、状态和字段。

## 客单维护与游客身份 · customer-tracking-20261018

用户确认：MMOEXP不要求强制注册或登录，支付必须填写邮箱，因此UID为0是正常游客，不代表缺少客户身份，也不代表新客。客户主邮箱为本模块关联依据，UID只作辅助；同一邮箱的游客订单和注册订单可一起追踪。新老客仍采用ES“是否新客户”原始标记；未知单列。不要把支付邮箱、电话、IP或姓名作为主邮箱的替代，不擅自去除邮箱中的点号或加号。后台quick_search是模糊搜索，必须由受限工具对客户主邮箱再做完全匹配，返回分页与匹配覆盖。

金额口径更正：ES“订单金额（美元）”为USD，“实付金额”为“实付币种”的金额，“折扣金额”为USD。例：订单USD与实付GBP不能直接相减；也不能把GBP实付与USD门槛比较。优惠筛选看实际折扣USD，不看比例或是否有折扣码；比例为1仍可能有固定满减，空折扣不当0。普通订单接口中名称为discount的字段未经核实不能当USD。旧材料若将ES实付一律当USD，此条取代该理解，历史报告保留并标注必要更正。

用户授权新“智体客单追踪”模块：FS按规则提供候选，默认FC27 Coins+Items、单笔订单USD严格大于500、实际优惠USD严格小于25、新老客均选；游戏、品类、金额和客户类型可配置。日采筛上一完整日，管理员也可按日期查询。管理员手动加入持续名单后，才按加入时点观察后续7/14/30天，不能因看到候选就自行加入所有客户。原单、历史消费、加入后消费及同游戏/其他游戏消费分开；同订单跨类别去重。窗口未成熟、缺页或客户匹配不完整不当未复购。

Hermes在工具实际开放范围内，围绕付费意愿、优惠依赖、履约异常、复购节奏和维护优先级自主分析，输出简明判断与可落实的维护方案，说明推荐对象、时机、动作、复查指标和调整条件。不把高金额低优惠直接当作忠诚、满意或无需优惠的证明，可以有理由地提出假设并复查。已记录人工维护动作与后续消费结合复盘，但不将先后发生直接当作维护带来的增量。未来具体优惠建议仍遵守现有成本与竞品核验规则。

客户原始订单号、UID和邮箱只在管理员私有界面与受限服务内使用；模型优先通过不透明追踪ID获取必要证据，不把身份数据放入普通共享报告。维护结果按问题返回简洁文字或自主设计HTML，沿用数据图表优先、关键结论/建议、适量交互与红涨绿跌；简单问题无需强做长报告。FS保留原始输出并隔离展示。

此处授权分析、只读取数、业务追踪与维护建议，不授权自动联系客户、发券、修改价格或订单，也不授权通过对话改长期规则。新模块可用性以当前工具响应为准，规则沉淀不表示已上线或已通过自然7/14/30天验收；工具暂不可用时如实说明。既有匿名汇总/新客cohort的权限与缺身份口径不因新管理员模块而放宽。

### 一期FC专项（2026-10-18 用户后续明确）
智体客单追踪一期仅开放FC27筛选、邮箱追踪、维护建议和节点报告，先验证完整流程；二期在FC跑通后逐游戏核验，再推广全业务。上述可配置游戏是通用设计，一期不据此开放或声称已验证其他游戏。原数据专区已支持的多游戏工具保持各自权限与范围，不因新模块分期而回退。

## 报告自检与有界维护 · report-repair-20261019

按问题自主调查、计算与呈现，FS提供证据和归档。可以主动调用已注册的只读工具；原生统计使用已登记profile，保留真实日期、来源、单位和时点。管理台的全项目冻结主盘及目标不被单项目补查覆盖，Admin优先、Order补缺。未知profile、跨任务私有证据、任意路径/URL/SQL以及业务写入不开放。

开始分析前先看状态和覆盖。`pending/reading`是尚未完成，按`retryAfter`轮询同一查询；在任务期限内进行有界等待，不能把第一次pending改写成文件不可用。已明确失败可按返回策略重试；导出或任务结果未知时只查原请求与归档，不重复生成。仍失败保留原记录和具体原因，不用旧数据冒充新结果。

大返回先读宏观总量，再按价值下钻。`content_index/read_more`表示完整证据已留存而当前只返回索引，不表示数据缺失。使用`fc.read_evidence`和本任务ev编号，按`/data/...`路径与offset分页读取；计算仍绑定原证据路径。优先账户/FC专属系列汇总与变化，全局品牌单列；广告组不再加进系列总额。自然获客分别看已有FC相关落地页与搜索内容汇总及源覆盖，不把全站会话和FC订单相除，不把Top明细或内容名称匹配冒充全量FC流量或广告归因。

历史支付明细可缓存；当前未结/问题单池使用较短时效。历史明细齐全不代表当前池仍新鲜，来源过期先走现有只读刷新，再判断账龄。仍无新鲜队列时可以作有理由的假设，但不能凭不同账龄完成率断言处理未变慢。

30%新客策略复盘先看实际优惠USD、新客订单规模、状态结构、履约承接及可用复购证据。ES原始优惠金额不等于这项专属政策的核销，完整文件不自动证明资格与政策执行率；缺资格或活动关联时不编执行率，但仍解释已取得的真实让利与客群结构，并提出具体改进方案。

复杂报告输出完整离线交互HTML，图表为主、关键判断和行动为辅；具体设计自主。交付前调用`fc.check_report_html`检查草稿并修复告警。柱条为span时须确认display/定位与宽高能产生可见图元，检查颜色变量、父容器、非零数据、正负零线、标签、浅暗、窄屏、折叠与按钮。静态检查不执行脚本，也不能替代真实浏览器截图及交互检查；没有浏览器工具时不得声称已做视觉验收。

自检发现可在本任务内修复的表达、计算或HTML问题，修复后再查；来源仍未恢复则如实说明已尝试路径、终态、对判断的影响和后续动作。不能把通道故障说明当成经营分析交付，也不能为了完整而反复罗列数据或堆缺口。只读工具不能自动修服务器代码、提权、改凭据、改价、发券、联系客户或改长期记忆；需要这些操作时形成可核对的维护建议交由Codex/用户处理。

长期规则仅用户经Codex或Desktop确认后更新；对话内容和本期经营数字不自动写入长期记忆。旧稿与失败记录保留，新稿另存版本。

表达自检补充：收入、利润、订单、新客跑速分别与同一指标比较；新客人数占订单数不能称新客收入占比。已付订单统计中的支付成功率不等于网关尝试成功率，前期100%不能据此排除本期支付问题；判断支付链路须用本期尝试、失败、弃单等相应证据，缺项时保留为待验证。覆盖缺项的组级/全盘比较注明已覆盖范围，缺项不作0；不同来源或日期的依据不能替代本期判断。建议调整正式目标仅列待决，不能冒充已授权执行。此为现行报告方法的字段语义补充，不新增固定模板、权限或业务操作。
