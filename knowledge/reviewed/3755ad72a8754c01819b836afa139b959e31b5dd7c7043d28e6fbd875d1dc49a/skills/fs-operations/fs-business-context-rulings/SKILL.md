# 业务裁定落档

适用于用户给出长期偏好、纠正、口径或授权；一次性取数、某份报告的结论留原任务。候选、批准和实际生效分开记录。候选与审批规则统一引用已审 `fs-evidence-reconciliation` 的“长期裁定”条目，不在这里维护另一套可写规则。

## 原生候选入口

复用现有 `propose_context.py`。在实际Hermes解释器中按当前HOME定位已有帮助脚本，不能创建第二个发布器：

```python
from pathlib import Path
import runpy
helper = Path.home() / "scripts" / "hermes-memory-approval" / "propose_context.py"
proposal = runpy.run_path(str(helper))["proposal"]
# old_text为空表示追加；替换须唯一匹配，new_text允许为空表示删除原明确片段。
result = proposal(old_text, new_text, reason, evidence)
```

此调用只保存候选。`pending_id`、`staged=true` 不是生效，回复说明等待Codex审核；实际完成以原审核回执和目标读回为准。运行环境变化时先核帮助脚本和HOME，不把本次位置当永久事实。

## 每个主题保留的字段

先用一两句复述理解的对象与范围，按当前北京时间记录日期。一块一主题，使用明确起止标记以便定位。保留：生效日期及时间区／用户原话要点／适用项目和动作／已确认结论／不得据此推导的其他权限／替代旧条目的关系／尚未明确之处和复核条件。本人指令、机器人转述、推断分开，身份按原消息和已验证绑定核实。

旧规则被推翻时说明替代哪条并保留原文；待明确事项得到本人回答后形成只改对应片段的新候选，不篡改历史候选。已给出的授权不重复询问，但来源未取到或范围没答时不替本人补成永久许可。来源或目标改变先重读并按原CAS流程核对。

## 不采用的旧写法

本版替代1.0.0中“本人当场确认便直接追加共享记忆”、就地改未决行和以写文件SHA冒充审核完成的旧段落。用户明确内容仍须走原候选与Codex审核；本修订是落实既有审核约定，不撤销已有终端或业务工具能力。过往原话、前值及审批审计保留，不整包删除既有历史。
