# AION2 金币成本「本机代抓 DD373」—— 破风控，恢复自动改价

> 2026-10-06 深夜 · 生产机 `47.85.224.112`（play187）· 代码 `/opt/d4follow`
> 触发：老板「你自己用浏览器打开网页是可以看到价格的，你先想办法解决问题先」

---

## 一、问题

AION2 金币自动改价**停止出单**。逐环排查后定位：

| 环节 | 状态 |
|---|---|
| 服务 / 定时任务 | ✅ 正常（`d4follow-collect.timer` 每 15 分钟、`aion2-watch.timer` 每 15 分钟） |
| D4 金币 | ✅ 每轮正常出单（走 IGGM/p2pah，不依赖 DD373） |
| **DD373 成本采集** | ❌ **服务器出口 IP 被阿里云 WAF 打入风控**（无痕验证滑块页，自 20:33） |
| 结果 | 成本冻结在 `19:49:34` → 目标价不变 → AION2 86 区全部 `hold` → 无单 |

**关键认知纠正**（老板提供的线索）：老板**手动用浏览器能正常看到价格** ⇒
**DD373 并没有封我们的 IP**，拦的是「**自动化请求的特征**」。

实测三连（本机、同一 URL、同一时刻）：

| 请求方式 | 结果 |
|---|---|
| 无 cookie | ❌ 11955 B 拦页（`glbdetail`/`aliyunCaptcha`） |
| 只带 `acw_tc` | ❌ 仍拦 |
| **带浏览器整套 cookie** | ✅ **200 / 142561 B / 20 条 `goods-list-item`** |

⇒ 服务器那边是**出口 IP 段被持续风控**；本机是**缺浏览器 cookie**。两条路都堵，但
**「本机 + 浏览器 cookie」这条路是通的**。

## 二、方案

**本机代抓**：老板电脑上用真实 Edge 过站点拿 cookie，再用轻量请求批量抓，
解析逻辑**完全复用服务器同一份 `core_dd373_cost.py`**（只替换底层 `_get`），
结果经 SSH 推给服务器落库。

```
本机 dd373_local_collect.py
  ├─ ① 真实 Edge（可见）访问 dd373.com 首页 → 取整套 cookie（缓存 6h，失效才重开窗口）
  ├─ ② monkey-patch dd._get：同款重试/解压逻辑 + Cookie 头
  ├─ ③ dd.fetch_costs(svs, rate)  ← 与服务器 100% 同一份代码/同一套口径
  └─ ④ scp → 服务器 /tmp/dd373_push.json → 本机回环 curl POST /api/dd373_cost
                                            ↓
服务器 app.py（新增）
  ├─ POST /api/dd373_cost → store.save_gold_cost（**只写 gold_cost 表**）
  └─ collect_gold_cost 新分支：本机 20 分钟内推过 ⇒ **跳过服务器自抓**（不再撞风控）
                                            ↓
                    定时轮 → build_plan 读 gold_cost → 生成 AION2 金币工单 → 派给本机执行器
```

服务器 `8900` 只监听回环（实测本机 `curl http://47.85.224.112:8900` = `000`），
所以走 SSH 中转（scp + 远端 `curl 127.0.0.1:8900`）。这与既有 `/api/our`
（「服务器访问 mmoexp 会超时，所以由本机抓、推给服务器」）是同一种模式。

## 三、改动清单

### 服务器 `app.py`（改前 `d1dcce7a` → 改后 `893af2ec`）

| # | 位置 | 改动 |
|---|---|---|
| ① | `@app.route("/api/our")` 之后 | **新增 `POST /api/dd373_cost`**：接收本机推送的 `{ts, game, costs}`，调 `store.save_gold_cost` 落库，并把 `pushed_at` 写入 `data/dd373_local_push.json` |
| ② | `Task.collect_gold_cost()` 开头 | **新增「本机代抓优先」分支**：`data/dd373_local_push.json` 的 `pushed_at` 距今 < 20 分钟 ⇒ 记一行日志后 `return 0`，**跳过服务器自抓** |

⛔ 边界未越：本机推送**只写 `gold_cost`**，绝不写 `gold_price`/plan/目标价 ——
与 `collect_gold_cost` 原有的三条边界完全一致（成本仅作监控与定价输入）。

### 本机 `dd373_local_collect.py`（新增，归档 `本机脚本/`）

| 能力 | 说明 |
|---|---|
| `grab_cookie()` | 真实 **Edge**（`channel=msedge`，**headless=False**，持久化 profile）访问首页取 cookie |
| cookie 缓存 | 存 `.dd373_cookie.json`；下次**先复用**，用探针区（Asia\|Siel）试抓 1 次，失效才开浏览器 ⇒ 平时**不弹窗** |
| `make_get(cookie)` | 替换 `dd._get`，其余重试/解压逻辑照旧 |
| `fetch_costs()` | **直接调用服务器同款函数**（86 区 / 只读第 1 页 / 买满 1 亿订单簿加权） |
| `push_to_server()` | `scp` + 远端 `curl POST /api/dd373_cost` |
| `run_collect_push.bat` | 一键：`dd373_local_collect.py --push`，日志追加到 `验证/push_log.txt` |

参数：`--limit N`（联调）、`--gap`（间隔秒，默认 1.5）、`--refresh-cookie`（强制换 cookie）、
`--max-cookie-age`（默认 6h）、`--push`。

## 六、风险与待定

1. **本机 IP 也可能被风控**：今晚累计约 200+ 次请求（全量 86 ×2 轮 + 区服树 + 联调），
   目前探针仍 ✅。**建议采集间隔 ≥ 20 分钟**，不要高频狂抓。
2. **cookie 有效期未知**：设计为「先试后刷」，失效自动开浏览器重取（上限 6h 缓存）。
   ⇒ 长期无人值守时，每 ≤6 小时会弹一次 Edge 窗口（几秒）。
3. **自动化间隔待定**：目前是**手动一键**。若要常态化，建议
   **每 20 分钟**跑 `run_collect_push.bat`（Windows 计划任务即可），
   正好衔接服务器侧 20 分钟的「跳过自抓」阈值 —— **间隔由老板定**。
4. **本机执行器依赖**：执行方式已是 `local`（`POST /api/exec/mode {"mode":"local"}`，21:57 起），
   工单由老板电脑执行 ⇒ **本机休眠/关机时工单会排队**。服务器执行器仍在，可人工改派。
