## 一、根因（三个，都不是你操作的问题）

### 根因 1（致命）：服务器 SQLite 版本太老，心跳接口每次都崩

服务器代码用了 `INSERT ... ON CONFLICT ... DO UPDATE` 这种写法。
这个语法要 **SQLite 3.24 以上**，而服务器（CentOS 7）自带的是 **3.7.17**（2011 年的版本）。

结果：执行器每次发心跳 → 服务器报错崩溃 → 网页上永远显示"离线"。

```
sqlite3.OperationalError: near "ON": syntax error
```

**为什么以前测不出来**：你自己电脑的 SQLite 是 3.53（新版），能跑通，
所以本地测试全绿，问题被完美掩盖了。

**修法**：改成两个最简单的语句（先查再改/新增），任何版本都能跑。

---

### 根因 2：网站的登录方式换了，执行器还在用老办法

**9 月 30 日**全站登录方式从"浏览器弹密码框"换成了"登录页 + 签名 Cookie"。
但 MLB 执行器这个**不通过浏览器跑的小程序被漏掉了**，它还在用已经被废弃的旧认证方式。

结果：服务器根本不认它，每次都把它踢到登录页 —— 而且给的是"跳转"信号而不是"没权限"信号，
导致报错信息完全不沾边（报的是"JSON 解析失败"，跟真正的"没登录"毫无关系）。

**修法**：执行器改成先调登录接口拿 Cookie，之后带着 Cookie 访问。
另外补上会话过期后自动重新登录。

---

### 根因 3：启动脚本的换行符是错的，Windows 根本执行不了

`启动执行器.bat` 这个文件是用 **Unix 换行符**保存的（39 个 LF，0 个 CRLF）。
Windows 的 cmd 对纯 LF 的 .bat 会出现标签跳转错乱、条件块被跳过、甚至**整段静默不执行**。

**这正是"双击没反应、也没窗口"的直接原因。**

**修法**：新增一个规范化工具，把 .bat 统一转成 Windows 换行符（CRLF）+ UTF-8 BOM；
打包脚本里加了强制自检，以后不会再产出这种文件。

### 根因 4：bat 的 BOM + chcp，把脚本解析彻底打乱（**上一轮修复引入的回归**）

上一轮我为了「让 cmd 正确显示中文」，给 bat 加了 **UTF-8 BOM + `chcp 65001`**。
这两个恰恰是错误做法：

| 问题 | 机理 | 截图里的表现 |
|---|---|---|
| **UTF-8 BOM** | 首行 `@echo off` 变成 `锘絖echo off`，cmd 找不到这条命令 | `echo off` 从未生效 → **每行命令都带 `C:\...>` 回显** |
| **`chcp 65001`** | cmd 按字节读 bat，中途换代码页导致字节偏移与字符解码错位 | 文字被拦腰截断 → `setpass`、`'etpass' is not recognized` |
| **bat 里有中文** | cmd 用控制台代码页（本机 **936/GBK**）解析 bat，不是 UTF-8 | `◆◆` 满屏 |

> 关键认知：**cmd.exe 读 `.bat` 用控制台代码页，不是 UTF-8。**
> 所以「把中文写进 bat」本身就是雷区，`chcp` 救不回来。

### 修法：釜底抽薪

1. **bat 全部改成纯 7-bit ASCII**，一个非 ASCII 字符都没有。
   所有中文提示移交 `mlb_agent.py` 输出 —— Python 能精确控制编码。
2. **绝不写 BOM**（删掉 `_normalize_bat.py` 里的 BOM 逻辑，它就是元凶）。
3. **bat 里不再出现 `chcp`**（代码页切换交给 Python 侧 `_setup_console()`）。
4. `mlb_agent.py` 新增 `_setup_console()`：启动时把 stdout/stderr `reconfigure` 成
   UTF-8，并在真实控制台下 `SetConsoleOutputCP(65001)` —— 与 bat 分离，逻辑闭合。
5. `_normalize_bat.py` 从「编码转换工具」改为**强校验闸门**：
   检出非 ASCII / 裸 LF / chcp / BOM 任一项即 `SystemExit`，**拒绝出包**。
6. `_make_agent_zip.py` 取消 `try/except` 吞异常（原来会把坏字节照打进包 —— 事故成因），
   改为出包后对三条硬约束逐条复验。

### 根因 5：`goto` 在 if 括号块内不可靠（连带发现）

改密码逻辑时用 `goto :check_pass` 从 `if exist (...)` 块内跳出，
cmd 会中止整个块并报 `系统找不到文件 .`。改用**标志位变量** `PASS_SRC` 控制流，不再用 goto。

### 根因 6：密码文件被记事本改名

用户建的是 `.mlb_pass`，**记事本自动加扩展名**，落盘为 `.mlb_pass.txt`，
而程序只认无扩展名的名字 → 明明建了密码文件却还要输密码。
现在 `_password_file_candidates()` 展开 4 个变体
（`.mlb_pass` / `.mlb_pass.txt` / `mlb_pass.txt` / `mlb_pass`），
bat 侧也同步识别，并在启动时打印 `Password source: ...` 明确告知用的哪个。

### 根因 7：`"py -3"` 加引号导致退出码 9009

改用全路径探测（`python -c "import sys; print(sys.executable)"`）解决。
顺带修掉我误删 `--poll` 参数行造成的 `SyntaxError`（`py_compile` 扫出）。

## 六、这次最该记住的教训

1. **本地测试全绿 = 危险信号**。涉及数据库特性时，本机版本新会掩盖线上老版本的问题，
   必须在服务器上验一遍。
2. **换认证体系要搜全部调用方**。9 月 30 日切门户时漏掉了 MLB 执行器这个非浏览器客户端。
3. **非浏览器客户端的认证要有专门设计**。让脚本去模拟网页登录是脆弱的，
   长远看应该给内部服务发长期 token，或走 nginx 白名单。
4. **HTTP 302 要当一等公民处理**。登录门禁把"未登录"做成跳转而不是错误，
   客户端如果老实跟随，就会拿到 HTML 而报出与真实原因无关的错。
5. **`.bat` 铁律（两次事故换来的，写代码时照做）**：
   - 换行必须 **CRLF**
   - **绝不带 BOM** —— BOM 会让首行 `@echo off` 失效，导致全屏回显
   - **绝不在 bat 里出现非 ASCII 字符** —— cmd 按控制台代码页（本机 936/GBK）解析，不是 UTF-8
   - **绝不用 `chcp` 改代码页** —— 会在读文件中途换编码，导致字节偏移错位、文本被截断
   - **绝不在 `if (...)` 块内用 `goto`** —— 会中止整块并报「系统找不到文件」；改用标志位变量
   - 中文提示一律交给 Python 输出，Python 侧用 `reconfigure(encoding='utf-8')` +
     `SetConsoleOutputCP(65001)` 自己控制编码
6. **修复要「让错误不可能发生」，不是「修好当前这一个」**。
   规范化工具从"尽力转换"改成"检出问题就拒绝出包"，打包脚本不再 `try/except` 吞异常 ——
   原来的 `try/except` 正是把坏字节照打进包、送到用户手上的直接原因。
7. **验证必须实跑，不能只做静态检查**。本轮通过 6 个沙箱场景实跑 bat，
   才抓出 `goto` 块内失效和 `"py -3"` 退出码 9009 这两个纯静态检查发现不了的问题。

# 补充：第四轮故障 —— 登录 HTTP 303/308（2026-10-12）

## 现象
```
[X] 登录失败（HTTP 303）：被重定向到 https://47.85.224.112/__auth/login（多半是没登录或密码错）
```

## 结论：不是密码问题，是站点强制 HTTPS
nginx `/etc/nginx/conf.d/iggm-web.conf`：
```nginx
location /__auth/ {
    if ($scheme = http) { return 308 https://47.85.224.112$request_uri; }
    ...
}
```
门户启动日志：`secure_cookie=True`。

⇒ 走 `http://` 的登录 POST **在 nginx 就被308 拦掉，根本没到门户**。
用户看到的 303/308 全部由 nginx 产生；门户源码只有一处 `send_response(302)`。

**最有力的判据**：`journalctl -u auth-portal` 里最后一条 `wulv` 记录停在 10-05，
10-10 之后只有 `chenchao` —— 门户没收到我们的请求，直接排除密码错误与账号锁定。

## 实测响应码
| 请求 | 响应 |
|---|---|
| `GET http:///__auth/login` | 308 → https |
| `GET https:///__auth/login` | 200 |
| `GET http:///mlb/` | 302 → `/__auth/access/?next=/mlb/` |
| `POST http:///__auth/login` | 308 → https |

## 修复
1. `_normalize_site()`：http → https 强制升级；无 scheme 默认补 https。
2. 新增 `Hub._ssl_context()` / `Hub._opener()`，opener 带 `ProxyHandler({})` 强制直连。
3. **新增手动登录模式** `--manual-login`（用户明确要求）：
   弹真实 Chrome → 用户手登 → 轮询抓 `MMOEXP_AUTH` → health 校验。
   profile 用 `~/MLB新卡上架/portal_profile`，与 showdd 采集 profile 隔离。
4. `启动执行器.bat` 加登录模式菜单 `[1] 自动 / [2] 手动`。
5. 登录失败提示按 303/308 分别给出可操作原因。
