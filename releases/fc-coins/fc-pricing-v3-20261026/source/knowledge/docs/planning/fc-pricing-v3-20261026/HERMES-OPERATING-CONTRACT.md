## 3. 预测基数：每个字段如何算

| 字段 | 单位与来源 | 计算与核算条件 | 缺失时如何处理 |
| --- | --- | --- | --- |
| `orders_per_block` | 实际付费订单/6小时；同网站、游戏、Coins及价格组的Admin订单 | 订单数÷实际覆盖小时×6；七完整日为168小时，不能误除84个两小时块 | 用已核覆盖建立并标识初始估计；没有数量依据只给相对指数，不伪造绝对销量 |
| `reference_regular_usd` | 当前可见100K常规商品USD价格 | 与实际平台、地区系数、套餐和币种一致；历史均值映射到当前价属于冷启动假设 | 不用旧历史价格冒充当前公开价 |
| `target_revenue_per_order_usd` | 同批真实净实付USD/订单 | 同批净收入÷付费订单；是混合客单价，不是100K商品价 | 可用明确标注的估计，但不能把原币实付直接当USD |
| `purchase_k` / `bonus_k` / `delivered_k` | K金币，1K=1000金币 | 原订单购买K、历史赠送K分别核算；交付K=购买K+赠送K，乘订单行数量 | 不拿当前赠送规则替换历史赠送，不将未知补零 |
| `delivered_k_per_order` | K/实际订单 | 同批交付总K÷订单数，包含所有赠送 | 缺失时不能把每单固定当100K或105K |
| `new_customer_ratio` | 有效新客人数/同批订单 | 用已核客户邮箱去重及该笔下单时ES「是否新客户」（是/否），不得用Admin列表isNew或当前会员身份回推；窗口内首次合格订单归属，UID=0保留 | 单列身份覆盖；不将所有游客、GA newUsers或总订单当新客 |
| `retained_ratio` | 净保留比例 | 与所用AOV/优惠路径采用同一分母；净AOV已经含历史优惠，不能再重复扣一次 | 明示缺口，不混用地区系数与优惠留存 |
| `elasticity` | 无量纲 | 初始中心2，敏感性0.5/1/2/4；仅有真实有效价格曝光和订单后才能拟合 | 初始假设可以用于获授权探索，不能称拟合事实 |
| `backlog_k` | 当前可交付积压K | 按用户最终白名单，仅已支付新单、验证通过、发货中三种；按后台原生枚举映射，不限近7日付款，已暂停和所有其他状态排除。问题单（账号/密码错误、待客服或重新验证）排除，不为其逐单校验；退款、争议和待客户动作不混入供给压力 | 已知部分单列覆盖，不能填0或冒充完整当前积压；问题单可单列数量，但不驱动提价/限流 |
| `capacity_k_per_block` | 可交付K/6小时 | 已核供应能力；没有承诺值时可用明确标注的近期观测吞吐推算并持续验证 | 观测吞吐≠供应承诺；说明样本窗口、旧cohort遗漏与估计性质 |
| `capacity_reserve_ratio` | 0至小于1 | 默认留10%容量余量；按全局/价格组真实共享关系一次合并入流 | 不给Console和PC各自使用同一份全局容量 |
| `mtd` / 区间 | 当月同范围净收入USD | 只用已核付款日期、目标范围与金额口径；截至日、今日缺口和未分类上界一起显示 | 已核下界可用于决策，但不称实时精确累计；目标为空不编造目标值 |

## 7. 持续学习：样本如何进入、何时更新
