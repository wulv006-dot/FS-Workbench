# FC 自动改价锁、门禁与恢复处理规则

这份规则对应2026-10-13已上线的两个补强文件和当时其它活动保护，业务参数仍由原配置决定。历史错误保留；不得为求全绿删锁、改账本、换ID重放或恢复退役Player复验。

| 实际情况 | 处理规则 | 放行依据 |
| --- | --- | --- |
| 锁被活跃任务持有 | NB返回忙/等待，不清锁、不并发派发 | 原进程释放原inode；再次核队列/策略/最新任务 |
| 锁文件存在但无持有者 | 文件存在不等于死锁，不删除/重建inode | 原flock、owner/mode/nlink与inode检查 |
| 正常采集/预览/写价在途 | 保持原任务和期限，不新增替代任务 | heartbeat/任务阶段/原ID；超限或不明才进入待核对 |
| CDP/页面/点击短暂只读超时 | 原95秒预算内最多完整再读一次；原失败诊断留存 | 全部平台/单位/优惠/完整性检查仍通过 |
| 非核心来源缺失 | 沿已批非核心互兜；核心成本/汇率/可比来源仍必需 | 原quote/worker逐平台检查，缺项不填0 |
| 采集终态失败且未派发 | 原tick有界新采集恢复，不重放业务写入 | proven_prewrite及零请求/执行/ALL/Player副作用，原5/15/30/60分钟节奏 |
| 新输入完整但写前门禁未恢复 | 原证明桥接与两次健康观察，等待原门禁放行 | 同ID/配置/时序/最新采集及公开页归属、无UNKNOWN |
| ALL POST响应TimeoutError | 不重发；只GET两轮确认同源、目标、档位、保护字段与身份/策略 | 30秒窗口内两次稳定精确读回；单个在途GET仍原15秒限时 |
| POST未落地/第三值/拒绝/未知/读回失败 | 保留派发意图与needs_reconcile，后续平台不发 | 明确人工对账原ID；不能用新任务掩盖 |
| 缓存或公开价未确认 | 后台确认与公开完成分开；按原缓存/公开读回合同处理 | 原execution、合法身份、严格同run/同平台；不重复writer |
| Player仅展示卡无价 | 不作为异常或放行条件，不做价格/公式/同步生效复验 | 唯一category请求与原金币输入/身份保护；accepted仅为请求返回成功 |
| 用户OFF/Gallery OFF | 不自动开启，不当成待修服务 | 用户原开关独立有效 |
| 历史failed但后续任务已成功 | 历史保持failed或恢复history，不再冒充当前未恢复 | 当前任务、同周期证据及配置；恢复状态与历史日志分开 |
| 新代码发布 | 队列原inode→价格锁→三采集锁，全部NB；锁内两次SHA/CAS，精确两文件，备份/原子替换/读回 | 当前空闲且无UNKNOWN；check-only不写，--apply才替换；失败回退代码 |

13把相关锁已于本轮只读核对：queue/tick、价格、预览、snapshot、成本、汇率、Lootbar、IGGM/U4GM/U7Buy、两策略锁及独立collector锁。每种锁只管各自资源；服务在线、当前无锁持有、原请求成功、价格实际一致和下一自然周期成功是不同证据，不互相替代。

正常等待/重采/恢复观察应按当前状态解释；保留真正失败和未知的警报。新补强没有新增自动写价恢复任务、后台登录权限、报价系数、调度器或通知流程。无法确认的写入继续人工处理。
