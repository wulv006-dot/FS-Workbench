# SBC/Packs 改价回执：离线兼容合同

提供离线改价候选、回执解释和对账汇总，未接入或覆盖生产改价执行器。没有生产部署载荷、接口改动、定时任务或发布器。

- 旧回执：整轮和第八步分别按原布尔值显示。整轮报成功而任一步明确报失败，标记冲突。按精确步骤名称识别第八步，缺失或重复不猜测；历史记录始终保留。通用“完成”、旧响应计数和提交受理均不证明已写价，也不能证明零写入。
- 候选对账：固定计划里每个商品/区服键唯一；只统计同一操作关联的后台读回。无逐行证据记未知，不用后来碰巧相同的价格补证。只有确认不需要写且已比对才记未变；拒绝、未尝试、未知各自计数。有确认改价但部分仍未完成时才记部分成功。调用方必须先冻结计划并核实证据；本模块不产生证据、不代写后台。
- 核心逻辑未触碰：定价、取价来源、商品筛选、舍入、调用顺序、重试和上下架保持原样。后续要接执行链，先用脱敏或合成样本锁定三平台实际 100K 口径、SBC/Packs 费用与覆盖规则、自动/手动/上架设置差异；另验原权限、互斥、历史回执保留和安全回退。不能把旧归档视作当前线上版本。
- 独立上线门槛：需要现役接口契约、逐行对照样本和经过验证的发布/回退路径；不能为了满足旧发布前置检查而擅停自动改价或下架。上线后只读核对正常生产轮次，不手动重跑改价。
- 所有测试数据为合成数据。

## 按站点分流的离线替换候选

- 旧版自动拉商品时查询模板站点 0，而“所有站点”是另一个查询模式。主站 Coins 100K 取价是输入，不决定 SBC/Packs 商品该写哪个站点。
- `site_reprice` 先核模型、明确站点、区服、游戏、类别，再对得上唯一 Admin 商品行才生成候选。空配置、跨站、重复行、未知类别都不生成候选，模板站点 0 不迁移；当前真实逐模型配置未恢复，此包没有生产配置或默认路由。
- `reprice_plan` 使用显式且获确认的价格输入及规则。独立区分 100K 参考站与商品站。未核定的规则、现价字段或多数量行不猜测。候选计算须显式确认公式和舍入。已确认的人工整分目标价走单独路径，不重套加成、费用或下限；这不是对当前线上策略的证明。SBC/Packs 的价格策略或实际启用范围应在接入前对照。
- `shadow_verify` 只判读合成的同操作、同商品、同站点和同区服证据。折扣需归位时，先验证折扣中间态再验证单位价；比对折扣、单位价、数量和衍生售价。超时不猜，已发生部分效果不当作零写入。候选代码没有 Admin 请求、写入、重试或生产接线。

逐行仿真判定与整轮汇总仍是独立接口，不直接把逐行部分生效映射成改价确认；接入时须保留已证折扣效果与未确认目标价。
