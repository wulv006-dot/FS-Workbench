# SBC/Packs 改价回执：离线兼容合同

提供离线改价候选、回执解释和对账汇总，未接入或覆盖生产改价执行器。没有生产部署载荷、接口改动、定时任务或发布器。

- 旧回执：整轮和第八步分别按原布尔值显示。整轮报成功而任一步明确报失败，标记冲突。按精确步骤名称识别第八步，缺失或重复不猜测；历史记录始终保留。通用“完成”、旧响应计数和提交受理均不证明已写价，也不能证明零写入。
- 候选对账：固定计划里每个商品/区服键唯一；只统计同一操作关联的后台读回。无逐行证据记未知，不用后来碰巧相同的价格补证。只有确认不需要写且已比对才记未变；拒绝、未尝试、未知各自计数。有确认改价但部分仍未完成时才记部分成功。调用方必须先冻结计划并核实证据；本模块不产生证据、不代写后台。
- 核心逻辑未触碰：定价、取价来源、商品筛选、舍入、调用顺序、重试和上下架保持原样。后续要接执行链，先用脱敏或合成样本锁定三平台实际 100K 口径、SBC/Packs 费用与覆盖规则、自动/手动/上架设置差异；另验原权限、互斥、历史回执保留和安全回退。不能把旧归档视作当前线上版本。
- 独立上线门槛：需要现役接口契约、逐行对照样本和经过验证的发布/回退路径；不能为了满足旧发布前置检查而擅停自动改价或下架。上线后只读核对正常生产轮次，不手动重跑改价。
- 所有测试数据为合成数据。

## ALL 配置、MMOEXP 读回的离线替换候选

- 配置目标只允许 Admin 的 ALL 模板（站点 0），不是不筛选的全站查询或逐站写入。定价输入和结果读回只允许 MMOEXP 主站（站点 266）。二者以同模型、区服、游戏及类别对应，不复用主站在售商品 ID 作配置目标。
- `site_reprice` 只用唯一匹配的主站商品快照与明确的 ALL 规则生成模板配置候选。主站当前同价不能证明模板已配置。验证需要同一操作的 ALL 保存确认与 MMOEXP 主站读回；不验证卫星站传播，也不增加任何对 ALL 的运行时查询。
- `reprice_plan` 使用显式且获确认的价格输入及规则。独立区分 100K 参考站与商品站。未核定的规则、现价字段或多数量行不猜测。候选计算须显式确认公式和舍入。已确认的人工整分目标价走单独路径，不重套加成、费用或下限；这不是对当前线上策略的证明。SBC/Packs 的价格策略或实际启用范围应在接入前对照。
- `shadow_verify` 是历史逐行写法的独立仿真，不代表 ALL 配置脚本的协议。只判读合成的同操作、同商品、同站点和同区服证据。折扣需归位时，先验证折扣中间态再验证单位价；比对折扣、单位价、数量和衍生售价。超时不猜，已发生部分效果不当作零写入。候选代码没有 Admin 请求、写入、重试或生产接线。

逐行仿真判定与整轮汇总仍是独立接口，不直接把逐行部分生效映射成改价确认；接入时须保留已证折扣效果与未确认目标价。

生产接入前须验证现有 SBC 管理脚本的真实配置字段、作用域、版本保护与可恢复流程，及同一轮实际主站读回。没有可核证据时不重发或逐站补写。

这里的站点 0 只表示已知的 ALL 模板作用域，不假定现役管理脚本使用商品行接口或相同参数名。仿真价格只覆盖当前候选支持的单数量、整分情形；后台可能提供更高精度原值，未经对照不能把合法原值当作线上异常。

首次生产试点的准入条件（不是已实现的运行时闸门）：只选一个从现行配置核实、归属 SBC 且不属于独立 Bundle 写入任务的模型，锁定 ALL 下的具体平台及类别。所有 Packs 暂不参加首次试点；后续扩围前按真实站点模板、模型和平台核对写入归属，重复、缺失或不明确均不启用。下架保护名单不能作为改价排除名单，另一个任务的改价回执也不能作为 SBC 生效证据。
