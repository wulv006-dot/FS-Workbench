## 1. 取数原则与来源分工

- 同字段 Admin 优先，Admin 没有而 Order 有则直接补缺。用户已确认两源在经营用途可采用，不再因站点或平台范围差异拒用已有 Order 参考值；展示来源和范围即可。有效 0 保留，缺失保持未知。
- 经营总盘优先 Admin 原生统计。Admin 支付明细、ES 下载用于结构分析，不能因总额不同就改写原生总盘。完整结构内部可比较，不要求先与不同范围总盘强行核平；跨源绝对归因仍须说明范围差异。
- Admin 缺利润时，参考利润 USD = 对应期间 Admin 销售额 USD × 对应期间 Order 参考利润率 / 100。标为经营估算、非财务实结。整周、月累计使用对应整段参考率，不平均日率、不以最新采购价倒推历史成本。
- 查询先明确游戏、站点、平台、商品粒度、原状态、时间字段和时区。页面叫“下单时间”也不能擅自认定接口使用创建时间：已核 Admin 商品订单接口实际提交 paytime，保留原字段。历史近 7/14/30 日以昨日为 D1，今日数值标截至取数时刻。
- MMOEXP 与相关卫星站的经营范围按问题选择。G2G/ELD 分销不属于当前团队，但 Order 全局统计包含它们，允许按上述规则用作参考。折扣码推广分类不是站点归属证据。

## 2. 订单详情与问题原因

入口：**Order → 订单管理 → 订单列表 → 选择对应游戏 → 查看订单**。可筛游戏区服、付款/下单时间（保留实际字段）、商品类别、订单状态、产品标题、订单号、关键字。

这里的**关键字对应下单客户邮箱，即角色名字段**，不是供应商名。邮箱关联以实际核实一致为准，不能按姓名、电话、IP、相似邮箱猜同一客户，不擅自去除邮箱加号或点号。订单号精确查询优先于模糊匹配。

订单详情中的**订单日志**记录从下单到交付的过程及问题，问题单、退款单、CB/欺诈单的说明在此复核。汇总只能发现异常，不能代替逐笔日志判断原因。记录原订单、筛选条件、日志时间和原因分类；普通模型证据只传必要脱敏事实，客户邮箱和自由文本不进入公开报告或长期经验。

当前 Order 列表默认只显示部分活动状态；调查全部订单必须明确状态筛选，不能把默认列表当全量历史。仅用户界面可查询不等于 FS 已实现相应工具；工具不支持时明确缺项，继续已有来源可支持的判断。

## 3. Admin 全站订单下载、优惠和客户

入口：**Admin → 订单管理 → 销售订单下载（ES 销售订单下载）**。既有已核入口 `/admin/order/makeExcelByEs`，后台下载端点和身份沿现有受控导出服务，不另建登录。

按日期下载当日全部原状态订单，再按游戏、品类、金额、状态、新老客、来源及优惠筛选。已核导出字段含订单号、订单金额、实付及币种、付款时间、支付方式、新老客、订单来源、推广人、折扣码、国家、优惠类型、折扣比例、折扣金额；产品 SKU、站点与平台是否存在按实际版本核对，不能由汇总猜补。复用同一窗口原导出档案，不因切分组重导出；分页/文件集/去重冲突独立标示。

- 订单金额 USD；折扣/优惠金额 USD；实付金额保留实际支付币种，例如 GBP。不可用订单 USD 减原币实付推算优惠，不用折扣比例替代实际折扣筛选。
- 无码不等于无优惠，折扣比例不能替代固定满减。整单折扣只计一次，保留原正负号；退款是否冲回依实际记录，不自行补算。收入已扣优惠时不得再次扣同一折扣。
- 同订单多商品行不重复累计整单收入或整单优惠。混合订单的整单金额不能全部称为某个 SKU 收入，不无依据分摊。
- UID=0 是正常游客；支付邮箱必填不意味着客户邮箱与支付账号字段必然相同。以已核客户邮箱关联，UID 辅助，新老客按后台原始标记；游客不自动归新客。
- 新客订单数不等于去重客户数；期间老客占比不是同批新客留存。首单 30% 是已确认经营策略，不证明全部新客标记订单都符合资格或实际核销 30%。

## 4. 履约采购、供应商与成本

入口一：**Order → 订单管理 → 发货记录 → 订单交货记录**。可筛游戏、产品类型、交货类型、时间、订单号、关键字。**这里的关键字对应供货商名，与订单列表的邮箱含义不同。** 读取实际单笔成本、数量、类型、利润率、供应商及时间；金币数量统一 K，金额无特殊说明均 CNY（人民币）。

入口二：**同处 → 订单交货记录统计**。按游戏/区服看供应商采购总量、总价、最新单价。FC27 ▶ PS 指 PS 平台金币，不是所有平台总计。

Players、SBC、Packs 通常先由供应商给账号充 Coins，再由发货人员/自动化系统买球员或完成任务。核心采购成本链依赖实际金币：不能按球员售卖数量直接当 K，也不能把原价参数当真实采购。

**本次补充确认：**购买环节的自动化流量费、使用费统一算在自家库存里，本期不额外重复核算。供应商正常提供的金币仍有成本；“自家库存”不等于免费金币，也不自动证明实际总成本已逐单完整分摊。沿既有库存记录使用，不新造人工或系统费用费率。

报价当前成本继续采用对应平台、核实的最新有效**订单发货**成交成本，保留订单类型和时刻；不使用采购打款、销售补发/赠送或未知交货类型冒充常规采购单价。最新有效成交价是当前报价输入，不能拿来当整段历史 COGS。历史毛利须按对应订单/发货记录及已核汇率归属，避免一单多次发货重复计算收入。

## 5. Order 统计的用途

**统计管理 → 订单统计**：全局含 G2G、ELD 分销；按日期、游戏查看已完成、交易中、已取消、问题单及品类。游戏发货/供货商发货反映履约与供应商情况。状态池是取数时的存量，不自动等于历史日末积压。

**统计管理 → 发货统计**：销售总额、采购总额和 Order 利润率参考来源。用户经验判断包含分销且占比较小，可作经营参考和推断；包含范围及占比的本次独立量化核验另记，不能将“小”写成已测百分比，也不能因此禁用有效参考率。

后台原生利润率与自行计算毛利率分名。要自算时先统一收入/成本币种、范围、时间与退款处理，以总毛利/总收入计算，不平均订单率。缺完整费用不能称净利润，不默认再扣历史 5% 费用或虚构手续费。

## 6. 金币价格管理：四个同名陷阱

入口：**Order → 游戏产品（界面亦称游戏&产品）→ 金币价格管理 → 游戏/平台**。

| 页面字段 | 真实含义 | 可用于什么 |
|---|---|---|
| 最新采购价 | 对应平台最新订单成本单价，CNY/K；实际输入仍核订单类型与时效 | 当前成本线索，非历史整段成本 |
| 采购成本 | 控制售价的参数，不是实际采购经济成本 | 反算/设置 B2C 参数 |
| 利润率 | 页面固定的售价公式参数，不是实测经营利润率 | 仅用于页面换算 |
| 货币汇率（如 6.65） | 固定的售价公式参数，不是真实当前 FX | 仅用于页面换算 |
| B2C 价格 | MMOEXP 前台金币页每 K 售价，USD/K | 与实测前台/套餐核对 |

页面换算：`B2C USD/K = 采购成本参数 CNY/K / (1 - 利润率参数) / 汇率参数`。若页面显示百分数，计算时先除以 100。反算控制参数：`采购成本参数 = B2C USD/K × (1 - 利润率参数) × 汇率参数`。参数原值沿现有配置读取，不能用固定 6.65 证明当前经营换汇价。

真实采购成本、页面调价参数、实际市场汇率、Order 参考利润率分别存放、命名和解释。报价毛利核原引擎对赠送、成本及有效汇率的定义；基线计算价、实际前台价和候选模拟价三者分开。

### 尾价偏好（本次用户确认）

用户偏好整数临界附近采用 .99，**$10.09 → $9.99 只是可接受幅度的示例，不能固化为全价位 $0.10 阈值**。按前台实际展示套餐总价 `P`、对应交付成本 USD `C` 和原最低毛利率 `m`，计算向下 .99 的候选 `T=floor(P)-0.01`。不向上凑价；原价已是 .99 保持。

本次实施的保守控制预算（实施者计算控制，不冒称用户逐项指定）：让利不超过套餐价 1%、现有采购毛利额 5%、采购毛利率下降 1 个百分点，且不能突破原利润底线。四者同时满足，以最严格者确定每行可让利空间：`min(0.01P, 0.05(P-C), P-C/(C/P+0.01), P-C/(1-m))`，小于 0 时取 0；`m` 用小数。仅当 `P-T` 在预算内才取尾价。成本含实际交付金币及赠送，汇率用有效实际源，不用页面 6.65 参数。

这使同为 $10.09 的两个套餐在成本不同的情况下可以作不同决定，也允许高价套餐的美元绝对调整大于低价套餐；不以固定数值强行套全部平台。预算及原价/候选/毛利变化在模拟回执中列出，后续按真实效果复盘，不能宣称 .99 已被证明增加销量或利润。

必须用尾价重新核原利润底线、赠送、优惠与平台联动。触底保留原合格价并给原因，不能为尾数放宽底线。Coins 以每 K 参数联动各套餐，一个参数无法保证所有套餐都独立 .99；按引擎实际支持的展示基准与回读落实，不把总价让利误施到每 K，更不绕过原 writer。规则偏好不证明任何真实售价已改变。

## 10. Hermes 的学习和决策方法

先根据待做决定选择最小必要工具链：概况读原生统计；优惠/渠道读同窗口 ES；SKU 核真实产品；原因查订单日志；成本查订单交货；客户看已核邮箱/成熟观察窗；定价读取有效成本、当前可比竞品和实际前台，按原引擎模拟。目录、schema 和实际回执是工具能力依据，后台页面存在不能伪称已接入。

教学应让 Hermes 自己提出竞争解释、选择必要数据、绑定字段/数量口径/时点/来源计算、找反例、修正并给行动与撤回条件。Astra 的独立方案是教学对照基准，不能当 Hermes 自己学会、实测最优或自动执行授权；用未见过的场景检验其独立运用，失败如实保留。

长期保存的是经审核的方法、业务规则和反例；当前成本、价格、客户状态、运行开关留在任务事实与账本。经验候选人工审核/CAS 发布、可撤销，旧任务引用不改写；新方法差异按原等级审核，不开放自动策略修改、生产写价或任意插件安装。

现行 FC 跟价来源优先级继续保留：Lootbar 必须有效，U4GM/IGGM 有哪个用哪个，两者均缺才用 U7Buy；无有效其他参考跟 Lootbar，仍过成本、赠送与平台保护。新研究可突破旧降幅或提出新规则，但现有采价周期、自动化开关、利润底线、售卖链路保持。Player wiki 价格不恢复日常复验；用户主动 OFF 不当故障，不擅自开启。
