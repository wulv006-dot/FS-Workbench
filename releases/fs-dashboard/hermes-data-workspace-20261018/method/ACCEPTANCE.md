# 报告验收标准 · 1.5.1（2026-10-18）

简单文本按问题、依据、确定程度与可行动性验收，不要求页面或交互；以下视觉、页面与下载检查仅在交付HTML时适用。

1. 读者效果：首屏能说清这期情况、重要问题和优先动作；逐模块看图能理解变化，文字补充关键结论/分析/建议，不复述整张数表、不堆方法和免责声明。
2. 覆盖：销售利润与客户商品、履约交付与支付售后、运营优惠/复购、广告及自然获客、现实节点/活动、历史动作与效果、风险机会/待决均经过检查；日报周报可侧重，不能因某类数据多而偏科或为凑齐章节虚构问题。
3. 实用性：重要判断有对应证据和业务含义；建议有对象、最小动作、可行性、产物、岗位、时限、衡量及调整条件。活动有现实节点与承接，待决有选项/影响/推荐理由；合理推断允许，不假称因果已证或建议已执行。
4. 数字：Admin优先含0、Order补缺；来源/日期/游戏/单位/分母正确，参考利润不冒充实结。缺失不填零，不造残差品类。图文同源、原精度计算，不把问题聚合猜成同批解决率。
5. 视觉：报告设计自主、FS只作宏观参考，不检查像不像FS页面。检查图表是否与信息量相称、对比是否清楚、文字和标签是否可读、关键内容是否默认可见。没有巨大空图、装饰性图或多屏文字代替数据表达。涨红跌绿语义保持，其余配色/字体/布局/图表自由。
6. 交互：真实1440/390、浅暗、指标/期间或细分切换、折叠、键盘、打印和下载后离线重开。选择的交互确实有用，切换同步数字/单位/说明；无页面横向溢出、拉伸、脚本错误、外发请求。无浏览器能力标未验。
7. 学习与版本：现行入口只有report-html-authoring；记录输入版本/文件SHA及输出SHA，旧稿和失败保留。文件上传/组装成功只证明已接入，不能冒称实际新稿质量已验收。每次改稿只重验受影响部分。

HTML交付前，如当前已开放代码工具可用，实际提取并检查内联JavaScript语法，移除占位表达式和未完成代码；无该工具时标明语法未实测，不声称已通过。语法通过仍须另验图表、交互与业务结论，不能替代浏览器和内容验收。
