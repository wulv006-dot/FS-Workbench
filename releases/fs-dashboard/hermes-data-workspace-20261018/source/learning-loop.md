客单价不等于商品单位售价；聚合支付结构不能证明用户迁移或通道替代。高对照基数不能证明剔除后未恶化，大额单真实仍可能构成高基数。两周波动或无小时尖峰不能证明规律、排除全天事件/持续投放或认定通道故障。原因标可能/假说/待验证并列竞争解释和反转条件；AU为澳大利亚。UTC取证时点正确换算北京时间。

各指标按实际读取的现行条目与对应来源确定主盘，支付明细保留自身分母。仅同源、同范围、同冻结版本且已证实穷尽可加的集合做内部闭合；差异如实列来源与时点，不为核平改选主盘。无联合分组证据不从边际表或残差造交叉数据；缺失保留null。服务器联网不证明研究沙箱可外连；历史故障不是永久能力事实。

生成终检（2026-10-17真实日报复核）：提交最终成稿前逐条检查摘要、模块结论和行动触发条件，不只检查表格。对上周同日写“较上周同日”，只有上年同日期才叫同比；某日不在趋势窗口内，不能列为该窗口最高。客单价只能称客单价，缺数量档不能断言单位售价涨跌；已有竞争解释不能在模块结论中改写成已证实原因，支付成功率也不能单独排除支付故障。全盘订单阈值不能移用为任一平台阈值；新客人数除订单数不能称新客订单占比，无逐人订单关联不能由订单减付款人数推出复购笔数。数值门槛如为建议须写待校准，不能把跨范围比较当作反转条件。逐条修正后再输出，原始取数与证据引用保持不变。

上述区分同样适用于开头一句话：没有单位售价证据时，不把客单价变化说成已经排除了单位售价原因；获取端与供给端的解释按证据强弱表述，有足够证据可以作判断，否则保留为待验证假说。FC为订单驱动、无持货库存，分析供应商接单能力、商品可售状态与交付时效，不套用持货备货建议。没有对照批次当时T+N历史快照，就改用可获得的趋势或明确单批跟踪，不能声称未来复读能补出旧批次同日龄证据。计划以实际编制日为锚；过去日期可作历史复盘，不当成未来截止日。

利润计算与经营判断分开：利润主盘、参考估算及目标匹配按实际读取的现行数据与报告合同分别处理。保留同源、期间、分母、估算标记及覆盖；不把区间趋势冒充当日结果。成本回填、履约或结算时点可列为波动的待验证原因，有证据才能认定。参考估算不能代替具体新售价所需的有效成本和当前可比竞品实价。


## 流量与决策口径
- 空来源是“自然流量（业务默认）”，不等于已核实SEO成交；成交游戏与投放归属分开。
- FC27/FC 27（兼容FC-27、FC_27）或独立Coins名称按已确认规则筛选，排除其他FC年份、FC270及明确其他游戏（如Madden-SN-Coins）。google-FC27-PMAX-Coins-US是主站全局品牌例外，不整条归FC、不自动分摊；先用全量计算系列再筛游戏，Top仅展示。保留原文本、命中规则、账号币种、时区及覆盖；其他游戏名称线索不升级为已证订单归因。
- Ads原生CVR、平台ROAS与Admin成交并列，不拼虚假漏斗；互动分母缺失不以clicks替代，多系列缺合法分母不报聚合原生CVR。GA4全站不能叫FC流量；GSC查询/页面只用实际返回匹配，边际表不拼交叉表。
- 昨日/近7、14、30天截止昨日；月报取完整自然月，月累计标截止且不与完整月作月环比。不同源时区保留；同日营销缺失仅能标背景，不拿旧周替代。
- 收入下降调查：先用Admin同范围收入、订单、客单价，调用revenue_decomposition核对数值贡献；再查同期专属/品牌广告、相关页面/搜索、商品/国家/平台结构及支付/同订单群履约、退款/CB。当前池不当历史池，支付差额不全当积压，订单数不等于金币数量，PS Coins PID是平台产品族汇总。
- 判断按事实、支持证据、替代解释、动作、复查展开。证据充分可明确判断；只有同步下降时写优先方向。建议含范围、角色、前提、指标、护栏、日期及停止条件；无依据不编幅度，不自动改价/预算/派单/修复。
- 读取历史已执行行动的可信状态，再评效果；未执行不判无效，混杂因素写明。日报复查到期项；周报归纳有效行动及未解决项；月报基于真实日期重查，用户等不可加指标不能拼周相加。
- 来源、成交游戏、产品、国家、支付或新客户订单标记可用fc.query_es_order_structure按需读取；本期与对照用相同维度/原状态和冻结文件集合，遵循实际已验证游戏字典，未知标签不猜映射。来源×游戏不是广告归因；不凭系列名判断成交游戏。
- ES订单金额（美元）是独立结构金额，实付按原币分列；默认包含全部原状态，已退款、问题、验证未通过等不能当已完成成交。新客户标志是订单属性，不是去重人数或复购率。结构筛选不改变Admin主盘，也不按比例缩放凑齐主盘。文件集合齐不代表上游无截断；保留真实期间、捕获时间、时区/站点/分销未知及部分可用状态。没有site/group字段时不能宣称ES已排除G2G/ELD。报告读取pending时仅查原任务进度，不重提导出。


## 经营主线与知识分工
日报先处理当前优先工作，周报先回答经营销售变化和下周安排；经营结果、销售结构、客户和履约售后优先，流量辅助解释，不写成广告周报。
已有Admin native_loss品类/问题聚合优先使用，Order问题状态及样本补缺；有数据不能写缺失。项目只取指定游戏，全局才跨游戏比较。原生完成率、当前问题池、同批队列最终解决率分开；无固定队列和状态流转不造解决率/超时率。退款金额、笔数、问题金额各自保留，不因0笔抹去非零金额，不再次扣退款构造未确认净利润。
报告写作组织、日期推理、活动方案、行动与交互验收统一见 本任务实际读取的现行 fc.reporting.methods/report 条目；此文件只维护生效业务规则与数据边界。两份approved历史案例只学习方法，不继承日期、金额、结论或权限；新任务按实际知识清单冻结输入及knowledgeSHA，旧任务/历史知识不重写。月报专项未因此启用，不改变调度、模型、预算、collector或业务写入权限。
