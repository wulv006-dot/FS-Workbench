# 经营数据叙事

先明确读者要作的决定，再判断哪些数据值得展示。按经营影响安排重点；销售、利润、客户、履约支付、让利复购、广告及活动等是检查视角，不是必须逐章照搬的目录。

比较、趋势、构成及变化拆解优先用图表；图表选择由你决定。图旁文字提炼最重要的发现、可能解释、建议及验证条件，不重复逐项报数。简单问题可以一句话回答，不为一个数字强建图表。详细原数据放按需展开区域，关键证据和结论默认可见。

保留来源、日期、范围、币种和分母。未知不填零；未成熟观察窗不算失败或已完成。整单金额不是商品收入。将算术拆解与因果解释分开，允许有依据的判断与怀疑，同时说明替代解释和如何验证。

建议围绕实际可执行的动作、条件、时间和复查指标，不硬造责任人、预算或收益率。当前新客首单30%是已确认策略背景，不能反推全部历史订单资格，也不能仅以老客占比证明优惠带来留存。

本技能是FS经营场景适配版本，参考wshobson/agents business-analytics/data-storytelling的方法思想；并非上游插件运行时。用户当前指令与有效数据合同优先。

## 主方法1.5.1补充 · business-reading-20261018-r1

- 汇总原始折扣额/订单金额，与首单标称30%的适用资格、计价基数和范围可能不同；仅凭前者不能判断优惠执行不足或力度偏轻。可提出资格、展示方式及范围等合理假设，先用符合资格订单和对应折扣/核销证据核验。
- 按支付日归组的订单不具有统一单龄；快照距离该日结束的时长不能当作每单账龄。按实际支付时刻/年龄分布看履约，横截面状态不足以证明处理速度变化。
- 行动期限按实际生成时点安排为仍可执行的未来时间；历史分析窗口与未来行动分开，不能把已经过去的今日时刻当新任务期限。
- 经营报告正文提炼结论、影响和动作，不逐数字复述图表；重复口径、原值、计算和一般限制集中到可展开附录。只保留会改变决策的风险，不把修订、审计或验收过程塞进经营正文；布局、图表及阅读顺序自主，不固定章节。
- 已确认的FC游戏利润率按Admin优先、Order补缺规则使用；没有证据不得臆测D4/Aion2等其他游戏混入。参考利润仍为估算，不冒充财务实结。

## 经营判断与呈现检查 · business-reading-20261018-r2

- 优先提出有理由、可验证的经营判断，保持行动性；不要用广告花费占营收的比例排除广告贡献，不把零成交或零曝光直接判成技术故障。先区分流量不足、需求、资格与链路异常，只有实际链路报错或可复现失败才称故障。
- 平台、品类、新老客分别变化，不等于其交叉组合已被验证；可优先调查交叉假设，但不能把边际汇总拼成成交事实。订单数与去重人数、全部付款与新客子集分母明确；优先使用工具返回的scope/unit说明。
- 同批复查以真实历史快照和成熟观察窗为准；缺历史状态就从当前留档，不虚构同期基线。闭日采集的7日窗口结束后再评估成熟结果。抽样总数与分层覆盖要可执行，类别重叠时订单去重。
- 图内变化值也保持红涨绿跌；SVG文字的fill应与方向颜色一致，避免通用svg text规则覆盖，检查切换后的新节点和暗色主题。此项只固定涨跌语义，具体视觉仍自主。

## 周报经营者表达与策略复盘 · business-reading-20261018-r3

- 用户于2026-10-18认可日报bc518d的质量、模块排版和覆盖，日报可继续按其宏观标准执行；周报ab10仍被用户判定模块混乱、语言晦涩、判断和方案不足，技术检查通过不等于用户验收。当前周报须重新优化，不把旧周报当已批准范本，不复制日报数字或固定视觉。
- 周报先给独立主判断与推荐，再用图表和少量直白文字解释。每个模块边界、标题、留白和阅读层级清楚；图表大小与信息量相称、正文不复述报数。缺口只保留影响决策的关键项，不用缺数据清单替代分析。可提出有理由的推断，说明关键依据、反证和验证方式即可，不堆术语或免责声明。
- 运营策略按投入→获客规模与质量→履约承接→复购的经营链复盘，重点回应当前首单30%让利换新客再推复购。主动推荐继续、调整哪一环或小范围试验，给步骤、对象、负责岗位、未来期限、资源、观察指标及停止条件；未经资格/生效与成熟数据验证不伪称政策成效，聚合折扣比例不冒充30%执行率。
- 投放分析应解释专属系列的效率、变化与经营意义，全局品牌单列，联系市场、自然获客和落地页。给明确优先保留/排查/试验对象及具体方案；不凭花费占营收排除影响，也不因归因缺失拒绝提出有依据的小试建议。活动建议有机制、承接和复查，不空喊加预算。
- 上述是思考与沟通原则，不是强制栏目模板。日报、周报可各有侧重，视觉与表达形式仍自主；HTML或其他产物由Hermes创作，FS只提供工具、显示与归档。
