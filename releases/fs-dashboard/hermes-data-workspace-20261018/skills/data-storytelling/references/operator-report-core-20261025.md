# 报告生成与审核的核心逻辑

生效：2026-10-25，用户连续明确纠正。适用：Hermes产出任何报告，以及Codex/ChatGPT的撰写、指导和审核；不局限FC或日报。此规则优先于把历史字段教材、纠错案例机械扩成全篇审计的做法。

## 报告必须帮读者判断和行动

先弄清读者要决定什么，再给全局判断：主要矛盾在哪里，哪些变化最有价值，先做什么、为什么，哪些暂时不值得投入。然后用关键事实和清楚的图表支持，最后给行动与复查。允许有根据的推断和价值取舍，明确用“我判断”“更可能”“建议优先”等正常语言承担判断，不把观点埋进免责声明，也不把每个问题都退回“待验证”。

内部可以全维分析，前台按重要性组织。小问题不硬凑章节，大问题不删成只有漂亮图表。不是越深、越长、越多细节就越好；负责人读完应知道发生了什么、怎么看、先抓哪件事。

## 判断保持宏观，细节精力优先用于表达与可视化

在现有优先数据里，方向一致、影响量级和主次足够清楚，就给方向性判断。细微口径差异、明细未与总盘完全核平、归因尚未成熟、缺少精确单价分解，不自动取消趋势、集中问题、经营风险和优先级判断。限定适用范围即可，不必因此拒绝使用有效子源。

只有差异可能改变问题排序、建议方向、关键金额量级或造成实质误导时，再做最小必要核对；否则停止无收益下钻。工作判断不需要等待学术级因果证明。仍不编造数据、精确因果比例或未执行动作，重大对象/币种错误照常纠正。用户明确要审计、论文或严谨专项核算时，按那个任务的目的深入。

允许明确说“我更倾向这个解释，所以建议先处理这件事”，同时用一句话交代最重要的不确定性。反证与后续验证为行动服务，不要让每段都变成“不能证明A，也不能排除B”。分析建议与实际执行权限分开，既有财务公式、价格护栏、权限和未知写入保护不变。

## 语言要有逻辑，读起来像人说话

每个重点自然串起：判断、理由、业务意义、下一步。标题表达业务判断，不罗列字段名、长串数字或取证术语。重要推断可以鲜明，避免一边给结论一边立即把整段撤回。文字解释图表意味着什么，不逐项复读数字；避免术语矩阵、字段边界说教和反复自证严谨。

## 可视化按人的阅读习惯认真打磨

可视化是按需的表达方式，不是每个回答的前置条件。简单答复、短分析或不适合图表的问题直接用清楚的文字；需要比较、解释复杂结构或正式汇报时再用合适的图表/HTML。不为遵守可视化规则凑图、造页或增加交互；无论是否可视化，先回答核心问题、结论有主次、取舍有理由的逻辑不变。

首屏先给主判断和重点，日期/关键口径轻量呈现；不要让来源、技术限制或生成历史挡在结论前面。全篇层次、图表对照、尺寸、留白、字号、颜色、交互反馈和手机阅读都要实际看。

比较优先用图；不同量纲分开，标签与基准清楚，涨红跌绿兼正负号，非零数据有可见图元。期间/指标切换应符合直觉并同步更新标题、单位和比较对象。重点默认可见，原值、计算、详细口径与技术限制默认折叠；交互减少认知负担，不让用户点开很多处才凑出结论。具体视觉保留自主，不套死模板。

## Codex和Hermes共用的审核顺序

先看是否回答核心问题、是否有主次和可执行方向；再看推理是否连贯、语言是否通俗；然后实际检查视觉层次、图表、交互与阅读体验；最后处理会影响判断的数据问题。内部计算可以认真核，前台不因此膨胀。轻微差异或不影响方向的舍入说明不触发多轮整篇重写。

23号FC报告是用户指定的阅读和可视化参照：标题先判断、重点先呈现、图表比较与指标切换、原值折叠。参考其信息组织，不复制历史数字或不适用的内容。24号旧后补版已被用户否定，不能继续称作获用户认可的质量范本。

## 持久化与实际理解

本规则在项目入口、Git、现有Notion业务规则页及个人记忆更新中留存；Hermes正式报告技能引用同一优先级，并通过实际加载、理解解释和本次报告应用检查。存了文件不等于已经理解，理解复述不等于长期每次都做好。原报告、历史规则与纠错证据保留，但旧案例中的过度谨慎不能反过来覆盖本次用户要求。
