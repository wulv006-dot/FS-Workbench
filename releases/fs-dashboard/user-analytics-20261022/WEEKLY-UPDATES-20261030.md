# 用户分析周更新候选

用户已批准代码、测试、PR、合并及原发布器上线。本段是候选说明，生产是否启用以发布回执和页面 `weekly_update` 为准。本次不缩容历史数据库，不删除任何事实、快照、备份或共享归档。

## 使用方式

- 每周一北京时间04:18起更新上一完整自然周，默认显示周一至周日；开始日仍按日期选择，结束固定到最近成功发布的数据截止日。
- 平日页面刷新、筛选和Hermes使用同一个已发布事实版本。完整成功结果复用缓存；冻结ES文件临时读取失败或部分结果不进入成功缓存，下次查询重新核读同一组冻结文件，原失败快照仍可按ID查看。分类继续按原7/14/30、14/30/60等自然日规则，观察日固定，不随浏览当天漂移。
- 为核退款和更正，每个周批次按完整日重核常用的最近90日，并补齐上次成功版本后的遗漏。更早历史保留小范围轮巡、原未终态定向补查和已有历史回补；不声称所有历史订单每周都复核。超过90日的停更缺口停止自动扩大采集，另行核实恢复。
- 人数和复购率按事实去重，不累加日人数或平均日比例。旧快照ID和原事实保留；未采过、已缺失或覆盖不足的历史不承诺能还原。
- 所有日窗口、补查和跨月分类资料完成后原子切换周发布指针。若随后备份失败，页面明确显示“数据已发布，备份待完成”，后续只补该备份，不重新采集。

## 调度及失败恢复

保留原 `fs-user-analytics.timer` 及600秒服务上限。原04:18、04:33、04:48唤醒分段续同一批；平日完成时只读小状态后立即返回，不打开业务Store、不扫描订单、不生成新报告或完整备份。未完成批次可在后续04:18–05:00恢复窗口接续，锚点保持原批次。每次工作预算360秒，分日边界保存断点，原采集锁逐日获取和释放；遇忙正常让出，不强停其它任务。候选窗口须由父任务与原FC/Hermes工程最终协调，不改其它业务调度或权限。

首次采用从已验证recipe日快照固定事实版本，并将截止锚到上一周末；无可用基线则明确返回首次更新待完成，不能返回全零。已提交但断点未写回的日窗口按同周期完整回执对账，不盲重抓。发布提交后断点丢失则只恢复备份。合同/权限错误、旧单缺失暂停自动重试并保留原数据；瞬态错误接续原批次。

跨月分别确保所涉月份的新老客导出。周版本引用既有内容寻址ES文件的原SHA，读取精确文件集合，不调用“同日期最新导出”替代历史版本。继续复用原XLSX解析器及完整性规则，不改共享ES模块，不复制全部客户名单。

## 备份与容量

同一周批次记录并复用已存在的备份路径；若尚未创建任何目录，首次写入使用实际生成日期以保持原恢复合同。通过manifest内weekly_cutoff对账，跨日或断点丢失均不另造第二份；缺manifest或版本不符保留待对账，不覆盖重复制。旧周补备份若占用了新周同一天的日期目录，只有旧周恢复回执与文件元数据仍一致时才判为已知占用，新周延至下一实际日期接续，不重采、不覆盖；未知或已变化目录仍停止待对账。继续走原SQLite一致性备份、流式hash和恢复校验。周路径不调用永久删除轮换，当前关闭的保留策略不变。

备份仍会逐周增长；有限恢复点和原13GB存量须另列清单处理，不能把周更说成历史缩容已完成。

## 发布、回滚、验收

精确运行目标共8个：`/opt/fs-hermes-fc/` 下新增 `user_weekly.py`，更新 `user_runtime.py`、`user_contract.py`、`user_jobs.py`、`user_query.py`、`user_http.py`、`user_customer_types.py`、`user_tools.py`。界面目标为 `/var/lib/fs-navigation-formal-static/user-analytics-20261022-v1/{index.html,users.js}`。复用原 `user_store.read_at()` 与meta表，无schema变更；现役配置、回放算法和所有timer文件不变。

入口`deploy/release_weekly.py`仅将这10个目标（新增1个）绑定到已使用的host/P4发布器，保留原锁、CAS、原子备份、journal、准入和回滚。原发布器短暂维护Range及原5个采集timer，先核采集自然退出并恢复原状态，不改timer文件或日程，不重启FC、Admin、nginx或原生Hermes服务。共享发布由父任务串行协调；活动发布退出后重取现场hash、锁身份和服务状态，形成最终清单，不能用候选包或旧基线直接apply。必要Range加载、Hermes原生新会话工具说明载入分别留证，不将文件存在当模型实际使用。上线前重核实际hash、维护状态和并行任务，不套旧主机PID或静态保护hash。

回滚恢复该批文件并受控加载原读取服务，保留所有事实、周元数据、旧新快照和备份。旧读者仍能读取新recipe冻结快照；恢复旧日更代码会恢复原高频行为。先核周任务自然结束及备份目录，不盲重放未知状态。

新增测试覆盖默认完整周、按日开始日期、固定分类观察日、跨周跨月、未发布事实隔离、权限撤销、缓存、预算/断点/原子发布恢复、首次采用/首次安装、备份幂等及部分目录保护。原正式CI加入本测试模块，不新增workflow。实际周一源采集、耗时、原生模型使用及生产恢复效果仍须发布后单独验收。
