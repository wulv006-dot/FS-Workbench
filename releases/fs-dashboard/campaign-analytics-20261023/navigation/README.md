# 主站活动区与菜单一致性修复

范围：将活动转化分析移到球类工作区上方的独立「主站活动区」，加入商品编辑直达；正式看板移除演示和本机体验选项，保留真实正式/联调查询。

根因：现行静态首屏导航、共享 hubnav 内置快照和实时 navigation.json 不一致；仅改 JSON 无法同步各页面。prepare_release.py 从当前合法现场生成同一清单的静态菜单、共享脚本、数据分析目录及首页卡片，保留主题、抽屉、账号与权限校验。既有菜单功能不删减，活动入口只迁移一次。

发布：release_ui.py 复用现有 traffic-source-tabs UI 发布器、两把锁、逐文件CAS、持久回执、备份和限定回退。17个目标；只重载Nginx及重启活动服务，密钥/state/业务主页作为保持项；不重启业务采集或认证。先prepare、inspect，再按同一manifest SHA apply，结果未知先查原release ID，不能重放；回滚不恢复运行数据。仅服务端响应移除体验选项，开发包的离线调试能力保留。

验证：模块44个Node测试及3个发布/导航合同测试；候选两共享脚本语法与十个静态页面菜单顺序检查；真实入口、手机抽屉、主题、当前页高亮、两个PostHog来源及服务重启后真实读回另验。QA和部署状态以本次交付回执为准。

准备脚本是本次发布构建器，必须从修改前的实时基线执行一次；原候选、manifest与备份保留用于对账，不能在已发布现场盲目再运行。生成的Nginx配置/现场基线不入Git。
