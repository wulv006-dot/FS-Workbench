# Order 临时占用后的有限重读

本次只修改共享经营分析页及首页的前端读取状态处理，不改变 Admin 主源、Order 补源、财务口径、采购成本、自动采集或写价任务。

## 恢复的行为

- 已知临时占用 `collector_busy` 或 `scheduled_collection_due` 不再直接终止本次查询；在原 100 秒预算内每 30 秒重读一次，持续占用时最多在约 0/30/60/90 秒请求。
- 普通读取中仍沿用 2 秒轮询；永久错误和未知延迟原因不自动重试。切换日期或停止组件会取消旧查询。
- 没有历史 Order 值时不再显示“已过期”。实际保留的旧值仍显示过期状态，不能把缺失或旧数据伪装成新数据。
- 今日 900 秒、历史 7200 秒缓存与 D1=昨日保持不变。历史页面停留不新增周期轮询；此次有限重读只属于一次主动查询。

## 已验证与边界

dot 云端完成 18 项新回归、27 项相关后端测试、既有前端投影/图表、延迟、日期策略及发布入口引用检查。3 个修改的 JavaScript 文件语法检查通过。新回归已登记到原 pr-fast 受影响测试组。

本次前端修复可处理短暂占用后的重新读取；不承诺超过 100 秒的上游占用自动恢复，不解除服务端锁，不改变后台定时任务，不强制重放采集。

云端没有 sudo，真实 Linux root 所有权发布器测试需由已授权的 GitHub Actions 执行。模拟时钟验证不替代生产浏览器验收。
