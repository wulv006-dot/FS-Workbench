# FS 经营知识与纠错闭环

生效：2026-10-16，来源：吴律本次明确要求及施工方案V2。适用日报、周报、月报与独立定价策略分析。此说明替代旧“原生记忆不自动进入FS”的接线状态，不修改旧任务记录。

用户在Desktop明确纠正或确认一条业务规则后，立即保存到 /fs/desktop-business-context.md：记录日期、来源会话、规则、适用范围、生效条件、替代条目；先保存并读回，再说“已记住”。稳定业务要点可同步原生memory；只在旧会话中说过而没有保存，不能称长期记住。不需要用户每天再贴样稿或批准同一规则。

下一个新FS任务在复用判断之前读取已保存的业务约定、专用业务profile的MEMORY/USER与已审方法，自动按内容SHA发布不可变learning版本，冻结该任务的知识和方法。历史/在途任务保持旧版本。同request_id仍是原任务；知识更新须新请求，不重放旧模型。报告必须留知识版本及加载回执。未保存的聊天和研究新假说不能自动升级为已确认业务事实。

报告开始两三句讲结果、判断与优先动作；重要专题默认可读，详细口径和证据置附录。新闻采用已有中文经营分析，英文摘录只是来源预览。只凭单小时没有尖峰不能排除全天事件或持续投放。

日报分开业务日、前日、同星期与最近14完整日趋势；请求14日不代表已取得14日。用户原问题明确指定主对照时保持原意，历史15日报告以14日为主对照、8日为同星期。局部缺失只降级对应指标/图表，不补零、不从正文抄数充证据。周报/月报遵循各自完整自然周期与同口径比较，不累加去重人数或平均日率。

行动保留原文首查/执行窗口、全部复盘日期、优先级、对象、角色、条件和停止标准；今天/立即锚定原编制北京时间，未知日期写待安排，不因下载重排到明天。对不同支付日队列做同日龄比较，需要分别取得各队列T+3等快照；同一日把两批都查一遍不构成同日龄。

定价研究与经营报告分轨。允许有据运营判断和条件式建议，不因局部缺口把所有动作退成等待；真实新售价仍核有效成本与当前可比实价。学习规则可以自动生效，研究建议不因此自动获得改价、付款、账号或消息发送权限；已有明确业务授权按实际工具与合同执行，不重复索取一般授权。

## 2026-10-16 真实FS验收后的修订规则

来源：用户本次截图与“必须真实从FS生成后再验收”的明确纠正；实际新任务0d0085b0中发现表格简介未被阅读层识别、主对照未明确绑定、计算器参数错误不可见。以下替代之前允许英文简介、全文默认展开的呈现约定。

报告开头两三句摘要，随后单独一行写“主对照：YYYY-MM-DD 至 YYYY-MM-DD”。严格按任务规范窗口的primary_comparison，除非用户原问题明确指定另一窗口；前日、同星期和14完整日趋势分别分析，不用默认主对照给所有图强行换日期。为所用两期取完整汇总和需要的分组分页；缺主窗支付分组或参考率时，单列有证据的前日辅助，清楚标日期，不把有数据的订单量和利润整体弄丢。成本仅展示已有已核实来源；参考利润不是成本，不倒推财务成本。

活动与情报简介必须中文。对实际读取并在阅读版展示的每篇官方文章，给一到两句该文实际内容介绍，讲活动机制、资格、升级条件、版本修复或情报要点。不要用欢迎语、英文摘录、行动计划或“背景”两字代替内容；一文章一行，标题按实际来源保留，可用表格“发布日 | 文章标题 | 内容简介 | 影响判断 | 建议行动 | 来源URL | 实际读取时间”。六篇正文已读就逐篇给六条简介，背景文章也给简短内容要点；不能共用整段。英文原文仅在折叠来源内保留。若确未取得或未能整理，明确中文待补，不伪造内容。

完整研究默认折叠，关键判断和图表可直接看。支付模块同时给订单量和金额；缺项说明原因，不显示空表冒充已有。参考利润需保留真实对应日率及前日辅助，不因同星期率缺失而全部隐藏。

计算器每项values必须绑定同条实际ev的/data/...路径（从完整证据信封根开始，例如/data/total/revenue_usd；分组用实际groups数组下标），assumptions与values等长，真实证据项的assumptions为空字符串。返回invalid_arguments表示未计算，按code及实际证据结构修正，不能称工具已算对或反复猜路径；不得用虚假“假设”绕过真实字段校验。

出稿前复核：同日龄比较必须有各支付日队列各自T+1/T+2等真实历史快照，同一天查询两批不能当同日龄；缺历史就给分别观察方案。AU是澳大利亚，不能归为欧洲。对照期某分组大额单会抬高该分组基数，从而压低其本期差额，不能写反为放大整体增长。只凭两周或小时无尖峰不能断言“正常周内规律”、排除活动/持续投放或认定通道故障。预设百分比及日数是未校准观察建议，不得当已确认因果或自动停止政策。

用户随后明确：阅读页不展示历史原文；每个数据模块展示数据后必须给一句对应判断，不能只有数据。报告正文必须分别用“### 销售与订单结论”“### 平台与商品结论”“### 客户、支付与未完成订单结论”“### 利润与成本结论”“### 游戏与市场情报结论”各给一段短句，讲清本模块最重要的变化、对经营的含义或优先动作；仅一句、不要重复通用免责声明。这五段会由FS放到对应数据模块后，完整研究默认折叠。缺成本等真实缺口可在本模块判断中讲明影响，但不把整个模块退成“等待核对”。
