# FS 按业务日期归档

所有者：吴律；调用方：FS 经营准确区间/原生统计、营销区间、渠道效果、Hermes 原生统计工具。状态：候选，未上线；实际状态以验收记录为准。

复用现有 Admin/Order/营销读源、会话、原生区间锁、渠道日归档及 ES 导出。新层仅用 Python 标准库 SQLite 建日期/合同索引，以 gzip 保存不可变完整响应；不安装额外数据库或改变生产写价、采价、定价、自动化开关。

## 查询

- 历史完整区间优先归档；合同、游戏映射和精确日期须匹配。保留原取数时间，较旧归档立即返回，同时按原冷却/并发限制后台校正。今日、小时、当前队列和价格仍走原路径。
- 完整同口径日归档可推导加和财务字段；整段人数、原生率及维度保持未知，由原区间 API 异步补充，不平均日利润率。
- 渠道部分日期命中时仅补缺日；已有整段的自动校正及手动强刷仍保留。Admin 逐单单次至多一个月的完整分页合同沿用。
- 原生统计/Hermes、营销和渠道共用现有入口。`/range?mode=archive-catalog` 仅登录用户可读日期覆盖元数据；最早/最晚边界不表示连续完整，`complete=0` 的 ES 引用须由原导出阅读器实际校验。

## 调度及保留

新增独立 `fs-data-archive.timer`：上海时间 00:50 预热昨日与截止昨日的 7/30 日常用区间；01:00–06:45 每十五分钟有界续跑及补历史。每次最多八分钟、原并发/锁/限流保留，遇忙退让；不取消正常任务。原渠道 00:35、历史补采、营销和交易定时器不变。历史从 2026-09-01 起逐步补，未完成不声明覆盖。

按业务日期滚动保留三个月（按月回溯并钳制月末），更早日期按需走原接口、不重新长期归档。每日夜间清理由 catalog 精确列出的本层 gzip 对象，记录截止日、数量、字节及版本；不递归删除目录，不清理报告、审计、账本、备份或来源原始留证缓存。现存其他模块的清理由原模块继续负责；本模块不擅删可能被冻结报告引用的原文件。

## 验证与回退

`python -B -m unittest discover -s tests -v`：归档/源合同、原时间、缺日、不可加和字段、源禁用、损坏与边界、三个月保留、夜间候选及两个路由 driver。driver 通过不代表真实 Linux 接线。

按 `deploy/archive_release.py` 复用既有锁、CAS、准入栅栏、备份及回退发布器，只允许清单列出的十五个目标及两个新增单位。回退只还原代码/单位并停新增 timer，保留所有数据库、归档与回执。`archive_jobs.py --seed` 只导入已有完整且同合同的源或登记引用；`--scheduled` 安全重复并续用原请求。已装入 skill 须由新任务冻结清单证实，不等于模型已掌握。

## 借鉴

沿用 [DuckDB 日期分区过滤](https://github.com/duckdb/duckdb-web/blob/main/docs/current/data/partitioning/hive_partitioning.md) 的按日期缩小读取、[dlt 分段补采](https://dlthub.com/docs/examples/backfill_in_chunks) 的小批游标，以及 [Superset 缓存配置](https://github.com/apache/superset/blob/master/superset/config.py) 的分源有效期思路。当前数据量使用既有标准库即可，不引入其完整平台。
