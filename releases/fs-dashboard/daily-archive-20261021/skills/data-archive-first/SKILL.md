使用现有已授权工具。`fc.query_native_statistics`、`fc.query_marketing_snapshot` 及 FS 渠道查询已接通归档；相同日期、游戏、站点和统计合同的完整归档可直接复用，无须为“更新”重读全部历史。当前队列、今日、售价、库存等可变事实仍按原实时工具及有效期读取。

2026-10-22 用户更正：历史销售额、利润等经营汇总按已确认固定事实复用，不按两小时或十分钟重复采集。流量/营销有 3–5 日延迟，最近五个业务日及包含它们的常用区间需按日补采校正；此窗口内标为 provisional，不把首次 available 或空数据当作最终值。更早完整区间直接复用，仍保留手动刷新；成熟窗口不等于上游永不修订。

不能仅因日历跨过第五日就把早期快照冻结：第六日以后至少完整读取一次封账数据。若只有前几日的采集版本，接口标记 awaiting_final_recheck，先返回原版本并补读；完整成功后才退出滚动窗口。来源自身仍标临时或缺日时保留该限制。

1. 先明确业务日期、站点、游戏、状态、币种及指标来源。业务日期是事实所属的统计日期，不是补采日期。保留原取数时间与证据版本，不能把命中归档说成刚读取后台。
2. 看返回的 `archive`、`sources`、完整性及缺口。目录最早/最晚日期不证明中间无缺日；`complete=0` 只是待校验引用。部分、失败、空缺不能填零或当完整结果。
3. 优先使用同合同的完整区间归档。只有逐日事实完整且口径一致时才做可加和计算。金额、订单数可按去重和对应合同汇总；跨日人数、复购率、原生利润率及整段维度不可直接相加或平均。接口会给出可推导财务值和待整段查询字段，保留其未知状态。
4. 区分“统计覆盖完整”和“每单有成本”：未完成单没有成本；SCM 缺成本不是零成本。仅已核确切 FC 平台优惠券可按现行业务基准零成本计利润。
5. 历史归档按业务日期滚动保留三个月，更早日期仍可通过原接口按需重取。夜间补采从 2026-09-01 起，遇忙、权限拒绝或来源失败要报告缺口，不取消他人的任务，不换会话绕过，不重复强刷。

报告按计划发布，缺失部分数据不阻塞。先检查本任务来源和日期的完整性，复用已成功的证据；失败来源由原持久补采账本退避重试。可根据可比趋势、已核相关数据和明确经验推算，但必须逐项标注“预估，真实数据暂未提供”，列证据、计算方法、假设、适用范围、不确定性和复核条件；依据不足则保持未知，不填零。预估只存在于报告分析，不能混入真实采集、销售总额或已验证经验。真实数据到齐后回看原报告，核对估计与实际及误差，保留原稿并追加修订。采集成功不等于预估成立，尚未核对时明确待验证。

训练时自己说明：为何选此来源、哪些字段能算、还缺哪些证据、什么新事实会改变判断。给出答案不等于已学会；用另一个日期或游戏的真实只读任务检验迁移能力。本文不授予改价、写价、上品或策略自动修改权限。
